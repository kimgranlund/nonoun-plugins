## Hazards learned
- Never edit or move scripts while a bench or role run is live. Replace a script atomically (write a new file, then `mv`), and never restructure mid-bench.
- Killing by name pattern (`pkill`, `killall`, `kill $(pgrep ...)`, `ps` output piped into `xargs kill` or fed to `kill $(...)`, a kill word held in a shell variable like `p=pkill; $p x`) stops other sessions' processes: `hooks/block-pattern-kill.sh` (PreToolUse(Bash)) blocks it inside role runs (`SDLC_ROLE` set), failing closed on heredocs and shell or evaluator command words; builders stop only the PIDs they started and run formatters only on the files the step changed (`check.py` guards both builder.md phrases).
- In a headless session, ending the turn ends the session: role runs stay in the foreground. `scripts/bench.sh` raises the Bash timeouts for that. Headless means foreground, now enforced: `hooks/block-background.sh` denies Bash `run_in_background` calls and denies any Agent call unless `run_in_background` is explicitly `false` (Agent runs in the background by default, so a missing field counts as background) when `SDLC_ROLE` is set or `SDLC_HEADLESS=1`; bench.sh and fanout set `SDLC_HEADLESS=1`, and any other headless launcher must set it itself. `scripts/hook-live-probe.sh` (opt-in, one small model call) proves against a real `claude -p` session that the live PreToolUse(Bash) payload carries `tool_input.run_in_background` as a JSON boolean and that the hook denies it. In an interactive session a role or a bench task's /chain can take 15 to 30 minutes, past the Bash tool's 10-minute cap, so /chain, /bench, /fanout and the conductor must say: run `run.sh` with `run_in_background: true`, wait for the completion notification, never poll with `sleep`, read `<role>-<level>.md` once notified (ending the turn is safe there), and the foreground `timeout` rule is for headless sessions only. `check.py` enforces this in those four docs (chain, bench, fanout, conductor) (words `interactive`, `run_in_background`, `notification`, `sleep`, `SDLC_HEADLESS`; no unqualified `never run_in_background`).
- Benchmark tasks: the goal must name every name, field, path, and message format the hidden tests pin, and constraints must let builders update tests the change legitimately breaks. Red/green-verify a task in a throwaway worktree before adding it.
- A verifier pass with a hidden-check fail means find out which one is wrong before tuning anything.
- The merge-step conflict-marker guard reads `git diff-tree --cc HEAD` (`++` lines only), so a lane's own marker-like lines pass. The check.py probe holds seven cases: empty, marker, legit lane line, both-sides legit lane line, real conflict kept, aligned kept marker (the documented miss), and clean. A kept marker textually identical to a parent line passes by design.
- Fanout lanes live in the gitignored `<toplevel>/.worktrees/fanout`, not a sibling dir. `.gitignore` does not exclude `.worktrees/` from vitest, tsc, or file watchers (the project must exclude it in their config), and Node module resolution walks up from a lane worktree into the main tree's `node_modules`.
- Never touch the user's working trees, branches, or stash in other repos. Use throwaway worktrees and remove them.
- Role runs put throwaway worktrees only under `$SDLC_TMP_WORKTREES`: run.sh exports `SDLC_TMP_WORKTREES=<toplevel>/.worktrees/tmp/<role>-<pid>` and removes every worktree under it on any exit, then runs `git worktree prune`.
