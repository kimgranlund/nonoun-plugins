## Goal
Every place that describes the mailbox messenger says that a subagent can report only into a parent turn that is still running and cannot wake an idle host, and names the tested workaround.

## Intent

- Non-goals: any code change besides the entry template text; rewriting `docs/validation/release-0.20.2.md` or `docs/validation/messages-live-run.md`; the `wait` command (T-0181); the watcher (T-0182).
- Done when: the exact sentence `cannot wake an idle host` appears in each of the five files above, the checks in the step pass, and nothing else changed.

## Context
A user running Codex found that a messenger subagent cannot wake a host agent that has gone idle, so they keep the host in an active turn with `/goal ...` in Codex. The same holds on Claude Code: a subagent's report is delivered into a running parent turn, and no subagent can start a parent turn that has ended. The live runs in `docs/validation/messages-live-run.md` covered only an active parent: the Codex parent prompt told it to wait on the messenger and spawn it again until a report named a claimed message, and the Claude parent ran the messenger in the foreground. Released in 0.20.2 without this limit stated.

Wording to use, adapted to each file: "A subagent, including the messenger, can report only into a parent turn that is still running. It cannot wake an idle host on Claude Code or Codex. Keep the parent in an active turn: on Codex run `/goal` or have the parent wait on the messenger and spawn it again; on Claude Code keep the foreground session working. The live runs covered only an active parent." The entry template already has a `## Host limits` section; extend it, and keep every existing statement there.

The note file states the date (2026-10-01), the limit, the evidence it was not tested (the live run's parent prompt and the `wait` tool calls in `docs/validation/messages-live-run/codex-messenger.txt`), the workaround, and that T-0181 (a blocking `wait` command) and T-0182 (an external watcher design) address it. Entry files are generated by `messages.py` (the repo's `.sdlc/messages/AGENTS.md` is git-ignored output, not source). No em dashes anywhere.
