## Goal
Plan defects stop fewer lanes: a verifier-proposed replacement criterion is applied to the step handoff by `steps.py swap` and the step rebuilds, instead of a planner L3 replan, whenever the swap is provably safe, and the planner's rules keep criteria stable across main syncs and guards able to go red.

## Step 1: `steps.py swap` applies a verifier's replacement criterion, `next` routes to it, and the verifier states the swap format
level: L3
### Do

1. `plugins/sdlc-lite/scripts/steps.py`: add a `swap <step dir> [--timeout SECONDS]` subcommand (default 300, validated like `--guard-timeout`). Reuse the helpers that exist: `order.newest`, `order.ordered`, `order.counts_after`, `section`, `verdict_or_none`, `is_plan_defect`, the `criteria_lines` region rule, `line_spans`, `is_guard_line`, `guard_skipped`, `lint_steps`, `run_guard`, `tree_state`, `tree_changes`, `git_toplevel`. It writes only `<step dir>/handoff.md`, and only after every check below passes.
   - The proposal. A shared `swap_pair(path)` returns `(old span, new text)` from the `## For the next attempt` section of a verifier result, or None. A pair is exactly one line starting `swap old:` holding exactly one code span (stripped like `line_spans` strips), and exactly one line starting `swap new:` whose value is the rest of the line, stripped. Zero or two or more of either line, or a `swap old:` line with no span or several, is None.
   - Preconditions, each a refusal: the dir has a newest builder result and a newest verifier result; the verifier counts after the builder (`order.counts_after`); its Verdict is `fail`; `is_plan_defect` holds; `swap_pair` is not None; no other verifier result in the dir has a `swap_pair` (a second swap on one step is refused).
   - The target line: among the handoff's criterion lines (the same region as `criteria_lines`: under `### Acceptance criteria`, outside ``` fences, a `-` or `*` list item), exactly one holds the old span among its `line_spans`; zero or several refuse.
   - The replacement: the new text starts with `(guard)` exactly when the target line `is_guard_line`, else refuse; `line_spans` of `- ` plus the new text holds at least one span, else refuse (a swap needs a runnable criterion); no span is `guard_skipped` (a `HEAD^1` or `<placeholder>` span refuses); `lint_steps` on a one-step block whose only criterion is the new line returns no finding, else refuse quoting the finding.
   - The run: each new span runs through `run_guard` from `git_toplevel` of the step dir, else the step dir, under `--timeout`; a nonzero exit or a timeout refuses, because the build is in the tree, so the replacement must hold now. In a git work tree, `tree_state` before the first span and after the last must be equal (`tree_changes` empty), else refuse naming the paths; nothing is undone.
   - Already applied: when no criterion line holds the old span but one criterion line's text after its marker equals the new text, print `swap: already applied` and exit 0, writing nothing (the chain may have died between the swap and the rebuild).
   - The write: replace only the target line, keeping its indentation and list marker, as `<indent><marker> <new text>`. Print one line naming the step dir, the old span, and the new text.
   - Every refusal prints on stderr, ends with a last line that starts with `plan defect:` and ends with `; replan this step (/chain 4.2)`, exits 1, and writes nothing.
2. `next_action`: replace the `is_plan_defect(v)` branch. When `swap_pair(v)` is not None and no other verifier result in the dir has a `swap_pair`, return `('swap', <build level>, '<name> failed with a plan defect and proposes one criterion swap; apply it with steps.py swap, then rebuild at L<n>', read)`; otherwise `replan` as now. The reason text must hold `steps.py swap`. A swap-routed verifier stays uncounted for rebuild and bump, like any plan-defect fail.
3. Module docstring: add a `swap` paragraph stating the rules above, and add to the `next` rules: a `plan defect:` fail with one `swap old:`/`swap new:` pair and no earlier swap on the step -> `swap L<build level>`, else -> `replan`.
4. Selftest cases, each named so its line starts with `ok: swap: ` or `ok: next swap: ` when it passes:
   - (a) a pair applies: only the target line changes, its marker and a sibling `(guard)` line are kept, exit 0, stdout names old and new;
   - (b) already applied: exit 0, no write;
   - (c) refusals, each writing nothing with a `plan defect:` last line: old span in no line; in two lines; tag mismatch in both directions; new text with no command span; new span with an unquoted `||` join; new span with a `<placeholder>`; new span red now; new span that changes the work tree (a throwaway git repo as in case (o)); verifier older than the newest builder; newest verifier a pass; a fail with no `plan defect:`; a plan defect with no pair; two `swap new:` lines; a second swap on the step;
   - (d) `next`: a plan-defect fail with a pair -> `swap L2`; with two `swap new:` lines -> `replan`; a second swap on the step -> `replan`; the existing DEFECT fixture (no pair) still -> `replan`.
5. `plugins/sdlc-lite/agents/verifier.md`: after the `plan defect:` sentence, add the swap rule. When the verdict is a plan defect, the work matches the step, exactly one criterion is defective, and the build itself needs no change, the verifier may propose a swap by adding, after the `plan defect:` line, two lines: `swap old:` with the defective criterion's command span in backticks, verbatim from the handoff, and `swap new:` with the full replacement criterion (starting with `(guard)` when the old line has it, holding a runnable command span, no `||`, no pinned sha, no `<placeholder>`). It proposes only a replacement it has run: green on the built tree, and seen red in the throwaway worktree at HEAD (a new-behavior criterion) or in its un-negated or fixture form (a guard), and it says so in the note. Never a swap when the build still needs a change, when two criteria are defective, when the fix needs a change to the Do, or when the replacement is prose. State that `steps.py swap` applies it and reruns the spans, so a swap that does not hold now goes to a replan. `plan defect: <criterion> <why>` stays the first line.
6. `plugins/sdlc-lite/scripts/check.py`: add `'swap old:': ('agents/verifier.md', 'scripts/steps.py')` and `'swap new:': ('agents/verifier.md', 'scripts/steps.py')` to `PLAN_DEFECT_DOCS`, and name the swap in the docstring's item 5.

## Risks
- The swap runs verifier-proposed commands from the conductor's session, the same trust `split --only` gives planner guards; the tree-change check refuses side effects but undoes nothing.
- The green-now run proves only that the spans exit 0 with the build in place; the reverify after the rebuild is the real check, and a swapped criterion that a fresh verifier still finds vacuous comes back as a second plan defect, which the cap sends to a replan.
- A builder's `plan defect:` note (T-0152's stale `children:` line came from a builder) stays on the replan path by design, so part (c) of the ticket helps only verifier-found defects.
- Peers T-0124 and T-0125 edit `planner.md`'s rule list and `steps.py`'s lint in parallel lanes; conflicts at the end of the rule list and in `PLAN_DEFECT_DOCS` are likely and mechanical, and a T-0125 lint lands in `lint_steps`, which the swap reuses.
- Step 3's `check.sh` guard takes 2 min 16 s on this host; a loaded host near 300 s would report a false plan defect at `split --only 3`.
- Rules 11 and 12 are prompt rules with phrase guards, not lints: "can go red" and "membership" are semantic, so compliance is the planner's, checked by the verifier's checks-that-bite pass.
