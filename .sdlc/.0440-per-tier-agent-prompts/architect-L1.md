## Approach
Split each role prompt into an invariant body and a per-level overlay, joined at generation time. `agents/<role>.md` stays the one hand-written contract and is the complete answer to "what is identical at every tier": brief, rules, stop ceilings, resume, output sections and the `results.py` schema, hooks, the red checkpoint, no push or publish, the tmp worktree prefix, the model-family rule. A new `plugins/sdlc-lite/overlays/<role>.md` holds one `## L<n>` section per level that needs one. Both generators (`claude_roles.py definitions()`, `codex_roles.py instructions()`) insert the row's section as a `## At this level` block immediately before the body's `## Output` heading (every role body has exactly one), with a fixed first line: `You run at level L<n>. Where this section seems to differ from the sections above, those win.` A row with no section gets today's byte-identical body, so rollout is per row and the mechanism alone is a no-op. Overlays are keyed by level, not model or effort: level is the one scale both hosts share (check.py item 43), the Codex rows reuse the same files unchanged, and `dispatch.py prepare` can move a verifier or plan-reviewer to another model family at the same level (dispatch.py:208-218), so an overlay must never name a model. The generator refuses an overlay that would touch the invariants: any `## ` heading inside a section, any heading from `results.SCHEMA` for that role, a section over 20 lines, a file for a role with no `levels.json` row, an unknown level key, or the whole-word tokens push, publish, PR, pkill, killall, run_in_background, /tmp (matched as words, so "PR" inside another word passes). Overlay text is emphasis, defaults and framing; it refers to body rules by number instead of restating them.

What varies, by band. The bottom row of a role's table, where it runs at low effort (builder L1 Sonnet low, solo L1 Sonnet low, scout L1 Haiku low), gets a directed overlay: an ordered procedure that names the body rules in the order they fire, and gap defaults for gaps the body does not already route (a file the Do names that does not exist: create it; the Do and a criterion disagree on a name: the criterion wins, note it; two readings both pass the criteria: the smaller edit, say which; no convention given for a new test or file: copy the nearest existing one in the same folder; read nothing past Read first and the files the Do names), closing with "stop only for the gaps rules 3 and 8 route". The top row of each role's table, where it runs at xhigh or at the strongest model (builder L4 Opus xhigh and L5 Fable xhigh, planner L3 Opus xhigh, verifier L3 Fable xhigh, solo L3 Opus xhigh; architect L1 Fable high and plan-reviewer L1 Opus high as single-row roles), gets a goal-framed overlay: the goal in one line (a closed step, a plan that passes review first time, one actionable verdict), a KPI the role can observe (first verifier pass; for the verifier, minutes to verdict and one settlement per criterion; for the planner, fewest steps that pass review), the body's own ceiling restated as the budget, and judgment rules whose delta over rule 10 and T-0428 is explicit: decide instead of enumerating (two designs that both meet the criteria: the smaller diff, the other in one line), investigate only what a failing check points at, trace contract dependents only for the contract the diff changes, and for builder L5 read every earlier builder-*.md and verifier-*.md in the step dir and write the root cause in one Notes line before the first edit. Middle rows (builder L2 and L3, planner L1 and L2, verifier L1 and L2, solo L2, researcher L1 to L3, archaeologist L1, filer L1) are the baseline the bodies were written for and get no overlay until an A/B says otherwise. Conductor and messenger have Codex rows but no `levels.json` row and get none: the lookup finds no file, and the check.py item refuses one. Codex carry-over is the same files: `instructions(role, level)` picks the same `## L<n>` section for the row's level whatever its Codex effort, alternates share their level, fingerprints change as any regeneration does; the Codex prelude is untouched and no Codex-specific overlay exists, so the first build changes exactly `sdlc-builder-l1` and `sdlc-builder-l5` on Codex.

Proof is a role-level replay, not a full-chain bench: the planner's level choice would confound it and the chain costs ten times more. The fixed set is the five bench tasks (`plugins/sdlc-lite/bench/tasks/*.md`), each with an archived plan and step dirs under `plugins/sdlc-lite/bench/results/2026-09-27-<name>/`. The replay unit is one step handoff built in a throwaway worktree at the task's `base`, dispatched with `dispatch.py prepare builder <level> <step handoff>`, recorded with `dispatch.py record --transcript` so the row is priced, graded by the task's hidden `check:` command, then one verifier at the rubric level. Arms: A is a plugin root at the commit before the overlay files (or the same commit with `overlays/` removed and regenerated, which is byte-identical by construction), B is main with the overlays; `bench.sh` already takes the plugin root. Cells: 5 tasks at L1 and 3 tasks at L5, both arms, two repetitions (32 builder runs plus their verifiers; L5 cells dominate the cost at an estimated $100 to $250 [U], which the maintainer caps). Measures, all from records that exist: cost_usd per builder run by level (runs.jsonl; estimates, tool_uses capped at 50), builder blocked rate (`fleet_collect.py` results.builder.blocked), first-pass rate (hidden check pass and the first verifier attempt pass), builder and verifier minutes from attempt records (finished_at minus started_at, by level, the 2026-10-10 method). Drop rules: the L1 overlay is dropped if its blocked rate is not below arm A's, or any task's first-pass rate falls, or cost rises more than 10 percent; the L5 overlay is dropped if cost per closed step is not at least 15 percent under arm A's at equal or better first-pass rate; any hidden-check regression drops that overlay outright (pillars: quality gates stay). Dropping means deleting the overlay file and regenerating; the mechanism stays at zero cost. The result is recorded as `.sdlc/evals/0005-builder-overlays.md` plus a dated report; the table lock is untouched because no model row changes.

Build split: the first ticket is the mechanism in both generators plus `overlays/builder.md` with `## L1` and `## L5` only, the two ends of the hypothesis on the role the evidence names; it lands on main and is a no-op for every other row. The second ticket is the A/B spike above. The third, gated on the A/B, extends `overlays/builder.md` to L2 and L4 and adds `overlays/verifier.md` (L3), `overlays/planner.md` (L3), `overlays/solo.md` (L1 and L3, additive to the per-level Stop rules and Verification text that check.py items 18, 21 and 25 pin in `agents/solo.md`, which stays where it is), `overlays/scout.md` (L1), `overlays/architect.md` (L1) and `overlays/plan-reviewer.md` (L1).

## Constraints and assumptions
- Each generated definition is the role body verbatim under a generated frontmatter: verified by claude_roles.py:92-106 and the selftest case at claude_roles.py:189.
- Codex builds developer_instructions per role, not per level, from the same body: verified by codex_roles.py:53-62 and 134-145.
- Every role body has exactly one `## Output` heading to insert before: verified by `grep -c '^## Output' plugins/sdlc-lite/agents/{builder,solo,verifier,planner,researcher,scout,architect,archaeologist,filer,plan-reviewer}.md` (1 each).
- An overlay cannot live in `agents/`: check.py:282-290 treats every `agents/*.md` stem that is not a session agent or a generated stem as a role file needing `levels.json` rows; the Claude `plugin.json` has no `agents` key, so the host scans the default `agents/` dir. Whether it scans subdirectories: unverified, which is why `overlays/` sits at the plugin top level.
- A verifier or plan-reviewer definition may run on another model family at the same level and effort: verified by dispatch.py:208-218 and selftest cases 1452-1460, so overlay text never names a model.
- Level is the one scale for roles, tickets and solo: verified by check.py docstring item 43 and the level-rubric "One level scale" table.
- The measures exist in collected records: cost by role (fleet_collect.py runs.cost_usd), builder blocked (fleet_collect.py:18-20, 371), attempt minutes and level (`.sdlc/0440-per-tier-agent-prompts/architect-L1.attempt.json` holds level, model, effort, started_at), transcript pricing (dispatch.py:87-89).
- `bench.sh` runs headless with `--plugin-dir "$root"` (bench.sh:29) and bench results hold planner files and step dirs (`bench/results/2026-09-24-button-geometry-model/`): verified by listing.
- Solo's per-level text is pinned in `agents/solo.md` by check.py items 18, 21 and 25: verified in the check.py docstring, so solo is not in the first build.
- The low-end evidence is from Sonnet low plan-doc drivers (docs/reports/2026-10-11-plan-doc-live-run.md), not from builder L1 runs; the high-end evidence is lane cost (the $39.24 L5 step and three planner rounds in docs/reports/2026-10-09-l4-full-chain-cost-replay.md), not prompt cost: verified as stated in those reports; whether a prompt change moves either: unverified, the A/B decides.
- Model and effort rows stay as they are: no row is read or written by this design; verified against the handoff constraints.

## Rejected alternatives
- One body with conditional markers (`<!-- L1 -->` spans in `agents/<role>.md`): Codex `body()` and the check.py phrase checks read the role file raw, markers mix invariant and variant text so "what is identical at every tier" is no longer enforceable by file, and the verbatim selftest loses its meaning.
- Per-row hand-written bodies (`agents/builder-L1.md` as a source): eleven rules times five copies drift, and about thirty check.py phrase checks pin `agents/<role>.md` and would need per-row copies; T-0276 introduced the generator to end that.
- Injecting the tier text into the brief (`dispatch.py prepare`, `solo_run.py`, `fanout.py`, `run.sh`): four producers whose prompt shape the dispatch selftests pin (dispatch.py:1722), a user-message line weighs less than the definition's system prompt, and Codex request prompts are a fifth path.
- Keying overlays by effort or model: effort differs per host for the same level (Claude verifier L1 medium, Codex low; Codex planner L3 high, Claude xhigh), so hosts would diverge for one level; model-keyed text lies under the family remap.
- Changing stop ceilings or budgets per level: the ceilings are shared Stop rules in the body and the ticket budget table is a user decision; the overlay restates the ceiling as a budget and adds no number of its own.
- Starting with solo: it already varies Stop rules and Verification by level in its body, so an overlay would be a second mechanism on one role, and its level text is pinned by three check.py items.
- Full-chain bench A/B: the planner picks the builder level, so the ends of the hypothesis are rarely exercised, and a chain run costs ten times a step replay.
- No change: the observations are real costs, and the mechanism with no overlay files is free; the A/B returns to no change by deleting two files.

## Risks
- The hypothesis may be wrong in either half: more text to a low-effort model can make it more literal, and a goal frame can make a strong model widen scope; the drop rules are the only defense, and n is two repetitions over five tasks, so a null result means "no visible effect at this cost", not "no effect".
- If the host scans `agents/` subdirectories the risk is moot since overlays live outside it; if a future host flag relocates agents, the check.py item catches an overlay placed under `agents/`.
- A `levels.json` row change moves the model under a level's text; overlay text speaks to the level's "fits when" from the rubric, never a model, and the eval that any row change needs is where the overlay is re-read.
- A literal L1 model might echo `## At this level` into its report; `results.py validate` would then flag an unknown section. If the live L1 dispatch in the first build shows this, the insertion changes to an H3 under the role's last pre-Output section.
- The bench repos are referenced by a stale machine path (`/Users/kimba/...`); if they are not on this machine the A/B needs a new fixed set, which is a ticket of its own.
- Cost rows are estimates with tool_uses capped at 50, so the 15 percent L5 threshold rides on noisy figures; minutes and first-pass rate carry the verdict when cost is within noise.
