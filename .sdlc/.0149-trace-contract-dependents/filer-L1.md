## PR title
T-0149: Planner and verifier trace contract dependents into step scope

## PR body
### Summary
When a step changes a shared contract, the planner now finds the contract's dependents and puts them in the same step. The verifier traces dependents in the diff too. A broken dependent outside the step's scope comes back as a `plan defect:` fail, so the replan widens that step. Before this change, a later step or the final gates step tripped on the stale dependent. The source was the gen-ui-system-svelte-lite overnight run on 2026-09-28.

### Changes
- `plugins/sdlc-lite/agents/planner.md`: new `## Contract dependents` section between `## Criteria that can pass` and `## Entry files`. It defines a shared contract (catalog or registry entry, type, exported symbol, schema key, CLI flag, output format). It tells the planner to `git grep` for dependents (tests, fixtures, lint fixtures, snapshots, generated files). Each dependent the change can break goes into the same step's Do, its scope criterion, and a criterion that runs it. A dependent left untouched on purpose is named in the Do with the reason.
- `plugins/sdlc-lite/agents/verifier.md`: item 2 now traces contract dependents with `git grep` and runs the ones the change can break. A broken dependent inside the step's scope is an ordinary `fail`. One outside it is a `fail` whose `## For the next attempt` starts with `plan defect:` and names the paths. The existing `plan defect:` and swap wording is unchanged.
- `plugins/sdlc-lite/scripts/check.py`: `PLAN_DEFECT_DOCS` gets a `'contract dependents'` entry for `agents/planner.md` and `agents/verifier.md`, next to `'owns that budget'`. This pins the wording in both docs.
- `plugins/sdlc-lite/adapters/codex/agents/sdlc-planner-l1/l2/l3.toml` and `sdlc-verifier-l1/l2/l3.toml`: regenerated by `codex_roles.py generate`, not edited by hand.
