## Rejected alternatives

- Keep `slow-commands.json` and `measure` (the addendum's A): a second store of a fact the plan already measures, with the addendum's own "goes stale" risk; both timeout findings were a conductor that never passed `--guard-timeout`, which no skill or agent documents (grep over chain, conductor, planner, handoff-format: no match). A plan-level `guard timeout:` line honored by split removes the file, the subcommand and the pattern table.
- Run `red` always in a worktree at HEAD (the addendum's A): misses the "already green because an earlier uncommitted step delivered it" class, which is the T-0183 step 3 finding; the current-tree run with the existing side-effect snapshot catches it at the only time it is decidable.
- Run every untagged criterion at the base instead of adding `(red)`: matches planner rule 1 and needs no tag, but scope criteria and probe-style criteria would need an opt-out, which is a larger contract change than this addendum should carry; kept `(red)` opt-in and named what it misses (finding 16).
- Let `run_lifecycle.py` amend the run line after the child exits: `runs.jsonl` is append-only and ordered by line index (order.py header); rewriting a line breaks `order.py` ranking.
- `replan-handoff` as a second handoff file: invisible to `read_goal` and the `## Plan review` detection (steps.py:278, :1302-1304); the planner reads the file named in the prompt and nothing else.
- Reuse exit 3 for the budget stop: already means "result failed validation" to the conductor (conductor.md:29).
- File D at L2 as written: skips plan review on a runner change that the conductor must parse, against design.md:226; a one-step plan at L3 is the cheaper honest form, or an explicit exemption in the ticket.
- Treat a stale result as `invalid result`: that path stops and asks the user (steps.py:1163); the point of B is an automatic rerun.
- An A that waits for T-0201 before any of it ships: the run.sh gate plus the timeout line needs only `specgate.py check` and would have caught two of the three mechanical findings this week; splitting A into A1 and A2 ships the free gate first.

## Risks

- The replay claim after the fix still depends on tagging: without `(red)` on the T-0183 step 3 criteria, only the duplicate-span finding and the split-time run catch them, not the pre-review gate; if the author keeps "3 of 3 at review time" as the target it stays unmeetable.
- A `(red)` or untagged span with side effects run in the current tree: the snapshot refuses after the fact, not before; a span that writes outside the tree (a cache, a port) is not seen. The worktree form exists for that case and the planner's read-only rule remains the control.
- `stale_input` exclusion in three readers plus `footprint.py` is four copies of one rule; if any reader misses it, one stale rerun forces a plan review or flips a lean ticket to full.
- The hook's `.running` check denies the user's own legitimate edit during a long run; the escape is `change.md`, which only the conductor text enforces. A marker left by a SIGKILLed run keeps denying until `run_lifecycle.py recover` unlinks it.
- Budget covers Claude `run.sh` roles only; if most spend moves to conductor sessions or Codex, the meter reads low and the warn never fires.
- Concurrent worktrees carry copies of every task dir; a budget computed in one tree after a partial merge double-counts until `attempt_id` dedupe sees both copies, and counts nothing for runs whose copies were never merged.
- The design was read against 355e853; `steps.py` line numbers drift with T-0197, T-0196, T-0200 and T-0201, and `conductor.md` with T-0199, so every cited line must be re-read when the tickets are planned.
