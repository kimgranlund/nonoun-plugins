## Goal
`steps.py split` refuses a plan whose acceptance-criterion commands do not parse, the planner proves each criterion can go red and green before writing it, and a `plan defect:` note from the builder, the verifier, or the split lint routes to a planner L3 replan instead of a rebuild or a level bump.

## Step 1: steps.py lints criterion commands and refuses a plan that does not parse
level: L3
### Do
In `plugins/sdlc-lite/scripts/steps.py`:
- Add `lint_steps(plan, steps)` returning a list of finding strings (empty when clean). For each block from `parse_steps`:
  - Take the lines after a line whose stripped text is `### Acceptance criteria`, up to the next line starting with `## ` or `### `, or the block end. Skip lines inside a ``` fence.
  - On each such line, find Markdown code spans with the regex (`+)(.+?)\1 (a run of backticks to the next run of the same length, non-greedy); strip one space on each side of the content. Skip a span with no whitespace inside (a path or an identifier).
  - Command head: split the content on whitespace; skip leading tokens matching `^[A-Za-z_][A-Za-z0-9_]*=` and a leading `!`; the next token is the head. The span is command-like when `shutil.which(head)` finds it, or the head contains `/`, or it ends with `.py` or `.sh`, or it is one of the builtins `cd`, `test`, `[`, `echo`, `printf`, `export`, `set`, `true`, `false`, `time`, `type`, `command`, `eval`, `exec`, `source`, `.`, or when a skipped assignment token contains `$(`. Every other span (prose, JSX, a `--flag` fragment, `close <slug>`) is skipped. Measured on the 41 plans under `.sdlc/` and `bench/results/`: this keeps 538 of 800 spans and flags three, each a span split by a backtick inside it, which a planner should rewrite anyway.

The `--` is load-bearing: without it bash reads a span starting with `--` as its own option. `bash -n` parses and never executes.

## Step 2: A plan defect routes to a replan, never to a rebuild or a level bump

Whoever sees it runs planner L3 on the task handoff; it never triggers a rebuild, a level bump, or a `## Previous attempt` note.

## Risks
- The static lint would not have caught T-0029 itself: its stray quote sat inside a double-quoted grep pattern, which parses. What catches that shape is planner rule 1 (a `(guard)` criterion that prints `0` on the current tree) and the `plan defect:` route. On the 41 past plans the lint has no true hit and three splits from a backtick inside a span; its value is the cheap code gate the ticket asked for, not a catch-all.
- A prose span whose first word is also a binary (`find`, `sort`, `time`, `test`) and that holds an apostrophe or a parenthesis is a false positive. The cost is one planner L3 rerun, at most two, then the user.
- The route is followed by instruction (chain, conductor, rubric), the same channel the second report's conductor ignored in 4.2. A `steps.py next <step dir>` helper that reads the newest builder and verifier through order.py and prints the next action would enforce it in code; out of scope for a size S bug, worth a follow-up ticket.
- The live-run criterion in step 2 is a model call at Sonnet low. A builder that reports done there means the builder.md wording is too weak, not that the check should be skipped.
- Planner rule 1 asks the planner to run criteria; a criterion that mutates the tree, run by a planner, dirties the working tree. The rule limits it to read-only commands, by instruction only.
