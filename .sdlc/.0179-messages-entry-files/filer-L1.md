## PR title
T-0179: Messages entry files and fresh-role live validation

## PR body
### Summary
A harness that reads `.sdlc/*` can now learn the mailbox from the entry files alone. `messages.py` generates a root `AGENTS.md` and a three-line `AGENTS.md` for each of `new/`, `read/` and `done/`. `tickets.py roadmap` writes the same files, and the router Mailbox line links `messages/AGENTS.md`. A fresh Claude role and a fresh Codex role, each given only a message path and no skill, read, reply and ack correctly. The recorded runs also include the real `messenger` agent on both hosts.

No new skill, version bump, daemon or hook was added. Every step passed its verifier.

### Changes
- `plugins/sdlc-lite/scripts/messages.py`:
  - Added `ENTRY_TEMPLATE`, `STAGE_TEMPLATES`, `entry_files()` and `write_entries(mbox)`.
  - `send` and `reply` call `write_entries` after `compose` and before `deliver`, so a refused send writes nothing.
  - The generated commands use an absolute script path, because a role with no skill cannot resolve `<plugin-root>`.
  - Added six `entry files:` selftest cases. The `race: one winner` leftovers check now skips the state-level `AGENTS.md` and `CLAUDE.md`.
- `plugins/sdlc-lite/scripts/tickets.py`:
  - `write_roadmap` calls `messages.write_entries` after `write_router`.
  - The router Mailbox line links `messages/AGENTS.md`.
  - Added six `router:` selftest cases.
- `plugins/sdlc-lite/skills/ticket/SKILL.md`: one sentence on the mailbox entry files.
- `plugins/sdlc-lite/skills/handoff-format/SKILL.md`: the `.sdlc/messages/` layout row now names `AGENTS.md`.
- `.sdlc/AGENTS.md`: regenerated by `tickets.py roadmap`. This also fixed a router block that was stale at HEAD.
- `docs/reports/messages-live-run.md` and `docs/reports/messages-live-run/`:
  - New dated validation doc with a probe script, an injected-defect file and five evidence files.
  - Linked from `docs/README.md`.
- `docs/specs/ticket-stages/design.md` and `docs/references/sdlc-internals.md`: status and internals updated.

- Step 2, `roadmap` writes the files. Verifier L1 passed.
  - In a fresh repo, `roadmap` and `send` produce byte-identical entry files.
  - `roadmap` restores an edited or deleted entry file.
  - A refused roadmap writes no mailbox.
  - The router-link check was red at base.
  - With the `write_entries` call replaced by `pass`, the tickets selftest fails.
  - The `tickets`, `fanout` and `board` selftests pass.
- Step 3, live runs. Verifier L3 passed. Both hosts ran without skills or the installed plugin.
  - Claude path-only arm: result `pass`.
    - Isolation was proved by `skills: []` and `slash_commands: []` in the init event.
    - The stamps satisfy `send_time <= read_time <= ack_time`, and a reply was sent.
  - Codex path-only arm: result `pass`. Isolation was recorded as `isolation=yes`, with 0 sdlc mentions under an isolated config and 68 without it.
  - Negative control: with a wrong command injected into the entry file, the Claude path-only run fails (probe exit 1, `result=fail`). The same role passes with the generated files.
  - Messenger arms: Claude and Codex both passed. The Claude arm shows state lines `new`, `read`, `done` in order. The Codex spawn is confirmed from the rollout files.
  - The probe's own selftest passes. The verifier planted six defects and each went red.

Limits recorded in the validation doc:
- One trial per arm, on one machine and one account per host.
- The negative control ran on Claude Code only.
