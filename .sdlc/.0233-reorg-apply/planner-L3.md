Settled interface. Do not re-decide these; each names its evidence.

1. CLI: `reorg.py apply PLAN [--root DIR] [--dry-run] [--approve DIGEST]` and `reorg.py selftest`. `--root` defaults to the Git top level of the current directory (inventory.py's `--root`). Exit 0 on success or a clean dry run, 1 on a refusal or a failed final check, 2 on a usage error.
2. Plan input (settles N1, N9, N15). A JSON file at any path, written from the session's plan; procedure Step 2 already puts that plan outside the repository (reorganization-plan-procedure.md:19). There is no plan ticket and no `onboard plan`, because N1 and N9 (reorganization.md:130, :135) show the ticket flow is broken. Shape: `{"version": 1, "batches": [{"name": str, "moves": [{"from": path, "to": path}], "links": [{"file": path, "old": target, "new": target}]}]}` with repo-relative paths. `links` is optional. A batch needs at least one move or one link fix. A wrong version, an unknown key, an empty name, or a wrong type is refused. Link fixes exist because the only applicable items in the one real plan (docs/reports/reorg-inventory-live-run/maison-plan.md, "Links to rewrite") are link retargets with no move.
3. Approval and digest. `--dry-run` runs every refusal except the approval, prints the listing, and writes nothing. Apply without `--dry-run` needs `--approve DIGEST` equal to the digest recomputed now; a missing value refuses, and a different one refuses with `reorg.py: refused: digest mismatch` at the start of the line. This replaces the draft's ticket status `ready` with the onboard precedent: dry run, show, ask once, then write (design.md:86). Digest: SHA-256 hex of the sorted lines `path <p>` for every tracked file outside `.sdlc/`, `file <p> <sha256 of the working-tree bytes>` for every tracked, non-frozen file outside `.sdlc/` (always including `docs/layout.md`), and `plan <json.dumps(plan, sort_keys=True, separators=(',', ':'))>`. `.sdlc/` is left out so changing run records never invalidates a plan (reorganization.md:75). The `plan` line makes a hand edit to the plan refuse (N15).
4. Stdout, the same listing for dry run and apply: `batch <n>: <name>`, then `move <from> -> <to>`, `fix <file>:<line> <old> -> <new>` per link fix, `rewrite <file>:<line> <old> -> <new>` per rewritten link, mention, or path token, `baseline <file>: <target>` per link that was already broken, and last `digest <64 hex>`. `<file>` is the path before that batch. `<old>` and `<new>` are the target text as written, with the anchor and query kept. Apply then prints `commit <sha> <name>` per batch and `final check: pass`. Stderr: each refusal is one line starting `reorg.py: refused: `. A failed check prints `reorg.py: final check failed: <file>: <target>` lines, then `reorg.py: restored to <sha>`.
5. Frozen: under `.sdlc/`, ignored by Git, or matched by a `## Frozen paths` pattern of `docs/layout.md`. Read the layout with `onboard.parse_layout` and match with `onboard.frozen_match` over the path and each parent folder, as `onboard._frozen` does (onboard.py:243-262). Import onboard and rename_refs the way docs_check.py:26-27 imports onboard. A missing `docs/layout.md` or a LayoutError refuses with "run onboard.py setup first", because the layout is the only place frozen paths are listed (reorganization.md:42).
6. Refusals, all before any write and also in the dry run: a malformed plan; `docs/layout.md` missing or unparsable; a move whose `from` is not a tracked file, is frozen, or is named `AGENTS.md`, `CLAUDE.md`, `README.md`, or `docs/layout.md` (reorganization.md:28); a move whose `to` is frozen, under `.sdlc/`, exists, equals another move's `to`, or equals any tracked path, untracked path, or other `to` after case folding (settles N2); a path moved twice in one plan; a link fix whose `file` is frozen, is not tracked Markdown, moves in the same batch, or has no link whose target text equals `old`; a citation the script cannot rewrite (item 7); a staged change anywhere (the index differs from HEAD); uncommitted changes to a file that a move or rewrite touches (reorganization.md:101); a held `.run.lock` (item 9); and, outside the dry run, a missing or different `--approve`. Uncommitted changes to files the plan does not touch never refuse. Each refusal line names its reason; a frozen source or destination is named with the word `frozen`.
7. Citations and rewriting (settles N5; the link and mention forms are inventory.py's, inventory.py:13-23). Batches are computed in order on an in-memory copy of the tree, so batch k sees the batches before it. Each occurrence is rewritten once. Inside a Markdown link target only the resolution rule (second bullet) applies. Everywhere else, text equal to the repo-root path `from` is the token case (first bullet), never a relative mention, even in a file at the repository root. For each move, in every tracked, non-frozen file that decodes as UTF-8:
   - A repo-root path token equal to `from` becomes `to`, anywhere in the file, code included. Use rename_refs.py's token rule (`token_regex` and `in_url`, rename_refs.py:44-52), which T-0246 used across this repository.
   - In Markdown files (.md, .mdx, .markdown), outside fenced code: an inline link, a reference definition, an HTML `href` or `src`, and a backticked or bare mention (inventory.py `MENTION`) whose target resolves to `from` (relative to the citing file's folder, or to the root when it starts with `/`) becomes the relative path from the citing file's folder after this batch to `to`. Keep the `./` style, the anchor, and the query. `docs/AGENTS.md:12` cites `codex-role-execution.md` as a bare backticked name that resolves relative to `docs/`; this rule exists to rewrite that kind of citation instead of refusing it.
   - Inside each moved Markdown file, outside fenced code: every relative link, broken or not, and every mention that resolved before the move is recomputed from the new folder so it points at the same target (reorganization.md:116).
   - A citation the script cannot rewrite refuses the move and names the file and line (procedure step 3.3, reorganization-plan-procedure.md:41): a relative link or mention that resolves to `from` inside a fenced code block of a non-frozen Markdown file; a relative mention, other than the repo-root path text, that resolves to `from` in a non-Markdown file; and a non-UTF-8 tracked non-frozen file that contains the bytes of `from`.
   - A citation inside a frozen file is accepted and left byte-identical (reorganization.md:48). Matching is by resolved path, so a target naming a different file with the same name is never touched.
8. Managed blocks. Rewriting a link inside an onboard managed block would make `onboard.py check` call it edited (design.md:113), and setup would then never refresh it, which the draft's last apply step relies on (reorganization.md:90). So when a rewrite changes the body of a block found by `onboard.find_block` (onboard.py:741) whose stored hash equals `onboard.digest` of the body before the rewrite, set the start marker to `onboard.START_MARKER` with the block's own version and `onboard.digest` of the new body. A block already edited by hand keeps its hash.
9. Running check: before any write, take a non-blocking exclusive `fcntl.flock` on every `.run.lock` under the root (the lock run_lifecycle.py:29-31 takes) and release each one right after. Skip `.git/` and every nested folder that holds its own `.git` entry, because that is another work tree (this lane itself sits under the main checkout's `.worktrees/`). A lock that cannot be taken refuses. A file that exists but is not held never refuses.
10. Apply, commit, check, restore (settles N8). One commit per batch follows the handoff and procedure step 3.4 (reorganization-plan-procedure.md:42) over the draft's "the user ... commits" (reorganization.md:90). Record the start HEAD S. Per batch: `git mv` each move (create parent folders), write the link fixes, rewrites, and managed-block hash refreshes, run the final check on the real tree, then stage exactly the batch's paths and run `git commit` with the subject `reorg: <name>` and a body of `move <from> -> <to>` lines plus `plan digest <hex>`.
    - Final check: every link (the forms of item 7, outside fenced code) in every tracked non-frozen Markdown file resolves to a tracked path, a folder holding tracked paths, or an existing path, except baseline entries; no tracked non-frozen file still holds a repo-root path token of a moved `from`; and every tracked frozen file outside `.sdlc/` has the content hash it had at the start (`.sdlc/` is left out because other runs write there).
    - Baseline: the broken links before the first batch, keyed by (file at the start, resolved target). A moved file's key follows its move. The draft's key `{file, line, target}` would break when a rewrite shifts lines.
    - Restore: on any failure after the first write (a git error, a write error, a commit hook, a failed check), HEAD returns to S, every path the apply touched gets its S content and index entry, folders the apply created and left empty are removed, and files the apply did not touch stay byte-identical, including unrelated uncommitted changes and untracked files. Then exit 1.
11. Selftest: fixture repositories in temp dirs (a Git identity set per fixture), no model call, no network. Negative controls are in-process variants passed to gate functions, in onboard.py's `gate_*(impl)` style (onboard.py:1006). No CLI flag or environment variable disables a gate, unlike inventory.py's `SELFTEST_ESCAPES`. Print `ok <gate> positive` and `ok <gate> negative` per gate and `FAIL <gate> <case>: <reason>` per failure, and end with the line `reorg selftest: PASS` or `reorg selftest: FAIL` (exit 0 or 1). The gates follow the draft table (reorganization.md:112-122). Its Classification row is left out because a session now writes the plan (reorganization-plan-procedure.md:5):
    - `digest`: positive: an unchanged fixture applies, and a change under `.sdlc/` after the dry run leaves the digest the same. Negative: An edited document and an edited plan each refuse.
    - `approve`: positive: a matching `--approve` applies. Negative: No `--approve` refuses and writes nothing.
    - `frozen`: positive: a layout-listed frozen file that cites a moved file stays byte-identical and the apply passes. Negative: A source under `.sdlc/`, a listed frozen source, an ignored source, and a frozen destination each refuse.
    - `rewrite`: positive: an inline link, a reference definition, an HTML `href`, a root token in a non-Markdown file, a bare mention, a backticked mention, and the moved file's own links are rewritten, with anchors kept. Negative: A link and a mention that name a different file with the same name are unchanged.
    - `citation`: positive: a citation in a frozen file does not refuse. Negative: A relative link to the moved file inside a fenced block refuses and names the file and line.
    - `baseline`: positive: a fixture with one link that was already broken applies and passes. Negative: A variant that skips one rewrite fails the final check.
    - `running`: positive: an unheld `.run.lock`, and a held one inside a nested work tree, do not refuse. Negative: A `.run.lock` held by a child process refuses.
    - `collision`: positive: a free destination applies. Negative: An existing destination, a case-only difference from a tracked path and from an untracked path, two moves to one destination, and an entry-file source each refuse.
    - `dirty`: positive: an unrelated modified file does not refuse and is byte-identical after the apply. Negative: A modified touched file and a staged change each refuse.
    - `restore`: positive: a passing apply leaves the moves committed. Negative: A failing check in batch two leaves HEAD at the start, the touched paths as before, the unrelated modified file byte-identical, and no created folder.
    - `commit`: positive: a two-batch plan makes exactly two commits with the subjects `reorg: <name>`, each holding only its batch's paths. Negative: A variant that commits both batches at once is caught.
    - `dryrun`: positive: the dry run prints every move, every rewrite, and the digest. Negative: A variant that writes during the dry run is caught by comparing the tree and HEAD.
    - `managed`: positive: an unedited managed block whose link is rewritten is not labeled edited by onboard's check. Negative: A variant without the hash refresh is labeled edited, and a hand-edited block keeps its old hash.
    - `linkfix`: positive: a fix retargets the matching link and the check passes. Negative: A fix whose `old` matches no link refuses, and a fix to a missing target fails the check and restores.

Focused checks: `python3 plugins/sdlc-lite/scripts/reorg.py selftest`, then `onboard.py selftest` and `rename_refs.py selftest`, which must stay green because reorg.py imports them and does not edit them.
