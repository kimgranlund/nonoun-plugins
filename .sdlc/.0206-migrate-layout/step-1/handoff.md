It checks these in order and raises `Fail` ending `nothing written` on the first that fails, before any write:
   - `layout_paths(root)` parses (a bad `layout` or `ticket_root` line already raises).
   - `<root>` is inside a git work tree. Find the toplevel the way `outside_refs` does (593-650, with `GIT_ENV_DROP`). Outside git, refuse: `outside_refs` returns no files without git, so the scan would pass blind.
   - The work tree is clean: `git status --porcelain` from the toplevel is empty, untracked files that are not ignored included. Otherwise refuse with a message holding `uncommitted changes` and the first paths. Id uniqueness is not checked (design.md:183: each worktree resolves its own root).

Checking this before any write means a run never ends on a `check` that fails on `root_strays`.

2. Moves, printed `move <src> -> <dst>` relative to `<root>`, sorted:
   - a ticket folder directly under `<root>` (a `load(root)` folder, or a `DOT_RE` name) goes to `tickets/<name>`;
   - any other dir directly under `<root>` that is not in `ROOT_ALLOWED` and not `_`- or `.`-prefixed goes to `work/<name>`;
   - `roadmap.md` goes to `tickets/roadmap.md` and `notes.md` to `notes/notes.md`, each only when it exists.

   With `ticket_root: tickets` already set, the ticket folders stay where they are. Moves use `Path.rename`, as `cmd_archive` and `cmd_number` do (1795, 1835), never `git mv`: a ticket root is often git-ignored (the `outside_refs` docstring).
3. Cite scan and `migrate_text`. The existing rewrite cannot do this. A plan-time probe on the step's fixture showed `outside_refs(.sdlc, 'alpha')` lists `.sdlc/beta/links.md`, whose `../alpha/handoff.md` stays valid once both folders move, and `rewrite_files(..., '.sdlc/tickets/alpha')` left `../.sdlc/rel-x/handoff.md` and `../rel-x/handoff.md` unchanged and broken. Leave `literal_re`, `outside_refs`, `ref_tokens` and `rewrite_files` as they are: `close`, `archive` and `number` and their selftest cases (near 2980-3175) use them. Add `migrate_text(text, top, f, moves)`. `moves` is the list of `(src, dst)` toplevel-relative posix paths, and `f` is the citing file's toplevel-relative path before the move. It returns the text with each path token rewritten so it resolves after the moves to the same file it resolved to before:
   - Tokens are `TOKEN_RE` matches holding a `/`, with trailing `.,;:!?` stripped, as in `ref_tokens`. A token on a line inside the managed block that `onboard.find_block(text)` reports (status `block`; `Block.start` and `Block.end` are 0-based marker line indexes) never changes. Those blocks are generated: a probe showed a hand rewrite of `.sdlc/roadmap.md` inside the root `AGENTS.md` onboard block turns `onboard.py check` from `stale AGENTS.md` into `edited AGENTS.md`, which `setup` then refuses to replace without `--force`.
   - A token names a move's src by `ref_tokens`' rule: one of its components equals the src's last name, the token up to that component resolves to src (from the file's dir, from the toplevel, or as an absolute path, also after `realpath`), and the whole token lands on src or under it. The first base it resolves from sets its form: absolute when it starts with `/`, file-relative when the prefix lands on src from the file's dir, toplevel-relative when it lands only from the toplevel. Its new form depends on that form and on the citing file. When the token is file-relative and `f` itself moves (it lies under a move src, or is `notes.md`), the new form is `os.path.relpath` from `f`'s new dir to the moved target. Otherwise the one matched component is replaced by the dst's path relative to the src's parent (`tickets/alpha`, `work/rel-x`, `notes/notes.md`, `tickets/roadmap.md`), and every other byte stays.
   - In a file that moves, a file-relative token that names no src but resolves from the file's old dir to a path that exists before the move is re-expressed with `os.path.relpath` from the file's new dir to that target's post-move path. `relpath` leaves a same-offset target unchanged, and the existence test leaves prose alone. This covers links out of a moved folder (this repo has 15 such files under `.sdlc`, mostly `../../CLAUDE.md`) and plain relative tokens in `notes.md`, which moves one level down. A token that resolves to nothing stays.
   - Keep a token's trailing `/`, and a leading `./` when the new relative form does not start with `../`.

   The candidate files are the union of `outside_refs(root, name, own=True, roadmap=<root>/roadmap.md)` over each moved name (each folder, `roadmap.md`, `notes.md`) and the files under moved paths that hold `../` (one `git grep --untracked --no-exclude-standard -I -l -z --full-name -F -e ../ -- <moved paths>`). The old `<root>/roadmap.md` is never a candidate, since it is regenerated. A candidate is a citing file only when `migrate_text` changes it. An unreadable candidate refuses the run, named, even with `--rewrite-refs`. `outside_refs` returns `(None, '', '', [])` on any git failure, so a `None` toplevel from it, or a failing `git grep`, refuses the run with `cite scan failed` and `nothing written`; otherwise a mid-scan failure would migrate with no rewrites.
