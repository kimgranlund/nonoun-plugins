## Goal
Add a `/ticket` skill backed by `scripts/tickets.py`. It has four commands: `new` stamps a typed ticket with the next id, `roadmap` writes `.sdlc/roadmap.md` from ticket front matter in dependency order, `check` fails on any bad ticket or a stale roadmap, and `selftest` shows that every check failure fires.

## Step 2: scripts/tickets.py with new, roadmap, check, selftest, wired into check.sh
level: L3
### Do
- Create `plugins/sdlc-lite/scripts/tickets.py`, a stdlib-only Python 3 script modeled on `/Users/kimba/Projects/nonoun/gen-ui-system-svelte-lite/scripts/tickets.py`. Leave out `close`, which belongs to T-0003.
- CLI: `tickets.py [--root DIR] {new <type> <slug> ["title"] | roadmap | check | selftest}`. `--root` defaults to `.sdlc` relative to the cwd, like `board.py`.
- Tickets are every `<root>/<dir>/handoff.md` where `<dir>` does not start with `_` or `.`. A handoff with no front matter block is not a ticket: skip it silently, never report it as an error. This follows the handoff-format rule that handoffs without front matter keep working.
- Front matter parsing:
  - The block is between the opening `---` and the next `---`.
  - `[a, b]` values are lists.
  - `"..."` values are unquoted.
  - Strip a trailing `  # comment` only on unquoted values, so `title: "Fix #12"` survives.
- `check` exits 1 and prints one stderr line per problem, naming the slug, for each of these:
  - A missing required field (id, title, type, status, size, priority, depends, created).
  - An enum value outside its allowed set: type feature|bug|chore|spike|idea, status proposed|ready|blocked|done|dropped, size S|M|L|XL, priority P1|P2|P3.
  - An id that does not match `T-\d{4}`, or equals `T-0000`.
  - `created` not matching `\d{4}-\d{2}-\d{2}`.
  - A duplicate id.
  - A `depends` entry that names no ticket.
  - A `from` that names no ticket.
  - A dependency cycle, including a ticket that depends on itself. Report the cycle as a problem line containing `cycle`, not as a traceback.
  - A stale roadmap: `<root>/roadmap.md` is missing or differs byte-for-byte from what `roadmap` would write. Zero tickets and no roadmap.md counts as ok.
  - On success it prints `ok: <n> tickets, roadmap current` and exits 0.
- `roadmap`:
  - Refuses (exit 1, problems printed) when any validation problem exists.
  - Otherwise writes `<root>/roadmap.md`: a `# Roadmap` heading, a line saying it is GENERATED by `tickets.py roadmap` and must not be edited by hand, and a pointer to `/ticket new` and `/board`.
  - The table has columns `| ID | Ticket | Title | Type | Size | Pri | Depends on | Status |`. Ticket is a link `[slug](slug/handoff.md)`. Depends on shows `none` when empty. Status shows the glyph and the word, using the reference GLYPH map.
  - Rows are in topological order by `depends`, with ties broken by id ascending.
  - `|` in a title is escaped. No timestamps, so the output is stable byte-for-byte across runs.
- `new <type> <slug> ["title"]`:
  - The slug must match `^[a-z0-9]+(-[a-z0-9]+)*$`.
  - The template comes from `<root>/_templates/<type>.md` if it exists, else from `<plugin>/skills/ticket/templates/<type>.md`. `<plugin>` is the script's parent's parent.
  - An unknown type exits nonzero, listing the available types.
  - An existing `<root>/<slug>` exits nonzero without writing.
  - It refuses (exit 1) if the existing tickets have validation problems.
  - It creates `<root>` if missing.
  - The new id is max existing id + 1, zero-padded to 4 digits (`T-0001` when there are none).
  - It replaces `id: T-0000`, `created: YYYY-MM-DD` (today) and `title: ""` (the title with `"` turned into `'`). It then regenerates the roadmap and prints the created path.
- `selftest`:
  - Builds fixtures in a `tempfile` dir and drives the same functions the CLI uses.
  - Base case: `new` twice gives T-0001 then T-0002. With T-0001 made to depend on T-0002, the roadmap lists T-0002's row first, and `check` passes on the clean base.
  - Negative control: a handoff with no front matter added to the base still passes.
  - One mutation per failure class must each fail with its expected message: bad type, bad status, bad size, bad priority, missing field, bad id, bad created, duplicate id, dangling depends, dangling from, cycle, self-cycle, stale roadmap (roadmap edited by hand).
  - Prints `tickets selftest: PASS` and exits 0, else lists what did not bite and exits 1.
- Edit `plugins/sdlc-lite/scripts/check.sh`: add `python3 "$root/scripts/tickets.py" selftest || fail=1` after the coverage_check line, and update the header comment.
### Acceptance criteria
- `python3 plugins/sdlc-lite/scripts/tickets.py selftest` exits 0 and prints `tickets selftest: PASS`.
- New/roadmap/check on a fixture: `R=$(mktemp -d)/s; S=plugins/sdlc-lite/scripts/tickets.py`. Then:
  - `python3 $S --root $R new feature alpha "Alpha"` then `python3 $S --root $R new bug beta "Beta"` create `$R/alpha/handoff.md` (`id: T-0001`, `title: "Alpha"`, today's `created:`) and `$R/beta/handoff.md` (`id: T-0002`, `type: bug`). `$R/roadmap.md` exists.
  - Change alpha to `depends: [T-0002]`. `python3 $S --root $R check` then exits 1 with a `stale` message. `python3 $S --root $R roadmap` then `check` exits 0, and the T-0002 row comes before the T-0001 row in `$R/roadmap.md`.
  - Running `roadmap` twice leaves `$R/roadmap.md` unchanged (`cmp` of the two copies exits 0).
- Negative controls, each on a copy of the passing fixture: each mutation makes `check` exit 1, and stderr names the problem.
  - Set `type: epic`.
  - Set `status: wip`.
  - Delete the `size:` line.
  - Set `id: T-12`.
  - Give beta `id: T-0001`.
  - Set `depends: [T-0099]`.
  - Add `from: T-0099`.
  - Make beta depend on T-0001 while T-0001 depends on T-0002: exit 1, stderr contains `cycle`, no Python traceback.
  - Append a line to `roadmap.md`.
- Adding `$R/plain/handoff.md` with no front matter keeps `check` at exit 0 (after `roadmap`).
- `new idea alpha` on the fixture exits nonzero and leaves `$R/alpha/handoff.md` unchanged. `new epic gamma` exits nonzero and lists the five types.
- `plugins/sdlc-lite/scripts/check.sh` exits 0 and its output includes `tickets selftest: PASS`.

## Risks
- This repo's own backlog lives in flat files, `.sdlc/tickets/T-*.md`, not in `.sdlc/<slug>/handoff.md`. The script follows the documented handoff-format layout, so those flat tickets will not show up in a roadmap for this repo. Their ids also overlap task dirs like `ticket-intake-roadmap/` (both T-0002). Scanning both layouts would report duplicate ids. Bringing this repo's backlog under `/ticket` is left as a follow-up.
- `claude plugin validate` might object to non-SKILL `.md` files under `skills/ticket/templates/`. If it does, move the templates to `plugins/sdlc-lite/templates/tickets/` and update the lookup path in Step 2.
- The CLAUDE.md edit could break the regexes in `check.py` that read level tables. Step 3's check.sh criterion catches that.
