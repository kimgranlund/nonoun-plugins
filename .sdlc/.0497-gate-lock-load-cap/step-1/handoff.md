## Task goal
`gate_lock.py` admits no new grant while the host load average exceeds a declared cap, in addition to the unit capacity, and keeps one repo from starving another, so a critical gate is not stretched by other repos' CPU-bound gates.

Settled interface, each with its evidence:
- Policy key: a top-level `max_load` in `policy.json`, a whole number, compared with the 1-minute load average as the host reports it (`os.getloadavg()[0]`). It is an absolute load, so the operator picks load per CPU times CPU count (the handoff's example is cap 24 on 20 CPUs). Absent or 0 means off. `BUILTIN_POLICY` (line 65) gains no key, so the default policy and `policy show` on a fresh root are unchanged (handoff Constraints), and the hand-built policy in `case_rr` (line 1254) keeps working because a missing key is off. Whole numbers only, because `parse_needs` (line 327) accepts `RES=N` with digits.
- `load_policy` (lines 301-318): accept an optional `max_load` that is a non-bool int of 0 or more, else raise the same `state_unavailable` error; a file without the key loads as today. An older plugin reads only `capacity` and `default_need`, so a file with the key does not break an older session on the same state root.
- `policy set max_load=<n>`: in `cmd_policy` take `max_load` out of the parsed capacity arguments before the "a capacity must be 1 or more" refusal (line 825), so it never lands in `capacity`. `max_load=0` removes the key (off). `policy set max_load=24` alone is a valid call. `policy reset` already removes the file. `policy show` and `capabilities --json` print the key through their `**pol` spread; add `; max load <n>` to the `policy set:` confirmation line only when the key is set. Update the usage strings and the module docstring.
- `host_load()`: a new function. When the env var `SDLC_GATE_LOAD_FILE` names a readable file holding one number, return that number (the test seam: one file shared by every process of a case, so a case can raise and lower the load while a holder runs). Otherwise return `os.getloadavg()[0]`; when that raises `OSError`, return None and the cap is not applied. The `SDLC_GATE_` prefix matters: `env_for` (line 1041) strips that prefix from the inherited environment, so no selftest case inherits a seam from the caller. A per-process env number was rejected: `run_top` calls `schedule` again in its `finally` (lines 696-700), so a holder started under a low number would admit an over-cap waiter when it exits.
- `schedule(ledger, pol, legacy_n=0, load=None)` (lines 377-406): `load=None` means read `host_load()` once per call. Inside the `while` loop, after the head `entry` is chosen and before the `fits` test, stop granting when `max_load` is set and the load is above it, on one line that ends with the marker comment `# LOAD-CAP` (the form the `# SLOT-CAP` line 365 uses). Equal to the cap admits. `fits` keeps its signature and the `# SLOT-CAP` line is untouched (check.py item 35 and the `weighted cap` control pin it). `schedule` never removes a grant, so a held grant survives a load rise with no extra code. Round robin needs no new code: `rr` moves only on a grant (line 403), so a head refused for load keeps its turn (docstring lines 378-379).
- `status`: `status_data` reads the policy and the load; a policy that does not load gives no load fact and never fails `status`. `status --json` gains a top-level key `load` with `value`, `max_load` and `over`, present only when `max_load` is set. The text form prints one more row after the queued rows, exactly `waiting: load 36.5 over cap 24` in shape (the load with one decimal, format `.1f`; the cap as the whole number), only when the queue is not empty and the load is above the cap. The waiter's periodic stderr report and the timeout text stay as they are (the handoff scopes the reason to `status`).

Selftest, in the existing control pattern (lines 1353-1374): add `case_load(py, base, label)` and one row in `controls` with the label exactly `load cap`, a marker constant `M_LOAD` built by joining so the line does not match itself (as `M_CAP` line 976), a mutant that turns the marked line into a no-op, and the tell `ran over the load cap`. The case uses `env_for(base, label, SDLC_GATE_LOAD_FILE=<a file under base>)`, runs `policy set max_load=24`, writes 1, starts a holder, writes 36.5, starts a waiter, and expects: the waiter is queued and has not run (the miss text holds the tell), `status` still shows the holder `admitted` and prints `waiting: load 36.5 over cap 24`, then after writing 10 the waiter runs.
