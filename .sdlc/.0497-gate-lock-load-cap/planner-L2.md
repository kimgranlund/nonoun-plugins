## Risks
- The default-policy guard compares `policy show` with the exact built-in numbers, the only form seen red at base. A main sync that changes `BUILTIN_POLICY` turns it red on this step.
- The rule is proven with a fake load. That a real cap shortens a real gate on a loaded host is not proven by this step.
- With `max_load` set and the load held high by work outside the queue, every gate waits until its own `--timeout`, even with no holder. This is the handoff's intent and the cap is off by default.
- The 1-minute load average lags, so several heads can be admitted in the seconds after the load drops under the cap.
- `max_load` takes whole numbers only.
- The 897 s `check.sh` record is old. A run near 2700 s reads as a timeout, not a red.
- The two run criteria sleep 2 s between a start and a check. On a very loaded host a slow start can fail them; rerun before calling it a defect.
