## Goal
`docs/validation/` is `docs/reports/`, every reference to the old path is rewritten, and nothing else changes: same file names, same content apart from path text, with a check that proves no stale reference remains.

## Intent
- Do: (1) Preconditions, checked first and recorded: the `reorg-inventory` branch is merged into main (it was, as 24fdd8c on 2026-10-05; confirm it), `git status` is clean, and `tickets.py check` passes. (2) Baseline, recorded in the evidence folder: tracked file count under `docs/validation/` (385 on 2026-10-05), the list of tracked files citing the string `docs/validation` outside that folder (about 325 to 329 on 2026-10-05; recompute it, the number moves as files are added; including `AGENTS.md`, `plugins/sdlc-lite/scripts/specgate.py` (2 citations), `docs/README.md`, release records, and `.sdlc` ticket handoffs and results), and a whole-tree Markdown link check with the count of broken links. (3) Move in one commit: `git mv docs/validation docs/reports`, and `git mv docs/readiness-recovery-validation.md docs/reports/readiness-recovery-validation.md` (it was frozen only because it travelled with `docs/validation/`; keep its name). (4) Rewrite in batches, one commit per batch, each undoable by `git revert`: batch A code and entry files (`specgate.py` and its selftest, `AGENTS.md`, `plugins/sdlc-lite/AGENTS.md`, `README.md`, any `check.py` or hook text), batch B `docs/` and `.sdlc` Markdown. The rewrite is path-token-aware, like the reference scan in `tickets.py close`: a token that starts a path (start of text, or after whitespace, a quote, a backtick, a paren or a bracket) and matches `docs/validation` followed by `/`, end of token or punctuation; it never rewrites inside a URL, never rewrites `docs/validation-`-style longer names, relative links are recomputed (`../validation/x.md` from `docs/<topic>/` becomes `../reports/x.md`, and links from inside the moved folder to its siblings are recomputed), and anchors survive. Dated records keep their content; only path text changes. (5) Amend the freeze sentence in `docs/repo-onboarding/reorganization.md` (about line 143, the one that says `docs/validation/` is listed as frozen and stays) so it no longer freezes the folder, in the same commit as the move; also update `docs/layout.md` of this repository if it exists (homes, `## Legacy` glob for existing non-conforming report names, so the new `YYYY-MM-DD-slug` rule applies to NEW reports only), and add the one-line mapping to `docs/docs-schema/design.md` Resolved decisions (already recorded by the design ticket). (6) A citing-file scan proves zero remaining `docs/validation` references except an explicit allowlist: this ticket's own handoff, release-record sentences that are explicitly about the rename, and text bound to a tag (see Constraints). The scan runs as a check with a negative control (reintroduce one stale reference in a fixture and the check fails). (7) Re-run the whole-tree link check: the broken-link count must not increase. Run `bash plugins/sdlc-lite/scripts/check.sh` (full), `python3 scripts/check-packaging.py`, `codex_roles.py generate --check`, `tickets.py check`, `git diff --check`, and the `specgate.py` selftest.
- Non-goals: renaming any file inside the folder, rewriting dated content, editing any tag or any already-published GitHub release body, moving other folders (the other migration moves are T-0244), a version bump, tag, push, or publish.
- Done when: the freeze sentence in `docs/repo-onboarding/reorganization.md` is amended and a grep for it finds the old wording nowhere, the move and rewrites are committed in the batches above, the baseline and after numbers are in a committed evidence note under `docs/reports/`, the stale-reference check and its negative control pass, an independent verifier passed with an overall pass (it must sample at least 15 rewritten references of different kinds: code, entry file, relative link, ticket handoff, release record), and `git revert` of the last batch commit on a throwaway branch restores a green `tickets.py check`.

## Context
Decided by the user on 2026-10-05, against the design's recommended default (legacy home bound to reports), in the docs-schema decision round: rename now, so there is one `reports/` home and no legacy exception for validation (`docs/docs-schema/design.md`, Resolved decisions). Blast radius measured on 2026-10-05: 385 tracked files under `docs/validation/`, about 325 to 329 other tracked files that cite `docs/validation`, of which only `plugins/sdlc-lite/scripts/specgate.py` (2) and `AGENTS.md` (1) are code or entry files outside Markdown history. `docs/repo-onboarding/reorganization.md` currently freezes `docs/validation/` ("They are to be listed as frozen and stay where they are"); this ticket amends that sentence in the same commit as the move, because the freeze no longer holds. It must run after the `reorg-inventory` merge because that branch adds files to `docs/validation/` and edits `docs/README.md`; moving first would make that merge conflict on every added file. Size M, solo lane. Philosophy: "Done is better than perfect." The gated apply tool from the reorganization project does not exist yet; this is a one-off mechanical rename with the same safety properties (dry-run list, citing scan, commit per batch, revert).

## Constraints
Route decision: this runs as its own one-step ticket now, with the safeguards in the Intent above (dry-run list, path-token-aware rewrite, commit per batch, stale-reference check with a negative control). It does not wait for the gated apply tool T-0233 and does not use it; `depends:` stays empty.
- Historical tags and already-published releases keep the old paths: tags `v0.20.0` to `v0.20.8` contain `docs/validation/...` and cannot change, and the published GitHub release pages for v0.20.1 to v0.20.8 cite `docs/validation/...` paths in their bodies and are NOT edited. This is an accepted limit: the links on those pages resolve only at the tag, and the next release record must say so in one sentence.

- One authoritative statement of the old and new path: this ticket.
