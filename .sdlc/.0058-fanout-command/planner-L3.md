## Goal
`/fanout <lane>=<ids>...` runs one headless conductor per lane worktree, merges each lane into an integration branch `fanout/<date>` under a lock with gates and a reset on red, closes tickets there, and `board.py --lanes` shows every worktree; all proven by selftests on throwaway repos, with `check.sh` green.

## Step 1: `board.py --lanes`, a per-worktree view from `git worktree list`
level: L3
### Do
In `plugins/sdlc-lite/scripts/board.py`:
- Add `--lanes` to `main()`'s argparse. With it, `main()` renders a lanes table instead of the task board and returns; it never calls `render()` and never touches the state file. `--waiting` still prints its line above the table; `--summary`, `--task`, and `--sort` are ignored under `--lanes`. Nothing else in `main()` or `render()` changes: the default board output must stay byte-identical.
- Add `lanes(root)`: find the repo of `root` the way `tickets.worktree_roots` does (`git -C <root or nearest existing parent> rev-parse --show-toplevel`, with `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE` dropped from the env), compute `rel = root.resolve() relative to the toplevel`, then read `git worktree list --porcelain` and build one row per `worktree <path>` entry, in list order: Lane = the worktree path's basename, Branch = the `branch refs/heads/<name>` short name or `(detached <7-char sha>)`, Board = `summary(<worktree>/<rel>)` or `no tasks` when that dir has no task, resolving both paths with `.resolve()` (macOS `/var` vs `/private/var`). Outside a git work tree (any git failure), print `<root>: not inside a git work tree` on stderr and exit 1.

Keep case 1 (byte-for-byte 4-column render) as is.

## Step 2: `scripts/fanout.py`: lanes, headless conductors, locked merges into `fanout/<date>`
level: L4
### Do
Create `plugins/sdlc-lite/scripts/fanout.py` (Python 3.9, `import tickets` from the same dir like `board.py`; no third-party modules). Subcommands: `run` and `selftest`.

`run <lane>=<id>[,<id>...]... [--root .sdlc] [--base REF] [--integration BRANCH] [--lanes-dir DIR] [--gate CMD]... [--driver CMD] [--dry-run]`:
- Preflight, all before any write (a refusal prints on stderr, exits 2, creates nothing): cwd must be in a git work tree with a commit (as `run.sh` checks); `--root` (default `.sdlc`, relative to cwd) must lie inside the toplevel, and its path relative to the toplevel (`rel`) is what every worktree uses; lane names match `^[a-z0-9]+(-[a-z0-9]+)*$`; each id matches `T-\d{4}`, resolves through `tickets.load(root)` to exactly one folder whose `status` is not `done` or `dropped`, and appears in one lane only; the integration branch is `--integration` or `fanout/<YYYY-MM-DD>`; lane branches are `<integration>-<lane>` (a slash form would collide with the integration ref itself); `--lanes-dir` defaults to the sibling `<toplevel>-fanout`; refuse when a lane branch or `<lanes-dir>/<lane>` already exists.
- `--dry-run` prints the plan (base sha, integration branch, per lane: branch, worktree dir, tickets with slugs and titles, the gates, the driver command) and exits 0 without creating anything.
- Setup, sequentially on the main thread: create the integration branch at `--base` (default `HEAD`) unless it exists (then reuse it and say so); `git worktree add <lanes-dir>/integration <integration>`; per lane `git worktree add -b <lane branch> <lanes-dir>/<lane> <integration>`; refuse (exit 2, after removing what this run created) when the handoff of any ticket is missing in the lane worktree (the `.sdlc/` trail must be committed). Make `<lanes-dir>/logs/`.
- Then one thread per lane; each lane walks its tickets in order and stops at its first failure, recording every later ticket as `skipped`:
  1. sync: in the lane worktree `git merge --no-edit <integration>`; conflict → `git merge --abort`, outcome `sync conflict`.
  2. driver, outside the lock: `--driver CMD` run with `bash -c CMD`, cwd the lane worktree, stdin `/dev/null`, stdout and stderr to `<lanes-dir>/logs/<lane>-<id>.log`, env `FANOUT_LANE`, `FANOUT_TICKET`, `FANOUT_SLUG`, `FANOUT_HANDOFF` (absolute), `FANOUT_ROOT` (absolute lane root), `FANOUT_INTEGRATION`, `FANOUT_PLUGIN_ROOT`. Default driver: `claude -p --plugin-dir <plugin root> --agent sdlc-lite:conductor --model opus --effort medium --dangerously-skip-permissions "<prompt>"` with `BASH_DEFAULT_TIMEOUT_MS` and `BASH_MAX_TIMEOUT_MS` set to 3600000 as `bench.sh` does; the prompt: run `/sdlc-lite:chain <handoff path relative to the worktree>` unattended, never ask, in the file stage run the filer only and do not close the ticket because /fanout closes it on the integration branch after the merge, and never commit, push, or publish. Non-zero exit → outcome `driver failed rc=<n>`, tree left as is.
  3. commit in the lane: `git add -A` then `git commit -m "<id>: <title>"`; nothing staged → outcome `no changes`, no merge, no close.
  4. under an exclusive `fcntl.flock` on `<lanes-dir>/merge.lock` (no `flock` binary on macOS), in the integration worktree: `before = HEAD`; `git merge --no-ff --no-edit -m "Merge <lane branch>: <id>" <lane branch>`; conflict → `git merge --abort`, outcome `merge conflict`. Then each `--gate` in order via `bash -c`, cwd the integration worktree, output to `logs/gate-<lane>-<id>-<k>.log`; first non-zero → `git reset --hard <before>`, outcome `red: <gate> rc=<n>`. No gates given: say so once in the report. All green → close: if `<integration wt>/<rel>/<slug>/` holds no `filer-L*.md`, copy `<lane wt>/<rel>/<slug>/` there (`shutil.copytree(dirs_exist_ok=True)`); run `tickets.cmd_close(root, slug)` (in-process or `python3 tickets.py --root <rel> close <slug>` with cwd the integration worktree); on refusal outcome `merged, close refused: <first line>` and the merge stands; on success `git add -A -- <rel>` and commit `close <id>` when anything is staged; outcome `merged`. Release the lock.
- Print one line per event as it happens (`[<lane>] <id> <outcome>`), write `<lanes-dir>/report.md` (`| Lane | Ticket | Outcome | Commit |`, plus the integration branch, its tip, and the worktree paths) and print it at the end. Exit 0 only when every ticket is `merged`, else 1. Never run `checkout`, `switch`, `reset`, or `commit` outside the lanes dir; never push. Lane worktrees stay in place for inspection.

`selftest`: in a temp dir, a throwaway repo (`git init -b main`, local `user.name`, `user.email`, `commit.gpgsign false`) with five ready tickets `a`..`e` (T-0001..T-0005) committed under `.sdlc/`; a stub driver script that writes `$FANOUT_TICKET.txt`, `ls` of the worktree into `$FANOUT_TICKET.saw`, a minimal `filer-L1.md` (`## Warnings` None, `## Follow-ups` None) into `$FANOUT_ROOT/$FANOUT_SLUG/`, touches `RED` for T-0003, and for T-0002 polls (`sleep 0.1`, at most 60 s) until `git cat-file -e <integration>:T-0001.txt` holds. Run `fanout.py run alpha=T-0001,T-0003,T-0005 beta=T-0002,T-0004 --base main --integration fanout/test --lanes-dir <tmp>/lanes --driver <stub> --gate 'test ! -e RED'` as a subprocess with cwd the repo, then assert: exit 1; `main` sha unchanged and `git status --porcelain` empty in the repo; `fanout/test` has exactly three merge commits; its tree holds `T-0001.txt`, `T-0002.txt`, `T-0004.txt` and neither `T-0003.txt` nor `RED`; `git show fanout/test:.sdlc/<slug>/handoff.md` says `status: done` for a, b, d and `status: ready` for c and e; the report names T-0003 as `red`, T-0005 as `skipped`, and no `T-0005.txt` exists in the alpha worktree; `T-0004.saw` in the beta worktree lists `T-0001.txt` (the pre-ticket sync); `board.py --lanes --root <repo>/.sdlc` lists rows for `alpha` and `beta` with branches `fanout/test-alpha` and `fanout/test-beta`. Also: `--dry-run` creates no branch or dir; the same id in two lanes, an unknown id, and a done ticket each exit 2 creating nothing. Print `fanout selftest: PASS` or a FAIL list on stderr, like `board.py`.

Wire `python3 "$root/scripts/fanout.py" selftest || fail=1` into `plugins/sdlc-lite/scripts/check.sh` (and its header comment). Add a `scripts/fanout.py` bullet to the Layout section of the root `CLAUDE.md`: lanes as worktrees under `<toplevel>-fanout`, one headless conductor per lane, sync before each ticket, lane commits made by the script, the `fcntl` lock, gates with `git reset --hard` on red, close on the integration branch, exit codes, `--driver` for stubs, and that main is never touched.
### Acceptance criteria

## Risks
- The default driver (a headless conductor told to skip the close and never commit) is checked only by the dry run and reading; the selftest uses a stub. A live run on a throwaway repo (as T-0063 asks for the merge step) is the first real proof of the prompt.
- The merge lock is `fcntl.flock` because macOS has no `flock` binary; on a filesystem without advisory locks (some network mounts) it silently degrades.
- A red gate is undone with `git reset --hard` rather than `git revert -m 1`, so the lane can be fixed and merged again; the rejected merge leaves no trace on the branch, only in `report.md` and the logs.
- Fanout needs the `.sdlc/` trail committed; a target repo that gitignores it has no handoffs in the lane worktrees and the run refuses at setup.
- The conductor's model and effort for the lane driver copy `bench.sh` (Opus medium); that is a new use of an existing choice, not a new decision, but the user may want it settled.
