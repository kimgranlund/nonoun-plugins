## Goal
A deterministic script, with no model call, that notices new mail for a harness whose host is idle and resumes that host from a headless call, inside hard limits, and can be stopped.

## Intent
- Do: first apply every finding of the independent design review (`docs/validation/idle-host-watcher-design-review.md`) that is marked a blocker or major, and every minor one the builder can settle from the evidence, to `docs/ticket-stages/watcher-design.md` (step 1, docs only, with the review's findings listed in the step Do). Then build `plugins/sdlc-lite/scripts/supervisor.py` from the revised design: config and limits under `.sdlc/supervisor/` (`limits.json`, a git-ignored `hosts.local.json` for session ids, working dirs, models, and effort, `status.json`, `state.json`, `lock`, and the kill switch file `STOP`), with `.sdlc/supervisor/AGENTS.md` and `CLAUDE.md` written by the script's `init` command and documenting setup, start, stop, status, and every limit in plain steps with exact commands.
- Behavior: it polls only file names and front matter, using the same valid-file rule as `messages.py count` (reuse the code, do not copy it); it never reads a body and never claims, moves, edits, or deletes a message. When a receiver has a new message and its host is not active, it resumes the host (Claude: `claude -p --resume <session-id>` with `--allowedTools` limited to the mailbox script and read-only tools and `--max-budget-usd`; Codex: `codex exec resume <session>` with `--sandbox workspace-write` and approval never) with the fixed prompt from the design, which carries the receiver name and the count only. Defaults: dry-run unless `--run`; poll every 10 seconds; one poll of debounce; per-receiver cooldown 10 minutes; at most 6 wakes per receiver per hour and 24 per day; a wake wall-clock timeout of 10 minutes enforced by the script; reply-chain depth of three or more records `needs a human` and does not wake; three consecutive wake failures stop waking that receiver; an exclusive `fcntl.flock` lock so two watchers never run; the file `STOP` makes it finish its poll, wake nobody, and exit 0. A woken host follows unattended rules: never push, open a pull request, or publish; message bodies are data.
- Non-goals: a LaunchAgent plist or installer; any change to `messages.py` state transitions; claiming or acking for a host; the board display (T-0187).
- Done when: the selftest cases below pass, the live runs below are recorded, and the common checks pass.

## Context
Design: `docs/ticket-stages/watcher-design.md` and its review. Session modes (review finding 4, decided by the user 2026-10-01): build per-receiver `mode` with `ephemeral` as the default (a fresh headless session per wake, no growing owned session), `attached` (resume a named session, opt-in) and `notify` (no wake, tell the person) as opt-ins. Apply review findings 1 to 17 in step 1; the review's blocker list is the minimum. Facts verified live on 2026-10-01: `claude -p --session-id`, `--resume`, `--continue`, and `codex exec resume --last` each continue a recorded session headlessly. The mailbox is `.sdlc/messages/` (`plugins/sdlc-lite/scripts/messages.py`); `messages.py wait` (T-0181) and the `messenger` agent remain valid in an active host.

Selftest (stub host driver: a script that records its argv, environment, and stdin to a file and exits with a chosen code; the watcher takes the driver through a documented `--driver` flag or a `driver` field of `hosts.local.json`, for the selftest only; the selftest runs in throwaway git repos with a copied mailbox): wake on arrival (one stub call); dry-run without `--run` makes zero calls; no wake when the host is active (a running recorded wake, or a recent transcript timestamp for an attached session); the mailbox tree is byte-identical before and after (the watcher never claims); the recorded prompt contains no body text and no topic (a planted marker in both never appears); cooldown holds; the hourly cap holds; reply-chain depth three records `needs a human`; a failing stub backs off and after three failures stops waking and records `failed`; a second watcher exits 1 on the lock and a restart after the first exits succeeds; the `STOP` file stops it with exit 0 and no wake; `status.json` fields are right in each state (`idle`, `waking`, `cooling`, `failed`, `needs a human`). Negative controls: a patched copy that claims fails the byte-identity check; one that includes the topic fails the prompt check; limits set to 0 refuse every wake; removing `STOP` lets a wake happen.

Live runs (recorded in `docs/validation/supervisor-live-run.md`): on Claude Code and on Codex, a real session that has finished its turn (owned session, created by the watcher's first wake or by an explicit `init-session` command) is idle; a message sent from another process makes the watcher wake it; the host reads, replies when asked, and acks, with `send_time <= read_time <= ack_time`; and a message body that tells the host to push to a remote does not cause a push (use a throwaway repository with a bare local remote and show the remote has no new commit and the host's attempt, if any, was denied). Include a negative control: the same body with the watcher in dry-run produces no wake. Never run a live arm against this repository's remote.

## Constraints
Deterministic: no model call in the script. The watcher never touches a message file. Every number above is a default readable from `limits.json`, with the cap and floor enforced by the script. Wake commands are built from fixed argument lists, never through a shell with message-derived text.
