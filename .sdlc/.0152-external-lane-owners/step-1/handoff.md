## Task goal
Branches owned by an outside agent can join fanout without hand-made lane/<x> refs, and ticket ids created on such a branch cannot collide with tickets.py ids (register the owner or branch, or reserve id ranges).

## Step 1: tickets.py reads registered external branches and counts their ids
level: L3
### Read first
- `plugins/sdlc-lite/AGENTS.md`
### Do
Change only `plugins/sdlc-lite/scripts/tickets.py`.
1. Next to `CONFIG_RE` add `EXTERNAL_RE = re.compile(r'\s*external_branch\s*:\s*(\S+)\s*(?:#.*)?')` and `external_branches(root)`: the captured names from `<root>/config` in file order, deduplicated, skipping blank and `#` lines the way `config_numbered` does; `[]` when the file is missing. `config_numbered` and `ensure_numbered_config` stay as they are.
2. Add `branch_tickets(root, branch)` returning `[(slug, meta)]` for the ticket folders at `<branch>:<rel>`, read from git objects with no checkout. Anchor, `rel`, and the env without `GIT_ENV_DROP` as in `worktree_pairs`. List the tree with `git ls-tree` (tree-ish `<branch>` when `rel` is `.`, else `<branch>:<rel>`), keep dirs by `load()`'s rule (skip names starting with `_` or `.` except a `DOT_RE` fullmatch), read every `<branch>:<rel>/<dir>/handoff.md` through one `git cat-file --batch` process (a `missing` or non-blob answer is skipped), `parse()` each blob and keep those with front matter, sorted by dir name. Return `[]` on any git failure, a missing branch, a non-git root, or a root outside the toplevel; an undecodable or malformed handoff is skipped, never raised.
3. `id_floor(root)`: fold the max `ID_RE` id over `branch_tickets(root, b)` for every registered `b` into today's max over `worktree_roots(root)`. A root with no registration takes the same path as today (an empty list, floor unchanged), so `stamp` in `cmd_new` and the follow-up id in `cmd_close` both stay above the registered branches' ids with no other change.
4. `cmd_check`: when the root is inside a git work tree, append to the ok output one `warning: external_branch <b> is not a local branch` line per registered `b` with no `refs/heads/<b>` (`git rev-parse -q --verify refs/heads/<b>^{commit}` fails); exit stays 0 (the same shape as the numbered-config warning). Outside git no warning.
5. Docstring: the usage block gains the `external_branch: <branch>` config line and what `new`, `close` and `check` do with it; the "Ids across git worktrees" paragraph says ids committed on a registered branch are read from git objects and counted, while an unregistered branch checked out nowhere stays unseen until `check` catches the clash after merge; `id_floor`'s docstring names the registered branches.
6. Selftest, inside the existing worktree block (git present): (i) `external_branches` on a config holding two `external_branch` lines, a `#` comment, blank lines, a trailing `# note`, a duplicate name, and the numbered line yields exactly the two names in order, and `config_numbered` still holds; (ii) a branch `ext` checked out nowhere (`checkout -b ext`, commit, back to `main`) holding `0002-b` (T-0002), `.0003-c` (T-0003, done), `_templates/handoff.md` (T-0009 front matter) and `plain/handoff.md` (no front matter): `branch_tickets` returns exactly the two tickets; a missing branch and a root outside git return `[]` without raising; (iii) case (b): with `external_branch: ext` registered and T-0002 committed only on `ext`, `new` in main mints T-0003, and a close follow-up filed with `--ticket 1 --expect` mints above it too; negative control: the same repo without the line mints T-0002 (the collision); (iv) `check` on a root registering `nosuch` prints the warning and exits 0, and `new` there still mints the next local id with empty stderr.
