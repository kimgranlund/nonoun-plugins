## Layout

- `scripts/run.sh`: the one runner. Holds the role:level → model/effort table, a git preflight (exits 2 outside a git work tree or before the first commit), the Fable-never-verifies-Fable swap, and a post-run check that the saved result holds the role's required section (it exits 3 and names the section when missing; the result file and `runs.jsonl` line are kept), and read-only enforcement (Edit/Write disallowed for every role except builder). Read-only does not block Bash, so the verifier's no-git-state-changes rule lives in its prompt. After the git preflight it reads the target repo's toplevel `.nvmrc`, matches it against `$NVM_DIR` (else `~/.nvm`) `versions/node` (exact, or the highest numeric prefix match), and prepends that `bin` to PATH, or leaves PATH unchanged with one stderr line for a missing version or an alias; it never sources nvm, and `SDLC_DRY_RUN=1` shows the resolution. run.sh exports `SDLC_TMP_WORKTREES=<toplevel>/.worktrees/tmp/<role>-<pid>` and removes every worktree under it on any exit, then runs `git worktree prune`.
- `hooks/block-publish.sh`: PreToolUse(Bash) hook. Inside a role run (`SDLC_ROLE`, set by run.sh per role run and by fanout for lane drivers) it blocks `git push`, `gh pr/issue` writes, `gh release`, mutating `gh api`, and package publishing. It matches after masking heredoc bodies, quoted string contents, and comments, so a command that only writes or quotes a publish phrase passes; a `$(...)` or backtick substitution inside double quotes or an unquoted heredoc stays scannable. It scans the raw text instead when a shell or evaluator (such as `bash`, `sh`, `eval`, `xargs` or `ssh`) is present as a command word, or when parsing fails (python3 missing, an unterminated quote or heredoc). Your own session is not affected, so `/file` can publish after approval.
- `hooks/block-background.sh`: PreToolUse(Bash, Agent) hook. In a headless session (`SDLC_ROLE` set by run.sh or fanout, or `SDLC_HEADLESS=1`) it denies any Bash call with `run_in_background: true` and any Agent call unless `run_in_background` is explicitly `false` (Agent runs in the background by default, so a missing field counts as background) (exit 2) and tells the model to run in the foreground with the Bash timeout at 600000 or more and never end the turn while it runs, because ending the turn ends the session and abandons the work. Convention: every headless launcher sets `SDLC_HEADLESS=1`; bench.sh and fanout do, and any other (a dogfood script) must set it itself. Interactive sessions are not affected. Its fixtures live in `scripts/hook-selftest.sh`; `scripts/hook-live-probe.sh` confirms the live payload shape against a real session (opt-in, one model call).
- `hooks/block-pattern-kill.sh`: PreToolUse(Bash) hook. Inside a role run (`SDLC_ROLE` set) it blocks killing by name pattern (`pkill` or `killall` in command position, `kill` fed by `pgrep`) (exit 2), because a pattern also hits processes other sessions, lanes, or the user started; `kill <pid>` and quoted mentions pass. It fails closed, scanning the raw text, on a heredoc, a shell or evaluator command word, an unterminated quote, or a missing python3. Builders stop only the PIDs they started and run formatters only on the files the step changed; `check.py` guards both phrases in `agents/builder.md`. Its fixtures live in `scripts/hook-selftest.sh`.
- Feed: `scripts/board.py` renders the status board from `.sdlc/` (skill `/board`; `/chain` reports with it); it adds ID and Ticket columns, read with `tickets.py`'s parser, when a rendered task has ticket front matter, and leaves off tasks whose ticket is `dropped` or `done` with no recorded step work, and renders a `done` ticket with no plan as a `closed` task row (and `--summary` line); by default (no `--sort`) it orders by ticket id when any rendered task has ticket front matter (unticketed tasks follow by recency) and by recency otherwise; `--sort id|name|recent` overrides, and `--sort recent` restores recency; its "· changed" cache lives in a per-user cache dir outside the repo (`SDLC_BOARD_STATE_DIR` overrides it), so `/board` writes nothing into the tree; it prints a one-line hint when a legacy `.sdlc/.board-state.json` is present (never deleted automatically, never in `--summary`). `board.py --lanes` instead prints one `| Lane | Branch | Board |` row per `git worktree list` entry (worktree basename, branch, and that worktree's `--summary` line of the same-relative root), exits 1 outside a git work tree, and leaves the default board unchanged. `scripts/statusline.sh` shows line 1: model, dir, git (branch, dirty, ahead/behind, worktree), context % (🟡 at 70, 🔴 at 85), session cost and duration; line 2 only when `.sdlc/` has tasks: the live role run plus `board.py --summary` (task %, 🔴 count, ⚠ L5); it is wired in `~/.claude/settings.json` by absolute path to `plugins/sdlc-lite/scripts/statusline.sh` (backup: `settings.json.bak-statusline`). `output-styles/sdlc-feed.md` is an optional session style (`/output-style`). `run.sh` keeps `<role>-<level>.running` during a run so both can see live work.
- Agent skills: an agent's frontmatter `skills:` list is loaded by `run.sh` (appended with `--append-system-prompt-file`, plugin paths filled in), because `claude --agent` does not preload them (token probe with a positive control, 2026-09-24). planner ← `level-rubric`, architect ← `decompose`, verifier ← `checks-that-bite` (brought in from the user-level skill) and `checking-rules` (ported from harness checking-rules, trimmed). `check.py` fails on a declared skill that does not exist.
- `scripts/tickets.py`: backs `/ticket`. `new <type> <slug> ["title"]` stamps a ticket with the next id, and `new` and `close` follow-ups take the next id above the max across the same-relative ticket root in every `git worktree list` tree (local root only outside git); `check` fails on two tickets sharing an id and names both folders, which also catches branches not checked out in any worktree after merge, `close <slug> [--force]` (run by `/file`; `close <slug> --reason "<text>"` closes a ticket finished by other work, without a filer file; `close <slug> --ack-warnings "<why>"` closes while Warnings are open, files follow-ups normally, and appends a `## Closed` section with the date, the reason, and the quoted warnings, refusing with `--force` or `--reason`, with empty text, or when no warnings are open, and with `--dry-run` passing the gate and writing nothing) sets the ticket `done`, files its filer follow-ups as `proposed` idea tickets, skipping any that exactly duplicate another ticket (normalized title or slug; the ticket being closed never counts), and refuses while Warnings are open unless forced; a no-filer refusal names each other worktree's same-relative `<slug>/` folder holding a `filer-L*.md` (glob only, never read) so it can be committed or copied in; `close --dry-run` lists the proposed follow-ups with indices and duplicate marks, then one `open T-NNNN <title> [<slug>]` line per other proposed, ready, or blocked ticket, plus each open ticket that exists only in another git worktree's same-relative ticket root as `open T-NNNN <title> [<slug>] (worktree <name>)` after the local lines (a local copy decides any id it holds), and writes nothing, ending with an `expect <digest>` line of the ordered follow-ups, and `close --skip N[,N...]` files all but the named ones, requires `--expect <digest>`, and refuses, writing nothing, when the digest no longer matches (`/file` runs the dry run and confirms the follow-ups first; none of these flags combines with `--reason`), `roadmap` regenerates `.sdlc/roadmap.md` in dependency order, `check` fails on a bad ticket or a stale roadmap, `selftest` proves each check failure fires. `--root DIR` sets the ticket root (default `.sdlc`). Numbered folders are opt-in: `--numbered` on `new`/`close`/`roadmap`/`check` or a `ticket_folders: numbered` line in `<root>/config` names folders `NNNN-<slug>` from the stamped id and makes `check` enforce the prefix only then, and `roadmap` refuses on a prefix mismatch in numbered mode; a successful `new --numbered` or `close --numbered` also persists that config line, so a later plain `check` enforces it, and plain `check` warns, without failing, when every folder has an `NNNN-` prefix but the config lacks the line; plain slugs are the default. In numbered mode `close` also renames `NNNN-<slug>` to `.NNNN-<slug>` so Finder and `ls` hide finished work; every tool treats a `.NNNN-<slug>` folder as a closed ticket in either mode (user decision, T-0054), `check` fails on a dot folder that is not done or dropped, and `archive [--dry-run]` renames existing done/dropped numbered folders; `_templates` and other dot entries stay skipped. Templates: `<root>/_templates/<type>.md` first, else `skills/ticket/templates/<type>.md`.
- `scripts/order.py`: the shared ordering rule for which result is newest (builder, verifier, planner): latest `runs.jsonl` record (run.sh records `file` on each line), else level then rerun index then name; never mtime. `check.sh` runs its selftest.
- `scripts/steps.py`: `split <planner.md | task dir> [--only N]` writes `step-<n>/handoff.md` per the step template, refuses a step dir holding builder or verifier output, refuses, with `plan defect` on stderr, a plan whose acceptance criterion command spans do not parse under `bash -n` or join two checks with `||` (an unquoted `||`, except after `test $# -eq 0`), or hold a criterion that pins a commit sha (the word `git` plus a 7 to 40 char hex run with a digit and a letter; compare against `HEAD` instead), or one that compares a count over a changing set with a fixed number (`wc -l`, `grep -c`, or `grep --count` over a `*` glob, `ls`, or `find`, compared with a literal of 2 or more), and with `--only N` runs that step's `(guard)` command spans under `--guard-timeout` (default 300s) from the git toplevel, skipping `HEAD^1` and `<placeholder>` spans, and refuses on a red guard or timeout with a `plan defect:` last line and writes nothing, and also refuses when its guards changed the work tree, tracked or untracked, versus before they ran, naming the paths (outside git there is no check; a tree already dirty before is fine) (full `split` and `lint` execute nothing), `lint <planner.md | task dir>` runs the same check and writes nothing, `next <step dir>` (read-only) prints the next action (`build`, `verify`, `reverify`, `rebuild`, `bump`, `replan`, `done`, `stop`, `inherited`) from the newest builder and verifier results by `order.py` and exits 1 with `steps next:` on stderr on a bad dir (a builder result with no done/blocked Status is not an error: it maps to `rebuild` at its level, and two in a row map to `stop`; a builder Status `inherited red: <tests>` (a gate already red at the pre-build HEAD) maps to `inherited`, never a fail, rebuild, bump, or replan, `board.py` renders that step 🔴 inherited red, and `run.sh` accepts that Status; a verifier result with no pass/fail verdict is not an error: it maps to `reverify`, is never counted as a fail, and two in a row stop), and `selftest` proves each failure; `/chain` steps 3 and 4.2 run `split`, and step 4 runs `next` after every builder and verifier run.
- `scripts/fanout.py`: `run <lane>=<id>[,<id>...]... [--root .sdlc] [--base REF] [--integration BRANCH] [--lanes-dir DIR] [--gate CMD]... [--driver CMD] [--dry-run]` runs ticket lanes in parallel. Each lane is a git worktree under `<toplevel>/.worktrees/fanout/<lane>` by default (`--lanes-dir` overrides); preflight refuses (exit 2, telling you to add `.worktrees/` to `.gitignore`) when `.worktrees/` is not git-ignored, and an explicit `--lanes-dir` inside the tree must be ignored too. Caveat: `.gitignore` does not exclude `.worktrees/` from vitest, tsc, or file watchers, so a project must exclude it in their config, and Node module resolution walks up from a lane worktree into the main tree's `node_modules`. Each lane is on branch `<integration>-<lane>`, cut from the integration branch (`--integration`, default `fanout/<YYYY-MM-DD>`, created at `--base`, default `HEAD`, or reused), which is checked out in `<lanes-dir>/integration`. One thread and one headless conductor per lane (`claude -p --agent sdlc-lite:conductor`, Opus medium, told to run `/sdlc-lite:chain` unattended, run the filer without closing, and never commit, push, or publish); `--driver CMD` replaces it (stubs, the selftest) and gets `FANOUT_*` env, `SDLC_HEADLESS=1`, and `SDLC_ROLE=conductor`, so `hooks/block-publish.sh` guards the Claude sessions it launches. Per ticket, in order: sync the lane from the integration branch (under the lock, so a lane never picks up a merge still in its gates), run the driver, then the script makes the lane commit `<id>: <title>` (nothing staged: `no changes`). Under an exclusive `fcntl.flock` on `<lanes-dir>/merge.lock` (macOS has no `flock` binary) it merges the lane with `--no-ff` in the integration worktree, runs each `--gate` there, and on the first red one runs `git reset --hard` to the pre-merge commit; all green, it closes the ticket on the integration branch (`tickets.py close`, copying the lane's ticket folder in when the integration copy lacks a `filer-L*.md`) and commits `close <id>`. A lane stops at its first outcome other than `merged` and marks the rest `skipped`. It prints `[<lane>] <id> <event>` lines, writes and prints `<lanes-dir>/report.md`, and exits 0 only when every ticket merged, 1 otherwise, 2 on a refusal (preflight and `--dry-run` create nothing; unknown, done, or twice-listed ids, existing lane branches or dirs, and uncommitted handoffs refuse). Main is never touched: checkout, reset, and commit run only inside the lanes dir, nothing is pushed, and the worktrees stay for inspection. `selftest` proves it on throwaway repos with a stub driver; `check.sh` runs it.

## Decisions

- **Clean context is the default.** Agents start with no conversation history. Everything an agent needs arrives through its prompt, `$ARGUMENTS`, or a handoff file on disk (goal, decisions, paths).
- **Launch pattern: every role runs headless through the runner**, because only `claude -p --model --effort` can set effort (skill and agent frontmatter cannot). A skill with `context: fork` plus `agent:` is used only where effort does not matter.
- **Builders have 5 levels, each with a fixed model and effort:**

  | Level | Model | Effort |
  |---|---|---|
  | L1 | Sonnet | low |
  | L2 | Opus | low |
  | L3 | Opus | high |
  | L4 | Opus | xhigh |
  | L5 | Fable | xhigh |

- **Builders run headless, not as in-session subagents.** Agent and skill frontmatter have no `effort` field (checked against the docs on 2026-09-24), so every launcher skill calls `scripts/run.sh`, which runs `claude -p --agent sdlc-lite:<role> --model <m> --effort <e>`. Input and output go through handoff files (see `skills/handoff-format`).
- **Researcher, Planner, and Verifier have L1 to L3:**

  | Role | L1 | L2 | L3 |
  |---|---|---|---|
  | Researcher | Sonnet medium | Opus medium | Opus high |
  | Planner | Sonnet medium | Opus medium | Fable xhigh |
  | Verifier | Sonnet medium | Sonnet high | Fable xhigh |

  Verifier level follows build level: builder L1 or L2 → verifier L1, L3 → L2, L4 or L5 → L3. A replan forces Planner L3. `run.sh` never lets a verifier run on the build's model family (user decision, T-0005): after a Fable or Sonnet build, a verifier on that family becomes Opus at the same effort.
- **Fable** is Builder L5, Verifier L3, Planner L3, and Architect. All models and efforts were confirmed by the user on 2026-09-24; Verifier L2 moved from Fable medium to Sonnet high on 2026-09-25 (user decision, cost: 98 Fable L2 verifies cost about $145 in one day). There is no L6: when L5 fails, escalate to the user.
- **When `/build` gets no level**, the skill takes `level:` from the handoff if present. Otherwise it assesses the step against the rubric in `skills/level-rubric/SKILL.md` and picks the lowest fitting level. The same applies to every leveled role.
- **Headless runs use `--dangerously-skip-permissions`.** Every `claude -p` call includes it, so builders can edit files and run tests without prompts. (`auto` denied writes headless; `acceptEdits` needs allow rules for shell commands.) Run builders only in a repo or worktree you are willing to let them change.
- **A plan defect goes to a replan, never a rebuild.** The tag is the literal prefix `plan defect:`, emitted as the first line of a blocked builder's `## Notes`, the first line of a failing verifier's `## For the next attempt`, or the last line of a `steps.py split` refusal. `/chain` (and the conductor) answer it with a planner L3 replan on the task handoff, recording split refusals under the handoff's `## Plan review`; it never triggers a rebuild, a level bump, or a `## Previous attempt` note, and never counts toward a bump. A red guard in `steps.py split --only N` (a step's `(guard)` criterion failing or timing out against the current tree) is a plan defect too, and so is a guard that changed the work tree. The `steps.py split` lint (criterion command spans must parse under `bash -n`), the `split --only` guard run (red guard or a guard that changed the work tree), and `steps.py next`, which routes a `plan defect:` tag or a blocked build to `replan`, are the code gates; the rest is instructions. The planner runs each criterion once before writing it (red now for new behavior, green now for a `(guard)`), and scopes whole-file or repo checks to "no new findings versus the base commit". A recurring finding (a fail or block repeating an earlier attempt's criterion and root cause after it was addressed) is recorded as a `recurring finding:` entry under `## Plan review` and takes the same planner L3 replan, which must change the criterion, step, or rule, never bump a level. `check.py` guards the tag's and the `recurring finding` rule's presence across the docs (T-0060).
- **A full-context fork (`subagent_type: "fork"`) is an exception.** Use one only with a stated reason. It always runs on the parent's model and inherits the parent's blind spots, so it is never an independent reviewer.
- **A merge is a standard builder step.** The `merge-step` template lives in `agents/planner.md` and `skills/handoff-format/SKILL.md`. On a merge step the builder runs `git merge --no-ff <branch>` and makes the merge commit; that is the only step kind where the builder commits. Push and publishing stay blocked, and the verifier never changes git state. Its criteria are two parents, the branch as an ancestor, no MERGE_HEAD, no conflict-marker lines the merge itself added (the lines `git diff-tree --cc` marks as new versus both parents, so a lane line that starts with seven `<` or `>` passes; a kept marker line textually identical to a parent line and aligned with it also passes, an accepted limitation that the check.py probe pins), and gates with no new findings versus HEAD^1. `check.py` keeps the two copies identical and lint-clean, runs their conflict-marker guard against a throwaway repo, and keeps them in step with builder.md.
