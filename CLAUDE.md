# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Status

Paths below are relative to that plugin folder unless they start with the repo root. Git remote: `kimgranlund/sdlc-lite` (private). ## Commands

- Check everything: `scripts/check.sh` (the `merge-step` template guard in check.py, level tables in run.sh, level-rubric, and this file agree; every agent has a run.sh case; the tickets, board, steps, fanout, and run selftests; `hook-selftest.sh` (block-publish.sh, block-background.sh, block-pattern-kill.sh, block-stray-worktree.sh, block-repo-format.sh); `hook-live-probe.sh --selftest` (offline); shellcheck; `claude plugin validate`). Run it after any change to a level, model, effort, or role. The validate warning about this CLAUDE.md is expected: it guides work on this repo and is not shipped as context.
- Load it in a session: `claude --plugin-dir /Users/kimba/Projects/nonoun/sdlc-agents/plugins/sdlc-lite`, then `/sdlc-lite:<skill>`. Or install from this repo as a marketplace (`/plugin marketplace add /Users/kimba/Projects/nonoun/sdlc-agents`).
- This repo's own sessions run as `sdlc-lite-author` (`.claude/agents/sdlc-lite-author.md`, set in `.claude/settings.json`, which also enables `harness@nonoun-plugins` for authoring tools in this repo only; the shipped plugin never depends on it): the maintainer's invariants, after-change checks, and learned hazards. Keep it in sync with this file.
- Default agent: in a target repo's `.claude/settings.json`, `"agent": "sdlc-lite:conductor"` makes every session there the conductor (routes asks to skills, dispatches roles, reports with /board, makes only trivial edits itself). Declare it per repo, never in user settings.
- Run one role directly: `scripts/run.sh <role> <level> <handoff.md>` (writes `<role>-<level>.md`, `.log`, and a `runs.jsonl` line next to the handoff; a rerun writes `<role>-<level>-<k>.md` and never overwrites)
- Live hook probe (opt-in): `scripts/hook-live-probe.sh [--agent] [--out FILE] [--model M] [--timeout SEC]` runs one small real `claude -p` session (default model haiku) told to call Bash with `run_in_background: true`, captures the PreToolUse(Bash) payload Claude Code sends, and passes only when `tool_input.run_in_background` is a JSON boolean `true` and `hooks/block-background.sh` denies the call (exit 2) with `SDLC_HEADLESS=1`. `scripts/hook-live-probe.sh --agent` instead makes two small runs (a deny run told to leave `run_in_background` out, an allow run told to pass `run_in_background: false`) and passes only when both calls reach PreToolUse as `tool_name` `Agent`, the hook denies the first (exit 2, field absent or boolean `true`) and passes the second (exit 0, field the JSON boolean `false`), and a PostToolUse(Agent) record proves the allowed call ran; a match-all logger names the tool called instead (for example `Task`) on a FAIL. Live mode spends model calls, so `check.sh` runs only its offline `--selftest` (stub claude), which covers both the Bash and the Agent path; exit 0 PASS, 1 FAIL, 2 setup error.
- Check a level mapping without a model call: `SDLC_DRY_RUN=1 scripts/run.sh builder L3 <handoff.md>`
- Fan out lanes: `scripts/fanout.py run <lane>=<ids>...` (skill `/fanout`: dry run, confirm, run, report, then an optional `git merge --ff-only` of main after approval).
- Benchmark: `scripts/bench.sh [task ...]` runs tasks headless (raises Bash timeouts so role runs stay in the foreground), then `scripts/bench-summary.sh`. The bench dir (tasks, results, logs) resolves in this order: `--bench-dir DIR`, then `SDLC_BENCH_DIR`, then `<project>/bench/` (git toplevel), then the plugin's `bench/`, via `scripts/bench-dir.sh`. This repo's root has no `bench/`, so the dev bench stays at `plugins/sdlc-lite/bench/`.

## Layout

- `scripts/run.sh`: the one runner. Holds the role:level → model/effort table, a git preflight (exits 2 outside a git work tree or before the first commit), the Fable-never-verifies-Fable swap, and a post-run check that the saved result holds the role's required section (it exits 3 and names the section when missing; the result file and `runs.jsonl` line are kept); a builder Status or verifier Verdict `inherited red: <tests>` is accepted), and read-only enforcement (Edit/Write disallowed for every role except builder). Read-only does not block Bash, so the verifier's no-git-state-changes rule lives in its prompt. After the git preflight it reads the target repo's toplevel `.nvmrc`, matches it against `$NVM_DIR` (else `~/.nvm`) `versions/node` (exact, or the highest numeric prefix match), and prepends that `bin` to PATH, or leaves PATH unchanged with one stderr line for a missing version or an alias; it never sources nvm, and `SDLC_DRY_RUN=1` shows the resolution. run.sh exports `SDLC_TMP_WORKTREES=<toplevel>/.worktrees/tmp/<role>-<pid>` and removes every worktree under it on any exit, then runs `git worktree prune`. At run end it compares a before and after snapshot of worktrees and branches, excluding this run's own prefix, and when a stray appeared (created from inside a script or program, not the Bash tool text the hook sees) it prints a stderr line quoting `stray worktree appeared during this run` and records `stray_worktrees` and `stray_branches` fields in the `runs.jsonl` line; this is report only, it does not change the run's exit code, and a dry run takes no snapshot.
- `hooks/block-publish.sh`: PreToolUse(Bash) hook. Inside a role run (`SDLC_ROLE`, set by run.sh per role run and by fanout for lane drivers) it blocks `git push`, `gh pr/issue` writes, `gh release`, mutating `gh api`, and package publishing. It matches after masking heredoc bodies, quoted string contents, and comments, so a command that only writes or quotes a publish phrase passes; a `$(...)` or backtick substitution inside double quotes or an unquoted heredoc stays scannable. It scans the raw text instead when a shell or evaluator (such as `bash`, `sh`, `eval`, `xargs` or `ssh`) is present as a command word, or when parsing fails (python3 missing, an unterminated quote or heredoc). It also scans the raw text on interpreter inline code: an interpreter (python, python3, node, perl, ruby, path-qualified too) as a command word with an inline-code flag (python `-c`; node `-e`, `-p`, `--eval`, `--print`; perl `-e`, `-E`; ruby `-e`), also when options taking a separate value word come before the flag (`python3 -X dev -c`, `node --require x -e`, `perl -I lib -e`), while `python3 script.py` keeps the masked scan. Your own session is not affected, so `/file` can publish after approval.
- `hooks/block-background.sh`: PreToolUse(Bash, Agent) hook. In a headless session (`SDLC_ROLE` set by run.sh or fanout, or `SDLC_HEADLESS=1`) it denies any Bash call with `run_in_background: true` and any Agent call unless `run_in_background` is explicitly `false` (Agent runs in the background by default, so a missing field counts as background) (exit 2) and tells the model to run in the foreground with the Bash timeout at 600000 or more and never end the turn while it runs, because ending the turn ends the session and abandons the work. Convention: every headless launcher sets `SDLC_HEADLESS=1`; bench.sh and fanout do, and any other (a dogfood script) must set it itself. Interactive sessions are not affected. Its fixtures live in `scripts/hook-selftest.sh`; `scripts/hook-live-probe.sh` confirms the live Bash payload shape against a real session (opt-in, one model call), and `scripts/hook-live-probe.sh --agent` confirms that the subagent tool reaches PreToolUse as `Agent`, is denied without `run_in_background: false`, and runs with it (opt-in, two model calls); its offline selftest covers the Agent path too.
- `hooks/block-pattern-kill.sh`: PreToolUse(Bash) hook. Inside a role run (`SDLC_ROLE` set) it blocks killing by name pattern (`pkill` or `killall` in command position, `kill` fed by `pgrep` or `ps` (`kill $(pgrep ...)`, `kill $(ps ... | awk ...)`, `pgrep` or `ps` piped through `grep` and `awk` into `xargs kill`), and a kill word held in a shell variable (`p=pkill; $p x`, `k=killall; ${k} node`, also one assigned through a `$(...)` or backtick substitution, `p=$(command -v pkill); $p x`)) (exit 2), because a pattern also hits processes other sessions, lanes, or the user started; `kill <pid>`, `kill %1`, `kill $(cat pidfile)`, `echo $! | xargs kill`, a variable holding another command (`cmd=ls; $cmd -la`), and quoted mentions pass. It fails closed, scanning the raw text, on a heredoc, a shell or evaluator command word, an unterminated quote, or a missing python3. Builders stop only the PIDs they started and run formatters only on the files the step changed; `check.py` guards both phrases in `agents/builder.md`. Its fixtures live in `scripts/hook-selftest.sh`.
- `hooks/block-stray-worktree.sh`: PreToolUse(Bash) hook. Inside a role run (`SDLC_ROLE` set) it denies (exit 2) a worktree add with `-b`, `-B`, or `--orphan`, any worktree add without `--detach`/`-d` (because git can otherwise create a branch, a remote-only name becomes a tracking branch, or check one out), and any worktree add whose path is not under `$SDLC_TMP_WORKTREES`; the detached form with a path under the prefix passes, and nothing changes when `SDLC_ROLE` is unset. It fails closed, scanning the raw text, when the command cannot be parsed safely. fanout.py's own worktrees are untouched because they are not Bash tool calls, and run.sh's EXIT cleanup of the prefix stays. A worktree or branch made from inside a script or program a role runs, rather than through the Bash tool text the hook sees, bypasses this hook; run.sh reports any such stray at run end (see the `scripts/run.sh` bullet above). Its fixtures live in `scripts/hook-selftest.sh`.
- `hooks/block-repo-format.sh`: PreToolUse(Bash) hook. Only inside a builder run (`SDLC_ROLE=builder`; every other role and a session with no role pass) it denies (exit 2) a repo-wide formatter, `--fix` linter, or format script: a project format script (`npm`, `pnpm`, `yarn`, `bun run`, or `make` with a name such as `format`, `fmt`, `prettier`, `lint:fix`, or `fix`, bare `pnpm`/`yarn`/`bun <name>` too) and a formatter or fixer in write or fix mode (`prettier --write`, `eslint --fix`, `black`, `ruff format`, `ruff check --fix`, `gofmt -w`, `go fmt`, `cargo fmt`, `rustfmt`, `biome ... --write`, `dprint fmt`, `stylelint --fix`, `clang-format -i`) whose targets are missing, a directory, `.`, a glob, a trailing `/`, a `./...` pattern, or a `$` expansion. Explicit file paths pass (`prettier --write a.ts`, `npm run format -- a.ts`), as do check-only modes and quoted mentions; package.json and Makefiles are never read. It fails closed, scanning the raw text, on a heredoc, a shell or evaluator command word (so `bash -c 'npm run format'` is blocked), an unterminated quote, or a missing python3. Its fixtures live in `scripts/hook-selftest.sh`.

The scan finds the folder name, then keeps files with a literal `<rel>/<slug>` (counted only where it starts a path token, at the start of the text or after whitespace, a quote, a backtick, a paren, or a bracket, so `other/<rel>/<slug>`, an absolute path into another tree, and `../other/<rel>/<slug>` are not references, and neither is a URL or prefixed form such as `https://.../<rel>/<slug>` or `key=<rel>/<slug>`; ending at `/`, the end of a token, or punctuation, never running on into a longer folder name such as `<rel>/<slug>b`) or a path token that resolves to the folder, whether toplevel-relative, relative to the citing file's directory, or absolute. Templates: `<root>/_templates/<type>.md` first, else `skills/ticket/templates/<type>.md`.

- `scripts/fanout.py`: `run <lane>=<id>[,<id>...]... [--root .sdlc] [--base REF] [--integration BRANCH] [--lanes-dir DIR] [--gate CMD]... [--driver CMD] [--rewrite-refs] [--dry-run]` runs ticket lanes in parallel. Each lane is a git worktree under `<toplevel>/.worktrees/fanout/<lane>` by default (`--lanes-dir` overrides); preflight refuses (exit 2, telling you to add `.worktrees/` to `.gitignore`) when `.worktrees/` is not git-ignored, and an explicit `--lanes-dir` inside the tree must be ignored too. Caveat: `.gitignore` does not exclude `.worktrees/` from vitest, tsc, or file watchers, so a project must exclude it in their config, and Node module resolution walks up from a lane worktree into the main tree's `node_modules`. Each lane is on branch `<integration>-<lane>`, cut from the integration branch (`--integration`, default `fanout/<YYYY-MM-DD>`, created at `--base`, default `HEAD`, or reused), which is checked out in `<lanes-dir>/integration`. One thread and one headless conductor per lane (`claude -p --agent sdlc-lite:conductor`, Opus medium, told to run `/sdlc-lite:chain` unattended, run the filer without closing, and never commit, push, or publish); `--driver CMD` replaces it (stubs, the selftest) and gets `FANOUT_*` env, `SDLC_HEADLESS=1`, and `SDLC_ROLE=conductor`, so `hooks/block-publish.sh` guards the Claude sessions it launches. Per ticket, in order: sync the lane from the integration branch (under the lock, so a lane never picks up a merge still in its gates), run the driver (a driver run leaving a `step-<n>/` whose `steps.py next` action is `inherited` gives the outcome `inherited red: step-<n>: <tests>`, also after a non-zero driver exit, then with the driver rc as a ` (driver rc=<n>)` suffix (a non-zero exit with no inherited step stays `driver failed rc=<n>`): no `<id>: <title>` lane commit, no merge, no close, the lane stops, and the work is kept in the stop's `wip(<id>)` commit below), then the script makes the lane commit `<id>: <title>` (nothing staged: `no changes`). Under an exclusive `fcntl.flock` on `<lanes-dir>/merge.lock` (macOS has no `flock` binary) it merges the lane with `--no-ff` in the integration worktree, runs each `--gate` there, and on the first red one runs `git reset --hard` to the pre-merge commit; all green, it closes the ticket on the integration branch (`tickets.py close`, copying the lane's ticket folder in when the integration copy lacks a `filer-L*.md`) and commits `close <id>`. When a lane stops (any outcome other than `merged`, including a driver failure), the script commits a dirty lane tree as `wip(<id>): <outcome>` on the lane branch; a lane tree already dirty before a ticket's sync is committed as `wip(<id>): dirty before sync` and that ticket stops with the outcome `dirty before sync` (no sync, driver, lane commit, or merge). Both commits stay on the lane branch only, are never merged, and their sha shows in the report. A lane stops at its first outcome other than `merged` and marks the rest `skipped`. It prints `[<lane>] <id> <event>` lines, writes and prints `<lanes-dir>/report.md`, and exits 0 only when every ticket merged, 1 otherwise, 2 on a refusal (preflight and `--dry-run` create nothing; unknown, done, or twice-listed ids, existing lane branches or dirs, and uncommitted handoffs refuse). Main is never touched: checkout, reset, and commit run only inside the lanes dir, nothing is pushed, and the worktrees stay for inspection. `selftest` proves it on throwaway repos with a stub driver; `check.sh` runs it. `--rewrite-refs` (opt-in, numbered mode) passes the flag to `tickets.py close`, and the `close <id>` commit stages every file the close rewrote. Without it, a citing file gives `merged, close refused: ...` with a hint naming the flag. The dry run's `close:` line shows the mode.

Escalation is enforced by `/chain` instructions and three code gates: `steps.py next` computes the step 4 action after each builder and verifier run, the `steps.py split` lint refuses a plan whose criterion commands do not parse, and `steps.py split --only N` refuses a step with a red guard or a guard that changed the work tree.

## Decisions

- **Clean context is the default.** Agents start with no conversation history. Everything an agent needs arrives through its prompt, `$ARGUMENTS`, or a handoff file on disk (goal, decisions, paths).
- **Launch pattern: every role runs headless through the runner**, because only `claude -p --model --effort` can set effort (skill and agent frontmatter cannot). A skill with `context: fork` plus `agent:` is used only where effort does not matter.
- **Builders have 5 levels, each with a fixed model and effort:**

  | Level | Model | Effort |
  |---|---|---|
  | L1 | Sonnet | low |
  | L2 | Opus | low |
  | L3 | Opus | high |
  | L4 | Opus | xhigh |
  | L5 | Fable | xhigh |

- **Builders run headless, not as in-session subagents.** Agent and skill frontmatter have no `effort` field (checked against the docs on 2026-09-24), so every launcher skill calls `scripts/run.sh`, which runs `claude -p --agent sdlc-lite:<role> --model <m> --effort <e>`. Input and output go through handoff files (see `skills/handoff-format`).
- **Researcher, Planner, and Verifier have L1 to L3:**

  | Role | L1 | L2 | L3 |
  |---|---|---|---|
  | Researcher | Sonnet medium | Opus medium | Opus high |
  | Planner | Sonnet medium | Opus medium | Fable xhigh |
  | Verifier | Sonnet medium | Sonnet high | Fable xhigh |

  Verifier level follows build level: builder L1 or L2 → verifier L1, L3 → L2, L4 or L5 → L3. A replan forces Planner L3. `run.sh` never lets a verifier run on the build's model family (user decision, T-0005): after a Fable or Sonnet build, a verifier on that family becomes Opus at the same effort.
- **Fable** is Builder L5, Verifier L3, Planner L3, and Architect. All models and efforts were confirmed by the user on 2026-09-24; Verifier L2 moved from Fable medium to Sonnet high on 2026-09-25 (user decision, cost: 98 Fable L2 verifies cost about $145 in one day). There is no L6: when L5 fails, escalate to the user.
- **When `/build` gets no level**, the skill takes `level:` from the handoff if present. Otherwise it assesses the step against the rubric in `skills/level-rubric/SKILL.md` and picks the lowest fitting level. The same applies to every leveled role.
- **Headless runs use `--dangerously-skip-permissions`.** Every `claude -p` call includes it, so builders can edit files and run tests without prompts. (`auto` denied writes headless; `acceptEdits` needs allow rules for shell commands.) Run builders only in a repo or worktree you are willing to let them change.
- **A plan defect goes to a replan, or to one verifier-proposed criterion swap, never a fail rebuild.** The tag is the literal prefix `plan defect:`, emitted as the first line of a blocked builder's `## Notes`, the first line of a failing verifier's `## For the next attempt`, or the last line of a `steps.py split` refusal. `/chain` (and the conductor) answer it with a planner L3 replan on the task handoff, recording split refusals under the handoff's `## Plan review`; it never triggers a rebuild, a level bump, or a `## Previous attempt` note, and never counts toward a bump. The one exception (T-0123): a verifier plan defect whose note holds one `swap old:`/`swap new:` pair, the first on the step, makes `steps.py next` print `swap`; when `steps.py swap` accepts it, it rewrites that one criterion in the step handoff and the step rebuilds at the same level, with no bump and no `## Previous attempt`, recorded as a `swap applied:` line under `## Plan review`; a refused swap, or a second swap on the step, replans; a builder never proposes a swap, because whoever writes the work never sets its check. A red guard in `steps.py split --only N` (a step's `(guard)` criterion failing or timing out against the current tree) is a plan defect too, and so is a guard that changed the work tree. The `steps.py split` lint (criterion command spans must parse under `bash -n`), the `split --only` guard run (red guard or a guard that changed the work tree), `steps.py next`, which routes a `plan defect:` tag or a blocked build to `replan` (or a verifier's first swap pair to `swap`), and `steps.py swap`, which reruns the new spans and refuses a red one or one that changed the work tree, are the code gates; the rest is instructions. The planner puts whole-suite gate guards on one final `gates green` step, never on every step (check.py guards the phrase). The planner runs each criterion once before writing it (red now for new behavior, green now for a `(guard)`), sees each `(guard)` red first (un-negated, or on a fixture) so it is a check that can go red, checks files other lanes change by membership or structure, never by an exact line, and scopes whole-file or repo checks to "no new findings versus the base commit". A recurring finding (a fail or block repeating an earlier attempt's criterion and root cause after it was addressed) is recorded as a `recurring finding:` entry under `## Plan review` and takes the same planner L3 replan, which must change the criterion, step, or rule, never bump a level. `check.py` guards the tag's and the `recurring finding` rule's presence across the docs (T-0060).
- **A full-context fork (`subagent_type: "fork"`) is an exception.** Use one only with a stated reason. It always runs on the parent's model and inherits the parent's blind spots, so it is never an independent reviewer.
- **A merge is a standard builder step.** The `merge-step` template lives in `agents/planner.md` and `skills/handoff-format/SKILL.md`. On a merge step the builder runs `git merge --no-ff <branch>` and makes the merge commit; that is the only step kind where the builder commits. Push and publishing stay blocked, and the verifier never changes git state. Its criteria are two parents, the branch as an ancestor, no MERGE_HEAD, no conflict-marker lines the merge itself added (the lines `git diff-tree --cc` marks as new versus both parents, so a lane line that starts with seven `<` or `>` passes; a kept marker line textually identical to a parent line and aligned with it also passes, an accepted limitation that the check.py probe pins), and gates with no new findings versus HEAD^1. `check.py` keeps the two copies identical and lint-clean, runs their conflict-marker guard against a throwaway repo, and keeps them in step with builder.md.
