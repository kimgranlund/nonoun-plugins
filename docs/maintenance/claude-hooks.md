# Claude hook maintenance

Read when changing Claude hook behavior or its checks. Paths below are relative to `plugins/sdlc-lite/`. Hook registration lives in `adapters/claude/hooks.json`; the Claude manifest references it explicitly. Do not restore a shared `hooks/hooks.json`, which would leak Claude hooks into Codex discovery. These controls do not describe Codex enforcement.

## `hooks/block-publish.sh`

PreToolUse(Bash) hook. Inside a role run (`SDLC_ROLE`, set by run.sh per role run and by fanout for lane drivers) it blocks `git push`, `gh pr/issue` writes, `gh release`, mutating `gh api`, and package publishing. It matches after masking heredoc bodies, quoted string contents, and comments, so a command that only writes or quotes a publish phrase passes; a `$(...)` or backtick substitution inside double quotes or an unquoted heredoc stays scannable. It scans the raw text instead when a shell or evaluator (such as `bash`, `sh`, `eval`, `xargs` or `ssh`) is present as a command word, or when parsing fails (python3 missing, an unterminated quote or heredoc). It also scans the raw text on interpreter inline code: an interpreter (python, python3, node, perl, ruby, path-qualified too) as a command word with an inline-code flag (python `-c`; node `-e`, `-p`, `--eval`, `--print`; perl `-e`, `-E`; ruby `-e`), also when options taking a separate value word come before the flag (`python3 -X dev -c`, `node --require x -e`, `perl -I lib -e`), while `python3 script.py` keeps the masked scan. Your own session is not affected, so `/file` can publish after approval.

## `hooks/block-background.sh`

PreToolUse(Bash, Agent, Monitor) hook. In a headless session (`SDLC_ROLE` set by run.sh or fanout, or `SDLC_HEADLESS=1`) it denies any Bash call with `run_in_background: true` and any Agent call unless `run_in_background` is explicitly `false` (Agent runs in the background by default, so a missing field counts as background), and every Monitor call (Monitor only watches background work) (exit 2) and tells the model to run in the foreground with the Bash timeout at 600000 or more and never end the turn while it runs, because ending the turn ends the session and abandons the work. Convention: every headless launcher sets `SDLC_HEADLESS=1`; bench.sh and fanout do, and any other (a dogfood script) must set it itself. Interactive sessions are not affected. Its fixtures live in `scripts/hook-selftest.sh`; `scripts/hook-live-probe.sh` confirms the live Bash payload shape against a real session (opt-in, one model call), and `scripts/hook-live-probe.sh --agent` confirms that the subagent tool reaches PreToolUse as `Agent`, is denied without `run_in_background: false`, and runs with it (opt-in, two model calls); its offline selftest covers the Agent path too. `hook-selftest.sh` holds the Monitor fixtures (denied headless, passed interactive).

## `hooks/block-pattern-kill.sh`

PreToolUse(Bash) hook. Inside a role run (`SDLC_ROLE` set) it blocks killing by name pattern (`pkill` or `killall` in command position, `kill` fed by `pgrep` or `ps` (`kill $(pgrep ...)`, `kill $(ps ... | awk ...)`, `pgrep` or `ps` piped through `grep` and `awk` into `xargs kill`), and a kill word held in a shell variable (`p=pkill; $p x`, `k=killall; ${k} node`, also one assigned through a `$(...)` or backtick substitution, `p=$(command -v pkill); $p x`)) (exit 2), because a pattern also hits processes other sessions, lanes, or the user started; `kill <pid>`, `kill %1`, `kill $(cat pidfile)`, `echo $! | xargs kill`, a variable holding another command (`cmd=ls; $cmd -la`), and quoted mentions pass. It fails closed, scanning the raw text, on a heredoc, a shell or evaluator command word, an unterminated quote, or a missing python3. Builders stop only the PIDs they started and run formatters only on the files the step changed; `check.py` guards both phrases in `agents/builder.md`. Its fixtures live in `scripts/hook-selftest.sh`.

## `hooks/block-stray-worktree.sh`

PreToolUse(Bash) hook. Inside a role run (`SDLC_ROLE` set) it denies (exit 2) a worktree add with `-b`, `-B`, or `--orphan`, any worktree add without `--detach`/`-d` (because git can otherwise create a branch, a remote-only name becomes a tracking branch, or check one out), and any worktree add whose path is not under `$SDLC_TMP_WORKTREES`; the detached form with a path under the prefix passes, and nothing changes when `SDLC_ROLE` is unset. It fails closed, scanning the raw text, when the command cannot be parsed safely. fanout.py's own worktrees are untouched because they are not Bash tool calls, and run.sh's EXIT cleanup of the prefix stays. A worktree or branch made from inside a script or program a role runs, rather than through the Bash tool text the hook sees, bypasses this hook; run.sh reports any such stray at run end (see the `scripts/run.sh` bullet above). Its fixtures live in `scripts/hook-selftest.sh`.

## `hooks/block-repo-format.sh`

PreToolUse(Bash) hook. Only inside a builder run (`SDLC_ROLE=builder`; every other role and a session with no role pass) it denies (exit 2) a repo-wide formatter, `--fix` linter, or format script: a project format script (`npm`, `pnpm`, `yarn`, `bun run`, or `make` with a name such as `format`, `fmt`, `prettier`, `lint:fix`, or `fix`, bare `pnpm`/`yarn`/`bun <name>` too) and a formatter or fixer in write or fix mode (`prettier --write`, `eslint --fix`, `black`, `ruff format`, `ruff check --fix`, `gofmt -w`, `go fmt`, `cargo fmt`, `rustfmt`, `biome ... --write`, `dprint fmt`, `stylelint --fix`, `clang-format -i`) whose targets are missing, a directory, `.`, a glob, a trailing `/`, a `./...` pattern, or a `$` expansion. Explicit file paths pass (`prettier --write a.ts`, `npm run format -- a.ts`), as do check-only modes and quoted mentions; package.json and Makefiles are never read. It fails closed, scanning the raw text, on a heredoc, a shell or evaluator command word (so `bash -c 'npm run format'` is blocked), an unterminated quote, or a missing python3. Its fixtures live in `scripts/hook-selftest.sh`.


Use `bash plugins/sdlc-lite/scripts/hook-selftest.sh` and `bash plugins/sdlc-lite/scripts/hook-live-probe.sh --selftest` from the repository root for offline validation. Actual host payload changes also require the relevant opt-in live probe; it makes model calls. See the probe script usage for its Bash and Agent modes.
