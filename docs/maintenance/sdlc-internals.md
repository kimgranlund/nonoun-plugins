# SDLC implementation reference

Read only the entry relevant to the subsystem being changed. Paths in this reference are relative to `plugins/sdlc-lite/`; commands run from that directory. Shared scripts and their tests own executable behavior. Update affected entries when behavior changes.

Descriptions of Claude flags, skill preloading, background tools, permissions, and the default lane driver below apply to the Claude backend only. For Codex execution, sandboxing, and native delegation, read [Codex role execution](../codex-role-execution.md). The backend is selected with `SDLC_BACKEND`; the legacy default is Claude.

## Implementation map

## `scripts/run.sh`

the one runner. Holds the role:level → model/effort table, a git preflight (exits 2 outside a git work tree or before the first commit), the verifier family rule (a verifier never runs on the build's model family: a Fable or Sonnet build moves it to Opus at the same effort; the build is the newest builder result in the handoff dir or, when it holds none (a verifier launched at the task dir), the newest builder result of the highest-numbered `step-<n>/` under it that holds one, leaving out `step-<n>.superseded-<k>/` dirs; `run-selftest.sh` case `task dir`), the plan-reviewer family rule (a plan-reviewer never runs on the newest planner result's model family: an Opus planner moves the review to Fable at the same effort, a Fable or Sonnet planner keeps Opus), and a post-run check that the saved result passes `results.py validate --role <role>` (header, key section with an allowed first value, declared sections in declared order; on failure one stderr line `run.sh: <role> result <reason>; see <file>` and exit 3, with the result file and `runs.jsonl` line kept; a builder Status or verifier Verdict `inherited red: <tests>` is accepted, and a declared section out of order, such as a verifier `## Criteria` before `## Verdict`, exits 3 naming `comes before`, `run-selftest.sh`); the result-pick heading comes from `results.py key <role>`, and read-only enforcement (Edit/Write disallowed for every role except builder). Read-only does not block Bash, so the verifier's no-git-state-changes rule lives in its prompt. After the git preflight it reads the target repo's toplevel `.nvmrc`, matches it against `$NVM_DIR` (else `~/.nvm`) `versions/node` (exact, or the highest numeric prefix match), and prepends that `bin` to PATH, or leaves PATH unchanged with one stderr line for a missing version or an alias; it never sources nvm, and `SDLC_DRY_RUN=1` shows the resolution. run.sh sets `BASH_DEFAULT_TIMEOUT_MS` and `BASH_MAX_TIMEOUT_MS` to 3600000 for the role run unless already higher (fanout sets them too), so a long foreground command is not moved to the background by Claude Code, which no PreToolUse hook sees (T-0105). It logs the run as `--output-format stream-json --verbose` (the `.log` is one JSON event per line) and saves the last `result` event holding the role's required heading, else the last one whose origin is not `task-notification`, else the last one, because a background-task notification can end the session with its own result. run.sh exports `SDLC_TMP_WORKTREES=<toplevel>/.worktrees/tmp/<role>-<pid>` and removes every worktree under it on any exit, then runs `git worktree prune`. The role runs in the background and run.sh waits on it, so INT, TERM, or HUP reach the exit handler at once rather than after the role exits: it sends a still-running role TERM, then KILL after 2 s, and only then cleans up, well inside `run_lifecycle.py`'s 5 s grace before its SIGKILL (`run-selftest.sh` case `term cleanup`). A run SIGKILLed anyway leaves its prefix behind, so a real run also calls `scripts/reap-tmp-worktrees.sh <toplevel> <own prefix>` at the start and again at exit: it removes each dead-owner prefix under `.worktrees/tmp` (a `<role>-<pid>` dir whose pid names no live process, never the caller's own) with its registered worktrees, then prunes; it never deletes a branch and never fails (`run-selftest.sh` case `stale prefix`). At run end it compares a before and after snapshot of worktrees and branches, excluding this run's own prefix, and when a stray appeared (created from inside a script or program, not the Bash tool text the hook sees) it prints a stderr line quoting `stray worktree appeared during this run` and records `stray_worktrees` and `stray_branches` fields in the `runs.jsonl` line; this is report only, it does not change the run's exit code, and a dry run takes no snapshot. For builder and verifier it also exports `SDLC_BASE_SHA`, the build-start base: HEAD at the step's first builder run, kept in the step dir's `base-sha` file (rewritten when missing, not an ancestor of HEAD, or passed by a resync merge, which moves it to the newest first-parent merge); every other role gets it unset. Scope criteria compare with `git diff --name-only "$SDLC_BASE_SHA"` plus untracked files, so they hold whether or not the work is committed later. When a role edits run.sh while it runs (a builder rewriting the file in place), the running process is unaffected: the whole body after `set -euo pipefail` is one `{ ... }` group ending in `exit`, so bash parses it before executing any of it, keeps its behavior, and still saves its result (`run-selftest.sh` case `self-edit`). When the runner exits 0 without a result file, `run_lifecycle.py` (the lifecycle owner) records the run as failed with exit 1 and prints a `wrote no result` stderr line naming the expected result and the `.log` (`lifecycle-selftest.py` case `test_exit_zero_without_result_fails`). Before it launches a role (dry runs too, never in the `run_lifecycle.py` child), run.sh sums `messages.py count --receiver` for the role name and the backend name and, when the sum is above 0, prints one stderr line `run.sh: <n> new message(s) for <role>; read with messages.py`; a failed count adds 0, and the notice never prints a body or changes the exit code.

## `scripts/results.py`

The one declared result schema per role. `SCHEMA` is the only copy of the table: for each role a key section (required), an allowed set for the key section's first non-blank line (builder `## Status` done, blocked, `inherited red: <tests>`; verifier `## Verdict` pass, fail, `inherited red: <tests>`; plan-reviewer `## Verdict` pass, replan, blocked; empty for the other roles), and the declared section order from the `## ` lines of `agents/<role>.md`. Only the key section is required; declared sections that are present must appear in declared order, and undeclared headings are ignored. The first line must be the header `run.sh` writes. CLI: `validate <result.md> [--role R]` exits 0 or prints one `results.py: <file>: <reason>` line and exits 1; `schema [--role R]` prints the table; `key <role>` prints the key section name; `selftest`. Reasons: `no such file`, `cannot read`, `empty result`, a header that is missing or names an unknown or different role, `lacks ## <Key>`, `## <Key> first line "<v>" is not one of <allowed>`, and `## <A> comes before ## <B>`. `validate` runs every check and backs `run.sh` exit 3. `structure_error` skips the key presence and value checks for roles with an allowed set, so `steps.py` still routes a missing or disallowed Status or Verdict to `rebuild` or `reverify` and reports only structural defects as `invalid result`. `key_value` reads the allowed token for `steps.py`. `check.py` checks each agent body against `SCHEMA`. The selftest proves each reason on temp fixtures and runs `steps.py next` against them, with a negative control: a copy of `steps.py` beside an accept-all `results.py` prints `verify` where the real one prints `invalid result`. `check.sh` runs it.

## `scripts/evals.py`

Dated model and effort eval records in `.sdlc/evals/`, and the lock that ties the model table (the role:level rows of `scripts/run.sh` plus `adapters/codex/models.json`) to one of them. The record format and the canonical table text live in [the evals entry file](../../.sdlc/evals/AGENTS.md) and the evals.py docstring; this entry does not copy them. CLI: `evals.py [--root DIR] [--plugin DIR] <cmd>`, with `--root` the `.sdlc` folder (default `.sdlc` in the cwd) and `--plugin` the dir holding `scripts/run.sh` and `adapters/codex/models.json` (default the plugin holding the script). Commands: `add <slug> ...` writes the next `NNNN-<slug>.md` and refuses an invalid record without writing; `list` prints one line per eval and always exits 0; `check` validates every eval and the lock against the current table hash; `lock --eval PATH` cites an eval, and a replacement must be dated later than the eval it replaces; `hash` prints the current table sha256; `selftest`. Exit codes: 0 ok, 1 refusal or failed check, 2 usage error. Python API: `FIELDS`, `canonical_table(plugin)`, `table_sha256(plugin)`, `validate_text(text, repo)`, `validate_eval(path, repo)` (each validator returns None or one reason string, so later callers can validate a record without the CLI), and `check_problems(root, plugin)`. `.sdlc/evals/table-lock.json` holds exactly three keys: `eval` (the cited eval), `previous_eval` (the eval it replaced, or null), and `table_sha256` (the hash the cited eval covers); only `lock` writes it, and evals.py never writes `run.sh` or `models.json`. `check.py` docstring item 15 runs the check when `<plugin>/../../.sdlc` exists, printing each problem as `FAIL evals: <line>`, and prints `skip: evals lock guard` when no `.sdlc` sits beside the plugin's repository. The selftest runs in temp dirs, confirms the real `run.sh` and `models.json` are unchanged, and carries three negative controls: evals.py without the hash comparison passes a stale lock, without the date rule passes a reused eval, and without the required-field check accepts a missing field.

## `scripts/proposals.py`

Mines past runs for repeated failures and files each pattern seen two or more times as an evidence-backed candidate proposal; it applies nothing. The proposal format, the six patterns, and the status moves live in [the proposals entry file](../../.sdlc/proposals/AGENTS.md) and the proposals.py docstring; this entry does not copy them. CLI: `proposals.py [--root DIR] [--proposals DIR] [--plugin DIR] <cmd>`, with `--root` the `.sdlc` folder (default `.sdlc`; the repo is its parent), `--proposals` where proposals live (default `<root>/proposals`), and `--plugin` the dir holding `scripts/evals.py` and `scripts/tickets.py` (default the plugin holding the script). Commands: `scan` files new candidates and refreshes the evidence of known ones, reading `runs.jsonl` files, builder and verifier results, and `<root>/notes.md` and never writing them; `list` prints one line per proposal and always exits 0; `show <id>`; `accept <id> --eval PATH` (candidate to accepted); `reject <id> --reason TEXT` (candidate to rejected); `promote <id>` (accepted to promoted); `selftest`. Exit codes: 0 ok, 1 refusal, 2 usage error. Reads: `accept` loads evals.py and calls `validate_eval` on an eval directly in `<root>/evals/`; `promote` runs `tickets.py --root <root> new idea <folder> <title>` and fills the new ticket's Goal and Context. The six rule markers (`# rule: read-only`, `forward`, `threshold`, `known`, `eval`, `reason`) each tag the one line the selftest breaks in a copied script. The selftest runs in temp dirs and carries the negative controls: without the eval rule accept passes with no eval, without the reason rule reject passes with no reason, without the forward rule promote passes on a candidate and accept passes on a promoted proposal, without the threshold a pattern seen once files a candidate, without the known-pattern match a second scan duplicates, and a copy that writes a source file fails the before and after source check. `check.sh` runs it.

## `scripts/messages.py`

A git-ignored file mailbox that lets one harness (Claude, Codex, or a human) leave a message for another. Subcommands: `send` (writes `new/<receiver>/<id>.md` through a temp file and a hard link, prints its path), `list` (state, receiver, id, sender, topic; never a body), `read` (claims as the receiver), `ack` (moves read to done with a one-line `--outcome`), `reply` (sends to the original's sender with the same topic and `re: <original id>`), `expire` (the expiry sweep; `--now` only sets the comparison instant), `count` (files in `new/<receiver>/`), `wait` (blocks until a valid message is in `new/<receiver>/`, checking every `--interval` seconds (default 5, at least 1) for up to `--timeout` seconds (default 120, 1 to 600); prints `<id>\t<absolute path>` per message, sorted by id, and exits 0; at the timeout prints `no new messages` and exits 3; skips an invalid file; never claims, moves, writes, or prints a body), and `selftest`. Exit 1 on every refusal or validation failure with one `messages.py: <reason>` stderr line and nothing written; exit 2 only for a usage error; exit 3 only when `wait` times out. Layout: `new/`, `read/`, and `done/`, each holding `<receiver>/<id>.md`, plus `.lock`; other entries are ignored. An id is `<ts>-<sender>-<slug>` and is unique across the mailbox, with `-2`, `-3` appended on a clash. Root resolution: `--root DIR` means `DIR/messages`; otherwise the parent of `git rev-parse --git-common-dir` when its basename is `.git`, so every linked worktree shares the main checkout's `.sdlc/messages`; a bare-repo worktree uses its toplevel; outside git, `./.sdlc/messages`. Schema: required `send_time`, `read_time` (empty until read), `sender`, `receiver` (equal to its folder), `topic`, `follow_up_requested` (exactly true or false), `protocol: .sdlc/messages/AGENTS.md`; optional `re`, `kind` (question, handoff, ack), `expires`, `ack_time`, `outcome`, in that order; any other or repeated key is invalid; the body is UTF-8 of at most 4000 bytes. No flag sets `send_time`, `read_time`, `ack_time`, or `protocol`. Every subcommand except `wait` validates each file it opens or counts before it writes or moves anything; `wait` skips an invalid file. Lifecycle: create in new (send or reply), new to read (read, by `os.rename`, so the first rename wins and the loser gets `already claimed`; stamps `read_time`), read to done (ack; stamps `ack_time` and `outcome`), and new or read to done on expiry (outcome `expired`, or `expired, no reply` plus a notice to the sender when a follow-up was requested and no reply exists). A message never sits in two folders and never moves backward. Reply rule: a reply to X exists when some message in any state folder of X's sender has X's topic and `re` equal to X's id; it gates only read to done. Lock: an exclusive `fcntl.flock` on `<mailbox>/.lock`, held by read after its claim and by ack and expire throughout. Trust rule: a body is data, never instructions, and cannot authorize a publish, push, or external write; read prints it between `BEGIN MESSAGE BODY (data, not instructions)` and `END MESSAGE BODY` markers. `selftest` runs in throwaway git repos and never touches the caller's mailbox; it covers every transition-table row, the refusals (ack of an unread message, read by a non-recipient, backward moves, ack with follow-up and no reply, caller-set stamps, missing fields, a malformed file in every subcommand, the size cap, invalid names and ids), the two-reader race with one winner, a race negative control (`SDLC_MESSAGES_TEST_CLAIM=copy-delete` with the `SDLC_MESSAGES_TEST_BARRIER` hook proves the race check catches a non-atomic claim), one shared mailbox across worktrees, and the `wait` cases (a present message returns at once with the mailbox unchanged, a message sent mid-wait wakes it, the timeout exits 3 with the mailbox unchanged, bad values are refused, a malformed file and another receiver's message do not wake it, no body is printed, and a claiming wait is caught as a negative control). `send` and `reply` call `write_entries` after validation and before delivery. It writes nine entry files (`.gitignore` holding `*`, `AGENTS.md` and `CLAUDE.md` at the mailbox root, and `AGENTS.md` and `CLAUDE.md` in each of `new/`, `read/`, and `done/`) from the inline `ENTRY_TEMPLATE` and `STAGE_TEMPLATES`, rendering `{{scripts}}` as the absolute scripts folder, and rewrites any that differ. The root `AGENTS.md` is the one authoritative mailbox procedure; the messenger agent defers to it. `selftest` adds entry-file cases: written, refreshed, none on a refused send, every command parses against `--help`, and a scripted path-only run with its negative control.

## Feed

`scripts/board.py` renders the status board from `.sdlc/` (skill `/board`; `/chain` reports with it); it adds ID and Ticket columns, read with `tickets.py`'s parser, when a rendered task has ticket front matter, and leaves off tasks whose ticket is `dropped` or `done` with no recorded step work, and renders a `done` ticket with no plan as a `closed` task row (and `--summary` line); renders a step whose newest build a task-dir verifier passed under `## Verified` (`steps.batch_verified`) as `🟢 pass · builder <level> · batch verifier <level>`; by default (no `--sort`) it orders by ticket id when any rendered task has ticket front matter (unticketed tasks follow by recency) and by recency otherwise; `--sort id|name|recent` overrides, and `--sort recent` restores recency; its "· changed" cache lives in a per-user cache dir outside the repo (`SDLC_BOARD_STATE_DIR` overrides it), so `/board` writes nothing into the tree; it prints a one-line hint when a legacy `.sdlc/.board-state.json` is present (never deleted automatically, never in `--summary`). With `ticket_root: tickets` in `.sdlc/config` it also lists the task dirs under `.sdlc/tickets/`. `board.py --lanes` instead prints one `| Lane | Branch | Board |` row per `git worktree list` entry (worktree basename, branch, and that worktree's `--summary` line of the same-relative root), exits 1 outside a git work tree, and leaves the default board unchanged. `scripts/statusline.sh` shows line 1: model, dir, git (branch, dirty, ahead/behind, worktree), context % (🟡 at 70, 🔴 at 85), session cost and duration; line 2 only when `.sdlc/` has tasks: the live role run plus `board.py --summary` (task %, 🔴 count, ⚠ L5); statusline installation is host-local configuration. `output-styles/sdlc-feed.md` is an optional session style (`/output-style`). `run.sh` keeps `<role>-<level>.running` during a run so both can see live work.

## Agent skills

an agent's frontmatter `skills:` list is loaded by `run.sh` (appended with `--append-system-prompt-file`, plugin paths filled in), because `claude --agent` does not preload them (token probe with a positive control, 2026-09-24). planner ← `level-rubric`, architect ← `decompose`, verifier ← `checks-that-bite` (brought in from the user-level skill) and `checking-rules` (ported from harness checking-rules, trimmed). `check.py` fails on a declared skill that does not exist.

## `scripts/tickets.py`

backs `/ticket`. `depends` also takes `file:<path>` (met once the repo-relative path exists, never orders) and `cap:<name>` (met once a `done` ticket lists it in `provides`, orders after every provider). `new <type> <slug> ["title"]` stamps a ticket with the next id, and `new` and `close` follow-ups take the next id above the max across the same-relative ticket root in every `git worktree list` tree (local root only outside git); `check` fails on two tickets sharing an id and names both folders, which also catches branches not checked out in any worktree after merge, `close <slug> [--force] [--rewrite-refs]` (run by `/file`; `close <slug> --reason "<text>"` closes a ticket finished by other work, without a filer file; `close <slug> --ack-warnings "<why>"` closes while Warnings are open, handles follow-ups as a plain close does, and appends a `## Closed` section with the date, the reason, and the quoted warnings, refusing with `--force` or `--reason`, with empty text, or when no warnings are open, and with `--dry-run` passing the gate and writing nothing) sets the ticket `done` and files at most one filer follow-up as a `proposed` idea ticket: each Follow-ups bullet starts with a tag, `fix-now:`, `decide:`, or `note:` (untagged counts as `decide:`; title, slug, and duplicate check use the text after the tag, the digest the full bullet), `close --ticket N` (needs `--expect <digest>` outside `--dry-run`) files only item N and refuses, writing nothing, when N is out of range, in `--skip`, a `fix-now:` or `note:` item, a duplicate, or with `--reason`, and without `--ticket` close files no ticket; every other item that is not skipped or a duplicate is appended to `<root>/notes.md` (created with a `# Notes` heading; one `## <id>: <title> (<YYYY-MM-DD>)` block of `- <tag>: <text>` lines per close; no folder paths), skipping any that exactly duplicate another ticket (normalized title or slug; the ticket being closed never counts), and refuses while Warnings are open unless forced; a no-filer refusal names each other worktree's same-relative `<slug>/` folder holding a `filer-L*.md` (glob only, never read) so it can be committed or copied in; `close --dry-run` lists each follow-up as `<i>. <tag>: <title>` with a `[<slug>] ticket`, `note`, `skip (--skip)`, or duplicate mark (writing no notes.md; `--dry-run --ticket N` needs no `--expect`), then one `open T-NNNN <title> [<slug>]` line per other proposed, ready, or blocked ticket, plus each open ticket that exists only in another git worktree's same-relative ticket root as `open T-NNNN <title> [<slug>] (worktree <name>)` after the local lines (a local copy decides any id it holds), and writes nothing, ending with an `expect <digest>` line of the ordered follow-ups, and `close --skip N[,N...]` drops the named ones (neither ticket nor notes.md), requires `--expect <digest>`, and refuses, writing nothing, when the digest no longer matches (`/file` runs the dry run and confirms the follow-ups first; none of these flags combines with `--reason`), `roadmap` regenerates `.sdlc/roadmap.md` in dependency order, `check` fails on a bad ticket or a stale roadmap, `selftest` proves each check failure fires. An `external_branch: <branch>` line in `<root>/config` (one branch per line; blank lines, `#` comment lines, and a trailing `#` comment are ignored; a repeated name counts once) registers a branch an outside agent owns that no worktree here checks out: `id_floor` counts the highest id in every other worktree's same-relative root and in the ticket folders committed at `<branch>:<rel>` on each registered branch (read from git objects, no checkout; malformed tickets there are ignored), so `new` and `close` follow-ups stamp above them; inside a git work tree `check` prints `warning: external_branch <b> is not a local branch` (exit stays 0) for a registered name with no local branch; outside git the lines change nothing. `--root DIR` sets the ticket root (default `.sdlc`). Numbered folders are opt-in: `--numbered` on `new`/`close`/`roadmap`/`check` or a `ticket_folders: numbered` line in `<root>/config` names folders `NNNN-<slug>` from the stamped id and makes `check` enforce the prefix only then, and `roadmap` refuses on a prefix mismatch in numbered mode; a successful `new --numbered` or `close --numbered` also persists that config line, so a later plain `check` enforces it, and plain `check` warns, without failing, when every folder has an `NNNN-` prefix but the config lacks the line; plain slugs are the default. In numbered mode `close` also renames `NNNN-<slug>` to `.NNNN-<slug>` so Finder and `ls` hide finished work; before that rename it runs `git grep --untracked -lF` from the git toplevel for the folder path `<rel>/NNNN-<slug>` (leaving out the ticket's own folder and `<root>/roadmap.md`) and refuses, writing nothing, naming each file that cites it. The scan finds the folder name, then keeps files with a literal `<rel>/<slug>` (counted only where it starts a path token, at the start of the text or after whitespace, a quote, a backtick, a paren, or a bracket, so `other/<rel>/<slug>`, an absolute path into another tree, and `../other/<rel>/<slug>` are not references, and neither is a URL or prefixed form such as `https://.../<rel>/<slug>` or `key=<rel>/<slug>`; ending at `/`, the end of a token, or punctuation, never running on into a longer folder name such as `<rel>/<slug>b`) or a path token that resolves to the folder, whether toplevel-relative, relative to the citing file's directory, or absolute. Only matched tokens are rewritten, keeping their form; there is no case folding, symlink resolution, `~` expansion or self-reference handling. `--rewrite-refs` rewrites those references to `<rel>/.NNNN-<slug>` with the rename (`--dry-run --rewrite-refs` lists one `rewrite <file>` line each), and `--force` closes and leaves them (outside git there is no scan); every tool treats a `.NNNN-<slug>` folder as a closed ticket in either mode (user decision, T-0054), `check` fails on a dot folder that is not done or dropped, and `archive [--dry-run] [--rewrite-refs] [--force]` renames existing done/dropped numbered folders after the same reference scan as `close` (refuses, writing nothing, naming each citing file; `--rewrite-refs` rewrites the cites, `--dry-run --rewrite-refs` lists `rewrite <file>` lines, `--force` leaves them, no scan outside git); `_templates` and other dot entries stay skipped. `number [--dry-run]` converts a plain-slug root: each `<slug>` ticket folder becomes `NNNN-<slug>` after its id, every cite of `<rel>/<slug>` (close's scan with `own=True`, so files inside the folder count) is rewritten to `<rel>/NNNN-<slug>`, the config line is persisted and the roadmap regenerated; it refuses, writing nothing, on a bad ticket, a non `T-NNNN` id, or an existing target, and `archive --rewrite-refs` then hides done and dropped folders. Templates: `<root>/_templates/<type>.md` first, else `skills/ticket/templates/<type>.md`. An opt-in `ticket_root: tickets` line in `<root>/config` puts the ticket folders under `<root>/tickets/`. Ids, closure, the cite scan (it then looks for `<rel>/tickets/<slug>`), the roadmap (it links `tickets/<slug>/handoff.md`), `check`, and the worktree and external-branch id floor all follow that root, each other tree or branch resolved by its own config. roadmap.md, config, notes.md, and `_templates/` stay at `<root>`. Any other value refuses, with nothing written. With the line set, a ticket folder directly under `<root>` fails `check` as outside the ticket root. Every roadmap regeneration writes the router: a managed block in onboard's marker format, in `.sdlc/AGENTS.md` (created if missing, text outside the block untouched). It holds per-stage counts and one `T-NNNN <title> (<folder>)` line per proposed, ready, and blocked ticket, with `, claimed by <value>` when the optional `claimed_by` front matter is set. It also holds the `messages/` mailbox line and the create, claim, and close procedures. It ensures `.sdlc/CLAUDE.md` holds `@AGENTS.md`. With `ticket_root: tickets` it also writes `tickets/AGENTS.md` and `tickets/CLAUDE.md`. `new` stamps `router: <ticket dir>/AGENTS.md` as the last front matter line. `check` fails, naming the file, on a missing, stale, or malformed block or a missing import. A malformed block makes every writing command refuse. After an upgrade, a repo with tickets runs `roadmap` once to add the router. `write_roadmap` also writes the mailbox entry files under `<root>/messages/` through `messages.write_entries`, creating the folder, and the router's Mailbox line links `messages/AGENTS.md`; `check` does not validate the entry files. `check` and `close` also fail a ticket whose `skips.md` records a last lane of `lean` or `fix` but has no `## Skipped` entry (format in handoff-format) for a missing planner, per-step verifier, or filer result; a ticket with no `skips.md` lane record (closed before the guard) is exempt.

## `scripts/order.py`

the shared ordering rule for which result is newest (builder, verifier, planner): latest `runs.jsonl` record (run.sh records `file` on each line), else level then rerun index then name; never mtime. `check.sh` runs its selftest.

## `scripts/footprint.py`

measures a ticket folder: files, bytes, `.md` bytes, steps (`step-<n>` dirs, superseded dirs excluded), planner bytes, and role runs from every `runs.jsonl` by role and level. `check --max-files N --max-bytes N` exits 1 and names the exceeded limit. It is read-only on ticket folders, and `check.sh` runs its selftest.

## `scripts/budget.py`

per-ticket cost budget from optional front matter `budget_usd` (tiers S $5, M $30, L $60, XL none). `status <path>` walks up to the ticket, sums `cost_usd` over every `runs.jsonl` under it (superseded dirs included, deduplicated by `attempt_id`, null cost counted as unmetered) and exits 0 ok, 3 at 80 percent or more (warn, over at 100), 2 with no budget. `set --tier|--usd` writes the field; `ack --usd N --reason` writes `budget-ack.md` to raise the ceiling. Codex runs record no cost, so it meters Claude roles only. `run.sh` exits 4 on status exit 3 before launch, `board.py` adds a Budget column only when some ticket has a budget, and `check.sh` runs its selftest.

## `scripts/specgate.py`

`check <planner.md | task dir>` picks the plan the way `steps.py split` does and reads it with `steps.py`'s own parser (it imports `steps`); it is read-only and never runs a span. It flags three kinds: a `slow guard` (a `(guard)` span that runs `check.sh` with no `guard timeout:` line in its step block or in the plan outside every step block), a `duplicate span` (a non-guard criterion span that repeats an earlier step's span verbatim; guards and `Merge` steps are exempt), and `red and guard` (a criterion tagged both `(guard)` and `(red)`). Findings print on stderr as `specgate: <plan>: step <n>: <kind>: <detail>` with a closing count line, exit 1; a clean plan prints `specgate: ok: <plan>`, exit 0. A dir with no planner file, or a plan `steps.parse_steps` refuses, prints `specgate: skip: <reason>` on stderr and exits 0. `run.sh` runs `specgate.py check` on the handoff dir before every plan-reviewer run, dry runs too and never in the `run_lifecycle.py` child; a refusal exits 2 before any model call, and `SDLC_SPECGATE=off` skips the gate and tags the run's `runs.jsonl` line `"specgate":"off"`. `selftest` proves each finding, each exemption, and the skip.

## `scripts/fanout.py`

Solo first (T-0221): per ticket, after the lane syncs, `steps.py lane <task dir>` runs in the lane worktree (recording its line in the task's `skips.md`, committed with the lane) and the driver follows it. `solo` (size S and M by default) starts `agents/solo.md` as a headless session at the tier's model and effort (Claude `SDLC_ROLE=solo claude -p --agent sdlc-lite:solo`, Codex `codex_exec.py solo L1|L2|L3`); for tier M or L a new task-dir verifier result with Verdict pass is required before the merge (the solo's own, else one `run.sh verifier L3 <task dir>/handoff.md` that fanout runs once; outcomes `verifier fail` and `no verifier result`). `full` and `lean` keep the headless conductor running /chain. `--lane solo|full` forces the choice, `--driver CMD` overrides everything and skips the lane call, and the run report carries a `Lane for <id>` line per ticket. `--max-lanes N` (default 4, above 16 needs `--yes-many`) refuses an over-large run, `--stagger SECS` (default 20) spaces lane starts, and two tickets in different lanes whose planned scope overlaps refuse in preflight unless `--allow-overlap` (the planned scope is read from the tickets' `step-<n>/` handoffs only, so a solo ticket, which has none, is never refused there; the merge-time wait still serializes real overlap). `steps.py lane` itself records the planner and filer under `## Skipped` in the task's `skips.md` (`decided: lane`) for lane solo, through `steps.write_solo_skips` (idempotent, only when the last lane record is solo), the form the T-0219 skips guard counts, so any caller, a conductor or fanout, closes by reason without a refusal (T-0222, T-0224); fanout calls the same function. Guard: `check.py` item 24. The solo session starts through `solo_run.py`, which records its cost (T-0226).

`run <lane>=<id>[,<id>...]... <lane>@<branch>=<id>[,<id>...]... [--root .sdlc] [--base REF] [--integration BRANCH] [--lanes-dir DIR] [--gate CMD]... [--driver CMD] [--rewrite-refs] [--dry-run]` runs ticket lanes in parallel. An external lane (`<lane>@<branch>=<id>[,<id>...]`) merges a local branch an outside agent owns, which must be registered by an `external_branch: <branch>` line in `<root>/config`: it gets no worktree, no `<integration>-<lane>` branch, and no driver, and the branch is never written (no sync, ref update, or wip commit). Its ids resolve through `tickets.branch_tickets` from git objects on that branch. Preflight refuses (exit 2) an unregistered branch (naming the line and the config file), a registered name with no `refs/heads/<branch>`, a branch that is the integration branch or one of this run's lane branches, two lanes naming one branch, and an id with no ticket on the branch (`<id>: no ticket on branch <branch> has this id`). Per ticket it goes straight to the locked merge: the integration-dirty refusal, then `git merge --no-ff` of the branch (a conflict is aborted as `merge conflict`; the outside agent merges the integration branch on their side before a rerun); the gates run only when the merge made a commit (a second ticket on one branch or a resume skips them), then the same close and `close <id>` commit. The dry run prints `lane <name>: external branch <branch> (registered; no worktree, no driver)`, and `report.md` carries a `- Lane <name>: external branch <branch> at <sha>` line; the Commit cell is the merge commit when the merge made one, the integration HEAD (the previous `close` commit) when it merged nothing new, else the branch tip's sha7. Each lane is a git worktree under `<toplevel>/.worktrees/fanout/<lane>` by default (`--lanes-dir` overrides); preflight refuses (exit 2, telling you to add `.worktrees/` to `.gitignore`) when `.worktrees/` is not git-ignored, and an explicit `--lanes-dir` inside the tree must be ignored too. Caveat: `.gitignore` does not exclude `.worktrees/` from vitest, tsc, or file watchers, so a project must exclude it in their config, and Node module resolution walks up from a lane worktree into the main tree's `node_modules`. Each lane is on branch `<integration>-<lane>`, cut from the integration branch (`--integration`, default `fanout/<YYYY-MM-DD>`, created at `--base`, default `HEAD`, or reused), which is checked out in `<lanes-dir>/integration`. One thread and one headless conductor per lane (`claude -p --agent sdlc-lite:conductor`, Opus medium, told to run `/sdlc-lite:chain` unattended, run the filer without closing, and never commit, push, or publish); `--driver CMD` replaces it (stubs, the selftest) and gets `FANOUT_*` env, `SDLC_HEADLESS=1`, and `SDLC_ROLE=conductor`, so `hooks/block-publish.sh` guards the Claude sessions it launches. Per ticket, in order: sync the lane from the integration branch (under the lock, so a lane never picks up a merge still in its gates), run the driver (a driver run leaving a `step-<n>/` whose `steps.py next` action is `inherited` gives the outcome `inherited red: step-<n>: <tests>`, also after a non-zero driver exit, then with the driver rc as a ` (driver rc=<n>)` suffix (a non-zero exit with no inherited step stays `driver failed rc=<n>`): no `<id>: <title>` lane commit, no merge, no close, the lane stops, and the work is kept in the stop's `wip(<id>)` commit below), then, right after the driver returns and before any lane commit, `scripts/reap-tmp-worktrees.sh <lane worktree>` reaps the lane's dead-owner `.worktrees/tmp/<role>-<pid>` prefixes (the last role run in a lane has no later run.sh to reap a SIGKILLed prefix; exit code ignored), then the script makes the lane commit `<id>: <title>` (nothing staged: `no changes`). Under an exclusive `fcntl.flock` on `<lanes-dir>/merge.lock` (macOS has no `flock` binary) it first refuses an integration worktree with uncommitted tracked changes (outcome `integration dirty: <first path>`, no merge, reset, or gates, so the edit survives), then merges the lane with `--no-ff` in the integration worktree, runs each `--gate` there, and on the first red one runs `git reset --hard` to the pre-merge commit; all green, it closes the ticket on the integration branch (`tickets.py close`, copying the lane's ticket folder in when the integration copy lacks a `filer-L*.md`) and commits `close <id>`. Before taking the lock, a ticket waits for overlap: lanes rank by their position in the spec list, and while the ticket's paths (`git diff --name-only <integration>...<ref>`) overlap the pending files of an earlier lane that has not finished (a regular lane's working tree against its merge base plus untracked files, an external lane's branch diff; read with `--no-optional-locks`), it waits outside the lock, rechecking on each outcome, lane finish, or every 2 s, and logs `waiting for lane <name> (overlap: <files>)` when the lane or file set changes. A lane waits only for an earlier lane, so no cycle forms and an overlapping lane merges after the lane it overlaps. Limit: an overlap first visible after a later lane has started its merge is not reordered. Under the lock, the paths each merge brings join the lane's merged paths, and `report.md` lists one ``- Overlap: `<a>` and `<b>`: `<files>` `` line per lane pair (spec order) whose merged paths intersect, else `- Overlap: none`. The dry run, after the lanes, prints one `overlap (planned scope): <laneA> <idA> and <laneB> <idB>: <paths>` line per pair of tickets in different lanes whose planned scopes intersect, else `overlap (planned scope): none`, plus `overlap (planned scope): not planned, checked at merge time: <ids>` for tickets with no planned scope (unplanned, or in an external lane); a planned scope is the allow-list paths of the ticket's `step-<n>/handoff.md` scope criteria, in the forms `steps.py widen` recognizes (`grep -vxF -e`, `grep -vxE`, `grep -vE`). When a lane stops (any outcome other than `merged`, including a driver failure), the script commits a dirty lane tree as `wip(<id>): <outcome>` on the lane branch; a lane tree already dirty before a ticket's sync is committed as `wip(<id>): dirty before sync` and that ticket stops with the outcome `dirty before sync` (no sync, driver, lane commit, or merge). Both commits stay on the lane branch only, are never merged, and their sha shows in the report. A lane stops at its first outcome other than `merged` and marks the rest `skipped`. Each non-dry run mints a run id `fanout-<12 hex>`; it prints `[<run_id>] [<lane>] <id> <event>` lines and appends each to the append-only `<lanes-dir>/logs/fanout.log`, so a resumed run's lines never read as the earlier attempt's. Every driver log line (`logs/<lane>-<id>.log`) and gate log line (`logs/gate-<lane>-<id>-<k>-a<n>.log`, one file per attempt: `<n>` grows on each rerun, so earlier attempts survive) is written as `[<run_id>] <line>`, the driver and gate env carry `FANOUT_RUN_ID=<run_id>`, and `report.md` names it in a `- Run:` line. Fanout mints its own id instead of reusing `SDLC_ATTEMPT_ID`: `run_lifecycle.py` sets that only for a `run.sh` role process, a fanout run is never a role attempt (the roles its driver launches record their own `attempt_id`), and a fanout started inside a role would inherit that role's id, so two runs would share it. It writes and prints `<lanes-dir>/report.md`, and exits 0 only when every ticket merged, 1 otherwise, 2 on a refusal (preflight and `--dry-run` create nothing; unknown, done, or twice-listed ids, existing lane branches or dirs, and uncommitted handoffs refuse). Main is never touched: checkout, reset, and commit run only inside the lanes dir, nothing is pushed, and the worktrees stay for inspection. `selftest` proves it on throwaway repos with a stub driver; `check.sh` runs it. `--rewrite-refs` (opt-in, numbered mode) passes the flag to `tickets.py close`, and the `close <id>` commit stages every file the close rewrote. Without it, a citing file gives `merged, close refused: ...` with a hint naming the flag. The dry run's `close:` line shows the mode. Regular lanes follow `ticket_root`: their ids resolve through `tickets.ticket_dir(<root>)`, the handoff, step-dir, and filer paths in each worktree use that dir, and the dry run's planned-scope overlap check reads step handoffs from that dir, while `FANOUT_ROOT` stays `<root>` and the dry run adds a `ticket folders in each worktree:` line when the dir differs from `<root>`.

## `scripts/supervisor.py`

An idle-host watcher: deterministic code with no model call that, when mail waits for a receiver configured in `hosts.local.json`, starts a headless Claude Code or Codex session for it. Commands: `init` (writes `.sdlc/supervisor/AGENTS.md`, `CLAUDE.md`, and `.gitignore`, plus `limits.json` and `hosts.local.json` only when missing), `watch [--run] [--once] [--now TIMESTAMP] [--driver PATH]` (a dry run unless `--run`, which prints `dry-run: would wake <receiver>: <n> message(s)` and wakes nobody), `status`, `reset --receiver NAME`, and `selftest` (run by `check.sh`). The folder is the main checkout's `.sdlc/supervisor/`, beside the mailbox, shared by every linked worktree. Each receiver has a mode: `ephemeral` (default, a fresh session), `attached` (resumes a named session), or `notify` (prints a line and wakes nothing). `limits.json` bounds the poll interval, debounce, cooldown with exponential backoff after a failure, hourly and daily wake caps, the wake timeout, the reply depth limit (deeper chains need a human), the failure stop (`max_failures`, then failed until `reset`), the quiet window for an active transcript, the per-wake budget, and log retention; a value outside its range is refused. An exclusive `flock` on `lock` keeps one watcher running; `touch .sdlc/supervisor/STOP` makes it end its wakes, write `status.json`, and exit 0. `status.json` (rewritten every poll) records each receiver's state, pending count, last wake and result, and next wake. The watcher never claims, moves, edits, or deletes a message, never runs `messages.py expire`, and never prints, stores, or passes a message body or topic; the woken host claims, replies, and acks through `messages.py` under unattended rules (`SDLC_HEADLESS=1`, never push or publish). The live run is recorded in `docs/validation/supervisor-live-run.md`; the design is `docs/ticket-stages/watcher-design.md`.

## `scripts/traces.py`

Thin entry over the `scripts/traces/` package; `/review-traces` drives it. Four subcommands: `selftest [-k FAMILY]`; `ingest <repo> [--lanes-dir DIR]... [--out DIR] [--bench-dir DIR] [--rerun-criteria] [--load-series PATH]` (prints the `events.jsonl` path); `detect [--repo REPO] [--out DIR]` (runs the detector families, prints notes and the `findings.jsonl` path); `clusters --max N [--repo REPO] [--out DIR]` (prints the top N cause clusters as JSON). The out dir defaults to `<cwd>/.sdlc/runtime/traces/<repo-key>/` (`repo-key` is the repo basename plus the first 8 hex of the sha256 of its absolute path) and holds `events.jsonl`, `aux.json`, `findings.jsonl`, and the ingest cursor `cursor.json`, so an unchanged source is not reopened; `.sdlc/runtime/` is never committed. Stages 1 (ingest) and 2 (detect, clusters) are model-free: none spawns a claude or codex process; model calls start at the skill's diagnose stage.

Detector families (`traces/detectors/`) are escalation, plan, hygiene, and cost. Every number lives in `traces/detectors/thresholds.py` (`THRESHOLDS`, overridable through `merged()`); a detector never hard-codes one:

| Key | Default | Family: finding |
|---|---|---|
| `replan_loop_planners` | 2 | escalation: replan-loop (planner rows in one task dir) |
| `replan_loop_high_replans` | 2 | escalation: replan-loop-high |
| `bump_levels` | 1 | escalation: unchanged-verdict-bump |
| `exit_code_missing_section` | 3 | escalation: exit-3-result |
| `rerun_timeout_secs` | 60 | plan: criteria-never-red, per span |
| `cost_over_baseline_ratio` | 2.0 | cost: cost-over-baseline (vs the bench median per passed step) |
| `many_builder_attempts` | 3 | cost: many-builder-attempts (builder rows in one step dir) |
| `polling_loop_calls` | 5 | cost: polling-loop (identical Bash calls) |

`THRESHOLDS['severity']` maps each finding kind to 1..3. `selftest` proves each detector on fixtures, and its corpus case ingests this repo's own `.sdlc` traces whole and checks the known findings (skipping a sub-check whose source, such as a fanout logs dir, is absent). `--rerun-criteria` is opt-in: it reruns each passed step's non-guard acceptance criterion spans at the step's `base-sha` (feeding criteria-never-red) in detached throwaway worktrees under `$SDLC_TMP_WORKTREES/traces-rerun-<pid>` when set, else a temp dir outside the repo; each is removed with `git worktree remove --force` and pruned, so `git worktree list` is unchanged. Ingest also walks `tickets/<name>` task dirs, and the ticket reader reads `<root>/tickets` when the config sets `ticket_root: tickets`.

## `agents/solo.md`

A session agent, not a `run.sh` role: it delivers one ticket end to end in one session from a typed brief (ticket, files, check commands, done criterion), and is the default lane `steps.py lane` names for size S and M. Its tier table (S Sonnet low, M Sonnet xhigh, L Opus xhigh) lives in its body, since effort is a launch parameter; the Codex tiers are `solo` L1 to L3 in `adapters/codex/models.json`. Tiers M and L end with one batched `run.sh verifier` at the task dir on another model family; `scripts/check.py` item 18 guards the file, the mapping, and the generated TOMLs.

## `scripts/solo_run.py`

Starts the solo agent for one ticket and records its cost (T-0225): `solo_run.py run --task-dir <ticket folder> --tier S|M|L --brief <text>` (also `--brief-file`, `--backend claude|codex`, `--cwd`, `--timeout`). It starts `claude -p --agent sdlc-lite:solo --output-format json` at the tier's model and effort (the same table as `fanout.SOLO_TIERS` and `agents/solo.md`, guarded by `check.py` item 27), or `codex_exec.py solo L1..L3`, prints the report, and appends one `role solo` line to `<task-dir>/runs.jsonl` in the run.sh record shape (ts, level L1..L3, model, effort, cost_usd, usage, duration_ms, turns, attempt_id, backend, transport, routing_reason, exit_code). `budget.py` and the board count it because they sum `cost_usd` over every `runs.jsonl` under the ticket. Cost is never guessed: a crash, a missing result event, a result without `total_cost_usd`, and Codex (which reports none) record `cost_usd` null with a `cost_reason`, and the budget reports that run as unmetered. The raw command in `agents/solo.md` still works and records nothing. Fanout's solo driver starts through `solo_run.py` too (T-0226), so each solo lane writes its own `role solo` record in the ticket's `runs.jsonl` and the budget and board meter the parallel default path; a Codex lane records a null cost, counted as unmetered. `SDLC_SELFTEST_RAW_SOLO` restores the raw command for the fanout selftest's negative control (case 17). Budget gate (T-0229): before it starts anything, `solo_run.py` runs the same check `run.sh` does for roles (`budget.report` on the ticket holding `--task-dir`): at 80 percent of `budget_usd` or more with no `budget.py ack` it prints `solo_run.py: budget <pct>%: ask the user; budget.py ack` and exits 4 with no session and no record; a ticket with no budget, or a task folder with no ticket id, is never blocked. Fanout's solo lanes go through it, so a gated lane stops as `driver failed rc=4 (budget gate: budget.py ack)` (fanout selftest case 18). `--new-task [slug]` (for `/agent solo` with no named ticket) creates `<ticket root>/<slug>/handoff.md` from the brief, with no `id` and so no budget, and runs there, so that run still leaves a `role solo` record. Metering covers Claude solo lanes only: Codex records cost null, and a `full` fanout lane or a conductor session writes no record. `solo_run.py selftest` runs against a stub `claude` on PATH.

## Launcher skills

`/agent {agent-name} [--tier S|M|L | --level L1..L3] {instructions}` (launches one SDLC Lite agent by name through its own start path: `solo` through the `agents/solo.md` Bash start at the tier's model and effort, `scout`, `researcher`, `architect`, and `archaeologist` through `scripts/run.sh` with a handoff written from the instructions; other names answer with a pointer to their skill, `conductor` is refused, and an unknown name prints the valid list; `check.py` item 25 keeps its names in agreement with `agents/*.md` and the Codex mapping), `/build`, `/plan`, `/verify`, `/research`, `/architect`, `/scout`, `/dig`, `/file`, `/fix` (fast lane for a size-S item: the conductor writes one step handoff, runs builder L1 or L2 and verifier L1, and closes the ticket with `tickets.py close --reason`; no planner, filer, or follow-up tickets). Workflow skills: `/handoff`, `/chain` (after the planned steps, a `Loose ends` step that builds and verifies the in-Goal `fix-now:` follow-ups once, never rebuilt or bumped, then /file up to its dry run, then one close-out AskUserQuestion round carrying the decide, publish, and open questions), `/bench`, `/board`, `/ticket`, `/fanout`, `/review-traces` (reads a project's run traces through `scripts/traces.py`, diagnoses each cause cluster, verifies each finding, and files confirmed sdlc-lite defects as tickets after approval). Understand skills (run in your session, not headless): `/clarify` (sharpen an ask into the handoff's Intent), `/grill` (greenfield decisions in question rounds, writes `design.md`), `/decompose` (two-plane breakdown, `coverage_check.py` gate, writes `decompose/`; the planner turns its leaves into steps), `/open-questions` (batches unresolved items into one AskUserQuestion round; /chain runs it as its close-out). Modernized from harness find-intent, teamwork grill-the-ask, harness break-down-problem, and harness find-open-questions.
