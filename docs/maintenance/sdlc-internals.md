# SDLC implementation reference

Read only the entry relevant to the subsystem being changed. Paths in this reference are relative to `plugins/sdlc-lite/`; commands run from that directory. Shared scripts and their tests own executable behavior. Update affected entries when behavior changes.

Descriptions of Claude flags, skill preloading, background tools, permissions, and the default lane driver below apply to the Claude backend only. For Codex execution, sandboxing, and native delegation, read [Codex role execution](../codex-role-execution.md). The backend is selected with `SDLC_BACKEND`; the legacy default is Claude.

## Implementation map

## `scripts/run.sh`

the one runner. Holds the role:level → model/effort table, a git preflight (exits 2 outside a git work tree or before the first commit), the Fable-never-verifies-Fable swap, and a post-run check that the saved result holds the role's required section (it exits 3 and names the section when missing; the result file and `runs.jsonl` line are kept); a builder Status or verifier Verdict `inherited red: <tests>` is accepted), and read-only enforcement (Edit/Write disallowed for every role except builder). Read-only does not block Bash, so the verifier's no-git-state-changes rule lives in its prompt. After the git preflight it reads the target repo's toplevel `.nvmrc`, matches it against `$NVM_DIR` (else `~/.nvm`) `versions/node` (exact, or the highest numeric prefix match), and prepends that `bin` to PATH, or leaves PATH unchanged with one stderr line for a missing version or an alias; it never sources nvm, and `SDLC_DRY_RUN=1` shows the resolution. run.sh sets `BASH_DEFAULT_TIMEOUT_MS` and `BASH_MAX_TIMEOUT_MS` to 3600000 for the role run unless already higher (fanout sets them too), so a long foreground command is not moved to the background by Claude Code, which no PreToolUse hook sees (T-0105). It logs the run as `--output-format stream-json --verbose` (the `.log` is one JSON event per line) and saves the last `result` event holding the role's required heading, else the last one whose origin is not `task-notification`, else the last one, because a background-task notification can end the session with its own result. run.sh exports `SDLC_TMP_WORKTREES=<toplevel>/.worktrees/tmp/<role>-<pid>` and removes every worktree under it on any exit, then runs `git worktree prune`. At run end it compares a before and after snapshot of worktrees and branches, excluding this run's own prefix, and when a stray appeared (created from inside a script or program, not the Bash tool text the hook sees) it prints a stderr line quoting `stray worktree appeared during this run` and records `stray_worktrees` and `stray_branches` fields in the `runs.jsonl` line; this is report only, it does not change the run's exit code, and a dry run takes no snapshot. For builder and verifier it also exports `SDLC_BASE_SHA`, the build-start base: HEAD at the step's first builder run, kept in the step dir's `base-sha` file (rewritten when missing, not an ancestor of HEAD, or passed by a resync merge, which moves it to the newest first-parent merge); every other role gets it unset. Scope criteria compare with `git diff --name-only "$SDLC_BASE_SHA"` plus untracked files, so they hold whether or not the work is committed later.

## Feed

`scripts/board.py` renders the status board from `.sdlc/` (skill `/board`; `/chain` reports with it); it adds ID and Ticket columns, read with `tickets.py`'s parser, when a rendered task has ticket front matter, and leaves off tasks whose ticket is `dropped` or `done` with no recorded step work, and renders a `done` ticket with no plan as a `closed` task row (and `--summary` line); by default (no `--sort`) it orders by ticket id when any rendered task has ticket front matter (unticketed tasks follow by recency) and by recency otherwise; `--sort id|name|recent` overrides, and `--sort recent` restores recency; its "· changed" cache lives in a per-user cache dir outside the repo (`SDLC_BOARD_STATE_DIR` overrides it), so `/board` writes nothing into the tree; it prints a one-line hint when a legacy `.sdlc/.board-state.json` is present (never deleted automatically, never in `--summary`). `board.py --lanes` instead prints one `| Lane | Branch | Board |` row per `git worktree list` entry (worktree basename, branch, and that worktree's `--summary` line of the same-relative root), exits 1 outside a git work tree, and leaves the default board unchanged. `scripts/statusline.sh` shows line 1: model, dir, git (branch, dirty, ahead/behind, worktree), context % (🟡 at 70, 🔴 at 85), session cost and duration; line 2 only when `.sdlc/` has tasks: the live role run plus `board.py --summary` (task %, 🔴 count, ⚠ L5); statusline installation is host-local configuration. `output-styles/sdlc-feed.md` is an optional session style (`/output-style`). `run.sh` keeps `<role>-<level>.running` during a run so both can see live work.

## Agent skills

an agent's frontmatter `skills:` list is loaded by `run.sh` (appended with `--append-system-prompt-file`, plugin paths filled in), because `claude --agent` does not preload them (token probe with a positive control, 2026-09-24). planner ← `level-rubric`, architect ← `decompose`, verifier ← `checks-that-bite` (brought in from the user-level skill) and `checking-rules` (ported from harness checking-rules, trimmed). `check.py` fails on a declared skill that does not exist.

## `scripts/tickets.py`

backs `/ticket`. `new <type> <slug> ["title"]` stamps a ticket with the next id, and `new` and `close` follow-ups take the next id above the max across the same-relative ticket root in every `git worktree list` tree (local root only outside git); `check` fails on two tickets sharing an id and names both folders, which also catches branches not checked out in any worktree after merge, `close <slug> [--force] [--rewrite-refs]` (run by `/file`; `close <slug> --reason "<text>"` closes a ticket finished by other work, without a filer file; `close <slug> --ack-warnings "<why>"` closes while Warnings are open, handles follow-ups as a plain close does, and appends a `## Closed` section with the date, the reason, and the quoted warnings, refusing with `--force` or `--reason`, with empty text, or when no warnings are open, and with `--dry-run` passing the gate and writing nothing) sets the ticket `done` and files at most one filer follow-up as a `proposed` idea ticket: each Follow-ups bullet starts with a tag, `fix-now:`, `decide:`, or `note:` (untagged counts as `decide:`; title, slug, and duplicate check use the text after the tag, the digest the full bullet), `close --ticket N` (needs `--expect <digest>` outside `--dry-run`) files only item N and refuses, writing nothing, when N is out of range, in `--skip`, a `fix-now:` or `note:` item, a duplicate, or with `--reason`, and without `--ticket` close files no ticket; every other item that is not skipped or a duplicate is appended to `<root>/notes.md` (created with a `# Notes` heading; one `## <id>: <title> (<YYYY-MM-DD>)` block of `- <tag>: <text>` lines per close; no folder paths), skipping any that exactly duplicate another ticket (normalized title or slug; the ticket being closed never counts), and refuses while Warnings are open unless forced; a no-filer refusal names each other worktree's same-relative `<slug>/` folder holding a `filer-L*.md` (glob only, never read) so it can be committed or copied in; `close --dry-run` lists each follow-up as `<i>. <tag>: <title>` with a `[<slug>] ticket`, `note`, `skip (--skip)`, or duplicate mark (writing no notes.md; `--dry-run --ticket N` needs no `--expect`), then one `open T-NNNN <title> [<slug>]` line per other proposed, ready, or blocked ticket, plus each open ticket that exists only in another git worktree's same-relative ticket root as `open T-NNNN <title> [<slug>] (worktree <name>)` after the local lines (a local copy decides any id it holds), and writes nothing, ending with an `expect <digest>` line of the ordered follow-ups, and `close --skip N[,N...]` drops the named ones (neither ticket nor notes.md), requires `--expect <digest>`, and refuses, writing nothing, when the digest no longer matches (`/file` runs the dry run and confirms the follow-ups first; none of these flags combines with `--reason`), `roadmap` regenerates `.sdlc/roadmap.md` in dependency order, `check` fails on a bad ticket or a stale roadmap, `selftest` proves each check failure fires. `--root DIR` sets the ticket root (default `.sdlc`). Numbered folders are opt-in: `--numbered` on `new`/`close`/`roadmap`/`check` or a `ticket_folders: numbered` line in `<root>/config` names folders `NNNN-<slug>` from the stamped id and makes `check` enforce the prefix only then, and `roadmap` refuses on a prefix mismatch in numbered mode; a successful `new --numbered` or `close --numbered` also persists that config line, so a later plain `check` enforces it, and plain `check` warns, without failing, when every folder has an `NNNN-` prefix but the config lacks the line; plain slugs are the default. In numbered mode `close` also renames `NNNN-<slug>` to `.NNNN-<slug>` so Finder and `ls` hide finished work; before that rename it runs `git grep --untracked -lF` from the git toplevel for the folder path `<rel>/NNNN-<slug>` (leaving out the ticket's own folder and `<root>/roadmap.md`) and refuses, writing nothing, naming each file that cites it. The scan finds the folder name, then keeps files with a literal `<rel>/<slug>` (counted only where it starts a path token, at the start of the text or after whitespace, a quote, a backtick, a paren, or a bracket, so `other/<rel>/<slug>`, an absolute path into another tree, and `../other/<rel>/<slug>` are not references, and neither is a URL or prefixed form such as `https://.../<rel>/<slug>` or `key=<rel>/<slug>`; ending at `/`, the end of a token, or punctuation, never running on into a longer folder name such as `<rel>/<slug>b`) or a path token that resolves to the folder, whether toplevel-relative, relative to the citing file's directory, or absolute. Only matched tokens are rewritten, keeping their form; there is no case folding, symlink resolution, `~` expansion or self-reference handling. `--rewrite-refs` rewrites those references to `<rel>/.NNNN-<slug>` with the rename (`--dry-run --rewrite-refs` lists one `rewrite <file>` line each), and `--force` closes and leaves them (outside git there is no scan); every tool treats a `.NNNN-<slug>` folder as a closed ticket in either mode (user decision, T-0054), `check` fails on a dot folder that is not done or dropped, and `archive [--dry-run] [--rewrite-refs] [--force]` renames existing done/dropped numbered folders after the same reference scan as `close` (refuses, writing nothing, naming each citing file; `--rewrite-refs` rewrites the cites, `--dry-run --rewrite-refs` lists `rewrite <file>` lines, `--force` leaves them, no scan outside git); `_templates` and other dot entries stay skipped. Templates: `<root>/_templates/<type>.md` first, else `skills/ticket/templates/<type>.md`.

## `scripts/order.py`

the shared ordering rule for which result is newest (builder, verifier, planner): latest `runs.jsonl` record (run.sh records `file` on each line), else level then rerun index then name; never mtime. `check.sh` runs its selftest.

## `scripts/steps.py`

`split <planner.md | task dir> [--only N]` writes `step-<n>/handoff.md` per the step template, refuses a step dir holding builder or verifier output, refuses, with `plan defect` on stderr, a plan whose acceptance criterion command spans do not parse under `bash -n` or join two checks with `||` (an unquoted `||` that is a fallback join; allowed only after `test $# -eq 0` or when its right operand is a nonzero `exit`, bare or ending a `{ ...; }` group; `for`/`while`/`until`/`if`/`{` criteria are linted too, also when they end in a trailing redirect or pipe after the closing keyword (for example `done < f`)), or hold a criterion that pins a commit sha (the word `git` plus a 7 to 40 char hex run with a digit and a letter; compare against `HEAD` instead, except the deliberate ancestry form `git merge-base --is-ancestor <sha> HEAD`, which passes), or one that compares a count over a changing set with a fixed number (`wc -l`, `grep -c`, or `grep --count` over a `*` glob, `ls`, or `find`, compared with a literal of 2 or more; a bare `=` counts only with whitespace before it, so a bare assignment such as `n=26` is not a comparison), or one that requires a clean porcelain status (an emptiness test on `git status --porcelain` or `-s` with no `--` pathspec; use `git diff` plus untracked files instead), or one that requires a clean whole-tree diff (a `--quiet`/`--exit-code` diff or an emptiness test on diff output, with no `--` pathspec and no two-commit range; a clean check inside a script the span calls stays out of reach, since only span text is read), and with `--only N` runs that step's `(guard)` command spans under `--guard-timeout` (default 300s) from the git toplevel with `SDLC_BASE_SHA` set to HEAD (no build has started), skipping `HEAD^1` and `<placeholder>` spans, and refuses on a red guard or timeout with a `plan defect:` last line and writes nothing, and also refuses when its guards changed the work tree, tracked or untracked, versus before they ran, naming the paths (outside git there is no check; a tree already dirty before is fine) (full `split` and `lint` execute nothing), `lint <planner.md | task dir>` runs the same check and writes nothing, `next <step dir>` (read-only) prints the next action (`build`, `verify`, `reverify`, `rebuild`, `bump`, `replan`, `done`, `stop`, `inherited`, `swap`) from the newest builder and verifier results by `order.py` and exits 1 with `steps next:` on stderr on a bad dir (a builder result with no done/blocked Status is not an error: it maps to `rebuild` at its level, and two in a row map to `stop`; a builder Status `inherited red: <tests>` (a gate already red at the pre-build HEAD) maps to `inherited`, and so does a verifier Verdict `inherited red: <tests>` (found by the verifier's pre-build gate check), never a fail, rebuild, bump, or replan, `board.py` renders that step 🔴 inherited red, and `run.sh` accepts that Status and that Verdict; a verifier result with no pass/fail verdict is not an error: it maps to `reverify`, is never counted as a fail, and two in a row stop; a verifier `plan defect:` fail holding exactly one `swap old:` line with one code span and one `swap new:` line, with no other verifier result in the dir holding a pair, maps to `swap` at the build level, any other plan defect to `replan`), `swap <step dir> [--timeout SECONDS]` applies that pair: it requires a newest builder and a newest verifier counting after it, a fail verdict, the `plan defect:` tag, the pair, and no earlier swap on the step, exactly one criterion line holding the old span, and new text that keeps the old line's `(guard)` tag, holds a command span, skips no `HEAD^1` or `<placeholder>` span, and lints clean; it then runs each new span under `bash -c` from the git toplevel with `SDLC_BASE_SHA` set to the step dir's `base-sha`, else HEAD under `--timeout` (default 300s) and refuses on a red span or a timeout, and in a git work tree on a span that changed the work tree, naming the paths; every refusal writes nothing, exits 1, and ends with a `plan defect: steps swap refused: <why>; replan this step (/chain 4.2)` line; when the new text is already in place it prints `swap: already applied` and exits 0 writing nothing; otherwise it rewrites only the target line and prints one line naming the step dir, the old span, and the new text; and `selftest` proves each failure; `/chain` steps 3 and 4.2 run `split`, and step 4 runs `next` after every builder and verifier run, and `steps.py swap` when `next` prints `swap`.

## `scripts/fanout.py`

`run <lane>=<id>[,<id>...]... [--root .sdlc] [--base REF] [--integration BRANCH] [--lanes-dir DIR] [--gate CMD]... [--driver CMD] [--rewrite-refs] [--dry-run]` runs ticket lanes in parallel. Each lane is a git worktree under `<toplevel>/.worktrees/fanout/<lane>` by default (`--lanes-dir` overrides); preflight refuses (exit 2, telling you to add `.worktrees/` to `.gitignore`) when `.worktrees/` is not git-ignored, and an explicit `--lanes-dir` inside the tree must be ignored too. Caveat: `.gitignore` does not exclude `.worktrees/` from vitest, tsc, or file watchers, so a project must exclude it in their config, and Node module resolution walks up from a lane worktree into the main tree's `node_modules`. Each lane is on branch `<integration>-<lane>`, cut from the integration branch (`--integration`, default `fanout/<YYYY-MM-DD>`, created at `--base`, default `HEAD`, or reused), which is checked out in `<lanes-dir>/integration`. One thread and one headless conductor per lane (`claude -p --agent sdlc-lite:conductor`, Opus medium, told to run `/sdlc-lite:chain` unattended, run the filer without closing, and never commit, push, or publish); `--driver CMD` replaces it (stubs, the selftest) and gets `FANOUT_*` env, `SDLC_HEADLESS=1`, and `SDLC_ROLE=conductor`, so `hooks/block-publish.sh` guards the Claude sessions it launches. Per ticket, in order: sync the lane from the integration branch (under the lock, so a lane never picks up a merge still in its gates), run the driver (a driver run leaving a `step-<n>/` whose `steps.py next` action is `inherited` gives the outcome `inherited red: step-<n>: <tests>`, also after a non-zero driver exit, then with the driver rc as a ` (driver rc=<n>)` suffix (a non-zero exit with no inherited step stays `driver failed rc=<n>`): no `<id>: <title>` lane commit, no merge, no close, the lane stops, and the work is kept in the stop's `wip(<id>)` commit below), then the script makes the lane commit `<id>: <title>` (nothing staged: `no changes`). Under an exclusive `fcntl.flock` on `<lanes-dir>/merge.lock` (macOS has no `flock` binary) it merges the lane with `--no-ff` in the integration worktree, runs each `--gate` there, and on the first red one runs `git reset --hard` to the pre-merge commit; all green, it closes the ticket on the integration branch (`tickets.py close`, copying the lane's ticket folder in when the integration copy lacks a `filer-L*.md`) and commits `close <id>`. When a lane stops (any outcome other than `merged`, including a driver failure), the script commits a dirty lane tree as `wip(<id>): <outcome>` on the lane branch; a lane tree already dirty before a ticket's sync is committed as `wip(<id>): dirty before sync` and that ticket stops with the outcome `dirty before sync` (no sync, driver, lane commit, or merge). Both commits stay on the lane branch only, are never merged, and their sha shows in the report. A lane stops at its first outcome other than `merged` and marks the rest `skipped`. It prints `[<lane>] <id> <event>` lines, writes and prints `<lanes-dir>/report.md`, and exits 0 only when every ticket merged, 1 otherwise, 2 on a refusal (preflight and `--dry-run` create nothing; unknown, done, or twice-listed ids, existing lane branches or dirs, and uncommitted handoffs refuse). Main is never touched: checkout, reset, and commit run only inside the lanes dir, nothing is pushed, and the worktrees stay for inspection. `selftest` proves it on throwaway repos with a stub driver; `check.sh` runs it. `--rewrite-refs` (opt-in, numbered mode) passes the flag to `tickets.py close`, and the `close <id>` commit stages every file the close rewrote. Without it, a citing file gives `merged, close refused: ...` with a hint naming the flag. The dry run's `close:` line shows the mode.

## `agents/<role>.md`

one per role; each defines its output format as its final message, which the runner saves.

## `skills/level-rubric`, `skills/handoff-format`

reference skills (not commands) that the launcher skills and `/chain` read. The rubric must match the table in `run.sh`.

## Launcher skills

`/build`, `/plan`, `/verify`, `/research`, `/architect`, `/scout`, `/dig`, `/file`, `/fix` (fast lane for a size-S item: the conductor writes one step handoff, runs builder L1 or L2 and verifier L1, and closes the ticket with `tickets.py close --reason`; no planner, filer, or follow-up tickets). Workflow skills: `/handoff`, `/chain` (after the planned steps, a `Loose ends` step that builds and verifies the in-Goal `fix-now:` follow-ups once, never rebuilt or bumped, then /file up to its dry run, then one close-out AskUserQuestion round carrying the decide, publish, and open questions), `/bench`, `/board`, `/ticket`, `/fanout`. Understand skills (run in your session, not headless): `/clarify` (sharpen an ask into the handoff's Intent), `/grill` (greenfield decisions in question rounds, writes `design.md`), `/decompose` (two-plane breakdown, `coverage_check.py` gate, writes `decompose/`; the planner turns its leaves into steps), `/open-questions` (batches unresolved items into one AskUserQuestion round; /chain runs it as its close-out). Modernized from harness find-intent, teamwork grill-the-ask, harness break-down-problem, and harness find-open-questions.
