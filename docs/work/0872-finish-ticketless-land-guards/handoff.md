## Goal
Landing a ticketless lane with `lanes.py finish --no-ticket` can never commit conflict markers, resolves conflicts in the repo's own generated files by regenerating them, and can rebuild the main checkout after the fast-forward.

## Intent
- Do: add a conflict-marker guard, configured generated paths with a regenerate command, and a post-land command to `finish --no-ticket`.
- Non-goals: a separate `lanes.py land` command (finish is the one landing path); rebase-based landing; changing the ticketed `finish` or `fanout.py land` merge rules beyond the marker guard.
- Done when: the criteria below hold.

## Context
- #92: landing by fast-forward came up about 20 times in one session and needed "install deps, rebase onto main, resolve conflicts, regenerate generated files, run the fast check and the typecheck, fast-forward, then install and build in the main checkout". A hand loop "staged files that still held conflict markers and continued the rebase", so two commits with `<<<<<<<` landed on main. Ask: stage a conflicted file only with no markers, refuse while `git grep '^<<<<<<< '` finds anything, generated paths from config taken from the incoming side and regenerated by a configured command, the configured fast check, fast-forward, then install and build in main.
- Already at HEAD in `plugins/sdlc/scripts/lanes.py` `finish_ticketless` (line 1547): commit step `git add -A` then commit (lines 1572-1579), merge in a detached scratch tree at into (lines 1585-1598), the `land_gate:` through `gate_lock.py` (lines 1599-1610), fast-forward of into (lines 1611-1615). A merge conflict stops with nothing merged. The commit step has no marker guard. Config keys are parsed by `config()` (line 373; docstring "Config" section).
- `fanout.py merge_generated` (line 1814) resolves sdlc's own generated files; do not reuse it for consumer files, but follow its shape (conflicted paths from `git diff --name-only --diff-filter=U`).
- Design:
  - Marker guard, marker-only (not `git diff --check`, which also fails on whitespace and would change landing for every repo): refuse when a line starting `<<<<<<< ` or `>>>>>>> ` (or a bare `=======` between them) is added by (a) the staged change in the commit step, before the commit, and (b) any commit in `<into>..<branch>`, checked before the scratch merge, so markers already committed on the lane branch (the #92 failure) never reach into. Use the repo's existing pattern in `agents/planner.md:82` (`^\+\+?(<<<<<<<|>>>>>>>)( |$)` over the diff). Name the first offending path and commit; nothing is committed or merged.
  - `lane_generated: <glob>...` and `lane_regenerate: <cmd>` config lines: when the scratch merge conflicts only in paths those globs match, take into's side, run the regenerate command in the scratch tree, stage those paths, re-run the marker guard, and commit the merge. Any other conflicted path stops as today.
  - `lane_after_land: <cmd>` (repeatable, in order): run in the main checkout after the fast-forward; a failure prints `after-land: failed rc=<n> (<cmd>)` and makes finish exit 1 with the landing kept.
- Name the hosts: these commands run through the shell the user's config names; Codex sandbox notes in `plugins/sdlc/AGENTS.md` Lanes apply.
- Put new cases in the lanes selftest shard holding `case_finish_no_ticket` (line 4506).
- Run scripts with `export SDLC_ALLOW_STALE_PLUGIN=1`. Read `plugins/sdlc/AGENTS.md` first.

- Found while building T-0870 (the `live` lane kind): `finish --no-ticket` stops on a lane whose `into` is not main, so a live lane opened with `--into <branch>` can be opened, readied and closed but not finished. Make `finish --no-ticket` land such a lane into its `into` branch, with a selftest case.

## Do
1. Add the marker guard to the commit step and over `<into>..<branch>` before the scratch merge.
2. Add `lane_generated:` and `lane_regenerate:` handling to the scratch merge.
3. Add `lane_after_land:`.
4. Add selftest cases: a staged lane file holding `<<<<<<< ` is refused at commit with nothing merged; a lane branch with an earlier commit holding markers (and a clean tip) is refused before the merge; a file with trailing whitespace still lands; a conflict only in a generated path lands with the regenerated content; a conflict in another path still stops; an after-land command runs in main and a failing one exits 1 with main fast-forwarded.
5. Document the keys in the `lanes.py` docstring Config and Finish sections, `docs/specs/sdlc/lane-lifecycle.md`, and the CHANGELOG `[Unreleased]`.

## Acceptance criteria
- The lanes selftest shard holding the new cases exits 0; with the marker guard removed, the marker case fails (state the observed red).
- `python3 plugins/sdlc/scripts/lanes.py selftest` with no shard option exits 0 once at the end.
- `bash plugins/sdlc/scripts/check.sh --fast` exits 0 and `git diff --check` is clean.

## Constraints
- A repo with none of the new config lines lands exactly as before, except that a commit holding conflict markers is now refused.
- Main moves only by fast-forward.
