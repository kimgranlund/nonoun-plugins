# SDLC Lite implementation reference

Read only the entry relevant to the subsystem being changed. Paths in this reference are relative to `plugins/sdlc-lite/`; commands run from that directory. Shared scripts and their tests own executable behavior. Update affected entries when behavior changes.

Descriptions of Claude flags, skill preloading, background tools, permissions, and the default lane driver below apply to the Claude backend only. For Codex execution, sandboxing, and native delegation, read [Codex role execution](codex-role-execution.md). The backend is selected with `SDLC_BACKEND`; the legacy default is Claude.

## Implementation map

## `scripts/run.sh`

the one runner. Holds the role:level → model/effort `case` rows (a mirror of `adapters/claude/levels.json`, kept until its Claude branch is retired; `check.py` compares the two), a git preflight (exits 2 outside a git work tree or before the first commit), the verifier family rule (a verifier never runs on the build's model family: a Fable or Sonnet build moves it to Opus at the same effort; the build is the newest builder result in the handoff dir or, when it holds none (a verifier launched at the task dir), the newest builder result of the highest-numbered `step-<n>/` under it that holds one, leaving out `step-<n>.superseded-<k>/` dirs; `run-selftest.sh` case `task dir`), the plan-reviewer family rule (a plan-reviewer never runs on the newest planner result's model family: an Opus planner moves the review to Fable at the same effort, a Fable or Sonnet planner keeps Opus), and a post-run check that the saved result passes `results.py validate --role <role>` (header, key section with an allowed first value, declared sections in declared order; on failure one stderr line `run.sh: <role> result <reason>; see <file>` and exit 3, with the result file and `runs.jsonl` line kept; a builder Status or verifier Verdict `inherited red: <tests>` is accepted, and a declared section out of order, such as a verifier `## Criteria` before `## Verdict`, exits 3 naming `comes before`, `run-selftest.sh`); the result-pick heading comes from `results.py key <role>`, and read-only enforcement (Edit/Write disallowed for every role except builder). Read-only does not block Bash, so the verifier's no-git-state-changes rule lives in its prompt. After the git preflight it reads the target repo's toplevel `.nvmrc`, matches it against `$NVM_DIR` (else `~/.nvm`) `versions/node` (exact, or the highest numeric prefix match), and prepends that `bin` to PATH, or leaves PATH unchanged with one stderr line for a missing version or an alias; it never sources nvm, and `SDLC_DRY_RUN=1` shows the resolution. run.sh sets `BASH_DEFAULT_TIMEOUT_MS` and `BASH_MAX_TIMEOUT_MS` to 3600000 for the role run unless already higher (fanout sets them too), so a long foreground command is not moved to the background by Claude Code, which no PreToolUse hook sees (T-0105). It logs the run as `--output-format stream-json --verbose` (the `.log` is one JSON event per line) and saves the last `result` event holding the role's required heading, else the last one whose origin is not `task-notification`, else the last one, because a background-task notification can end the session with its own result. run.sh exports `SDLC_TMP_WORKTREES=<toplevel>/.worktrees/tmp/<role>-<pid>` and removes every worktree under it on any exit, then runs `git worktree prune`. The role runs in the background and run.sh waits on it, so INT, TERM, or HUP reach the exit handler at once rather than after the role exits: it sends a still-running role TERM, then KILL after 2 s, and only then cleans up, well inside `run_lifecycle.py`'s 5 s grace before its SIGKILL (`run-selftest.sh` case `term cleanup`). A run SIGKILLed anyway leaves its prefix behind, so a real run also calls `scripts/reap-tmp-worktrees.sh <toplevel> <own prefix>` at the start and again at exit: it removes each dead-owner prefix under `.worktrees/tmp` (a `<role>-<pid>` dir whose pid names no live process, never the caller's own) with its registered worktrees, then prunes; it never deletes a branch and never fails (`run-selftest.sh` case `stale prefix`). At run end it compares a before and after snapshot of worktrees and branches, excluding this run's own prefix, and when a stray appeared (created from inside a script or program, not the Bash tool text the hook sees) it prints a stderr line quoting `stray worktree appeared during this run` and records `stray_worktrees` and `stray_branches` fields in the `runs.jsonl` line; this is report only, it does not change the run's exit code, and a dry run takes no snapshot. The `runs.jsonl` line also holds `loaded_context` (T-0252), built by `traces.py context` from the run's log: `{"source":"stream-json","paths":[...]}` lists the `Read` tool_use paths of a Claude log, `{"source":"rollout","paths":[...]}` lists the files a Codex rollout's shell reads (`cat`, `head`, `tail`, `sed`, `nl`, `less`, `more`, `bat`) opened, and `{"status":"log absent"|"log unreadable"|"rollout absent"|"rollout unreadable"|"collector failed"}` says why no list exists, with one stderr line `run.sh: loaded context not recorded: <status>` (an empty `paths` means the run read nothing through those channels; a missing source is never recorded as `[]`). `codex_exec.py` runs `codex exec --ephemeral`, which writes no rollout, so a Codex exec run records `rollout absent`. Entry files the host injects, a Claude Bash read, and a Codex read by another command are not captured. For builder and verifier it also exports `SDLC_BASE_SHA`, the build-start base: HEAD at the step's first builder run, kept in the step dir's `base-sha` file (rewritten when missing, not an ancestor of HEAD, or passed by a resync merge, which moves it to the newest first-parent merge); every other role gets it unset. Scope criteria compare with `git diff --name-only "$SDLC_BASE_SHA"` plus untracked files, so they hold whether or not the work is committed later. When a role edits run.sh while it runs (a builder rewriting the file in place), the running process is unaffected: the whole body after `set -euo pipefail` is one `{ ... }` group ending in `exit`, so bash parses it before executing any of it, keeps its behavior, and still saves its result (`run-selftest.sh` case `self-edit`). When the runner exits 0 without a result file, `run_lifecycle.py` (the lifecycle owner) records the run as failed with exit 1 and prints a `wrote no result` stderr line naming the expected result and the `.log` (`lifecycle-selftest.py` case `test_exit_zero_without_result_fails`). Before it launches a role (dry runs too, never in the `run_lifecycle.py` child), run.sh sums `messages.py count --receiver` for the role name and the backend name and, when the sum is above 0, prints one stderr line `run.sh: <n> new message(s) for <role>; read with messages.py`; a failed count adds 0, and the notice never prints a body or changes the exit code. Session limit (T-0260): when a run fails and its log shows a 429 or a session or usage limit, `run.sh` writes `<role>-<level>.limit` (one JSON line with the resume command and the matching log line, plus a `reset` field when the log prints `resets 1:40pm`) and prints `run.sh: session limit: resume with: <command>` (with ` (resets 1:40pm)` appended then); the exit code stays 1 and a later success removes the marker (`run-selftest.sh` case `session limit`, with a plain-failure control). Lane gate (T-0274): before a planner, builder, or plan-reviewer run on a task or step handoff of a ticket (an `id:` front matter line), run.sh runs `steps.py lane --check <task dir>` (the read-only form of `lane`); lane `solo` exits 5 with the `solo_run.py run --task-dir <dir> --tier <L1|L2|L3> --brief ...` command on stderr (the ticket level; an older one-letter size reads as its level) and no attempt record, unless `SDLC_LANE_OVERRIDE="<reason>"` is set, which appends `lane override: <reason>` once to the task's `skips.md` and adds `lane_override` to the `runs.jsonl` line. Other roles, tickets with no id, lanes other than solo, a `skips.md` whose last `lane:` record is not solo (a chain or conductor already recorded its reason), and fanout's forced `--lane full` or `--driver` runs (fanout sets the override) are not gated.

## `scripts/results.py`

The one declared result schema per role. `SCHEMA` is the only copy of the table: for each role a key section (required), an allowed set for the key section's first non-blank line (builder `## Status` done, blocked, `inherited red: <tests>`; verifier `## Verdict` pass, fail, `inherited red: <tests>`; plan-reviewer `## Verdict` pass, replan, blocked; empty for the other roles), and the declared section order from the `## ` lines of `agents/<role>.md`. Only the key section is required; declared sections that are present must appear in declared order, and undeclared headings are ignored. The first line must be the header `run.sh` writes. CLI: `validate <result.md> [--role R]` exits 0 or prints one `results.py: <file>: <reason>` line and exits 1; `schema [--role R]` prints the table; `key <role>` prints the key section name; `selftest`. Reasons: `no such file`, `cannot read`, `empty result`, a header that is missing or names an unknown or different role, `lacks ## <Key>`, `## <Key> first line "<v>" is not one of <allowed>`, and `## <A> comes before ## <B>`. `validate` runs every check and backs `run.sh` exit 3. `structure_error` skips the key presence and value checks for roles with an allowed set, so `steps.py` still routes a missing or disallowed Status or Verdict to `rebuild` or `reverify` and reports only structural defects as `invalid result`. `key_value` reads the allowed token for `steps.py`. `check.py` checks each agent body against `SCHEMA`. The selftest proves each reason on temp fixtures and runs `steps.py next` against them, with a negative control: a copy of `steps.py` beside an accept-all `results.py` prints `verify` where the real one prints `invalid result`. `check.sh` runs it.

## `scripts/claude_roles.py`

The Claude table home and its generated agents (T-0276). `adapters/claude/levels.json` holds `{role: {level: [model, effort]}}` for the pipeline roles (`L1` to `L5`) and the solo levels (`L1` to `L3`, row `solo`), the twin of `adapters/codex/models.json`. A Claude sub-agent takes its effort from its definition and its model from the Agent call, so `claude_roles.py generate` writes one definition per row into `agents/` (`<role>-L<n>.md`, `solo-L1|L2|L3.md`; a generated 0.21.x one-letter solo file is removed as an orphan): the role body of `agents/<role>.md` verbatim under a generated frontmatter (`name`, `description`, `model`, `effort`, `disallowedTools: Edit, NotebookEdit` for every role but `builder` and `solo`, and the role's `skills`). `generate --check` writes nothing and exits 1 on a missing, hand-edited, stale, or orphaned file; `selftest` covers both negative controls in a temp copy. `check.py` item 39 runs it, items 1, 2, 15, and 18 compare `levels.json` with `run.sh`, the level rubric, the evals lock, and `solo.md`. `evals.py` reads the lock table from `levels.json`; its hash equals the one the `run.sh` rows gave. The family remap for a verifier or plan-reviewer changes only the Agent `model` argument, so it adds no definition. Design: [sub-agent mode](../planning/sdlc-lite/subagent-mode.md) section 1. Write stays open for a read-only role until the T-0281 hook scopes it to the role's result file. The level rubric's one-line pointer to `run.sh` is left as is: the rubric is preloaded into the Codex planner and plan-reviewer agents, so editing it regenerates Codex files; repoint it when `run.sh` is retired (T-0288).

## `scripts/dispatch.py`

The pre-launch half of `run.sh` for sub-agent dispatch (T-0277; design: [sub-agent mode](../planning/sdlc-lite/subagent-mode.md) sections 1 to 3). `dispatch.py prepare [--dry-run] <role> <level> <handoff.md>` takes the model and effort from `adapters/claude/levels.json` (pipeline rows only; solo is T-0284), applies the verifier and plan-reviewer family rules with the same `model=` header read and `order.py` ordering as `run.sh`, and runs the same gates in the same order: preflight (handoff, git work tree with a commit, the generated `agents/<role>-<level>.md`, the role's declared skills), mailbox notice, goal precheck, lane gate, spec gate, budget gate. Refusals use `run.sh`'s exit codes: 2 for preflight, goal, spec gate, or a running attempt; 4 budget; 5 lane unless `SDLC_LANE_OVERRIDE` is set (`SDLC_SPECGATE=off` skips the spec gate; both are carried into the dispatch JSON for `runs.jsonl`). A refusal writes no new file. It replaces `run_lifecycle.py`'s directory lock: under a brief file lock, a running attempt record whose parent pid is dead is marked `interrupted` and recovered, and one whose parent is alive refuses a second prepare. On success it writes `<stem>.attempt.json` (running, `transport: subagent`, `parent_pid`) and `<stem>.dispatch.json` beside the handoff, `base-sha` for a builder or verifier, and prints the dispatch JSON: `subagent_type` (`sdlc-lite:<role>-<level>`), `name` (the Agent name `<role>-<level>-<slug>[-<k>]`, at most 64 characters), `model`, `effort`, `prompt` (the `run.sh` prompt plus a `Tree:` line, the throwaway-worktree prefix `.worktrees/tmp/<name>`, and for builder and verifier a `Base sha:` line, because a sub-agent cannot read `SDLC_BASE_SHA`), `result`, `tmp_prefix`, `base_sha`, and the `run.sh` runs-line facts. The stem `<role>-<level>[-k]` names the result and both records; it is the lowest free `k` where no `<stem>.*` file exists (`run_lifecycle.py`'s rule, so an interrupted attempt's record bumps `k`). The `.nvmrc` PATH change and skill appending are not carried over: a sub-agent inherits the parent's environment, and the generated definition's `skills:` list loads the skills. `selftest` compares model, effort, and result name against `SDLC_DRY_RUN=1 run.sh` for every table row and the family fixtures, compares each refusal's exit code with `run.sh`, and gives each gate a negative control that disables it and lets the bad input through. `run.sh` is unchanged. `prepare` also snapshots the registered worktrees and local branches into the attempt record (`worktrees_before`, `branches_before`) for `record`.

`dispatch.py record [--agent-id ID] [--tokens N] [--tool-uses N] [--duration-ms N] <dispatch.json>` (T-0278) is the post-launch half: it validates, records, and closes the attempt `prepare` opened. The result is the file the role wrote at the dispatch's `result` path, else stdin when that file is missing or empty; stdin text with a `## ` heading line is a result, any other stdin is the sub-agent's error text. It writes the `run.sh` header line from the dispatch (any header the role wrote is replaced), removes the worktrees and directory under the dispatch's `tmp_prefix` (only a path under `<tree>/.worktrees/tmp/`), reports strays (worktrees and local branches that appeared since `prepare`, its own prefix left out) and a handoff whose sha256 changed since `prepare` (`stale_input`), appends the `runs.jsonl` line, then runs `results.py validate --role`. None of cleanup, strays, or stale changes the exit code. The line has the key set `run.sh` writes plus `agent_id` and `cost_reason`, with `transport: subagent`; `cost_usd` is null with `cost_reason: subagent usage not priced` until the cost-estimate ticket (T-0280) prices it, and `usage` holds `subagent_tokens` and `tool_uses` when the flags give them; `specgate` and `lane_override` are carried from the dispatch only when set. Exit codes: 0 recorded, 1 failed sub-agent (the error text is saved as `<stem>.log`, the attempt is `failed` with the text, no `runs.jsonl` line, and a 429 or session-limit text writes `<role>-<level>.limit` with the `prepare` command to resume, removed by a later success), 2 an unreadable dispatch or attempt record, an attempt that is not `running`, or a result path outside the artifacts dir, 3 an invalid result (`dispatch.py: <role> result <reason>; see <file>`, the file and the line kept, the attempt `failed` with `exit_code` 3). `selftest` runs a real `run.sh` with a stub `claude` beside `record` for builder, verifier, planner, and plan-reviewer and compares the `runs.jsonl` key sets and result headers, proves `steps.py next` and `order.py` read both alike, and gives each invalid-result reason a negative control that passes it with an accept-all validator.

## `scripts/evals.py`

Dated model and effort eval records in `.sdlc/evals/`, and the lock that ties the model table (the pipeline-role rows of `adapters/claude/levels.json` plus `adapters/codex/models.json`) to one of them. The record format and the canonical table text live in [the evals entry file](../../.sdlc/evals/AGENTS.md) and the evals.py docstring; this entry does not copy them. CLI: `evals.py [--root DIR] [--plugin DIR] <cmd>`, with `--root` the `.sdlc` folder (default `.sdlc` in the cwd) and `--plugin` the dir holding `adapters/claude/levels.json` and `adapters/codex/models.json` (default the plugin holding the script). Commands: `add <slug> ...` writes the next `NNNN-<slug>.md` and refuses an invalid record without writing; `list` prints one line per eval and always exits 0; `check` validates every eval and the lock against the current table hash; `lock --eval PATH` cites an eval, and a replacement must be dated later than the eval it replaces; `hash` prints the current table sha256; `selftest`. Exit codes: 0 ok, 1 refusal or failed check, 2 usage error. Python API: `FIELDS`, `canonical_table(plugin)`, `table_sha256(plugin)`, `validate_text(text, repo)`, `validate_eval(path, repo)` (each validator returns None or one reason string, so later callers can validate a record without the CLI), and `check_problems(root, plugin)`. `.sdlc/evals/table-lock.json` holds exactly three keys: `eval` (the cited eval), `previous_eval` (the eval it replaced, or null), and `table_sha256` (the hash the cited eval covers); only `lock` writes it, and evals.py never writes `run.sh` or `models.json`. `check.py` docstring item 15 runs the check when `<plugin>/../../.sdlc` exists, printing each problem as `FAIL evals: <line>`, and prints `skip: evals lock guard` when no `.sdlc` sits beside the plugin's repository. The selftest runs in temp dirs, confirms the real `levels.json` and `models.json` are unchanged, and carries three negative controls: evals.py without the hash comparison passes a stale lock, without the date rule passes a reused eval, and without the required-field check accepts a missing field.

## `scripts/proposals.py`

Mines past runs for repeated failures and files each pattern seen two or more times as an evidence-backed candidate proposal; it applies nothing. The proposal format, the six patterns, and the status moves live in [the proposals entry file](../../.sdlc/proposals/AGENTS.md) and the proposals.py docstring; this entry does not copy them. CLI: `proposals.py [--root DIR] [--proposals DIR] [--plugin DIR] <cmd>`, with `--root` the `.sdlc` folder (default `.sdlc`; the repo is its parent), `--proposals` where proposals live (default `<root>/proposals`), and `--plugin` the dir holding `scripts/evals.py` and `scripts/tickets.py` (default the plugin holding the script). Commands: `scan` files new candidates and refreshes the evidence of known ones, reading `runs.jsonl` files, builder and verifier results, and `<root>/notes.md` and never writing them; `list` prints one line per proposal and always exits 0; `show <id>`; `accept <id> --eval PATH` (candidate to accepted); `reject <id> --reason TEXT` (candidate to rejected); `promote <id>` (accepted to promoted); `selftest`. Exit codes: 0 ok, 1 refusal, 2 usage error. Reads: `accept` loads evals.py and calls `validate_eval` on an eval directly in `<root>/evals/`; `promote` runs `tickets.py --root <root> new idea <folder> <title>` and fills the new ticket's Goal and Context. The six rule markers (`# rule: read-only`, `forward`, `threshold`, `known`, `eval`, `reason`) each tag the one line the selftest breaks in a copied script. The selftest runs in temp dirs and carries the negative controls: without the eval rule accept passes with no eval, without the reason rule reject passes with no reason, without the forward rule promote passes on a candidate and accept passes on a promoted proposal, without the threshold a pattern seen once files a candidate, without the known-pattern match a second scan duplicates, and a copy that writes a source file fails the before and after source check. `check.sh` runs it.

## `scripts/messages.py`

A git-ignored file mailbox that lets one harness (Claude, Codex, or a human) leave a message for another. Subcommands: `send` (writes `new/<receiver>/<id>.md` through a temp file and a hard link, prints its path), `list` (state, receiver, id, sender, topic; never a body), `read` (claims as the receiver), `ack` (moves read to done with a one-line `--outcome`), `reply` (sends to the original's sender with the same topic and `re: <original id>`), `expire` (the expiry sweep; `--now` only sets the comparison instant), `count` (files in `new/<receiver>/`), `wait` (blocks until a valid message is in `new/<receiver>/`, checking every `--interval` seconds (default 5, at least 1) for up to `--timeout` seconds (default 120, 1 to 600); prints `<id>\t<absolute path>` per message, sorted by id, and exits 0; at the timeout prints `no new messages` and exits 3; skips an invalid file; never claims, moves, writes, or prints a body), and `selftest`. Exit 1 on every refusal or validation failure with one `messages.py: <reason>` stderr line and nothing written; exit 2 only for a usage error; exit 3 only when `wait` times out. Layout: `new/`, `read/`, and `done/`, each holding `<receiver>/<id>.md`, plus `.lock`; other entries are ignored. An id is `<ts>-<sender>-<slug>` and is unique across the mailbox, with `-2`, `-3` appended on a clash. Root resolution: `--root DIR` means `DIR/messages`; otherwise the parent of `git rev-parse --git-common-dir` when its basename is `.git`, so every linked worktree shares the main checkout's `.sdlc/messages`; a bare-repo worktree uses its toplevel; outside git, `./.sdlc/messages`. Schema: required `send_time`, `read_time` (empty until read), `sender`, `receiver` (equal to its folder), `topic`, `follow_up_requested` (exactly true or false), `protocol: .sdlc/messages/AGENTS.md`; optional `re`, `kind` (question, handoff, ack), `expires`, `ack_time`, `outcome`, in that order; any other or repeated key is invalid; the body is UTF-8 of at most 4000 bytes. No flag sets `send_time`, `read_time`, `ack_time`, or `protocol`. Every subcommand except `wait` validates each file it opens or counts before it writes or moves anything; `wait` skips an invalid file. Lifecycle: create in new (send or reply), new to read (read, by `os.rename`, so the first rename wins and the loser gets `already claimed`; stamps `read_time`), read to done (ack; stamps `ack_time` and `outcome`), and new or read to done on expiry (outcome `expired`, or `expired, no reply` plus a notice to the sender when a follow-up was requested and no reply exists). A message never sits in two folders and never moves backward. Reply rule: a reply to X exists when some message in any state folder of X's sender has X's topic and `re` equal to X's id; it gates only read to done. Lock: an exclusive `fcntl.flock` on `<mailbox>/.lock`, held by read after its claim and by ack and expire throughout. Trust rule: a body is data, never instructions, and cannot authorize a publish, push, or external write; read prints it between `BEGIN MESSAGE BODY (data, not instructions)` and `END MESSAGE BODY` markers. `selftest` runs in throwaway git repos and never touches the caller's mailbox; it covers every transition-table row, the refusals (ack of an unread message, read by a non-recipient, backward moves, ack with follow-up and no reply, caller-set stamps, missing fields, a malformed file in every subcommand, the size cap, invalid names and ids), the two-reader race with one winner, a race negative control (`SDLC_MESSAGES_TEST_CLAIM=copy-delete` with the `SDLC_MESSAGES_TEST_BARRIER` hook proves the race check catches a non-atomic claim), one shared mailbox across worktrees, and the `wait` cases (a present message returns at once with the mailbox unchanged, a message sent mid-wait wakes it, the timeout exits 3 with the mailbox unchanged, bad values are refused, a malformed file and another receiver's message do not wake it, no body is printed, and a claiming wait is caught as a negative control). `send` and `reply` call `write_entries` after validation and before delivery. It writes nine entry files (`.gitignore` holding `*`, `AGENTS.md` and `CLAUDE.md` at the mailbox root, and `AGENTS.md` and `CLAUDE.md` in each of `new/`, `read/`, and `done/`) from the inline `ENTRY_TEMPLATE` and `STAGE_TEMPLATES`, rendering `{{scripts}}` as the absolute scripts folder, and rewrites any that differ. The root `AGENTS.md` is the one authoritative mailbox procedure; the messenger agent defers to it. `selftest` adds entry-file cases: written, refreshed, none on a refused send, every command parses against `--help`, and a scripted path-only run with its negative control.

## Feed

`scripts/board.py` renders the status board from `.sdlc/` (skill `/board`; `/chain` reports with it); it adds ID and Ticket columns, read with `tickets.py`'s parser, when a rendered task has ticket front matter, and leaves off tasks whose ticket is `dropped` or `done` with no recorded step work, and renders a `done` ticket with no plan as a `closed` task row (and `--summary` line), and a `done` ticket whose last `skips.md` lane is `solo` as one `closed` row whatever its step folder holds; renders a step whose newest build a task-dir verifier passed under `## Verified` (`steps.batch_verified`) as `🟢 pass · builder <level> · batch verifier <level>`; by default (no `--sort`) it orders by ticket id when any rendered task has ticket front matter (unticketed tasks follow by recency) and by recency otherwise; `--sort id|name|recent` overrides, and `--sort recent` restores recency; its "· changed" cache lives in a per-user cache dir outside the repo (`SDLC_BOARD_STATE_DIR` overrides it), so `/board` writes nothing into the tree; it prints a one-line hint when a legacy `.sdlc/.board-state.json` is present (never deleted automatically, never in `--summary`). With `ticket_root: tickets` in `.sdlc/config` it also lists the task dirs under `.sdlc/tickets/`, and with `layout: topics` too, the task dirs under `.sdlc/work/` (ticket-less tasks, resolved through `tickets.layout_paths`; an unsupported value lists root tasks only); `statusline.sh` has no layout logic of its own, because its line 2 comes from `board.py --summary` and its live-run search is recursive. `traces` lists the same dirs (`work/<name>` beside `tickets/<name>`, with `work` and `notes` skipped as non-tasks under `layout: topics`) and reads the notes file from `tickets.layout_paths(root).notes`. `board.py --lanes` instead prints one `| Lane | Branch | Board |` row per `git worktree list` entry (worktree basename, branch, and that worktree's `--summary` line of the same-relative root), exits 1 outside a git work tree, and leaves the default board unchanged. `scripts/statusline.sh` shows line 1: model, dir, git (branch, dirty, ahead/behind, worktree), context % (🟡 at 70, 🔴 at 85), session cost and duration; line 2 only when `.sdlc/` has tasks: the live role run plus `board.py --summary` (task %, 🔴 count, ⚠ L5); statusline installation is host-local configuration. `output-styles/sdlc-feed.md` is an optional session style (`/output-style`). `run.sh` keeps `<role>-<level>.running` during a run so both can see live work.

## Agent skills

an agent's frontmatter `skills:` list is loaded by `run.sh` (appended with `--append-system-prompt-file`, plugin paths filled in), because `claude --agent` does not preload them (token probe with a positive control, 2026-09-24). planner ← `level-rubric`, architect ← `decompose`, verifier ← `checks-that-bite` (brought in from the user-level skill) and `checking-rules` (ported from harness checking-rules, trimmed). `check.py` fails on a declared skill that does not exist.

## `scripts/tickets.py`

backs `/ticket`. `size` is the ticket level, `L1` to `L5` (L1 small, L2 medium, L3 large, L4 extra large, L5 reserved; the scale is the one table in the level-rubric skill). ## `scripts/cite_check.py`

`cite_check.py DOC [--root DIR] [--alias NAME=PREFIX]... [--strict]` opens every backticked `path:N`, `path:N-M`, or `path:N,M-K` span in a document and prints `warning <doc>:<line>: `<cite>`: <problem>` per problem (no such tracked file; exists but untracked or git-ignored, so no commit backs it; a line past the end of the file; a backwards range or line 0; an ambiguous bare name), then `ok: N citations resolved in <doc>` or `<P> of <N> citations have problems`. It exits 0 either way (a warning lint; `--strict` exits 1; 2 for a missing doc or a root that is not a git work tree), reads only the document and the cited files, and calls no model. Shorthand: a leading alias segment defined by a "`PC` means `<prefix>`" sentence in the document or by `--alias`; a bare name resolves to the last tracked file seen earlier in the document that ends in it, else the root file, else the one tracked file that ends in it. A citation inside `[O word ...]` (a word before the first backtick) names another repository and is skipped, and fenced code blocks are not read. Limit: it proves the file is tracked and the line exists, not that the line says what the claim says; a line number that drifted after an edit still passes. `selftest` builds a throwaway git repo and runs a clean document and a document with one of each defect; `check.sh` runs it.

## `scripts/fleet_collect.py`

turns one repo's run records and the machine state into one JSON fingerprint for the fleet retro: `collect <repo> [--since DATE] [--until DATE] [--gh] [--days N] [--du-timeout SEC]` and `selftest`. No model call, and read-only on every repo it inspects. Keys: `env`, `runs` (with `by_ticket`), `plan_review_share`, `tickets` (size and acceptance-criteria count per handoff; both key a ticket folder by its path under `.sdlc`, `tickets/<folder>` when any checkout's `.sdlc/config` sets `ticket_root: tickets`), `processes` (per-class `rss_mb`, and per-process `items` for hooks), `worktrees`, `ci` (per-workflow `by_event` and the 7-day push counts), plus a `summary` line (`runs: none` for a repo with no `.sdlc`; the same line goes to stderr). `runs` reads every `.sdlc/**/runs.jsonl` under the repo and each worktree (`git worktree list`, `.worktrees/*`, `.claude/worktrees/*`), deduplicated by `attempt_id` as `budget.py` does (a row with no `attempt_id` is deduplicated on its whole line, where `budget.py` counts each); a run's lane is the nearest `skips.md`'s conductor override (`Lane: <lane> ...`) over its `- lane:` record, with `lean` counted as `full` and role `solo` always `solo`. `--until` exists because a live repo keeps growing: the 193 runs of agent-ui's 2026-10-06 report reproduce only at the report's cutoff. `du` and every other probe run under a timeout and kill their process group; a timed-out `du` prints `size: unknown`. `check.sh` runs its selftest, whose negative control shows duplicates change the totals with dedupe off.

## `scripts/fleet_detect.py`

mechanical waste and stall rules over `fleet_collect.py` fingerprints: `detect <fingerprint.json>...` prints one JSON line per finding (`rule`, `repo`, `scope`, `evidence` path into the fingerprint, measured `value`, `threshold`, `source`, optional `detail`) and `selftest`. Pure over the JSON it is given: no model call, no `ps`, `gh` or repo reads, and a key a rule needs that is absent or mistyped (`runs: "none"`, `ci: "skipped"`, a fingerprint from before the key existed) silences that rule instead of failing. The rules and the one thresholds table (`THRESHOLDS`, a comment per row) sit at the top of the file; this entry does not copy them. A rule fires when the value is over its threshold. Machine-state rules (`hook_cpu`, `chromium_load`, `plugin_version_stale`) carry `scope: machine` because every repo's fingerprint of one run shows the same machine, so a report collapses them. `hook_cpu` approximates "over 50 percent for over 20 seconds" from one `ps` snapshot as lifetime-average CPU of a process alive longer than 20 seconds. Exit 0 with or without findings; 2 for usage or an unreadable fingerprint. `check.sh` runs its selftest, which holds a positive and an at-threshold negative per rule, a negative control that raising a threshold in the table silences its rule, the 2026-10-06 known findings, and old-shape fingerprints.

## `scripts/fleet_status.py`

decides whether each board row is really moving, for the fleet status (T-0311 collects, T-0312 renders): `collect [REPO ...] [--fleet FILE] [--state-dir DIR] [--stop-line N] [--active-minutes N] [--no-gh] [--no-write]` prints one JSON object, `render` draws it (below), and `selftest` runs fixtures for both. No model call, and read-only on every repo it inspects: only `ps`, read-only `git` plumbing (`GIT_OPTIONAL_LOCKS=0`, nothing fetched) and `gh pr list` run there. Repos come from the positional paths, else the active entries of `.sdlc/fleet.json` (`fleet_config.py`). Rows are the tasks `board.py` shows (`task_dirs`, `belongs_on_board`, `task_rows`; `render` is never called, so its state file is untouched). Each row gets one state, in this precedence: `live` (a `ps` command naming the ticket folder, a linked worktree named for the ticket id or folder, or a `*.running` marker whose same-role-and-level `*.attempt.json` with status running has a pid that is alive and started no later than the marker; the marker itself holds `date +%s`, not a pid), `dead` (a marker and no live pid), `idle` (a `runs.jsonl` row `ts` or a `*.log` mtime inside `--active-minutes`, default 15), then `stale` for a row the board shows yellow or red with none of those, else `queued` or `done`. `runs.jsonl` counts by its newest row `ts` because a git checkout or merge refreshes the mtime of every tracked file; `handoff.md` and `skips.md` never count. A ticket that is done or dropped while its board rows still claim work carries the flag `ticket-done-board-open`. Process matching uses the folder name without a closed ticket's leading dot, bounded by non-word characters, so a bare-id substring such as `10043` never matches; viewers, searches and `git` never count as workers. Load: `os.getloadavg()` appends `{ts, load1, load5, load15, cpus}` to `<state-dir>/load.jsonl` on every call (state dir default `<cwd>/.sdlc/runtime`, git-ignored, never inside an inspected repo), the trend is load1 against the oldest stored sample 20 seconds to 10 minutes old (else against load5), and the verdict is `over` above the stop line (default 60), `near` from 80 percent of it. Consumers by class (chromium, hooks, claude, watchers) come from one `ps`. `needs_you` lists blocked tickets with an `owner: user|conductor` line (handoff body, or a `notes.md` line naming the id; else `unknown`) and open non-draft PRs. `release` is local default branch against `origin/<default>`, the last tag, and unpushed commits. `<state-dir>/fleet-status.json` is the snapshot the next call diffs: `delta` lists state changes, tickets closed (keyed by ticket id, so the `.NNNN-` rename is a close and not a vanished row), new and vanished tickets, and PRs merged or closed. `render [--repos A,B] [--since last|DATE] [--ping] [--fleet FILE] [--state-dir DIR] [--stop-line N] [--active-minutes N] [--no-gh] [--no-write]` is `collect` plus a pure `render(data)` that prints, in this order and in at most 60 lines for three repos (a table's header, rule and closing blank line count like any line), Machine (one line), then plain aligned tables, indented two spaces, with the columns Repo, Row, State, Detail, Source (a header row, a dashed rule, each column padded with spaces to its widest cell where a colored circle counts two columns, no markdown pipes, a hyphen for an empty cell): Needs you (open PRs as State `merge`, blocked tickets for the user or an unknown owner as `decision` or `credential`, each with owner and age in Detail), Moving (one row per repo with its mark in State, row counts, `unread N` and the supervisor state, then the live and idle rows), Stale or stuck (dead and stale rows; every row flagged `ticket-done-board-open` is folded into one row per repo, `N closed tickets still shown on the board`, so closed tickets do not bury the rows that are really stuck), then Done since the last report as plain rows (the stored snapshot, or the `close T-NNNN` commits and merged PRs since DATE), then Release state as a table, plus the conductors to message with `--ping` (it sends nothing). State marks are colored emoji: 🟢 live, 🟡 idle, 🔴 dead, ⚠️ stale, ⚪ a repo with nothing moving. The unread ids are file names under `.sdlc/messages/new/<receiver>/`, never a body (the first one is named, the rest counted); the supervisor state is `.sdlc/supervisor/status.json`. Every row ends with its source in brackets, the last table column (the ticket folder under the repo's `.sdlc`, `PR #N`, `@ sha`, `.sdlc`, `.git`; the Repo cell names the repo, and because a column is as wide as its widest cell a table line stays within 150 columns for a realistic status where its names allow) and a row with no source raises `RenderError` (exit 1); list caps shrink together until the output fits; em and en dashes are turned into hyphens and a pipe into a slash, so the output holds neither. `--repos` narrows the active registry entries, an excluded name is skipped with a stderr note, an unknown one exits 2. The skill `/sdlc-lite:fleet-status` runs `render`, prints it verbatim and asks once for the Needs-you rows; guard 37 in `check.py` pins the skill, its route, the `RenderError` path and the schema file (it exists, parses as JSON, declares draft 2020-12 and requires the `machine`, `repos`, `needs_you` and `delta` keys). `check.sh` runs its selftest, whose controls plant a stale row (it must sit under Stale or stuck, then under Moving once a process backs it), a run of done-but-open rows (they must fold into one row per repo while a genuinely stale or dead row stays listed, and the same rows without the flag are all listed), a row with no source, a 60-line overflow, table well-formedness and a 150-column width check. The shape `collect` prints is pinned by `skills/fleet-status/resources/fleet-status.schema.json` (JSON Schema, draft 2020-12, shipped with the skill and linked from its SKILL.md), which is the authority for the key list, the types and the allowed values; the script's docstring points at it and keeps only what the values mean. ## `scripts/budget.py`

per-ticket cost budget from optional front matter `budget_usd` (by ticket level: L1 $5, L2 $30, L3 $60, L4 and L5 none; `set --tier` takes the level, an older one-letter name reads as its level). `status <path>` walks up to the ticket, sums `cost_usd` over every `runs.jsonl` under it (superseded dirs included, deduplicated by `attempt_id`, null cost counted as unmetered) and exits 0 ok, 3 at 80 percent or more (warn, over at 100), 2 with no budget. `set --tier|--usd` writes the field; `ack --usd N --reason` writes `budget-ack.md` to raise the ceiling. Codex runs record no cost, so it meters Claude roles only. `run.sh` exits 4 on status exit 3 before launch, `board.py` adds a Budget column only when some ticket has a budget, and `check.sh` runs its selftest.

## `scripts/specgate.py`

`check <planner.md | task dir>` picks the plan the way `steps.py split` does and reads it with `steps.py`'s own parser (it imports `steps`); it is read-only and never runs a span. It flags three kinds: a `slow guard` (a `(guard)` span that runs `check.sh` with no `guard timeout:` line in its step block or in the plan outside every step block), a `duplicate span` (a non-guard criterion span that repeats an earlier step's span verbatim; guards and `Merge` steps are exempt), and `red and guard` (a criterion tagged both `(guard)` and `(red)`). Findings print on stderr as `specgate: <plan>: step <n>: <kind>: <detail>` with a closing count line, exit 1; a clean plan prints `specgate: ok: <plan>`, exit 0. A dir with no planner file, or a plan `steps.parse_steps` refuses, prints `specgate: skip: <reason>` on stderr and exits 0. `run.sh` runs `specgate.py check` on the handoff dir before every plan-reviewer run, dry runs too and never in the `run_lifecycle.py` child; a refusal exits 2 before any model call, and `SDLC_SPECGATE=off` skips the gate and tags the run's `runs.jsonl` line `"specgate":"off"`. `selftest` proves each finding, each exemption, and the skip.

`red <task dir | handoff.md> [--step N] [--timeout S]` (T-0314) is the red-first control for a `(red)` criterion (a list item whose leading tags hold `(red)`): each of its spans must exit nonzero now. Without `--step` it reads a ticket handoff's `(red)` items (the solo case: `agents/solo.md` runs it before the first edit); with `--step N` it reads step N of the newest plan. A span that exits 0 (`red-first: [step <n>: ]`<span>` is green now; it cannot detect the change`), a timeout, or a span that changed the work tree refuses, exit 1; in a git work tree the changed paths are put back from a content snapshot taken before the first span (`steps.red_snapshot`, `red_restore`, `red_first`; the message ends `(restored)`). `steps.py split --only` runs the same rule beside its guards (`run_red`), `steps.py swap` refuses a swap that drops or adds `(red)`, and all of it is proven by mutation controls in the `steps.py` and `specgate.py` selftests.

## `scripts/gate_lock.py`

A machine-wide semaphore so at most N heavy gates (npm test, browser shards, tsc) run at once across every session and repo (T-0303). `run [--slots N] [--name X] [--nice] [--timeout SECS] -- <cmd...>` takes one of N slots (default 2, env `SDLC_GATE_SLOTS`; below 1 runs the command with no lock), runs the command in its own process group, and exits with the command's status. The lock dir is `${TMPDIR:-/tmp}/sdlc-gate-locks`: one file `slot-<i>` per slot holding the holder's pid, start time, name, and command, written whole and hard-linked into place under a short `flock` so two runs never share a slot. A slot whose pid is gone, a zombie, or reused by a process that started after the slot was taken is stolen. A run that finds every slot held waits up to `--timeout` seconds (default 1800), printing who holds the slots on stderr every `SDLC_GATE_REPORT_SECS` (default 15); a timeout prints one stderr line and exits 3. The command gets `SDLC_GATE_WORKERS=max(1, floor(cpus / slots))` for Playwright and vitest worker settings and `SDLC_GATE_LOCK_HELD=1`, so a `run` nested in a held slot runs with no second slot and cannot deadlock. `--nice` runs the command at nice 10. SIGTERM, SIGINT, and SIGHUP kill the command's process group first (SIGTERM, SIGKILL after 5 s), then free the slot, and exit 128 plus the signal. `status` lists slot, pid, name, and age. `reap [--older-than MIN] [--kill]` (T-0304) lists processes whose command line matches chrome-headless-shell, chromium or Chrome for Testing, playwright, or vite preview, whose parent pid is 1 or gone, and that are at least MIN minutes old (default 30), stops nothing unless `--kill` (SIGTERM, SIGKILL after 2 s, each pid printed), never lists or stops a process with a live parent, and has a selftest with a fake orphan, a live-parent fake, and a negative control (the `PARENT-CHECK` line removed) that must list the live-parent fake. `selftest` uses real child processes in a temp `TMPDIR`: two holders run and a third waits then runs, a SIGKILLed holder's slot is stolen, the workers variable and the exit status pass through, the timeout exits 3, SIGTERM frees the slot, and a negative control (a copy with the slot cap removed, the `SLOT-CAP` line) must fail the three-holder case; `check.sh` runs it. `fanout.py` runs each `--gate` through `gate_lock.py run --name <lane>/<id> --` (the gate log still gets the output, and the gate-vacuous check and rc handling are unchanged; a lock timeout is gate rc 3 with the `gate_lock: timeout` line in the log); `SDLC_GATE_SLOTS=0` or `--no-gate-lock` runs the gates bare. `agents/conductor.md` says heavy gates run through it. Guard: `check.py` item 35.

## `scripts/supervisor.py`

An idle-host watcher: deterministic code with no model call that, when mail waits for a receiver configured in `hosts.local.json`, starts a headless Claude Code or Codex session for it. Commands: `init` (writes `.sdlc/supervisor/AGENTS.md`, `CLAUDE.md`, and `.gitignore`, plus `limits.json` and `hosts.local.json` only when missing), `watch [--run] [--once] [--now TIMESTAMP] [--driver PATH]` (a dry run unless `--run`, which prints `dry-run: would wake <receiver>: <n> message(s)` and wakes nobody), `status`, `reset --receiver NAME`, and `selftest` (run by `check.sh`). The folder is the main checkout's `.sdlc/supervisor/`, beside the mailbox, shared by every linked worktree. Each receiver has a mode: `ephemeral` (default, a fresh session), `attached` (resumes a named session), or `notify` (prints a line and wakes nothing). `limits.json` bounds the poll interval, debounce, cooldown with exponential backoff after a failure, hourly and daily wake caps, the wake timeout, the reply depth limit (deeper chains need a human), the failure stop (`max_failures`, then failed until `reset`), the quiet window for an active transcript, the per-wake budget, and log retention; a value outside its range is refused. An exclusive `flock` on `lock` keeps one watcher running; `touch .sdlc/supervisor/STOP` makes it end its wakes, write `status.json`, and exit 0. `status.json` (rewritten every poll) records each receiver's state, pending count, last wake and result, and next wake. The watcher never claims, moves, edits, or deletes a message, never runs `messages.py expire`, and never prints, stores, or passes a message body or topic; the woken host claims, replies, and acks through `messages.py` under unattended rules (`SDLC_HEADLESS=1`, never push or publish). The live run is recorded in `docs/reports/supervisor-live-run.md`; the design is `docs/planning/ticket-stages/watcher-design.md`.

## `scripts/traces.py`

Thin entry over the `scripts/traces/` package; `/review-traces` drives it. Five subcommands: `selftest [-k FAMILY]`; `ingest <repo> [--lanes-dir DIR]... [--out DIR] [--bench-dir DIR] [--rerun-criteria] [--load-series PATH]` (prints the `events.jsonl` path); `detect [--repo REPO] [--out DIR]` (runs the detector families, prints notes and the `findings.jsonl` path); `clusters --max N [--repo REPO] [--out DIR]` (prints the top N cause clusters as JSON). `context <log> [--backend claude|codex] [--codex-home DIR]` (T-0252; prints one JSON line, the loaded-context record `run.sh` stores in `runs.jsonl`, from `traces/sources/context.py`; exit 0 whatever the status; ingest gives every joined row a `loaded_context` from the run record, else from the result's log, `{"status":"log absent"}` when no log sits beside the result). The out dir defaults to `<cwd>/.sdlc/runtime/traces/<repo-key>/` (`repo-key` is the repo basename plus the first 8 hex of the sha256 of its absolute path) and holds `events.jsonl`, `aux.json`, `findings.jsonl`, and the ingest cursor `cursor.json`, so an unchanged source is not reopened; `.sdlc/runtime/` is never committed. Stages 1 (ingest) and 2 (detect, clusters) are model-free: none spawns a claude or codex process; model calls start at the skill's diagnose stage.

Detector families (`traces/detectors/`) are escalation, plan, hygiene, and cost. Every number lives in `traces/detectors/thresholds.py` (`THRESHOLDS`, overridable through `merged()`); a detector never hard-codes one:

| Key | Default | Family: finding |
|---|---|---|
| `replan_loop_planners` | 2 | escalation: replan-loop (planner rows in one task dir) |
| `replan_loop_high_replans` | 2 | escalation: replan-loop-high |
| `bump_levels` | 1 | escalation: unchanged-verdict-bump |
| `exit_code_missing_section` | 3 | escalation: exit-3-result |
| `rerun_timeout_secs` | 60 | plan: criteria-never-red, per span |
| `cost_over_baseline_ratio` | 2.0 | cost: cost-over-baseline (vs the bench median per passed step) |
| `many_builder_attempts` | 3 | cost: many-builder-attempts (builder rows in one step dir) |
| `polling_loop_calls` | 5 | cost: polling-loop (identical Bash calls) |

`THRESHOLDS['severity']` maps each finding kind to 1..3. `selftest` proves each detector on fixtures, and its corpus case ingests this repo's own `.sdlc` traces whole and checks the known findings (skipping a sub-check whose source, such as a fanout logs dir, is absent). `--rerun-criteria` is opt-in: it reruns each passed step's non-guard acceptance criterion spans at the step's `base-sha` (feeding criteria-never-red) in detached throwaway worktrees under `$SDLC_TMP_WORKTREES/traces-rerun-<pid>` when set, else a temp dir outside the repo; each is removed with `git worktree remove --force` and pruned, so `git worktree list` is unchanged. Ingest also walks `tickets/<name>` task dirs, and the ticket reader reads `<root>/tickets` when the config sets `ticket_root: tickets`.

## `scripts/solo_run.py`

Starts the solo agent for one ticket and records its cost (T-0225): `solo_run.py run --task-dir <ticket folder> --tier L1|L2|L3 --brief <text>` (an older one-letter `--tier` is a deprecated alias, normalized to its level with a notice on stderr) (also `--brief-file`, `--backend claude|codex`, `--cwd`, `--timeout`). It starts `claude -p --agent sdlc-lite:solo --output-format json` at the level's model and effort (the same table as `fanout.SOLO_TIERS` and `agents/solo.md`, guarded by `check.py` item 27), or `codex_exec.py solo L1..L3`, prints the report, and appends one `role solo` line to `<task-dir>/runs.jsonl` in the run.sh record shape (ts, level L1..L3, model, effort, cost_usd, usage, duration_ms, turns, attempt_id, backend, transport, routing_reason, exit_code). `budget.py` and the board count it because they sum `cost_usd` over every `runs.jsonl` under the ticket. Cost is never guessed: a crash, a missing result event, a result without `total_cost_usd`, and Codex (which reports none) record `cost_usd` null with a `cost_reason`, and the budget reports that run as unmetered. The raw command in `agents/solo.md` still works and records nothing. Fanout's solo driver starts through `solo_run.py` too (T-0226), so each solo lane writes its own `role solo` record in the ticket's `runs.jsonl` and the budget and board meter the parallel default path; a Codex lane records a null cost, counted as unmetered. `SDLC_SELFTEST_RAW_SOLO` restores the raw command for the fanout selftest's negative control (case 17). Budget gate (T-0229): before it starts anything, `solo_run.py` runs the same check `run.sh` does for roles (`budget.report` on the ticket holding `--task-dir`): at 80 percent of `budget_usd` or more with no `budget.py ack` it prints `solo_run.py: budget <pct>%: ask the user; budget.py ack` and exits 4 with no session and no record; a ticket with no budget, or a task folder with no ticket id, is never blocked. Fanout's solo lanes go through it, so a gated lane stops as `driver failed rc=4 (budget gate: budget.py ack)` (fanout selftest case 18). `--new-task [slug]` (for `/agent solo` with no named ticket) creates `<ticket root>/<slug>/handoff.md` from the brief, with no `id` and so no budget, and runs there, so that run still leaves a `role solo` record. Metering covers Claude solo lanes only: Codex records cost null, and a `full` fanout lane or a conductor session writes no record. `solo_run.py selftest` runs against a stub `claude` on PATH. Process group (T-0293): the child `claude` runs in its own process group; a timeout, SIGTERM, SIGINT, or SIGHUP to the wrapper ends the whole group (TERM, then KILL after 2 s) and exits nonzero, and a lock file in the worktree's git dir (`solo_run.lock`, holding the wrapper pid) makes a second `run` there exit with `solo_run.py: another solo run is live (pid N)` before any session or record; a dead pid's lock is cleared, and every exit removes it (`solo_run.py selftest`, with a real child and a negative control). Session limit (T-0260): a failed session whose output shows a 429 or a session or usage limit writes `<task dir>/solo.limit` (resume command, evidence, and a `reset` time when the output prints `resets 1:40pm`) and prints a resume hint on stderr (ending ` (resets 1:40pm)` then); fanout WIP-commits the marker with the lane, and a later success removes it.
