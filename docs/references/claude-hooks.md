# Claude hook maintenance

Read when changing Claude hook behavior or its checks. Paths below are relative to `plugins/sdlc-lite/`. Hook registration lives in `adapters/claude/hooks.json`; the Claude manifest references it explicitly. Do not restore a shared `hooks/hooks.json`, which would leak Claude hooks into Codex discovery. These controls do not describe Codex enforcement.

## `hooks/_role.sh`

Sourced by the role hooks (`block-publish`, `block-pattern-kill`, `block-stray-worktree`, `block-repo-format`, `block-disk-scan`, `block-role-write`); never registered and never run on its own. `sdlc_role <hook-input-json>` prints the caller's role, or nothing. The role is `SDLC_ROLE` when it is set (run.sh sets it per role process, fanout per lane driver). Otherwise it is the hook input's `agent_type` for an SDLC Lite sub-agent with the `sdlc-lite:` prefix and the level suffix removed (`sdlc-lite:builder-L3` is `builder`, `sdlc-lite:plan-reviewer-L1` is `plan-reviewer`, `sdlc-lite:solo-L2` is `solo`, and the deprecated 0.21.x one-letter solo names resolve the same way), because a sub-agent inherits its parent's environment and only the hook input (`agent_type`, and `agent_id` on a sub-agent call) tells it from the parent (probe P2, [sub-agent probes](../reports/2026-10-06-subagent-probes.md)). A bare `agent_type` counts only when it names a pipeline role. `conductor` and `messenger` are session agents, not roles, and `Explore`, `general-purpose`, and another plugin's agents have none, so an interactive conductor can still publish after approval. Precedence: when both exist the variable wins, so a sub-agent of a headless parent that exports `SDLC_ROLE` resolves to the parent's role, not its own type; the sub-agent's type decides only in a session with no `SDLC_ROLE` (the interactive conductor's case). A payload with no `agent_type` costs no `jq` call. `SDLC_READONLY_ROLES` in the same file lists the roles that never edit the project (`planner`, `verifier`, `plan-reviewer`, `researcher`, `architect`, `scout`, `archaeologist`, `filer`), the set run.sh disallows Edit, Write, and NotebookEdit for and `claude_roles.py` gives `disallowedTools`. `hook-selftest.sh` holds one table of resolver cases and, for each role hook, a sub-agent role input that still blocks (stderr names the role) beside inputs with no role, an interactive conductor, and a non-SDLC agent that pass.

## `hooks/block-publish.sh`

PreToolUse(Bash) hook. Inside a role run (a role from `_role.sh`: `SDLC_ROLE`, set by run.sh per role run and by fanout for lane drivers, else the sub-agent's `agent_type`) it blocks `git push`, `gh pr/issue` writes, `gh release`, mutating `gh api`, and package publishing. It matches after masking heredoc bodies, quoted string contents, and comments, so a command that only writes or quotes a publish phrase passes; a `$(...)` or backtick substitution inside double quotes or an unquoted heredoc stays scannable. It scans the raw text instead when a shell or evaluator (such as `bash`, `sh`, `eval`, `xargs` or `ssh`) is present as a command word, or when parsing fails (python3 missing, an unterminated quote or heredoc). It also scans the raw text on interpreter inline code: an interpreter (python, python3, node, perl, ruby, path-qualified too) as a command word with an inline-code flag (python `-c`; node `-e`, `-p`, `--eval`, `--print`; perl `-e`, `-E`; ruby `-e`), also when options taking a separate value word come before the flag (`python3 -X dev -c`, `node --require x -e`, `perl -I lib -e`), while `python3 script.py` keeps the masked scan. Your own session is not affected, so `/file` can publish after approval.

## `hooks/block-background.sh`

PreToolUse(Bash, Agent, Monitor) hook. In a headless session (`SDLC_ROLE` set by run.sh or fanout, or `SDLC_HEADLESS=1`) it denies any Bash call with `run_in_background: true` and any Agent call unless `run_in_background` is explicitly `false` (Agent runs in the background by default, so a missing field counts as background), and every Monitor call (Monitor only watches background work) (exit 2) and tells the model to run in the foreground with the Bash timeout at 600000 or more and never end the turn while it runs, because ending the turn ends the session and abandons the work. Convention: every headless launcher sets `SDLC_HEADLESS=1`; bench.sh and fanout do, and any other (a dogfood script) must set it itself. Interactive sessions are not affected. Its fixtures live in `scripts/hook-selftest.sh`; `scripts/hook-live-probe.sh` confirms the live Bash payload shape against a real session (opt-in, one model call), and `scripts/hook-live-probe.sh --agent` confirms that the subagent tool reaches PreToolUse as `Agent`, is denied without `run_in_background: false`, and runs with it (opt-in, two model calls); its offline selftest covers the Agent path too. `hook-selftest.sh` holds the Monitor fixtures (denied headless, passed interactive).

## `hooks/block-pattern-kill.sh`

PreToolUse(Bash) hook. Inside a role run (a role from `_role.sh`) it blocks killing by name pattern (`pkill` or `killall` in command position, `kill` fed by `pgrep` or `ps` (`kill $(pgrep ...)`, `kill $(ps ... | awk ...)`, `pgrep` or `ps` piped through `grep` and `awk` into `xargs kill`), and a kill word held in a shell variable (`p=pkill; $p x`, `k=killall; ${k} node`, also one assigned through a `$(...)` or backtick substitution, `p=$(command -v pkill); $p x`)) (exit 2), because a pattern also hits processes other sessions, lanes, or the user started; `kill <pid>`, `kill %1`, `kill $(cat pidfile)`, `echo $! | xargs kill`, a variable holding another command (`cmd=ls; $cmd -la`), and quoted mentions pass. It fails closed, scanning the raw text, on a heredoc, a shell or evaluator command word, an unterminated quote, or a missing python3. Builders stop only the PIDs they started and run formatters only on the files the step changed; `check.py` guards both phrases in `agents/builder.md`. Its fixtures live in `scripts/hook-selftest.sh`.

## `hooks/block-stray-worktree.sh`

PreToolUse(Bash) hook. Inside a role run (a role from `_role.sh`) it denies (exit 2) a worktree add with `-b`, `-B`, or `--orphan`, any worktree add without `--detach`/`-d` (because git can otherwise create a branch, a remote-only name becomes a tracking branch, or check one out), and any worktree add whose path is not under `$SDLC_TMP_WORKTREES`; a path with any other variable (`$d/x`), `~`, or a glob is denied because the hook reads the command text and cannot know its value, so write `$SDLC_TMP_WORKTREES/<name>` or a literal path under it (T-0267); the detached form with a path under the prefix passes, and nothing changes for a session with no role. A sub-agent role has no `SDLC_TMP_WORKTREES` in its environment, so for a role that came from `agent_type` (no `SDLC_ROLE`) and no prefix variable, the prefix is the git toplevel of the hook input's `cwd` plus `/.worktrees/tmp`, the parent of every dispatch tmp prefix (`.worktrees/tmp/<agent name>`); any detached path strictly under it passes, which is weaker than a per-run prefix because parallel sub-agents share the parent directory, and a `cwd` outside a git work tree leaves no prefix, so every add is denied. It fails closed, scanning the raw text, when the command cannot be parsed safely. fanout.py's own worktrees are untouched because they are not Bash tool calls, and run.sh's EXIT cleanup of the prefix stays. A worktree or branch made from inside a script or program a role runs, rather than through the Bash tool text the hook sees, bypasses this hook; run.sh reports any such stray at run end (see the `scripts/run.sh` bullet above). Its fixtures live in `scripts/hook-selftest.sh`.

## `hooks/block-repo-format.sh`

PreToolUse(Bash) hook. Only inside a builder run (the role from `_role.sh` is `builder`: `SDLC_ROLE=builder`, or a `sdlc-lite:builder-L<n>` sub-agent with no `SDLC_ROLE`; every other role and a session with no role pass) it denies (exit 2) a repo-wide formatter, `--fix` linter, or format script: a project format script (`npm`, `pnpm`, `yarn`, `bun run`, or `make` with a name such as `format`, `fmt`, `prettier`, `lint:fix`, or `fix`, bare `pnpm`/`yarn`/`bun <name>` too) and a formatter or fixer in write or fix mode (`prettier --write`, `eslint --fix`, `black`, `ruff format`, `ruff check --fix`, `gofmt -w`, `go fmt`, `cargo fmt`, `rustfmt`, `biome ... --write`, `dprint fmt`, `stylelint --fix`, `clang-format -i`) whose targets are missing, a directory, `.`, a glob, a trailing `/`, a `./...` pattern, or a `$` expansion. Explicit file paths pass (`prettier --write a.ts`, `npm run format -- a.ts`), as do check-only modes and quoted mentions; package.json and Makefiles are never read. It fails closed, scanning the raw text, on a heredoc, a shell or evaluator command word (so `bash -c 'npm run format'` is blocked), an unterminated quote, or a missing python3. Its fixtures live in `scripts/hook-selftest.sh`.

## `hooks/block-disk-scan.sh`

PreToolUse(Bash) hook. Inside a role run (a role from `_role.sh`) it denies (exit 2) a search of the whole filesystem or a home folder, because such a search can run for many minutes with no output and stall the run, and `| head` does not stop it when nothing matches. It blocks `find`, `bfs`, `fd`, `fdfind`, `rg`, `ag`, `grep` or `egrep` with `-r`/`-R`/`--recursive`, `du`, `ls -R`, and `tree` in command position (also behind `sudo`, `command`, `env`, `nohup`, `timeout N`, `xargs`, or a `VAR=value` assignment) when a path operand is exactly `/`, `/*`, `~`, `~/`, `$HOME`, `${HOME}`, `$HOME/`, `/Users`, `/home`, `/Volumes`, `/System`, `/Library`, `/private`, or a home folder itself (`/Users/<name>`, `/home/<name>`); a quoted `"$HOME"` still counts. For `grep`, `rg`, `ag`, and `fd` the first positional word is the pattern, not a path. A root search with `-maxdepth` is blocked too. Its stderr names the role and tells it to search a bounded path: the repository, a named subfolder such as `~/.claude/plugins`, or `$CLAUDE_PLUGIN_ROOT`. A path below those roots (`/tmp/x`, `~/.claude/plugins`, `"$HOME/.claude/plugins"`, `/Users/me/Projects/x`), `find .` and relative paths, `ls /` without `-R`, quoted mentions (`grep -n "find / -name x" f`), and any session with no role pass. It fails closed, scanning the raw text, on a heredoc, a shell or evaluator command word (so `bash -c "find / -name x"` is blocked), an unterminated quote, or a missing python3. It is a Claude hook only; Codex roles are not covered by it. Its fixtures live in `scripts/hook-selftest.sh`.

## `hooks/block-role-spawn.sh`

PreToolUse(Agent) hook, registered after `block-background.sh` under the `Agent` matcher. It is the spawn gate for a conductor session: the payload's `agent_type` is `sdlc-lite:conductor` or `conductor`, or `SDLC_ROLE=conductor` is set; every other session passes. There it allows an SDLC Lite role agent only as a prepared dispatch (`dispatch.py prepare` printed it), and denies (exit 2) the call unless all four conditions hold, each its own denial that says which failed and ends with the prepare step:

1. `subagent_type` is `sdlc-lite:<role>-L<n>`. A level-less role (`sdlc-lite:verifier`), the solo level definitions `sdlc-lite:solo-L1|L2|L3` (dispatched by T-0284; the deprecated 0.21.x one-letter solo names still pass for one release, T-0342, and any other solo name, such as `solo-L4`, is denied), `sdlc-lite:messenger`, `sdlc-lite:conductor`, an uppercase name, and a bare role name (`verifier-L3`) all fail here.
2. `name` is `<role>-L<n>-<slug>[-<k>]` with the same `<role>-L<n>` as the `subagent_type` and the characters of an agent name (`A-Z a-z 0-9 _ -`, a non-empty slug).
3. A dispatch record sits beside the handoff named by the prompt's `Handoff: <path>` line (a relative path resolves against the hook input's `cwd`): the file `<name>.dispatch.json`, or any `*.dispatch.json` in that directory whose `name` is the agent name. `dispatch.py prepare` writes the record under the result stem, `<role>-L<n>[-<k>].dispatch.json`, with the Agent name inside it, so the second form is the real one. A prompt with no `Handoff:` line has no record.
4. The call's `model` equals the record's `model`. Prepare chose that model (it keeps a verifier off the build's family and a plan-reviewer off the planner's), so a missing `model`, a different one, or a record with no `model` is denied; a hook can rewrite tool input (`updatedInput`, probe P2), but this one only denies, so the conductor sees the model it must pass.

A fork (`subagent_type: fork`) is denied outright when the name starts with `verifier-` or `plan-reviewer-`, because a fork inherits the parent's context and model and cannot be independent. Any other fork, named or not, needs a line starting `Fork reason:` followed by text anywhere in the prompt (an empty reason or the words inside a sentence do not count). Another plugin's agent whose name after the colon holds a `builder`, `verifier`, `reviewer`, `planner`, or `checker` token (split on `-` and `_`) stays denied with a stderr pointing at `${CLAUDE_PLUGIN_ROOT}/scripts/run.sh` or a prepared dispatch. Helpers pass: `Explore`, `general-purpose`, `Plan`, any other name without a plugin prefix, another plugin's agent without those tokens (such as `harness:fact-finder`), and a call with no `subagent_type`.

The old deny of every `sdlc-lite:` spawn is gone, in the same change as the gate. A `run.sh` call is a Bash call, so this hook never sees it and a conductor that still runs roles through `run.sh` is unaffected; `hook-selftest.sh` runs a `run.sh` Bash payload as a conductor and checks `hooks.json` registers the hook only under `Agent`. Its fixtures live in `scripts/hook-selftest.sh` (a payload that passes, then one deny per condition changing one thing, the fork cases, and non-conductor negative controls); `scripts/hook-live-probe.sh --conductor` runs two sessions as the plugin's conductor and confirms the live `agent_type` value, the deny of an unprepared `sdlc-lite:scout` spawn, and the allow (opt-in, two model calls), and its offline selftest covers the conductor path. The dated run is in [the agent spawn hook live run](../reports/agent-spawn-hook-live-run.md); it observed `agent_type` `sdlc-lite:conductor` for a session launched with `--agent sdlc-lite:conductor`, not for one declared through `.claude/settings.json`. The prepared-dispatch allow path is checked on fixture JSON, not in a live session. It is a Claude hook only; Codex conductor sessions are not enforced by it and have no equivalent control.

## `hooks/block-role-write.sh`

PreToolUse hook under the `Edit|Write|NotebookEdit` matcher, registered before `warn-handoff-edit.sh`. It acts only for a read-only role (`SDLC_READONLY_ROLES` in `_role.sh`, resolved as above), so the builder, `solo`, the conductor, other agents, and a session with no role pass untouched, as does any other tool. For a read-only role it denies (exit 2) Edit and NotebookEdit (the generated definitions already disallow them through `disallowedTools`; this holds if a definition is not honored) and any Write except to its dispatch result path. A Write passes only when `file_path` is absolute, ends in `.md`, and equals the `result` of the `<stem>.dispatch.json` beside it (`verifier-L3.md` pairs with `verifier-L3.dispatch.json`) whose `subagent_type` is this agent's `agent_type` or whose `role` is the resolved role. The path must match byte for byte, so a `..` spelling, a relative path, another stem, a record whose `result` is a different file, and the record file itself are all denied. The role writes its result there because `dispatch.py record` reads it (design: [sub-agent mode](../planning/sdlc-lite/subagent-mode.md) section 3). Permission modes are not a control (probe P1 observed a `permissionMode: plan` sub-agent writing a file under a bypassing parent), so this hook and `disallowedTools` carry the read-only rule. Its fixtures live in `scripts/hook-selftest.sh` (the allowed result path, a table of denied writes, and the unrestricted roles).

## `hooks/warn-handoff-edit.sh`

PreToolUse hook under the `Edit|Write|NotebookEdit` matcher (shared with `block-role-write.sh`), acting in any session (the user edits handoffs too). When the edited file is named `handoff.md` and a `<role>-<level>.running` file sits beside it, a role is reading that handoff now. Warn mode, the default (user decision 2026-10-04): the edit is allowed (exit 0), one stderr warning names the running role, and one line is appended to `stale-edits.log` beside the handoff. `SDLC_HANDOFF_EDIT_MODE=deny` turns the same case into exit 2. Any other file name, or a handoff with no `.running` beside it, passes silently and logs nothing. This is Claude Code only. Codex has no hooks, so there the only signal is the runner's: `run_lifecycle.py` stores the handoff's sha256 at launch (`handoff_sha256` in the attempt record and `SDLC_HANDOFF_SHA256` in the child's environment), and `run.sh` rehashes the handoff before writing the run line, which then carries `handoff_sha256` and `stale_input: true|false` and prints `run.sh: stale input: <handoff> changed while <role> ran`. The exit code is unchanged. Limit: this ticket (T-0212, built as one step) stops at the flag and the hook. The `rerun <level> stale input` action in `steps.py next`, `resume` and `review`, and excluding a stale planner result from `review_action`, `lean_warnings` and `footprint.py`, are not built; the flag is on the run line for a conductor or a later ticket to act on.

Use `bash plugins/sdlc-lite/scripts/hook-selftest.sh` and `bash plugins/sdlc-lite/scripts/hook-live-probe.sh --selftest` from the repository root for offline validation. Actual host payload changes also require the relevant opt-in live probe; it makes model calls. See the probe script usage for its Bash, Agent, and conductor modes.

Hook speed: keep a hook linear in command length. Do not use `${var//pattern/}` on the whole command (quadratic on bash 3.2 for a bracket class, and for a literal `\\` once the text holds many backslashes); use `tr`, `grep` or one python3 call. `hook-selftest.sh` runs a 20 KB heredoc case (with backslashes) under a 2 s timeout for the five Bash hooks that scan the command (disk-scan, pattern-kill, stray-worktree, publish, repo-format); see [hook perf](../reports/hook-perf.md).

Headless permission allowlist: a headless conductor (`claude -p`) has no one to approve a prompt, and a Bash command that starts with a variable assignment (`VAR=x python3 ...`) does not match `Bash(python3:*)`. The conductor therefore passes the routing reason as `dispatch.py prepare --routing-reason "<why>" ...` and starts every command with the program name. The entries it needs in `.claude/settings.json` `permissions.allow` are `Bash(python3:*)` (dispatch.py, tickets.py, steps.py, solo_run.py, results.py, budget.py), `Bash(git:*)`, `Bash(bash:*)` (run.sh and the selftests), and the `Agent` tool.
