# Builder overlay replay A/B (T-0442)

Question: do the builder L1 and L5 `## At this level` overlays (T-0441, commit `00735e20`) improve cost, first-pass rate, blocked rate or verifier minutes on a fixed task set, or should the idea be dropped?

Verdict: drop
L1 overlay: drop
L5 overlay: unverified
Null at this sample size: no
Spend: 7.94 USD

Result in one line: on 10 L1 builder runs (5 per arm) over 3 bench tasks, the overlay changed nothing measurable. No builder blocked in either arm, first-pass rate was identical per task, builder cost rose 3.3 percent. The L1 overlay is dropped by the design's first rule, because its blocked rate (0 of 5) is not below arm A's (0 of 5). L5 never ran: the first L5 pair's $8 estimate did not fit the $10 replay cap.

## Method

- Arm roots. This session ran as `SDLC_ROLE=conductor` with no `SDLC_TMP_WORKTREES`, and `hooks/block-stray-worktree.sh` denied the detached-worktree form for `armB` ("SDLC_TMP_WORKTREES is unset, so this session has no throwaway worktree prefix"). As the handoff notes direct, every arm root and cell tree is a `git clone --shared` copy, detached at the named sha, under the dispatch tmp prefix `.worktrees/tmp/0442-s2-builder-L3/` (git-ignored). The clones and the evidence folder were removed with the tmp prefix when `dispatch.py record` recorded the builder run, so the hidden_check and minutes columns cannot be re-observed and stand as recorded claims.
  - `armB`: `git clone --shared <this repo> armB && git -C armB checkout --detach 27130b4a5f929aee1447319a0359d85751bd3a98` (HEAD, overlays present).
  - `armA`: the same clone, then `git show 00735e20^:plugins/sdlc-lite/agents/builder-L1.md > armA/plugins/sdlc-lite/agents/builder-L1.md`, and the same for `builder-L5.md`.
  - `git diff --stat 00735e20^ HEAD -- plugins/sdlc-lite/agents/builder.md` is empty. The builder frontmatter holds only name, description, model and effort, so it preloads no skills.
  - `diff -rq armA/plugins armB/plugins` lists only `agents/builder-L1.md` and `agents/builder-L5.md`. `diff` of each shows one hunk, `34a35,55` (L1) and `34a35,52` (L5), and that hunk is the `## At this level` section.
- Preflight. Each arm ran `claude -p --plugin-dir <arm>/plugins/sdlc-lite --model haiku --output-format stream-json --verbose "ok"` (Claude Code 2.1.296). The init event's `plugins` list held exactly one `sdlc-lite` entry, source `sdlc-lite@inline`, path `.../0442-s2-builder-L3/armB/plugins/sdlc-lite` for armB and `.../0442-s2-builder-L3/armA/plugins/sdlc-lite` for armA. One more preflight, from inside the first cell tree (an agent-ui clone with its own `.claude/`) using armA, showed the single `sdlc-lite` entry at the armA path.
- Cell tree: `git clone --shared <task repo> ab-<task>-<level>-<arm>-<rep> && git -C <cell> checkout --detach <base>`, then the task's `setup` (`npm ci`). The archived `bench/results/2026-09-27-<task>/step-1/handoff.md` was copied to `<cell>/.sdlc/ab-<task>/step-1/handoff.md`, unchanged. `prepare` pointed the Tree line at the cell itself.
- Builder: from the cell, `python3 armB/plugins/sdlc-lite/scripts/dispatch.py prepare builder L1 .sdlc/ab-<task>/step-1/handoff.md --routing-reason "T-0442 overlay A/B arm <A|B>"` (sonnet low every time), then `SDLC_HEADLESS=1 SDLC_ROLE=builder SDLC_TMP_WORKTREES=<dispatch tmp_prefix> claude -p --plugin-dir <arm>/plugins/sdlc-lite --agent sdlc-lite:builder-L1 --model sonnet --effort low --dangerously-skip-permissions --output-format json "<dispatch prompt>"`.
  - `FANOUT_ROOT`, `FANOUT_HANDOFF`, `FANOUT_PLUGIN_ROOT` and `CLAUDE_CODE_AGENT` were removed from the child environment so the cell session was not seen as part of this lane. Both arms got the same environment.
  - `SDLC_TMP_WORKTREES` was set to the prefix `prepare` printed, as `run.sh` does.
  - The JSON `result` was written to the dispatch's result path. Then `dispatch.py record <dispatch.json> --transcript ~/.claude/projects/*/<session_id>.jsonl --duration-ms <duration_ms>` ran, and all 20 records exited 0 with a priced row.
- Verifier: after the builder record, `prepare verifier L1` ran the same way with the armB root for both arms. It printed opus medium every time, the family remap after a sonnet builder. One verifier per cell, and no rebuild, bump or retry.
- Grade: after the verifier, each `test_paths` file was copied from `tests_from` (`git -C <repo> show <tests_from>:<path> > <path>`) and the task's `check` was run (bench skill step 4). `command-modal-footer` has a 4-step archived plan, so its step-1 replay is not graded, `hidden_check: n/a`, and first pass is the verifier verdict.
- Gates: no `prepare` refused. Every dispatch shows `lane_override: ""` and `specgate: ""`, and no prepare wrote to stderr.
- Order and budget: L1 rep 1 ran A then B for each task, and rep 2 ran B then A, in the order `subagent-tool-names`, `figma-stale-skip-report`, `command-modal-footer`. Before each pair the estimate was twice the costliest same-level builder plus verifier seen so far, or 2 x (0.46 + 0.57) = 2.06 from the archived costs for the first pair, or $8 for the first L5 pair.
