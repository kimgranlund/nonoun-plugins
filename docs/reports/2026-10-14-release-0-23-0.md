## Upgrade notes

1. Adopt 0.23.0 and run `/reload-plugins`. A Codex repository regenerates its agents with `codex_roles.py install`.
2. In each consumer repo, from its main checkout root, run `plugins/sdlc-lite/scripts/migrate-0.23.sh` (the installed plugin's copy) once as a dry run, read the planned moves, then run it again with `--apply`. It ignores `.claude/worktrees/`, moves landed `.worktrees/` lanes there with `git worktree move`, skips and reports locked, dirty, live or unlanded ones, and runs `tickets.py tidy`. Rerun it after a skipped lane lands.
3. Open tickets started before 0.23.0 finish where they started and close with an Outcome; closed ticket folders are untouched. `.sdlc/runtime/` ignores itself, so no `.gitignore` edit is needed for records.
4. Close: `tickets.py close <folder> --changed "<one line>"` is the default route. It needs a passing verifier result, or a recorded skip, or `--reason`. Use `--filer` only after `/file`.
5. New gates stop for a person: the replan cap (a third planner run), the step cap (L1 and L2 3 steps, L3 6, L4 10, L5 15), and the role and ticket time budgets. Each lets one run through with `--approved "<who: why>"`; headless lanes stop as `blocked`.
6. Builders run scoped checks; a heavy check inside a lane runs through `gate_lock.py`, as fanout `--gate` commands do.
7. Tickets gain optional `worktree:` and `branch:` fields, written by `lanes.py open --ticket <id>` and removed by `lanes.py close`; a hand-made worktree uses `tickets.py branch <id> <branch> --worktree <path>`.
8. `bash plugins/sdlc-lite/scripts/check.sh --fast` is the quick tier for builders and CI; the full `check.sh` stays the land gate.
9. CI runs only on `v*` tags and manual dispatch, never on every push or pull request.
