# Release 0.33.0 (2026-10-22)

Three CPU diagnostics from a second 18-core, 64 GB fleet machine (Claude and Codex, 2026-10-22) found one `node --test --test-concurrency=3` worker in ultimate-tokens at 13 to 18 GB resident and 280 to 338% CPU within 2 minutes, launched through the gate queue. The worker cap held; nothing bounded memory. T-0716 adds a memory watchdog to `gate_lock.py run`. Changes are listed in [CHANGELOG.md](../../CHANGELOG.md).

## Upgrade notes

1. Install 0.33.0, then `/reload-plugins`.
2. A gate whose process tree passes 25% of RAM (16 GB on a 64 GB machine) now stops with exit 137 and a `stopped ... over max_rss_mb` line. Raise it with `gate_lock.py policy set max_rss_mb=N`, or turn it off with `0`.
