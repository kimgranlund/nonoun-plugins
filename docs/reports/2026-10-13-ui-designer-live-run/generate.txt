## Decisions
- Built from the plan at .sdlc/plan/ui-designer-L2.md with one correction, listed below: the plan covers this exact goal and its DOM and CSS held up against the tree.
- Correction to the plan: `.summary-action` uses `padding-block` and `padding-inline`, not the physical `padding` shorthand the plan wrote. The file's convention is logical properties (styles.css:16, styles.css:34).
- The section is the last child of `.top`, after `.list` (index.html:29-49): it follows the products in reading and tab order, and it is not a product, so it stays out of the grid.
- Root is `<section class="card summary" aria-labelledby="summary-title">`: a named section is a region landmark. `section` over `aside` because the order is part of the page's main task.
- Root reuses `.card` (styles.css:25-30) for padding, border, radius, and background: one surface definition. `.summary` adds layout only.
- Heading is an `h2`: it names the landmark. The page has no `h1` yet, because `.title` is a div (index.html:11). Fixing that is outside this goal, so the outline starts at level 2 until it is fixed.
- Items are a `ul` with `role="list"`: a list announces its count, and `list-style: none` drops list semantics in Safari with VoiceOver unless the role is set.
- Each row has a name, a quantity as visible text ("Qty 1"), and a line total: one product can be added twice, and plain text needs no ARIA. Quantity is display only, because steppers are not in the goal.
- Subtotal is a `p` with `role="status"`: a polite live region, so a cart change is announced while focus stays on the product. It stays rendered when the order is empty, because a live region must exist before its first change.
- Checkout is `<button type="button">`: a deviation from the page's `div` plus `onclick` actions (index.html:16). A button brings focus, Enter and Space, the role, and native `disabled`. Button over link because the tree has no checkout URL.
- The empty state is derived with `:has()` from the rows, with no state class: the rows are the single source of truth. `hidden` on the list would lose to the author `display: grid`.
- The static markup ships the populated state with two sample rows ($24 + $14 = $38): the tree has no script, so an empty list could not show the items the goal asks for.
- Colors come from tokens only. The button uses `var(--color-accent)`, not the hex that styles.css:41 hardcodes.
- Hover is `color-mix()` of the accent and text tokens, and disabled is `--color-border` behind `--color-muted`: tokens.css has no state colors, and no token was added because tokens.css is not in the handoff's files.
- Deviations with no token to use: `1.25rem` and `font-weight: 600` (no type tokens), `1px` and `2px` (no border-width token), `28rem` (no size token). Each matches a literal already in styles.css or sits one step from it.
- The button fills the panel's inline size: it is the single final action. A deviation from the content-sized `.card-action` (styles.css:37-44).
- Rows share one grid through `subgrid`, and amounts use `tabular-nums` with `text-align: end`: quantity and total line up across rows on content-sized tracks, with no fixed widths.
- All rules sit in `@layer components`, one flat `summary-*` class per selector, after the `card-*` rules: no specificity fight with existing rules. `:disabled` is written after `:hover` so source order stops a disabled button from showing hover.
- Not built: loading, selected, and invalid states. The tree has no async call, no selection, and no input.
- Not checked in a browser: the tree has no dev server or test. The checks run were brace balance on styles.css (23 and 23) and a read of the diff.
