# Release 0.20.7

Recorded: 2026-10-05 (UTC; the work and live runs were on 2026-10-04 local time). SDLC Lite 0.20.7. Progressive Context stays at 0.1.2 (no change since 0.19.0). Previous release: SDLC Lite 0.20.6 (54f1c75, tag `v0.20.6`). Built from main commit 6c94302; the release branch merges that commit and adds the version bump, this record and a few small text fixes made after the fact-check passes (one wording line in `skills/agent/SKILL.md`; in the live-run records the counted-spend total, a stale sentence, the attempt-id limit sentence in `solo-cost-live-run.md` and the hidden-check list wording in `agent-command-live-run.md`; and the README link), and the release commit is the one tagged `v0.20.7`.

## What changed for consumers

This release completes the default lane: a ticket the conductor starts as `solo` closes under the skips guard, the solo session's cost is written to the run records when it is started through the new wrapper, so the budget and the board meter the default lane (Claude fanout solo lanes, and the conductor path when it follows `agents/solo.md`; the conductor session of a full or lean fanout lane is not recorded (the roles it starts record themselves), a Codex lane records null cost, and `--driver CMD` bypasses the wrapper; see Known limits), and one command launches an SDLC Lite agent by name. The first two close limits the 0.20.6 record listed.

## Upgrade notes

- Codex projects that installed generated agents need `python3 plugins/sdlc-lite/scripts/codex_roles.py install <project>`: the generated `sdlc-conductor-l1` and `sdlc-solo-l1` to `sdlc-solo-l3` agents changed (the conductor and solo bodies changed). `generate --check` passes on the release branch.
- New command `/sdlc-lite:agent` (see the table). Reload plugins to see it. It needs no settings change.
- Start solo through the wrapper to have its cost counted: `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/solo_run.py" run --task-dir <ticket folder> --tier <S|M|L> --brief "<typed brief>"` (the command `agents/solo.md` now gives). The raw `claude -p --agent sdlc-lite:solo` command still works and records nothing. A repository's own older notes that show the raw command are not updated by this release.
- A conductor-started solo ticket closes by reason with no extra step, provided `steps.py lane` ran for the task (it writes the lane line and, for `solo`, the Skipped entries). A ticket with no lane record is unaffected by the guard, as before.
- `budget.py` totals can rise for a ticket that has `role solo` records, since those records carry cost. A Codex solo started through `solo_run.py` (a fanout Codex lane, or a manual `--backend codex` call) records `cost_usd` null with the reason `codex reports no cost`, and the budget shows it as an unmetered run. `agents/solo.md` has a Codex conductor start `sdlc-solo-l1` to `l3` through the existing Codex role path, not the wrapper, and nothing in this release shows that path writes a `role solo` record, so the Codex conductor path is not metered.
- `check.py` guards now run 1 to 27 once each: guards 1 to 24 keep their numbers and this release adds 25 (agent command), 26 (solo lane skips) and 27 (solo cost capture); guard 23 rejects a duplicate number.
- No migration is needed and `tickets.py roadmap` is unchanged.

## Known limits

- How far the evidence supports "solo is the default and its cost is metered": the default lane is solo for size S and M (`steps.py lane` since 0.20.4, routing texts aligned in 0.20.5), a conductor-started solo ticket delivered and closed with the guard live in one run (T-0224: one tiny size M ticket, hidden check 9 of 9, 5 minutes 34 seconds, conductor $0.20 and verifier $3.09, the solo session's own cost not captured in that run because it predates the wrapper), and one real solo session started through the wrapper wrote a record whose cost equals the session's own result event (T-0225: size S, tier S, one run, 18 seconds, `cost_usd` 0.1315212, hidden check 3 of 3, `budget.py` and the board counted it). That is a single run on a tiny ticket per claim, on Claude Code. Metering of fanout lanes (T-0226) rests on a selftest with a stub `claude` and a mutant, not on a live fanout run with a real model. The conductor path is metered only when the conductor starts solo through the wrapper, which `agents/solo.md` now tells it to do; no live conductor run has used the wrapper yet.
- T-0224's live run: one run, one machine, Claude Code only, plugin from the `solo-skips` worktree (0.20.6 manifests plus the T-0224 change). The conductor started the solo from Bash itself with the tier M flags it read in `agents/solo.md`, not through a script. The selftest negative control (steps selftest, `(lane solo close)`) is what shows the guard still refuses without the entries.
- T-0223's live run: one run per arm on a tiny fixture, headless and in the foreground; about $3.74 of counted spend, of which $3.03 is the solo's verifier, and the solo session's own cost was not captured. Only `solo` and `scout` were launched; `researcher`, `architect` and `archaeologist` share the scout path but were not run. The outer sessions were plain sessions, not conductor sessions, so the rule that a conductor starts agents from Bash was not exercised and `block-role-spawn.sh` was not triggered. The interactive background launch of `/agent` was not tried.
- T-0225's live run: one arm, tier S only, no tier M or L run, no Codex run (`codex_exec.py` reports no cost, so a Codex solo is unmetered by design). The live run ran before the inherited-attempt-id fix, so it did not exercise that path; the selftest runs with both variables set and asserts the fix holds. The first branch verifier saw the defect fail the selftest and `check.sh` in the real branch tree, and the narrow verifier saw the selftest fail again with the defect restored in a throwaway copy; there is no separately labelled negative-control case. The budget meter still covers Claude roles only.
- T-0225 closed with no overall independent `pass`, although its own Done-when lists a passing independent L3 verifier as a condition: the narrow re-verification failed only on a defective criterion of its own (see above) and no third pass was run. Its `## Closed` text is stale on one point: it says fanout solo lanes were "not metered yet" (T-0226 meters them). The narrow re-verification's criterion 4 was rescoped and run by hand; that is recorded in the ticket's `## Closed` text and the message of commit 71051cf, and the only output of the rescoped command is the verifier's own criterion 4 entry.
- No Codex lane was run under fanout and no Codex conductor start of solo (carried over from 0.20.6 and 0.20.5); `/agent` is new in this release and was not run on Codex. The Codex solo did not launch its own verifier (0.20.5 limit, unchanged).
- T-0221 still has no passing whole-branch verifier of its own; the T-0222 verifier passed (carried over). The overlap refusal reads `step-<n>/handoff.md` only, so it cannot fire for a default-lane solo ticket (carried over). Also carried over from 0.20.6: the full-chain branch was never run under fanout; no lane count above four, no size L lane and no merge-time overlap case were run live; the lane cap counts regular lanes only; the 20 second `--stagger` default was never exercised live (the live runs used 3 seconds); a multi-ticket lane close is covered by a selftest with a stub, not a live lane; `--dry-run` with an overlap prints the refusal and exits 0.
- The 0.20.6 benchmark caveats stand: n=3, one run per cell, not blind to the author, tasks chosen from this repository's own closed tickets, `drive.log` and `drive2.log` per lean cell not committed, solo had no independent verifier, the lean arm used a minimal chain driver, no size S or L task, no Codex arm, and the solo arm was plain `claude -p --model opus --effort high` and not `sdlc-lite:solo` at the tier models.
- `steps.write_solo_skips` honours `SDLC_SELFTEST_NO_SKIPPED=1` for any caller, including a conductor's `steps.py lane` (it was `FANOUT_SELFTEST_NO_SKIPPED` in `fanout.py` in 0.20.6, whose record still uses the old name).
- `skills/fanout/SKILL.md` was not changed in this release: its solo-lane line still shows the raw `claude -p` start with no mention of `solo_run.py` or metering, and it still asks for the batched verifier only at size M although the code requires it for M and L (a 0.20.6 limit).
- Ticket T-0228 ships in this tree as `proposed`: `onboard.py setup` still writes a consumer root `AGENTS.md` block that routes work to `/sdlc-lite:chain`, `/fix` and `/build` and not to solo, which contradicts the lane rule this release headlines. T-0227 (orient) is on an unmerged branch and is not in this release. The `write_solo_skips` docstring in `fanout.py` says it is "called again here for the tier-sized reason", which does nothing on the automatic path (the T-0224 verifier showed this; unfixed).
- Metering happens only after a solo session ends. Neither `solo_run.py` nor `fanout.py` runs `budget.py status` before starting one, so a ticket already over its budget still starts solo, and the 80 percent stop applies to `run.sh` roles only (`budget.py` header: "run.sh calls status before launching a role and exits 4 on exit 3"). Ticket T-0229 (proposed, filed on main after this release) is for the fix; nothing is fixed yet. Also, the conductor session of a full or lean fanout lane, and any `--driver CMD` lane, is not recorded by the wrapper (the roles a conductor starts through `run.sh` do record themselves).
- `/agent solo` with no named ticket cannot use the wrapper (`solo_run.py` refuses a task dir with no `handoff.md`) and is unmetered; also T-0229.
- Details of the solo record: a solo session that ends with no result event (for example a crash) records `cost_usd` null with `cost_reason` `no result event` (a Codex session records `codex reports no cost` instead), `solo_run.py run --brief -` reads the brief from stdin, and the `role solo` record carries `file` empty.
- Still true from earlier records: `shellcheck` is not installed, so no shell script or hook is shellchecked (`check.sh` skips it), and the budget stop at 80 percent is exercised only by selftests with a stub `claude`.
- The parked tickets are not in this release: replan by delta (T-0200, T-0201, T-0213), the spec gate's second half (T-0211), the folder-layout migration (T-0205 to T-0208) and the board overview (T-0187).
