# Release 0.20.7

Recorded: 2026-10-05 (UTC; the work and live runs were on 2026-10-04 local time). SDLC Lite 0.20.7. Progressive Context stays at 0.1.2 (no change since 0.19.0). Previous release: SDLC Lite 0.20.6 (54f1c75, tag `v0.20.6`). Built from main commit 6c94302; the release branch merges that commit and adds the version bump and this record, and the release commit is the one tagged `v0.20.7`.

## What changed for consumers

This release completes the default lane: a ticket the conductor starts as `solo` closes under the skips guard, the solo session's cost is written to the run records so the budget and the board meter the default lane (conductor path and fanout lanes), and one command launches an SDLC Lite agent by name. The first two close limits the 0.20.6 record listed.

## Upgrade notes

- Codex users need `python3 plugins/sdlc-lite/scripts/codex_roles.py install <project>`: the generated `sdlc-conductor-l1` and `sdlc-solo-l1` to `sdlc-solo-l3` agents changed (the conductor and solo bodies changed). `generate --check` passes on the release branch.
- New command `/sdlc-lite:agent` (see the table). Reload plugins to see it. It needs no settings change.
- Start solo through the wrapper to have its cost counted: `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/solo_run.py" run --task-dir <ticket folder> --tier <S|M|L> --brief "<typed brief>"` (the command `agents/solo.md` now gives). The raw `claude -p --agent sdlc-lite:solo` command still works and records nothing. A repository's own older notes that show the raw command are not updated by this release.
- A conductor-started solo ticket closes by reason with no extra step, provided `steps.py lane` ran for the task (it writes the lane line and, for `solo`, the Skipped entries). A ticket with no lane record is unaffected by the guard, as before.
- `budget.py` totals can rise for a ticket that has `role solo` records, since those records carry cost. A Codex solo records `cost_usd` null with the reason `codex reports no cost`, and the budget shows it as an unmetered run.
- `check.py` guards now run 1 to 27 once each (25 agent command, 26 solo lane skips, 27 solo cost capture; guard 23 rejects a duplicate number). Anything outside this repository that cites a guard by number needs the new numbers.
- No migration is needed and `tickets.py roadmap` is unchanged.

## Known limits

- How far the evidence supports "solo is the default and its cost is metered": the default lane is solo for size S and M (0.20.5, `steps.py lane`), a conductor-started solo ticket delivered and closed with the guard live in one run (T-0224: one tiny size M ticket, hidden check 9 of 9, 5 minutes 34 seconds, conductor $0.20 and verifier $3.09, the solo session's own cost not captured in that run because it predates the wrapper), and one real solo session started through the wrapper wrote a record whose cost equals the session's own result event (T-0225: size S, tier S, one run, 18 seconds, `cost_usd` 0.1315212, hidden check 3 of 3, `budget.py` and the board counted it). That is a single run on a tiny ticket per claim, on Claude Code. Metering of fanout lanes (T-0226) rests on a selftest with a stub `claude` and a mutant, not on a live fanout run with a real model. The conductor path is metered only when the conductor starts solo through the wrapper, which `agents/solo.md` now tells it to do; no live conductor run has used the wrapper yet.
- T-0224's live run: one run, one machine, Claude Code only, plugin from the `solo-skips` worktree (0.20.6 manifests plus the T-0224 change). The conductor started the solo from Bash itself with the tier M flags it read in `agents/solo.md`, not through a script. The selftest negative control (steps selftest, `(lane solo close)`) is what shows the guard still refuses without the entries.
- T-0223's live run: one run per arm on a tiny fixture, headless and in the foreground; about $3.6 of counted spend, of which $3.03 is the solo's verifier, and the solo session's own cost was not captured. Only `solo` and `scout` were launched; `researcher`, `architect` and `archaeologist` share the scout path but were not run. The outer sessions were plain sessions, not conductor sessions, so the rule that a conductor starts agents from Bash was not exercised and `block-role-spawn.sh` was not triggered. The interactive background launch of `/agent` was not tried.
- T-0225's live run: one arm, tier S only, no tier M or L run, no Codex run (`codex_exec.py` reports no cost, so a Codex solo is unmetered by design). The live run ran before the inherited-attempt-id fix, so it did not exercise that path; the selftest runs with both variables set and has a negative control. The budget meter still covers Claude roles only.
- T-0225 has no verifier whose overall verdict is `pass` (see above): the narrow re-verification failed only on a defective criterion of its own, and no third pass was run.
- No Codex lane was run under fanout, no `/agent` run on Codex, and no Codex conductor start of solo (carried over from 0.20.6 and 0.20.5).
- T-0221 still has no passing whole-branch verifier of its own; the T-0222 verifier passed (carried over). The overlap refusal reads `step-<n>/handoff.md` only, so it cannot fire for a default-lane solo ticket (carried over).
- The 0.20.6 benchmark caveats stand: n=3, one run per cell, not blind to the author, solo had no independent verifier, the lean arm used a minimal chain driver, no size S or L task, no Codex arm, and the solo arm was plain `claude -p --model opus --effort high` and not `sdlc-lite:solo` at the tier models.
- Still true from earlier records: `shellcheck` is not installed, so `run.sh` and `run-selftest.sh` are not shellchecked, and the budget stop at 80 percent is exercised only by selftests with a stub `claude`.
- The parked tickets are not in this release: replan by delta (T-0200, T-0201, T-0213), the spec gate's second half (T-0211), the folder-layout migration (T-0205 to T-0208) and the board overview (T-0187). Tickets filed after 6c94302 (T-0227, T-0228) are not in this release.
