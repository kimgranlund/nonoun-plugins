# Release 0.20.6

Recorded: 2026-10-05 (UTC; the fanout live run was on 2026-10-04 local time). SDLC Lite 0.20.6. Progressive Context stays at 0.1.2 (no change since 0.19.0). Previous release: SDLC Lite 0.20.5 (244d0af, tag `v0.20.5`). Built from main commit 51df377; the release branch merges that commit and adds the version bump and this record, and the release commit is the one tagged `v0.20.6`.

## What changed for consumers

This release makes `fanout` follow the same solo-first rule as the conductor, closes three small limits the 0.20.5 record listed, and adds the benchmark record behind the default. A first release candidate built from 01559a6 was held back because this record's fact-check found that fanout's solo close was refused by the new skips guard; T-0222 fixed that and this release is cut from the fixed commit. Fanout is the only change that alters what a command does: a run that used to send every ticket through the full chain now starts `solo` for size S and M. The guard renumbering and the skips guard change affect maintainers and `tickets.py check`. The benchmark and live-run records are evidence only.

## Upgrade notes

- Behavior change in `/sdlc-lite:fanout`: lanes for size S and M tickets now start `solo` instead of a conductor running the full chain. Pass `--lane full` to restore the chain for a run. There is no setting that restores the old default for every run.
- Lane count and pacing: a run holds at most 4 lanes and starts them 20 seconds apart. Raise the cap with `--max-lanes N` (above 16 also needs `--yes-many`) and change the pacing with `--stagger SECS`. These defaults were chosen, not measured. The real limits are the plan's rate limit and merge conflicts on shared files, not the machine.
- A size M or L solo ticket needs a passing batched verifier result before its fanout merge; fanout runs one verifier if the solo did not.
- Two tickets in different lanes whose planned scope overlaps are refused at preflight unless `--allow-overlap`.
- Codex: no generated Codex agent changed between `v0.20.5` and this release, so `codex_roles.py install` is not needed for this release.
- `check.py` guard numbers changed (see the table). Anything outside this repository that cites a guard by number needs the new number.
- `tickets.py check` can now fail a done ticket, and `tickets.py close` refuses to close one, whose skips record names lane `solo` or `full` and lacks the required result or `## Skipped` entry. Fanout writes the solo planner and filer entries itself; nothing else does (see Known limits). A ticket with no `skips.md` or no lane record is unaffected.
- No migration is needed and `tickets.py roadmap` is unchanged.

## Known limits

- How far the evidence supports "solo-first is the default for fanout": the benchmark (n=3, one run per cell) shows a solo session matched the chain on pass rate at about a tenth of the cost and about a seventh of the time on three small size M tickets from this repository, and the fanout live run shows four disjoint tiny tickets going through four solo lanes and merging. Together that supports the default for small, disjoint tickets on Claude Code and no further.
- Fanout live run (T-0221, first run, before the T-0222 fix): one run of four tiny tickets (three size S, one size M) on one machine, 5 minutes 43 seconds end to end, hidden check 24 of 24. The lanes started 3 seconds apart; the record says the run set `--stagger 3`, a test setting (the file creation times fit it, the committed logs do not show the command), so the 20 second default was not exercised live. The solo sessions ran on `claude-sonnet-5-5` and the size M ticket's independent verifier on `claude-fable-5-1` (a different family). The $3.13 in the record is the verifier only: the solo sessions' own cost was not captured, so the run has no total cost. No more than four lanes were tried and the tickets were disjoint by construction, so merge-time overlap handling, a lane count above four and a size L ticket were not run live (the selftest covers the overlap refusal and the cap). The full-chain branch was never run under fanout: the selftest checks only the lane decision, and no fanout run launched a conductor. The record's recommended lane count for the plan is 4, to be raised only after watching limit use and merge conflicts.
- No Codex lane was run under fanout, in either run: `codex_exec.py solo` is built and selftested, not exercised live.
- Verification gap on T-0221 (above): no passing whole-branch verifier for T-0221 itself; the T-0222 verifier passed.
- The first fanout release candidate was held back: this record's fact-check found that fanout's solo close was refused by the T-0219 skips guard (`merged, close refused` for every auto-lane solo ticket). T-0222 fixed it by writing the planner and filer `## Skipped` entries when a solo lane starts, before the close, and left the guard unchanged. Selftest case 16 covers a multi-ticket lane with the real `steps.py lane`, driver choice and `tickets.py close` (a `claude` shim stands in only for the model), with a negative control. A live rerun of the same fixture (four lanes, three size S and one size M, `--stagger 3`) merged and closed all four tickets in 4 minutes 27 seconds with `hidden_check: 24/24 passed` (the record says the rerun used `--stagger 3`; the committed files show the 3 second spacing but not the command, and they do not name the plugin commit, which was `1c7a016` or its working tree), and an independent L3 Fable verifier passed 7 of 7 (`docs/validation/fanout-solo-live-run.md`, addendum, evidence in `docs/validation/fanout-solo-live-run/rerun-t0222/`). The rerun's solo sessions ran on `claude-sonnet-5-5`; the size M verifier cost $2.20 on `claude-fable-5-1`, and the solo sessions' own cost was not captured. The multi-ticket close is covered by the selftest and not by a live multi-ticket lane.
- Conductor-started solo (not fanout): `write_solo_skips` is called only from `fanout.py`. `agents/solo.md`, `agents/conductor.md`, the skills and `steps.py` do not write the solo planner and filer `## Skipped` entries, and the only instruction is `conductor.md`'s "Record every skip in the task's `skips.md`". A solo ticket the conductor started after `steps.py lane` wrote its lane line is therefore refused at `tickets.py close --reason` unless the conductor writes those two lines first. This release did not change that path and no run exercised it.
- `.sdlc/.0222-fanout-solo-skipped/handoff.md` is still the unfilled bug template (the T-0222 verifier noted it).
- The overlap refusal reads `step-<n>/handoff.md` only, so it cannot fire for a default-lane solo ticket, which has no step folders (merge-time overlap handling still serializes the merges); the live report shows `Overlap: none`. The cap counts regular lanes only, not external lanes. A `--dry-run` prints that the run refuses unless `--allow-overlap` and exits 0.
- `skills/fanout/SKILL.md` now says a good first run is up to 4 lanes (the default cap) of tickets that touch different files. It asks for the batched verifier only for a size M ticket although the code requires it for M and L.
- The benchmark's solo arm was a plain `claude -p --model opus --effort high` session with no sdlc-lite roles, not `sdlc-lite:solo` at the tier models fanout launches, so the benchmark supports the idea of a single session more than this exact configuration. The record's Evidence section also cites `drive.log` and `drive2.log` per lean cell, which are not in the committed folder.
- Benchmark caveats (from the record): one run per cell; not blind to the author; tasks chosen from this repository's own closed tickets; solo has no independent verifier, so a wrong change that passes the hidden check would go undetected; the lean arm used a minimal chain driver and not the released lean lane, so its overhead is an upper bound; no size S or size L task; no Codex arm.
- Solo evidence from 0.20.5 is unchanged: one trial per arm on one machine, the Codex solo did not launch its own verifier, and the Codex conductor start path was not run.
- The plugin under test in the fanout live run was the `fanout-solo` worktree (0.20.5 manifests) at commit adb9789 (8e6d835 only adds the run record), which does not contain T-0218 to T-0220.
- Still true from the 0.20.5 record: `shellcheck` is not installed, so `run.sh` and `run-selftest.sh` are not shellchecked; the budget stop at 80 percent is exercised only by selftests with a stub `claude`; and spend counts Claude `run.sh` roles only.
- The parked tickets are not in this release: replan by delta (T-0200, T-0201, T-0213), the spec gate's second half (T-0211), the folder-layout migration (T-0205 to T-0208) and the board overview (T-0187).
