# Release 0.20.4

Recorded: 2026-10-04. SDLC Lite 0.20.4. Progressive Context stays at 0.1.2 (no change since 0.19.0). Previous release: SDLC Lite 0.20.3 (82a6a54, tag `v0.20.3`). Released from commit 0d85f47 on main.

## What changed for consumers

The lane script, the spec gate, the runner rule and the conductor's lane choice (which makes `solo` the default for size S and M) act on any repository that runs the pipeline. The supervisor, the evals lock and proposals are opt-in or maintainer-facing.

| Change | Detail | Ticket |
| --- | --- | --- |
| Lane per ticket | `scripts/steps.py lane <task dir>` prints the lane first (`solo`, `lean`, or `full`; it never prints `fix`), then one `reason:` line per deciding fact, and appends each result to the task's `skips.md` (a lane never returns from `full`). Before planning, size decides: S or M gives `solo`, L or XL gives `full`. After planning, the lane is `lean` only when every lean condition holds, else `full`, and never `solo`. The `sdlc-lite` skill says to run it before work on a ticket and follow the first line, and `skills/chain/SKILL.md` describes what the script now computes | T-0197 |
| Skips guard | `tickets.py check` and `close` fail a done ticket whose `skips.md` records lane `lean` or `fix` but lacks a `## Skipped` entry for a role the full chain would have run. Any missing planner, verifier or filer result is accepted when a `- skip:` line covers it with `reason:` and `decided:` filled in (a verifier skip also needs `step: <n>` or `all`). A ticket with no `skips.md`, or no lane record, is exempt | T-0198 |
| Verifier family rule at the task dir | A verifier launched at the task directory (no builder result in its own handoff dir) now takes the newest builder result of the highest-numbered live `step-<n>/` (not `step-<n>.superseded-<k>/`), so the family-independence rule fires. `run.sh` and `codex_roles.py resolve` apply the same rule | T-0195 |
| Batched verification state | `steps.py next` calls a step done through a task-dir verifier whose `## Verified` section lists the step's newest build with Verdict `pass`, only for builds that qualify (the rule is `steps.batch_verified`). `board.py` renders it as `pass · builder <level> · batch verifier <level>` | T-0196 |
| Carry forward | `scout`, `researcher`, `architect` and `archaeologist` results end with a `## Carry forward` section (at most 15 lines, each with a path:line or source); the planner reads it first and searches only what it does not answer. `check.py` requires the section in the four producing agent files, and the planner and builder read it first (`results.py` does not require it in a result) | T-0202 |
| Fanout | `fanout.py --dry-run` prints a planned-scope overlap report (`overlap (planned scope): ...`) from each ticket's step scope allow-lists; a real run waits before a ticket's merge while that ticket's actual changed paths (`git diff --name-only <integration>...<ref>`) overlap an earlier unfinished lane's pending paths; lane tickets resolve through `tickets.ticket_dir(root)`, so `ticket_root: tickets` works | T-0203, T-0204 |
| Idle-host watcher | `scripts/supervisor.py` (`init`, `watch [--run] [--once]`, `status`, `reset`, `selftest`) is deterministic code with no model call. It polls the mailbox through `messages.py` functions, never claims, moves or reads a message body, and when mail waits for a configured receiver starts a headless host session for it. Default wake mode is a fresh ephemeral session per wake; attached and notify are opt-in. It is a dry run unless `--run`, and a wake follows unattended-run rules (`SDLC_HEADLESS=1`, never push or publish). Limits (cooldown, wakes per hour and per day, timeout, reply depth, failures) are in `limits.json` | T-0183 |
| Evals and the model-table lock | `scripts/evals.py` records model and effort experiments in `.sdlc/evals/` and a lock (`table-lock.json`) that ties the `run.sh` and `models.json` table to one eval. `check.py` fails when a model-table change has no new eval and lock. This is a maintainer rule for this repository's plugin, and no default changed | T-0185 |
| Proposals | `scripts/proposals.py` (`scan`, `accept`, `reject`, `promote`, `selftest`) mines run records and `notes.md` for repeated failures and writes candidate proposals under `.sdlc/proposals/`. Nothing is applied automatically | T-0186 |
| Maintainer guidance | The plugin `AGENTS.md` opens with the project philosophy and a rule to prefer the lean lane or `/fix`, running the full chain only with a stated reason. `agents/builder.md` adds a completion rule (smallest change that meets the criteria; report blocked instead of looping). The standing objective in `.claude/agents/sdlc-lite-author.md` and the philosophy line were hand edits, not builder output (the philosophy line in `plugins/sdlc-lite/AGENTS.md` was builder output) | T-0209 |
| Spec gate | New `scripts/specgate.py check <planner.md or task dir>` reads a plan with `steps.py`'s own parser and refuses it before any plan-reviewer call for three defects: a `(guard)` criterion that runs `check.sh` with no `guard timeout: <seconds>` line, a command span repeated verbatim across steps, and `(guard)` and `(red)` on one line. `run.sh plan-reviewer` runs it first and exits 2 with `specgate:` lines and no run record on a finding (`SDLC_SPECGATE=off` skips it and marks the run line `specgate: off`). A plan can carry a `guard timeout:` line, and `steps.py split --only` resolves `--guard-timeout` as the flag, then the step's line, then the plan's line, then 300. `planner.md` and `skills/handoff-format/SKILL.md` describe the line, and `skills/chain/SKILL.md` routes an exit 2 to a replan. This is the static half only: it does not run any criterion against the base commit | T-0210 |
| Solo operator | New session agent `agents/solo.md` (not a `run.sh` role, like `conductor` and `messenger`) delivers one ticket end to end in one session from a typed brief (ticket, files, check commands, done criterion). Tiers by ticket size: S Sonnet low, M Sonnet xhigh, L Opus xhigh on Claude (the file pins no model; effort is a launch parameter), and `sdlc-solo-l1`, `sdlc-solo-l2` and `sdlc-solo-l3` on Codex at `gpt-6.1-sol` low, high and xhigh from `adapters/codex/models.json`. Tier S has no verifier, as `/fix`; tiers M and L end with one batched independent verifier on a different model family. `steps.py lane` makes `solo` the default for size S and M before planning, and `conductor.md` says to run lean or full only with a stated reason. `check.py` covers the file, the Codex entry and the three generated agents. The Codex table change is tied to `.sdlc/evals/0001-solo-tiers.md` and the lock, which records a user decision and no experiment (`pass_rate` 0/0) | T-0215 |
| Design records | `docs/lean-sdlc/cost-control.md` (v0.3, with its review record and the user decisions), `docs/other/orchestration-optimization-question.md`, and updates to `docs/ticket-stages/watcher-design.md`. These are design and reference only. T-0187, T-0199 to T-0201, T-0205 to T-0208, T-0211 to T-0214 and T-0216 are not built at this commit | none |

Every ticket change above was built by a builder role under `scripts/run.sh` and checked by a per-step verifier role (T-0202's step 2 is the exception, see Known limits), and most also by a whole-branch L3 verifier whose result is committed (`.sdlc/verify-t0183`, `-t0195` to `-t0198`, `-t0202` to `-t0204`, `-t0210`; the T-0193 and T-0194 branch verifiers shipped in 0.20.3). The exceptions are listed under Known limits. The version bump and this record were made by hand.

## Upgrade notes

- Codex projects that installed generated agents should run `python3 plugins/sdlc-lite/scripts/codex_roles.py install <project>` for each project: the builder (L1 to L5), planner, researcher, scout, architect, archaeologist, conductor and plan-reviewer agents were regenerated for the new text, and `sdlc-solo-l1`, `sdlc-solo-l2` and `sdlc-solo-l3` are new. The solo agents run at `workspace-write`.
- No migration is needed. A ticket with no `skips.md` is exempt from the skips guard, and `steps.py lane` runs only when a conductor or the `sdlc-lite` skill calls it for a ticket.
- The supervisor is opt-in. To try it: `python3 plugins/sdlc-lite/scripts/supervisor.py init`, edit `hosts.local.json`, then `watch` (a dry run) before `watch --run`.
- The `check.sh` suite now also runs the `evals.py`, `proposals.py`, `specgate.py` and `supervisor.py` selftests.
- A change to a parsed table row of `run.sh` or to `models.json` now needs a new eval file and a lock in `.sdlc/evals/` (`evals.py lock`), else `check.py` fails. That binds maintainers of this plugin, not consumers.
- `run.sh plan-reviewer` can now exit 2 before a review when the spec gate refuses a plan: fix the plan, or set `SDLC_SPECGATE=off` once.

## Known limits

- Supervisor: one run per arm, one machine and one account per host. The second run's Codex wake arm failed and the same arm passed in the first run, so the outcome varied. After a prompt fix it passed 3 of 3 reruns, and the other six arms were not rerun on the fixed prompt. The attached idle signal cannot tell an idle open terminal from a closed one. Codex MCP and connector tools are not blocked by the wake command. A push stopped before git runs, or one using `--no-verify` or another `core.hooksPath`, is not seen by the pre-push hook (`docs/validation/supervisor-live-run.md`).
- Evals: the hash covers parsed table rows, not comments or layout; a hand edit of `table_sha256` alone in `table-lock.json` is not detected; URLs are not fetched; one machine, one run (`docs/validation/evals-live-run.md`).
- Proposals: `promote` ran only in the selftest and no ticket was filed in the live run; one machine, one run (`docs/validation/proposals-live-run.md`).
- Carry forward: Claude Code only, Codex was not run. The probe's metrics are heuristics over tool inputs, and the first two attempts at step 2 failed on the probe's own metric, so the limit is recorded and no third cycle ran. One small fixture, where the saving was one search (`docs/validation/carry-forward-live-run.md`).
- Runner family rule at the task dir: one trial on Claude only. Codex is covered by `codex-selftest.py` and a dry run, and the choice across steps by number is exercised only by the selftests (`docs/validation/runner-family-task-dir-live-run.md`).
- T-0202: step 2 ended `blocked` on the probe's own metric and no verifier ran on it; the ticket was closed with that acknowledged.
- Skips guard: it covers only tickets with a recorded lane. The guard keys on a last lane record of `lean` or `fix`; a ticket whose conductor never ran `steps.py lane` has no `skips.md` and is not covered. The guard also treats a last lane of `solo` as exempt, so the new default lane is not guarded. T-0199 would close the first gap and is not in this release.
- Verifier coverage: T-0186 and T-0209 have per-step verifiers and no whole-branch L3 verifier (T-0186 was merged under the course-correction cost rules). T-0185's whole-branch L3 verifier failed once on a doc reference broken while resolving a merge conflict, and its fix was made afterwards; no re-verification result is committed under `.sdlc/verify-t0185`. T-0215's whole-branch L3 verifier failed on four places that still described the old `fix` lane value (`skills/sdlc-lite/SKILL.md`, `skills/chain/SKILL.md`, and two lines in `docs/lean-sdlc/design.md`); after a small L2 fix step, a narrow L2 verifier (`.sdlc/verify-t0215-narrow`) passed, and the L3 branch verifier was not rerun.
- Solo operator: no live run was made. T-0215's own done condition (one size-M ticket delivered by solo with a batched verifier on each host) is unmet, and its filer recorded two warnings, that one and that the lane output was not recorded; T-0216 is filed for it. The tier models are a user decision, and the eval behind the table lock records no experiment.
- Solo launch and contradictions: no text tells a Claude Code conductor how to start `solo` (no launch command, no `run.sh` case), and the plugin's `block-role-spawn.sh` blocks `sdlc-lite:*` agent spawns from a conductor session. `agents/conductor.md` still says size S goes to `/sdlc-lite:fix` on one line and `solo` by default for S and M on the next, and `plugins/sdlc-lite/AGENTS.md` and the maintainer agent file still say `/fix` and the lean lane. T-0199 covers the conductor and skill text only (and, as written, says size S goes to `/fix`); no open ticket covers the `AGENTS.md` and maintainer-file text.
- Supervisor, further limits: Claude wakes load the user's installed plugins and skills (no `--safe-mode`), and every arm of the second live run ran uncommitted code from steps 1 to 6 (`docs/validation/supervisor-live-run.md`).
- Whitespace: `git diff --check v0.20.3..HEAD` flags trailing whitespace in some committed run records and in the runner-family dry-run text files. The plain `git diff --check` on the clean tree passed.
- Spec gate: no dated live-run record exists for it, and its checks are selftests. T-0210's branch verifier noted that `check.py`'s spec gate order guard keys on `run.sh`'s header comment, so deleting the gate command block does not turn `check.py` red (`run-selftest.sh` covers it), and that `docs/lean-sdlc/cost-control.md` line 41 does not mention the plan's `guard timeout:` line. In `check.py`, two guard comments and two docstring entries are labeled item 17 (spec gate and solo).
- `shellcheck` is not installed, so shell scripts were not shellchecked.
