# Release 0.20.5

Recorded: 2026-10-04. SDLC Lite 0.20.5. Progressive Context stays at 0.1.2 (no change since 0.19.0). Previous release: SDLC Lite 0.20.4 (dd3870b, tag `v0.20.4`). Built from main commit 108d518; the release branch is cut directly from it (a fast-forward), and the release commit is the one tagged `v0.20.5`.

## What changed for consumers

This release makes the lane choice reach the agent files and adds two runner safeguards. The conductor rules, the solo start path and the routing texts act on any repository that runs the pipeline. The budget gate is opt-in per ticket (a ticket with no `budget_usd` is untouched). The handoff freeze flags a stale input on every run line, and its hook warns by default.

## Upgrade notes

- Codex projects that installed generated agents should run `python3 plugins/sdlc-lite/scripts/codex_roles.py install <project>` for each project: `sdlc-conductor-l1`, `sdlc-solo-l1`, `sdlc-solo-l2` and `sdlc-solo-l3` were regenerated for the new text.
- Budget: a ticket opts in with `python3 plugins/sdlc-lite/scripts/budget.py set <ticket dir> --tier M` (or `--usd N`). When a run stops with exit 4, `python3 plugins/sdlc-lite/scripts/budget.py ack <ticket dir> --usd <higher ceiling> --reason "<why>"` lets the next launch through only if spend is under 80 percent of the new ceiling (`run.sh` gates on the new ceiling, so a small raise can still exit 4). A ticket with no `budget_usd` is not gated. Codex runs record no cost, so the meter bounds Claude roles only.
- Handoff freeze: no setup. The Claude Code hook is registered by `adapters/claude/hooks.json` and warns by default. Set `SDLC_HANDOFF_EDIT_MODE=deny` to block the edit instead. Codex has no hooks, so there the `stale_input` flag on the run line is the only signal.
- Solo: a conductor starts it with the command in `agents/solo.md` (see the table). No new script is needed.
- No migration is needed and `tickets.py roadmap` is unchanged. The release adds new optional files that appear only when used: `budget_usd` in a handoff's front matter and `budget-ack.md` beside it (budget), and `stale-edits.log` beside a handoff (freeze hook).
- The `check.sh` suite now also runs the `budget.py` selftest.

## Known limits

- The headline claim "solo is the default lane for size S and M" is supported as follows and no further. The lane script prints `solo` before planning for size S and M (the `steps.py` selftest guards the lane output; `check.py` item 19 guards the routing texts, not the lane output). The conductor, `/fix`, the plugin guidance and the author agent now agree on it (`check.py` item 19). One live run, `docs/validation/solo-live-run.md`, delivered one size-M ticket in a throwaway project: on Claude Code through a headless `sdlc-lite:conductor` session that was given only the ticket prompt, found the lane and a start command from its own agent files (it did not copy the command in `agents/solo.md` as written: it used the literal plugin path and added `CLAUDE_PLUGIN_ROOT=$P` to the solo launch and to `run.sh`), started solo at tier M from Bash, and ran one independent L3 verifier on a different family, and the delivered tree passed a 20-check hidden check (20 of 20). Two direct launches (Claude solo on Sonnet xhigh and Codex `sdlc-solo-l2` on `gpt-6.1-sol` high) also passed the same hidden check. What is not shown: one trial per arm on one machine and one account; no size S or size L run; the Codex conductor start path was not run; `hooks/block-role-spawn.sh` was not exercised (the conductor used Bash, so no spawn was attempted and no denial was seen).
- Solo and its verifier: on Codex the solo did not launch its own verifier (it cited the parent prompt's "do not spawn any other agent"), so the verifier was launched from outside the session; whether a Codex solo can start one itself is unproven. On the conductor path the conductor started the verifier after the solo exited, and neither agent file says who runs it when a conductor starts solo. On Claude Code (direct) the solo changed a test after the verifier passed and did not rerun it, so that verdict covers the tree before that one test-only addition (the hidden check covers the final tree).
- Other defects the solo live run recorded and did not fix: the conductor's start command differs from the one in `agents/solo.md` as above; the printed Lane line and the recorded one differ in wording; the solo's mutation loop wrote a backup to `/tmp`; `agents/conductor.md` says the next action comes from `steps.py next <step dir>`, which a solo task has no step dir for; `solo.md` says to read nothing else, yet the direct Claude solo read three plugin files. Part of the cost shown (about $0.6 to $0.8 per solo session) is `claude-fable-5-1` from an `advisor` tool in the maintainer's own setup, not the plugin.
- Plugin code versions in that run: the two direct arms ran at plugin commit `ff8b748` (it carries the 0.20.3 manifest version, is not an ancestor of `v0.20.4`, and differs from `v0.20.4` in `plugins/sdlc-lite` only by the two manifest version strings), and the conductor arm at `e2241e8` (after T-0217, manifest 0.20.4). Neither ran at this release's commit.
- Handoff freeze (T-0212): the step's L3 verifier returned `fail` on a real defect (`scripts/check-packaging.py` pinned three PreToolUse routes and the new hook made four, plus a scope criterion that contradicted the record criterion). The fix (a count pin from 3 to 4 plus a check that the hook route is present, five lines in `scripts/check-packaging.py`) was made afterwards with a negative control, and no re-verification result is committed. The `rerun <level> stale input` action in `steps.py` and the exclusion of a stale result from `footprint.py` are not built, so the flag is on the run line only and a conductor must act on it. There is no Codex arm. One live run per hook mode on Claude Code (`docs/validation/handoff-freeze-live-run.md`), on a throwaway project with the hook registered through `--settings` and rewritten paths, not through plugin loading; the verifier also found table columns in that record that the JSON evidence does not support, and they were left as written. The hook warns on stderr with exit 0, so a model may not see the warning on every host version.
- Budget (T-0214): the 80 percent stop is exercised by selftests with a stub `claude`, and a live run with a ticket seeded at 85 percent was not made. Spend counts Claude `run.sh` roles only: Codex runs record no cost, and the conductor and background sessions are not in `runs.jsonl`, so the budget bounds the pipeline, not a session. `shellcheck` is not installed.
- `agents/conductor.md` still says the stop rule applies to a ticket past its budget "once the budget ticket lands", which this release does; it does not name `run.sh` exit 4 or `budget.py ack`, and its stop rule (past the budget) differs from the runner's stop at 80 percent.
- T-0199, T-0216 and T-0217 have per-step L2 verifiers and no whole-branch L3 verifier. The conductor rules were exercised by the one conductor run above and by no other.
- The skips guard (`tickets.py`) is unchanged: it covers only tickets with a recorded lane and exempts any last lane other than `lean` or `fix` (so `solo` and `full`), so the new default lane is not guarded.
- `scripts/check.py`'s docstring numbers two guards 17 (Spec gate and Solo agent) and two guards 18 (Conductor rules and Handoff freeze), and a code comment cites item 17 for the budget guard whose docstring item is 20. Harmless today, and it clashed once at merge. A comment above the lean-lane check cites item 13 where the docstring's item is 14. None of it is renumbered in this release.
- The solo-vs-lean benchmark record is not part of this release: no results record for it exists at commit 108d518. The decision to make solo the default rests on the replan and cost data in `docs/lean-sdlc/cost-control.md` and `docs/other/orchestration-optimization-question.md` and on the T-0216 live run above, not on a finished benchmark. The benchmark record the solo ticket cites, `docs/validation/solo-vs-lean-benchmark-2026-10-04.md`, does not exist.
