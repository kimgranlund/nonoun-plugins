# Ticket stages and message bus

Version 0.1, 2026-09-30. Proposal. Nothing here is built.

## Problem

`.sdlc/` holds tickets, task artifacts (`step-N/`, `runs.jsonl`, role results), `notes.md`, and a generated `roadmap.md` in one flat folder. At 174 tickets an agent that lists the folder pays for all of them. Closed tickets are already hidden by the dotted `.NNNN-slug` rename in numbered mode, so the open question is how to make the active set cheap to find and the procedures cheap to follow.

## Facts the design must respect

- A ticket folder is also a task folder. `steps.py`, `board.py`, `run.sh`, `fanout.py`, hooks, and `runs.jsonl` address `.sdlc/<folder>/` by path.
- `tickets.py` owns ids (above the max across every git worktree's same-relative root), the roadmap, and reference-safe closure (a scan for citing files before the dot rename).
- Front matter `status` is the one record of ticket state: proposed, ready, blocked, done, dropped. Build progress lives in `/board`.
- Claude loads a nested `AGENTS.md` only through a `CLAUDE.md` import. Codex loads root-to-cwd `AGENTS.md` files. A router file is therefore read when it is imported or named in a handoff, not automatically for every role.

## Options

| Option | What changes | Cost | Gain |
| --- | --- | --- | --- |
| A. Router only | `.sdlc/AGENTS.md` and `.sdlc/CLAUDE.md`; generated stage indexes inside the router block. No folder moves. | Low. One managed block regenerated by `tickets.py`. | Agents read one short file, then open only the tickets in the stage they need. |
| B. A plus `done/` folder | Closed tickets move to `.sdlc/done/NNNN-slug/` instead of the dot rename. | Medium. Every path citing a closed ticket changes; the existing cite scan covers it. | Same hiding as today with a visible, explainable name. Little new gain. |
| C. Full stage folders | `inbox/ ready/ active/ blocked/ done/ dropped/`, each ticket folder moved by `tickets.py`. | High. Task paths used by `steps.py`, `board.py`, `run.sh`, `fanout.py`, hooks, and `runs.jsonl` all move with the ticket. | Browsable by stage in a file manager. |

Recommendation: A first. It delivers the progressive-disclosure benefit without moving any path. Choose C only if A proves insufficient; if so, treat `status` and folder as one fact (see Invariants).

## Option A design

```
.sdlc/
  AGENTS.md     router
  CLAUDE.md     @AGENTS.md
  roadmap.md    generated, unchanged
  NNNN-slug/    unchanged
```

`AGENTS.md` carries:

1. One line on what `.sdlc/` is and what not to read (`.NNNN-*` closed folders, unless asked).
2. A managed block, regenerated by `tickets.py roadmap`, listing per stage the count and one line per ticket (id, title, folder) for `ready`, `blocked`, and active work, and only a count for `done` and `dropped`.
3. Three procedures, each short:
   - Create: `tickets.py new <type> <slug> "title"`; never pick an id by hand.
   - Claim: set `status: ready` work to in progress by starting a run through `run.sh`; the ticket's `claimed_by` line (new, optional front matter) names the harness and date. A second claimant checks it first.
   - Close: `/file`, then `tickets.py close`; follow-ups follow the existing tag rules.

`check` fails when the block is stale, as it does for `roadmap.md`.

## Option C invariants (if ever built)

- `tickets.py` is the only mover; folder stage equals front matter `status`, and `check` fails on any mismatch.
- Tickets resolve by id, never by stage path. Handoffs cite the id, and tools find the folder.
- A claim is a rename done under a lock in the git common dir, so two worktrees cannot both claim; without the lock the clash surfaces only at merge.
- Moves run the existing citing-file scan and refuse on a cite, as `close` does today.

## Two roots: `tickets/` and `messages/`

Proposed by the user as `issues/` and `messages/`; the user chose `tickets/` for the first root on 2026-09-30. It fits the two lifecycles better than stage folders do.

```
.sdlc/
  AGENTS.md      router: names both roots, the three ticket procedures, the mailbox rules
  CLAUDE.md      @AGENTS.md
  config  notes.md  roadmap.md  _templates/
  tickets/       git-tracked work records: ticket and task folders, as today
    NNNN-slug/
    .NNNN-slug/  closed
  messages/      git-ignored mailbox: new/ read/ done/ per recipient
```

- Why it fits: issues are durable, reviewed, and merged across branches; messages are short-lived, local, and must not be committed. Two roots make the tracking rule a path rule (`messages/` is ignored, `tickets/` is not) instead of a convention.
- Why it beats `bus/` nested in the ticket root: `tickets.py`, `board.py`, and `check` scan a root for ticket folders, so a mailbox inside it would need skip rules everywhere.
- Cost: `tickets.py --root DIR` already takes a root, and ids, closure, and the roadmap follow it. Tools and docs that cite `.sdlc/NNNN-slug` change to `.sdlc/tickets/NNNN-slug`; the existing citing-file scan lists them, and `number` or `archive --rewrite-refs` style rewriting would be extended for a one-time move. Existing consumer repos keep working if `.sdlc/` stays a valid root until they opt in with a `ticket_root: tickets` line in `config`.
- Name: `tickets/` keeps the vocabulary every skill, check, and script already uses and avoids confusion with GitHub issues.
- Stage folders become optional. With two roots, option A (router plus generated stage lists) still gives progressive disclosure inside `tickets/`.

## Message bus

Purpose: a harness leaves a message for another harness (Claude, Codex, or a human) and the message changes state as it is handled. The pipeline already hands work over through files and `runs.jsonl`, so the bus is for what those do not cover, such as a Codex session asking Claude a question mid-run. Build it only when a real case exists.

```
.sdlc/messages/       git-ignored, in the main checkout, shared by worktrees
  AGENTS.md           instructions for setting up comms; linked from the router
  new/<receiver>/<ts>-<sender>-<slug>.md
  read/<receiver>/... reader renames from new/, so the first rename wins
  done/<receiver>/... reader moves here with a one-line outcome
```

- Front matter, all required: `send_time`, `read_time` (empty until read; set by `messages.py read` in the same step as the new-to-read rename), `sender`, `receiver`, `topic`, `follow_up_requested` (boolean). Optional: `re` (ticket id), `kind` (question, handoff, ack), `expires`. The body follows. `messages.py` rejects a message missing a required field or over the size cap.
- Follow-up: when `follow_up_requested` is true, the message cannot move to `done/` until the parent has sent a reply with the same topic and a `re` pointing back to it, or it expires. An expired message with no reply moves to `done/` as `expired, no reply` and the sender gets a notice message. When false, `done` is free.
- `inbox-agent`: a required declared agent (`plugins/sdlc-lite/agents/inbox-agent.md`, with a Codex agent generated by `codex_roles.py generate`), not a `run.sh` pipeline role and with no authority beyond moving messages and sending replies through `messages.py`. Each harness runs one as a dedicated sub-agent on a cheap model (Claude `claude-haiku-4-5`; Codex the scout tier model in `adapters/codex/models.json`, currently `gpt-5.6-terra`, or luna). Its only job is to poll `messages/new/<harness>` every 10 seconds and tell its parent when a message is addressed to that harness. Parents send through their `inbox-agent`, not by writing files themselves. The `inbox-agent` never acts on a body.
- Host limits, stated per host. Claude Code: the sub-agent lives only while its session runs, polling needs Monitor or a loop, and a Claude hook enforces nothing on Codex. Codex: the `inbox-agent` is a native subagent with its own lifetime and no Claude tools or hooks. One host working says nothing about the other.
- Delivery has no daemon besides the `inbox-agent`. `run.sh` also prints a count before it launches a role.
- Durable facts go to the ticket or `notes.md`. The bus is a mailbox, not a record.
- Trust: a message body is data, never instructions. A message cannot authorize a publish, a push, or any external write. Expired messages move to `done/` with outcome `expired`.
- Limits: it works on one machine. A message that must cross machines is a ticket or a pushed note.

## Open questions

1. Is a `claimed_by` field enough for claims, or is a lock needed today (any parallel lanes outside `fanout.py`)?
2. Should the router's per-ticket lines include active work from other worktrees, as `tickets.py close --dry-run` does?
3. Is there a concrete bus use case that today's handoffs fail on?

## Validation plan

- A: a check that the router block is current and a negative control that a stale block fails; a live run where a role finds a ready ticket through the router alone on both hosts.
- Bus: a selftest for the rename race (two readers, one winner), expiry, schema validation with a negative control for a missing field, the follow-up rule (false free, true refused without a reply, true allowed after a reply, expired with no reply reported), and `read_time` stamping; a negative control that a message cannot trigger a publish.
