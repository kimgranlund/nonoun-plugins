# Dual-host readiness and recovery validation

Recorded 2026-09-28 against plugin source version 0.17.0. The installed plugin cache was still 0.16.0 during these trials; the source version was not automatically installed into the cache.

Both Claude and Codex readiness checks reported `ready` for local configuration. This check does not establish authentication or model availability by itself. Separate live role runs exercised both hosts. Each throwaway `label-whitespace` task completed planning, build, independent verification, filing, and local ticket closure. An independent oracle confirmed the defect: the original function failed for repeated spaces, tabs, and newlines, while each implementation passed those cases and preserved empty/whitespace-only input. The fixture unit suites reported 5 Claude tests and 6 Codex tests passing.

Routing history is retained because it tests the escalation record as well as the final path. Claude's initial L1 plan was rejected for an ambiguous fallback criterion and replanned at L3 (Fable, xhigh); its final builder was Sonnet L1 low and verifier Opus L1 medium. Codex's L1 plan had an ambiguous “added tests” criterion; an Astra verifier marked the plan defective, and an L3 Astra high replan clarified coverage. The original implementation remained, while the superseded step and its record were preserved. The final verifier passed. An early Codex filer invocation was cancelled before closure; the completed filer attempt passed. These Astra calls all occurred before the user's later instruction not to use Astra.

A real Codex conductor-to-named-scout exchange completed and its request/attempt record reached `completed`. An earlier native probe failed when sandbox policy blocked `ps`; its failed attempt remains recorded. The implementation was subsequently changed to use a file lock for local runner ownership.

For both hosts, live interruption probes observed the host process start and then terminated the wrapper. Each returned exit code 143, recorded `interrupted`, and produced no report. This demonstrates preservation of interruption state; it does not establish that a host-managed Codex child has stopped. Recovery must be preceded by stopping or awaiting that child, then checking the working tree and retained reports before a fresh attempt.

The focused runner self-test passed after resetting its fixtures; packaging, generated-agent parity, and the role contract check also passed. The final `scripts/check.sh` run exited 0, including 13 Codex adapter tests, 3 lifecycle tests, runner and fanout regressions, hook checks, shellcheck, and plugin validation. The machine-readable case details are in [dual-host-readiness-recovery.json](validation/dual-host-readiness-recovery.json). Raw transcripts and fixture directories were kept outside the repository. These trials exercised roles one by one; they were not an unattended full-chain run or a multi-lane benchmark, and they did not cover every role and level.
