# Solo first: lane choice, budgets, and limits

Detail for the fanout skill's `Solo first` paragraph.

Solo first: for each ticket `fanout.py` runs `steps.py lane` in the lane worktree and follows it. `solo` (ticket levels L1 and L2 by default) starts the `solo` agent from a typed brief at the level's model and effort, in a headless session (Claude: `SDLC_ROLE=solo claude -p --agent sdlc:solo`, refused without `SDLC_CLAUDE_EXEC=1`, so use `prep` and `land` sub-agent lanes or `--driver`; Codex: `sdlc-solo-l1` to `l3` through `codex_exec.py`). A ticket of level L2 then needs one independent batched verifier with Verdict pass, from the solo or else one fanout runs (verifier L2, or L3 for the tickets `steps.py verifier-level` names), before any merge. Anything else keeps the headless factory running /chain (on Claude also needs `SDLC_CLAUDE_EXEC=1`). `--lane auto` (the default) follows the lane script; `--lane solo` or `--lane full` forces the choice, and the report lists each ticket's lane. Solo lanes start through `scripts/solo_run.py`, which checks the ticket's budget first (at 80 percent of `budget_usd` with no ack the lane stops as `driver failed rc=4 (budget gate: budget.py ack)` and nothing starts) and records the session's cost in the ticket's `runs.jsonl`, so the budget and the board meter Claude solo lanes only: a Codex solo lane records cost null, and a sub-agent lane's `prep` writes an unpriced `role solo` row that `fanout.py land --transcript <solo transcript jsonl>` prices (an estimate, per field, calibrated; T-0331), and a `full` lane starts a factory session that writes no record. One run holds at most `--max-lanes` lanes (default 4; above 16 it also needs `--yes-many`), starts them `--stagger` seconds apart (default 20; your plan limit and merge conflicts are the real limits, not the machine), and refuses two tickets in different lanes whose planned scope overlaps unless `--allow-overlap`. The report names the real model per backend for each solo level (Codex reads `adapters/codex/models.json`), and a gate whose output shows it ran no tests (`Ran 0 tests`, `no tests ran`, pytest rc 5) stops the ticket as `gate vacuous` unless `--allow-empty-gate`. A good first run is up to 4 lanes (the default cap) of tickets that touch different files; raise `--max-lanes` only after watching your plan's limit use and the merge conflicts. The planned-scope overlap refusal reads only a ticket's `step-<n>/` handoffs, so it cannot fire for solo tickets (they have no steps); merge-time overlap still serializes them.
