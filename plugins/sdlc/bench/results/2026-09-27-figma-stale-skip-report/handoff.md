## Goal
When the Figma plugin skips renaming a stale variable because its `_deprecated/` slot is already taken, it currently says nothing. It should report that skip to the user.

Interface the tests rely on (library mode):
- Each site that skips a rename records the skipped stale name(s) as an array named `skipped`: on `applyBundle`'s `colorReports[]` entries, `applyFloatPlans`'s `libraryReports[]` entries, and `applyFontPrimitivesModes`'s `libraryReport`, with a top-level `skipped` rollup on the `applyBundle` and `applyFloatPlans` results. Use `[]` when nothing was skipped.
- The apply completion notice names the count as `N stale skipped (rename target taken)`, next to the existing counts.
- The Type/Geometry part of the completion notice also names kept stale breakpoint modes as `N stale kept (published library)`, the way the color part already does.

## Context
- Plugin source: `figma/plugin/code.js` (the Figma sandbox side of the plugin; apply flows for color, float, and font/type/geometry variables live here).
- Plugin tests: `test/figma/plugin.mjs`, a self-reporting .mjs script run directly with node; the whole suite is `test/run.mjs` via `npm test`.
- Look at how the plugin already handles stale (dropped) variables and how apply results and notices are returned to the UI.

## Constraints
- Existing tests your change legitimately breaks may be updated to the new behavior; never delete a test or weaken an assertion to get green. The grader overwrites its own test files after the run, so edits to those do not count.
- Edit the source `figma/plugin/code.js`, not generated files. `figma/plugin/ui.html`, `src/ui/figma-plugin-assets.js`, and the binder `figma/binder/figma-semantic-binder/code.js` are regenerated by `npm run gen:figma-assets`, `npm run bundle`, `npm run gen:figma-ui` (all run by `npm test`).
