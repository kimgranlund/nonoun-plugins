## Verify the composition

Read the chosen project’s build and verification instructions. Numerical checks do not establish browser appearance, keyboard behavior or accessibility. Verify actual state transitions, disabled/invalid precedence, light/dark themes and affected geometry. Wait for intended transition settlement before inspecting final-state captures; also inspect the transition if it is part of the task. Keep comparisons until replacement verification, then remove superseded main-page examples if requested. Report broader platform audits separately.

A build can succeed with missing component CSS or wrong cascade order. A valid dependency list does not demonstrate correct use. Record source discovery, applied decisions and observable checks separately. Do not infer contrast, accessibility, renderer parity or general unattended reliability from one successful trial.

Updating this skill does not update the bundled snapshot, legacy assets or downstream projects. Do not overwrite one consumer with another, deploy either, or synchronize UI-KIT merely because these shared instructions changed. Legacy assets are retained for deliberate maintenance only.
