Consume the maintained kit directly. Preserve recipe__slot APIs; the local skill name is unrelated to the React library @base-ui/react. No framework or runtime package install is required.

Start commands with `python3 scripts/run.py --check` (use absolute script paths outside this kit). The launcher resolves an installed Node runtime without assuming PATH, installing or crawling. Run kit commands as `python3 scripts/run.py COMMAND.mjs ARGS`; it propagates the selected runtime to child commands.

For prose/recipe retrieval use `python3 scripts/run.py read RELATIVE_FILE [--page N]`: at most4000 content bytes, source hash and explicit nextPage. Consume each needed page separately; a continuation is not a complete read. Use structured component/token commands for JSON contracts.

Read [component authoring](references/style/components/authoring.md) for the used families. Retrieve `python3 scripts/run.py component-context.mjs --shared` once, then bounded `--records fields,choices --record-only` batches. Retrieve a recipe only when adapting it. Do not load all contracts, reports or catalog scripts by default.

When adding a component family later in the task, retrieve its contract before writing its markup, including markup created by JavaScript. Native tags still need kit anatomy: `details` → `disclosure`, buttons → `actions`. Before delivery, follow [rendered contract audit](references/rendered-audit.md) on the final artifact and relevant expanded/conditional states. Kit example tests and successful builds do not validate consumer composition. For routine local maintenance, use targeted checks and screenshots as described below; a full review session or gallery is not required for each edit. For new generated UI, broad layout reviews or kit release acceptance, work through the [topic-based review checklist](references/review/index.md). Use the [executable review session](references/review/session.md) to capture each app-defined state across the responsive matrix, inspect its bounded risk-based visual sample using next-topic packets and their bounded original-pixel detail samples, and record topic judgments without hand-building evidence JSON. Its outstanding-work queue keeps inspection and bookkeeping separate. Record visual composition separately from mechanical passes, including unreviewed states and unresolved findings. Builds are drafts: use the [review delivery gate](references/review/delivery.md) to bind the review before inspection and finish with an integrity-checked receipt. Missing, unfinished or stale reviews cannot produce a kit release.

Use `scripts/api.mjs` for describeKit, getAssetBundle, compileControls, getComponentContext and validateUI. The last function checks token membership only. For an explicitly single-file export, `python3 scripts/run.py build.mjs FRAGMENT NEW_HTML [CONTROLLER]` embeds the actual styles/compiler/runtime. For new modular pages, run `python3 scripts/run.py build-page.mjs FRAGMENT NEW_DIRECTORY [CONTROLLER]`; it creates editable CSS barrels and offline kit assets once, refusing existing directories. Follow the [modular stylesheet contract](references/page-styles.md) for subsequent edits. The reference site has its own project build. Use page__root page__flow for page margins and grouping. Preserve paired scheme roles and component anatomy; derive geometry and type sizes from the shared mathematical source. Geometry tiers are widget/product/content/brand; see [geometry and spacing](references/geometry-spacing.md). Use margin for edge-to-content spacing and gutter for sibling spacing.

For native button commands, use the runtime’s `onAction` helper and dedicated `data-action` hook; actions and collections records link its maintained recipe. Generic `on` remains for other event semantics.

For semantic component colors, retrieve the actions, feedback, identity or fields record: their semanticPalettes contract lists implemented intents, appearances and the maintained recipe. Raw palette availability does not establish a component mapping.

For custom state, retrieve `component-context.mjs --runtime`. createUIRuntime mounts supplied roots/definitions/stateKeys; it does not register review units. Review artifacts use the wireframe-review adapter instead. Recipes declaring const titleRequestDefinition or notificationChoiceDefinition are mounted explicitly by the consumer. Native CSS/HTML behavior remains preferred where supported by the contract.

For source-derived catalog data, see [package boundary](references/package-boundary.md). Catalog extraction and UI renderers belong here; review status and evidence publication belong to wireframe-review.

For browser-dependent checks, run `python3 scripts/run.py resolve-browser.mjs --check` once. Use its modulePath, or configure UI_PLAYWRIGHT_PATH. If the bundled browser is absent and an installed Chromium path is known, pass --executable PATH with --check; consume the returned executable in task checks. Successful resolution/launch is dependency evidence only. Consume the returned modulePath in actual interaction checks; report dependencyStatus, launchChecked and task-check outcome separately. Do not report unavailable when the resolver succeeds. Use the bounded [verification reporting](references/verification-reporting.md) route when preparing check claims. Discovery is bounded; missing dependencies are explicit and never trigger a filesystem crawl or download.

## Maintenance

This directory owns UI source. wireframe-review may contain generated compatibility copies; do not edit those. After changes, run affected checks, `python3 scripts/run.py seal.mjs`, then the consumer's `scripts/sync-ui-kit.mjs` and `--check`. Sealing records identity, not verification. Standalone checks are indexed in references/checks.json; old wireframe-review check commands forward here. Use generate-icons.mjs --check for in-place glyph parity. Versions/API changes need an intentional compatible release pair; no network fallback or silent lock update occurs during generation.

For evidence-driven kit improvements, reconcile the executable mechanism, contract projections, recipe and affected checks; a repaired consumer alone does not improve the kit. See [maintenance lessons](references/maintenance-lessons.md) for source-group fidelity, geometry and routing boundaries.

Keep evidence and accepted limitations. Disposable checks belong in /private/tmp. Keep the existing canonical system-review destination and preserve peer-owned files. [Package boundary](references/package-boundary.md) describes supported interfaces and migration limits.

Nested prose also needs a width budget: base-ui provides `reading-flow__root` on one outer padded region; see [reading regions](references/reading-regions.md). Narrow regions share one inline margin rather than accumulating it at every depth. The rendered audit enforces a bounded 24ch prose floor in expanded states.

Portable bundles include offline Bricolage Grotesque and IBM Plex Mono faces. For font loading or packaging changes see [bundled fonts](references/bundled-fonts.md); wait for `document.fonts.ready` before measuring geometry.

For the installed standalone kit, use [current geometry integration](references/geometry-spacing.md) and the [mathematical contract](../../../mathematical-design-system/references/geometry-contract.md). These supersede historical button/slot/curvature guidance in old recipe reports. Control anatomy has fixed 3n square icon/glyph wrappers, a 3n label, font-sized glyphs, internal icon/glyph budgets W, label inline padding L=n/2, zero internal slot gaps and no extra compensation. Radius defaults are Sharp for both Container and Control families. Validate actual sizes and report conflicts without altering requested geometry. Portable resolvers live in assets/geometry; do not import personal paths in consumers.

Legacy Chip/Badge/control-ladder recipes remain compatibility examples, not the current Control model. The separate project repository has its own contracts and is not automatically synchronized with this installed kit.

After geometry or stylesheet token changes, regenerate base-ui/scripts/generate-token-index.mjs before sealing. Verify generate-token-index.mjs --check and check-kit.mjs, then synchronize compatibility copies; sealing alone cannot detect stale token inventories.

For declared interaction states and conditional listbox paint insets, see [state punch list](references/interaction-states.md). Keep selected and hover geometry consistent, and reverse action color pairs atomically.

For new page generations, use the [modular stylesheet contract](references/page-styles.md). Keep styles/index.css as the reference entry and styles/recipes/index.css as the recipe entry; both consume styles/shared/index.css. Vendor tokens and kit projections live in styles/vendor/, authored mappings/common layout in styles/shared/, component rules in styles/components/ or styles/recipes/, and page arrangement in styles/pages/.

For component spec lists and heading/description/data compositions, follow [page layout patterns](references/page-styles.md#heading-description-and-data-layout). Use consistent compact label/value rows for numbers and formulas. Give the heading its own row and peer heading color; align the full-width description and data list beneath it, stacking the section on narrow screens.

For the geometry recipe pages, semantic intent/appearance/state axes and local behavior boundaries, read the [recipe library contract](../../../Projects/ui-kit/docs/system/recipe-library.md). Command and ContextMenu are implemented; follow the linked command recipe contract for keyboard ownership, focus return, CDN icons and dogfooding checks.

For Command/Cmd+K and ContextMenu, use [command recipes](../../../Projects/ui-kit/docs/system/command-recipes.md). Older ContextMenu recipes retain compatibility geometry; new command-menu consumers use full Control rows (H=3n+2m, fixed 3n internal slots, m clearance on each edge, E=m/2 gaps); ordinary selection-list rows remain 3n while retaining native button menuitems, shared slots and focus return. Preserve maintained button/input/select implementations; native select decoration has one owner. The reference site uses pinned Phosphor CDN weight stylesheets; portable offline kit exports retain their SVG option. Verify actual loaded fonts, geometry across densities, keyboard completion and focus restoration.

Table sort controls use the shared composition geometry: content-sized 2n+d minimum frame, d/2 edge allowance, derived control corners, and centered 2n glyph slots. Keep static row headers on the same text rail; never replace this with a full-width, zero-padding rectangle.

For Command composition, follow [shared palette and compact dialog](../../../Projects/ui-kit/docs/system/command-recipes.md#command--commanddialog): reuse one inline surface, let its dialog wrapper own modality/shortcut/focus return, and preserve d search/footer insets with an unpainted, zero-padding dialog wrapper plus shared Listbox results: Hc=2n+d rows, d/2 border-inclusive clearance, d/4 gutters and shared inset radii. For keyboard hints, retrieve the `kbd` component record and use [Kbd recipe](assets/recipes/kbd.html). Native `kbd.kbd__root` is a passive keycap using Badge sizing (minimum 2n, n+4 type); Each chord is one keycap with plus-separated keys (for example `⌘+K`). Do not register shortcuts or add button semantics to keycaps. Command footer and result hints consume this shared recipe.

For custom Select and editable Combobox popups, follow [shared Listbox consumption](../../../Projects/ui-kit/docs/system/select-combobox.md): use listbox__root/listbox__option, compact Hc rows, d/2 border-inclusive margins, d label slots, d/4 gaps and shared inset radii. Keep active highlight distinct from committed value; DOM focus stays on the trigger/input. Native select menus remain browser-owned. Verify actual popup bounds, selected check icons, keyboard commit/cancel and narrow/enlarged labels with targeted checks and screenshots.

Full-size `media` (avatars/logos/thumbnails) is internal Control anatomy: fixed `3n × 3n`, zero padding and zero centering inset. It occupies a leading/trailing slot and adds no internal slot gap. Do not apply the icon/glyph wrapper budget to media. See the current geometry contract for media-to-label spacing and guide semantics.

Media shape is asset-owned by default (circular avatar, unchanged logo). Explicit Control-shape inheritance uses `resolveMediaRadius` with actual media size and the immediate row/button required radius; Sharp overrides retained floors. Report physical conflicts without clamping. See the media opt-in contract.

The current slot model was also synced into the separate UI-KIT packages on 2026-10-18. See [integration record](../../../mathematical-design-system/references/ui-kit-integration.md) for package exports, rich Select descriptors, source ownership and measured-shape limitations. Do not assume the standalone kit and project share a build or identical compact-recipe migration status.

Wrapper shape ownership: Control slot wrappers own any resolved border radius and overflow clipping. Icon/glyph artwork and media img/SVG children retain their authored radius, overflow, and shape styles; do not reset or inherit these properties through parent selectors. Circular avatar defaults belong on the media wrapper. Keep sizing/placement rules separate from shape ownership. For physical conflicts, keep the fixed wrapper and render dashed diagnostics outside the clipping layer; never alter artwork styles to make a requested radius fit.

Icon/glyph/indicator wrappers in current Buttons and Listbox options inherit Control shape using the same candidate and immediate-parent retained floor as opted-in media; Sharp amount0 forces zero even with retention. CSS amounts/retention are fractions (0–1), resolver inputs percentages. Preserve fractional amounts; do not round before resolving. `--media-required-radius` is the wrapper-local measured override for these slots. CSS fallback supplies paint only, not physical-size validation. Standalone Base UI has no automatic media binding: consumer code must measure/validate each wrapper against its own immediate row/button, recompute on owner/context changes, and remove or restore the override and owned `data-geometry-conflict` on opt-out, replacement, destroy, and abort. Never carry a row's measured override into a cloned Select trigger; resolve the new owner independently. Restore authored prior styles/diagnostics rather than erasing consumer-owned values. Keep overflow clipping during conflicts; use an external diagnostic layer for required geometry. No child artwork radius or overflow reset is permitted.

Control-shaped wrappers and circular media defaults explicitly use `corner-shape:round`; inherited superellipse/bevel paint must not change the scalar-radius contract or turn a circular avatar into a squircle. This reset belongs on the wrapper only; artwork keeps its authored corner shape.

Current Control button boundary paint is independent of geometry: filled buttons have no inset stroke; secondary/outline controls use `--ui-control-border` (neutral `--ui-border`, intent `--ui-intent-border`), never implicit text color. Keep focus rings and paired interaction fills; do not add a layout border to replace paint.

Painted buttons own an outer content-clipping boundary matching their resolved radius. Clip descendant slots at that boundary, including intrinsic logos; keep slot dimensions, label padding and artwork-authored styles unchanged. This is separate from optional media-wrapper shape inheritance. Keep focus rings on the button and required-geometry conflict diagnostics in an external, unclipped layer.

Containment uses 0.05 CSS px tolerance consistently for edge equality, negative inset and parent bounds. Physical radius excess uses a separate 0.001 CSS px noise threshold; preserve exact requested radii and excess. Group validity is diagnostic, not a command to square every layer: paint each parent/row from its own physical validity, and retain containment and sibling failures separately. A failing child must not erase feasible parent or sibling radii. Keep genuine conflicts visible in consumer diagnostics even when overlays are hidden.

Menu command rows (`button.button__root[role=menuitem]`, also menuitemcheckbox/menuitemradio) use full Control height H=3n+2m, with m=(q−2)n/4 clearance on every edge. At n=8 this is 24/28/32/36/40px across Tight through Loose; internal slots remain 24px. Menu surface padding is separate. Keep icon/glyph budget W, label padding L=n/2 and zero internal slot gaps; collection row gaps remain E=m/2. Menu labels use the same L=n/2 rule. Ordinary Listbox options remain 3n high. Resolve menu rows with resolveControlSurface and validate their own measured frames/radii independently.

Tables and data-lists use full Control minimum row height H=3n+2m, centered minimum 3n slots and multiline growth. Cell padding P=m+W and column gutter E=m/2 are explicit and additive. Native tables reserve E/2 at internal facing edges; data-list grids use gap E. Paint one row-only `--ui-data-divider` and no cell strokes. See [table/data-list geometry](references/geometry-spacing.md#tables-and-data-lists).

For data-row comparison examples, include matching single-line and multiline Table/Data-list content across all five densities, measured multiline heights, and non-layout spacing guides. Keep readable measurements outside specimens and provide keyboard-accessible horizontal comparison navigation. See [comparison requirements](references/geometry-spacing.md#five-density-data-row-comparisons).

Buttons use L=n/2 on both label edges, independent of shape, density and slot occupancy, with zero extra compensation and zero internal slot gaps. Outer m, icon/glyph W and fixed squares are unchanged. Sharp and Pill buttons with identical content have equal natural width. `resolveButtonPadding` accepts `wrapperInset=surface.labelPadding` (L); `edgePadding` and `compensation` are zero-valued compatibility aliases. See [current geometry](references/geometry-spacing.md).

For Sharp/Pill comparison views and responsive specimen cards, follow [comparison scope and verification](references/geometry-spacing.md#sharppill-comparisons-and-specimen-cards). Fixed comparison shapes are explicit local overrides; surrounding cards follow Container settings independently. Per-arrangement readouts show leading/trailing label padding L and total edge-to-text inset, separating outer m and occupied slot widths.
