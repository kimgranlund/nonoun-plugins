# Review composition patterns

Retrieve the needed family records (`evidence-comparison`, `interval-timeline`, `allocation`) and their declared base-family dependencies. Read `assets/recipes/review-patterns.js` and the HTML example when adapting. Include the JS source once before your application controller in build.mjs's controller input. It declares `baseUIReviewPatterns`; it does not mount or own application state. Do not fork the pure helpers to alter domain decisions. Use the maintained functions directly and keep local business policy separate.

- `renderComparison({id,records,rows})`: exactly two unique `{id,label}` records; rows `{id,label,cells:[{recordId,state,value,provenance}]}`. Supply a cell per record and state unknown/disputed/confirmed explicitly. No inference of truth, approval or safety. Each row repeats record names for stacked reading. Provenance uses native disclosures. Instance IDs must be unique in the document; caller retains expanded state across replacement if needed.
- `renderIntervals({id,domain:[start,end],intervals,selected,action})`: numeric finite endpoints, positive durations inside domain; intervals `{id,start,end,label,timeLabel,uncertain,uncertainty}`. All tracks share one domain, and each track has proportional offset/span independent of label sizing. Text labels must include units/time zone and uncertainty; the helper cannot infer these from numeric values. `action` defaults to select-interval; bind using onAction and read data-interval-id. Buttons provide keyboard interaction and equivalent text. Decorative tracks do not replace that text. Caller preserves focus after rerender. Unknown gaps must be explicitly authored intervals or text, never interpolated as observations.
- `validateAllocation(total,parts)`: returns `{valid,allocated,remaining,errors}`; total is a nonnegative safe integer, parts are numbers or digit-only strings. Blanks, signs, fractions, nonnumeric values and unsafe sums fail. Does not silently rebalance. `renderAllocation({id,total,parts,label,showErrors})` accepts `{id,label,value}` parts and renders a plain field group, numeric fields and live total. Caller handles input without losing focus/caret, retains drafts per record, and uses validation again on attempted commit. Receipt validity, evidence revision, conflict resolution and release eligibility remain application responsibilities.

Use an outer reading-flow__root task card for nested prose. Comparison columns stack based on available container width; they do not require global mobile breakpoints. Test normal and enlarged text, both schemes, long names and RTL content. Interval acceptance measures bar width/track width and offset/domain correspondence, not button width or no-overflow alone. Test invalid domains, empty allocations, over/under-allocation, selected interval keyboard behavior and simultaneous independent instances. Run the rendered contract audit after expanded/dynamic states.

The interval renderer emits numeric domain/endpoint data attributes consumed by the rendered audit. `INTERVAL_GEOMETRY` detects corrupted tracks (including minimum widths imposed for text). Keep these attributes consistent with the authored values; labels cannot validate their own domain.

Allocation showErrors marks invalid values (or all parts of an unconserved total) with aria-invalid and associates them with the shared status. Consumers must clear/recompute those attributes and status after edits; do not leave stale validation paint.
