# Common component families

Read the authoritative family being composed with `node scripts/component-context.mjs ID` from the skill root; `--list` lists the twenty-two common families plus native-select and navigation-menu. This returns the exact selected record and shared constraints without the other family records. The [contract](contract.json) remains the source of truth; read its relevant record directly if the CLI is unavailable. Adapt the [catalog fragment](../../../assets/recipes/components.html). Its [runtime](../../../assets/recipes/components.js) demonstrates local behavior; in a review artifact, adapt handlers into the controller lifecycle rather than embedding script tags or copying document-global selectors across proposals.

For instructions for a maintained canonical example, use `node scripts/demonstration-context.mjs MEMBER_ID`; `--list` names the 44 members. The [demonstration guide](../../../../wireframe-review/references/style/components/demonstrations.json) owns authored task instructions and typed recipe/style/controller identities, while family contracts own semantics and applicability. The lookup returns one member, validates its prepared dependency snapshot and never promotes instructions to observed state coverage. Follow its optional-runtime and native-browser limits; saved payloads remain outside the corpus.

All classes ship in wireframe.css. Checkbox/radio classes opt into custom native-input paint; unclassed native inputs retain browser rendering. The embedded check/minus are Phosphor regular glyphs, with attribution in assets/phosphor-license.txt. Radio dots, tracks and thumbs are geometry, not icon replacements. The native input owns semantics and focus. Never hide it with display:none to draw a replacement.

The mark is not the pointer target. Use the associated choice/switch label to provide at least a 24px interaction frame. Icon-only actions at small geometry sizes need an explicit target policy; do not assume every micro cell meets that floor. Content wrapping grows rows; never clip a label to preserve a fixed row height. Our 32/24/16/8 product spacing hierarchy remains separate from compact control internals.

Inherited geometry is authoritative. Switch thumb=icon, clearance=margin/4, track height=icon+2clearance and track width=height+icon; slider rail=margin/2. These ratios are recipe choices supported by the catalog checks, not new engine invariants. Density uses an explicit data-size context; do not independently shrink every part. Tables use margin/2 block and margin inline cell padding, with content-driven row height.

For collection choices, use `label.choice__root > input.checkbox__control + .choice__body`; place the title and `.choice__description` inside that body. The shared mark-to-body gap is one full margin and the title-to-description gap is one margin. Use `ul.list__root > li.list__row > label.choice__root` for flat selectable collections. The row owns one margin of padding; its full-width choice label adds no block padding, preventing doubled margins. Shared CSS owns this composition; no recipe-specific padding reset is needed. Keep the title and metadata together in `.choice__body.list__body`. Their enclosing card keeps four margins, with three-margin group gaps. These are different relationship levels, not one uniform list gap. See the [collection composition](../composition.md#collection-followed-by-a-task) and its [equipment-loan example](../../../assets/recipes/collection-workflow.html).

Consume surface foreground aliases together. Labels use --ui-label; values --ui-ink; explanations --ui-muted; selection uses the paired --ui-action/--ui-on-action. Invalid state includes visible error text and aria-invalid; the baseline uses a dashed focus-colored boundary, not an unverified danger-palette pairing. Hover must not erase selected state. Focus remains visible. Disabled styling is applied once to a choice row.

Tabs and segmented controls share some styling but not semantics. The catalog demonstrates keyboard-operated tabs and pressed mode buttons. A table with buttons remains a table; implement an ARIA grid only when its keyboard model is required. Sorting changes rows, filtering changes actual visible rows, and select-visible must match those rows. [hidden] wins over component display rules.

Existing [native-select](../select/contract.json) and [navigation-menu](../navigation-menu/contract.json) contracts remain authoritative for those patterns. The extended families now supply bounded tooltip, notification and tree examples. Read their family contract before composing them; the declarations do not imply unrestricted application behavior.

Run scripts/check-components.mjs PLAYWRIGHT OUTPUT to build the standalone catalog and check geometry, states, task behavior and negative controls. Also run the existing spacing/product gates after changing shared CSS. Chromium results do not establish Safari, Firefox or assistive-technology behavior. Native range pseudo-elements have separate WebKit and Firefox rules; both need actual-browser review before claiming cross-browser parity.

Implementation evidence and limits: [component-family report](../../../../wireframe-review/references/reports/component-families-2026-10-09.md).

The [native patterns recipe](../../../assets/recipes/native-patterns.html) supplies declarative dialog commands and named exclusive disclosures alongside destination popovers. Read [native-first guidance](../native-first.md) for platform requirements and verification evidence. Application validation and saved state remain consumer behavior; do not bind a second opening controller to a native command button.

Breadcrumbs use a labelled nav and ordered list, with aria-current on the current page. The horizontal list owns its geometry gap and aligns item text baselines. Reset direct-item margins so prose list spacing cannot push later crumbs down; preserve wrapping for long labels and narrow widths.

Disclosures retain native details/summary behavior. Shared CSS replaces the browser triangle with a bundled Phosphor caret-right mask in a trailing geometry icon-sized square, separated from the label by one margin. Summary headers use full-width control geometry: minimum height, half-margin block padding, 1.5-margin inline padding, explicit geometry-derived inner radius, geometry text size, UI font, centered cross-axis alignment and start-aligned wrapping labels. The caret stays at inline-end. Closed points inline-end (including RTL); open points down. The decorative pseudo-element adds no accessible text and needs no initializer.

The details element owns the complete border, radius and surface. Summary is its header, not a separately bordered button; open headers keep the top corners and show a divider. Wrap expanded content in disclosure__body with 2-margin padding and use nested flow classes for content relationships. Do not put display:grid/flex on details itself or clip its focus ring.

Summary backgrounds stay transparent so they cannot paint over the details border. Resolve the summary radius explicitly from control geometry minus border width; do not rely on `border-radius:inherit` across native details internals. Keep overflow visible on the disclosure and verify closed, open and keyboard-focused states: the entire rounded border and focus ring must remain visible.

Code samples use `<pre class="card__root"><code>…</code></pre>`. Reuse card margin, border and presentation radius from the inherited geometry/density context; do not assign independent pixel padding or square corners. The shared profile adds monospace geometry-sized text, wrapping and scrolling. A page may bound the code region height for reading, but must not override its container geometry. Inline `code` is not a card.

Breadcrumb anatomy is `nav[aria-label] > ol.breadcrumbs__root > li`: the class belongs to the ordered list, never the nav. Direct children own the items and current location uses `aria-current="page"`. See `breadcrumbAnatomy` in the navigation family contract.

Each family contract records `implementation.anatomy`, `native`, `javascript` and `fallback`; shared CSS and verification ownership are in `implementationDefaults`. Use those boundaries when composing a new pattern. Read the relevant family rather than the catalog runtime source merely to discover its responsibilities.

Public CSS outside interactive families is classified in `classGroups`. These groups explain ownership without inventing standalone components. Source sheets show their classification beside CSS excerpts. Token-domain selection guidance and scoped-variable fixtures live in the compact style contract, not in generated HTML.

Choice validation pairs `aria-invalid` with a visible described error. Clear both when corrected and restore both when the requirement becomes unsatisfied; a checked glyph alone does not clear programmatic invalidity. The catalog demonstrates this local transition and disabled radio keyboard skipping. Its controller-dependent validation specimen is omitted without scripts. Static notices have ordinary semantics; reserve live status regions for actual updates.

Action appearances own foreground/background pairs across states. A generic hover background must not override secondary or ghost backgrounds while retaining their surface ink. Use the shared rules; verify rest, focus, hover and pressed states with `check-action-contrast.mjs PLAYWRIGHT OUTPUT`. Its old-rule negative control must fail. This checks default opaque surface contexts; custom backgrounds need separate measurements.

Disabled tabs stay outside the roving sequence; arrows and Home/End address enabled tabs only. For filtered tables, an empty result has visible recovery guidance and no enabled all-visible selector. Clearing the filter restores rows without silently losing prior selection. The catalog demonstrates both transitions.

`stateApplicability` maps every public family class to its supported state vocabulary and names the state owner. Unlisted states are not supplied by that pattern. Containers and decorative subparts reflect their control or data owner; they do not gain independent interactivity. This is a declaration, not a test-result matrix; browser evidence must demonstrate applicable transitions and visual states separately.

The extended catalog demonstrates required radio choice cards with described errors, labelled indeterminate progress, a static error notice, and an image avatar beside persistent identity text. Missing imagery must not erase the person’s accessible identity or change its reserved geometry. Loading illustrations are explicitly labelled as examples; they do not imply real background work.

An input group is one painted control: the wrapper owns the invalid dashed boundary and focus outline; the native input owns `aria-invalid`, editing, readonly and disabled behavior. A disabled group dims once, including its prefix. Readonly values remain readable, selectable and focusable without a disabled treatment. The catalog includes all three compositions; `check-composed-states.mjs` tests actual editing, state removal and wrapper paint.

The dedicated select/navigation contracts expose the same `implementation` ownership fields as these families, retaining their existing anatomy and customization owners. `check-implementation-ownership.mjs` checks all 13 declarations and their stylesheet/verifier/guidance links. This validates ownership routing, not unsupported-browser fallback behavior.

A choice card reflects both checked and indeterminate native inputs with the selection boundary. The catalog All collections card demonstrates a real aggregate mixed state; clicking it selects all available children. The native input owns indeterminate state, and the controller coordinates children. Its no-script fallback omits the aggregate control.

Field help remains visible and associated with its native control when empty, focused, invalid, read-only or disabled. Error text is conditional: attach its ID to `aria-describedby` when the error is visible, and remove that ID when correction or restore clears the error; preserve any persistent help ID. After attempted validation, correct input clears the local error and renewed invalid input restores it. Do not expose an inactive hidden error as the current description. The catalog and `check-field-descriptions.mjs` demonstrate this lifecycle and caption/margin geometry. These DOM associations do not prove screen-reader announcements.

Non-tabular collection transitions are demonstrated by the [directory recipe](../../../assets/recipes/list-states.html) and its [local controller](../../../assets/recipes/list-states.js). Native checkboxes own selection; filtering retains hidden checks and sorting moves existing rows. `aria-sort` belongs to table headers, so a list announces order through its status message. Empty lists expose recovery guidance with no visible row/body content. Preserve row margin and related title/metadata gaps; do not add full card padding to each row.

List separators follow visible rows. Filtering must not leave a trailing divider merely because hidden rows follow the final displayed item; keep the last-child fallback and the shared visible-sibling rule. The directory verifier rejects the old DOM-last-only rule.

Feedback notices use the same four-margin container relationship as cards/dialogs. Static feedback specimens must identify themselves as examples, without claiming a user action succeeded. A live notice uses status semantics only when the local controller actually updates it; skeletons remain decorative inside a named busy context. The local-check specimen demonstrates this distinction.

Action containers are layout hosts: hover/focus/active/disabled/busy belong to their buttons, not to the container as an independent control. `check-action-overlay-hosts.mjs` verifies the host relationships and native popup/dialog state. Read-only and disabled imported-value examples demonstrate application-owned errors, with visible described recovery outside the unavailable control. Their native `willValidate` is false; do not invent native constraint failures. `check-field-descriptions.mjs` verifies these explicitly labelled source-error specimens.

Each implementation includes an `evidence` route and scope. Resolve a family’s `environmentSet` through `implementationDefaults.testedEnvironments`; dedicated contracts name their environments directly. The [authored support record](../../../../wireframe-review/references/reports/component-support-2026-10-09.md) separates tested engine versions from installed Safari, assistive technology, physical touch and older-platform paths. Treat those fields as bounded evidence metadata, not minimum-version or accessibility guarantees.

Forced-colors mode uses the user’s system palette for essential custom paint. Checkbox/radio marks return to native appearance. Switch paint already uses system colors; slider rails/thumbs and the disclosure caret now do so as well, with forced-color-adjust:none restricted to those painted parts. Default palette declarations remain authoritative outside this mode. Do not preserve brand colors across a whole control or page merely to retain appearance. Run `check-forced-colors.mjs PLAYWRIGHT OUTPUT`: it checks actual raster visibility of the rail/caret, native state/keyboard interaction, focus and reduced-motion scroll behavior, with paint-removal controls. This emulation is separate from physical OS palettes, assistive technology and a complete contrast audit.

Geometry control height is the minimum interaction frame for actions and textual inputs/selects; content or enlarged text may increase it. Action names, including data-slot=label, wrap inside their frame rather than overflowing or ellipsizing. A selected-value slot remains a distinct one-line value presentation. Actions/textual fields retain half-margin block gutters as the frame grows; preserve the default inline margin, icon and radius roles; do not shrink text to force the original height. Choice marks align against their input’s actual em size for the first line. `check-text-enlargement.mjs PLAYWRIGHT OUTPUT` doubles initial computed text sizes and checks actual text-node bounds, native editing and deliberately too-short action frames. This synthetic stress is separate from native browser zoom.

Use `component-context.mjs --help` for the bounded interface rather than reading its implementation. `--output NEW_FILE` saves exact JSON outside the corpus and refuses replacement; use an existing output directory and a fresh filename. Keep read logs outside the saved-payload directory as well as the skill root. The lookup does not expand CSS, recipes or evidence guides; follow applicable references separately. It reduces this read boundary, not necessarily total session cost or downstream truncation.

Verify with `scripts/check-scrolling-flow.mjs PLAYWRIGHT OUTPUT`, including plain/slotted labels and doubled text. This is a layout relationship, not a larger geometry token.

Essential boundaries differ from decorative outlines. The shared profile uses --ui-label for editable field borders, unchecked checkbox/radio outlines, switch tracks, slider rails and input-group boundaries. Cards and dividers retain --ui-border/--ui-divider. Required paint must remain distinguishable against both interior and surrounding surfaces; custom backgrounds need their own measurement. Run `scripts/check-control-boundary-contrast.mjs PLAYWRIGHT OUTPUT` for the authored catalog boundary/glyph/switch/input-group-focus checks and old-outline negative controls. Its computed-paint scope excludes normal slider raster paint and a complete interaction or accessibility audit.

Checkbox/radio checked and mixed marks, switch on tracks and slider filled rails/thumbs use `--md-color-primary` paired with `--md-color-primary-on-primary`. Neutral action button aliases remain independent. Switch tracks and thumbs retain round/pill geometry at the 2n track height. Switch thumb position and background use the shared [Apple Smooth sampled spring](../../apple-smooth-motion.md); reduced motion disables these transitions.

Firefox paints slider progress natively. Chromium/WebKit use `--ui-range-progress` (a percentage, initially matching the value); update it on input/change and after programmatic updates using clamped `(value-min)/(max-min)*100`. The component recipe controller demonstrates this small paint synchronization. Without that controller, the native value still works but the authored fill cannot track changes; do not claim live CSS-only progress. RTL fills from the inline start.

Segmented controls fill their available inline width. Direct buttons use equal flex shares and stretch to the tallest option; long labels wrap within those shares instead of creating irregular rows. Keep options few enough to remain usable at the target width.

For margin composed controls, the container owns the outer radius and margin. Derive the child radius as `max(0px, outer radius - padding - border width)` so adjoining curves have the same center. Segments expose `--ui-composed-radius` and `--ui-composed-margin`; the outer radius includes presentation factors. Apply this relationship to the immediate contained surface, not all descendants. Independently sized nested cards keep their own geometry; asymmetric margins require corner-specific treatment.

Authored state colors share `--ui-state-duration:800ms` and `--ui-state-easing` (the [Apple Smooth sampled spring](../../apple-smooth-motion.md)): backgrounds, foregrounds, borders, outline colors, shadows and disabled opacity transition together across buttons, fields, marks, switches, tabs, segments, navigation, disclosures and selection rows. Use an explicit property list, never `transition:all`. State semantics, focus availability, visibility, dimensions and slider values change immediately. Reduced-motion and forced-colors contexts use zero duration. Ordinary links inherit their foreground immediately; they do not interpolate text color when an ancestor scheme or surface changes immediately. Check theme switches at intermediate frames as well as settled rest states. Native platform popup contents remain browser-owned. The gradient slider fill follows value synchronization directly; it is not a CSS-interpolated background image.

Identity avatars are square at `calc(var(--g-height) + 2 * var(--g-margin))`, adding two local margin units to the control frame. Initials retain the geometry text role; images fill the same square with object-fit cover. Size follows the inherited geometry context.

When a modal autofocuses a prefilled text input or textarea, put the caret at the end without selecting its value. The optional `assets/recipes/modal-autofocus.js` opening-toggle listener implements this after native autofocus. It checks the active element and selection support; it does not change subsequent manual selections, non-text inputs, focus trapping or dismissal. Include this helper with extracted dialog specimens when that behavior is required. Without it, native opening still works but caret placement remains browser-defined.

Table select-visible controls belong in the selection-column header, replacing its visible Select label with an accessible checkbox name. Mark header and body cells `data-selection`; their column hugs the minimum checkbox target plus standard cell gutters. Keep row checkbox names specific, mixed header state synchronized and the header disabled for an empty filtered result.

## Action labels in constrained rows

Use the shared action geometry for short and long names. Buttons use `flex-shrink:0`; buttons and their label slots use `overflow-wrap:break-word`. Short words retain intrinsic sizing while bounded long labels can wrap. In an inline field/action row, the field takes remaining space; do not give the action a character-sized track or fixed width. Let action groups wrap when needed. Check plain text and label-slot anatomy, long words, narrow rows and enlarged text. This is CSS layout, not a styling initializer.

For choice validation, keep the error description synchronized with validity. Hiding an error does not remove it from an explicitly referenced accessible description. Remove only the cleared error ID from aria-describedby, preserve other help IDs, and restore it if the error returns. Verify invalid mark styling against the native-input base rule as well as aria-invalid ownership.
