# Context efficacy hill-climbing, protocol 1

Status: exploratory fresh-context runs and a [controlled variant-guidance comparison](../references/reports/variant-contrast-2026-10-09.md) have been collected. That comparison passed its own frozen contrast and task-quality gates, including an unseen holdout. It does not complete the broader foundation/context, accessibility or corpus-growth protocol below.

Freeze task JSON, this protocol, foundation bytes, skill revision/hash, model/version and sampling settings before a round. Consumer runs start fresh. Give the evaluator a separate copy of acceptance rules; generator outputs cannot edit them. Store each run under OUTPUT/round/condition/task/repeat with prompt.txt, retrieval.json, artifact files, checks.json and review.json. Preserve failures; repairs create successor attempts. Record actual prompt bytes and contributing paths; token counts require a named tokenizer. Missing telemetry is unavailable, not zero.

Conditions: A gets task plus foundation CSS and starter example; B gets those plus SKILL and task-relevant context through its routes. Freeze the allowed source sets and compare three repeats per development task in both conditions. Keep model/settings fixed. Do not supply B-only guidance to A. Use another operator/runner to start independent model sessions; hand-authored specimens are not benchmark evidence.

Acceptance checks: valid artifact/build, native semantics, resolved token roles, geometric invariants applicable to the task, keyboard reachability, no critical clipping or unintended operations. Evaluate actual behavior rather than matching class names. Inject one known defect per relevant detector and verify rejection before trusting it. Score unsupported/inconclusive separately from failure and pass.

Blind review: randomize IDs and hide conditions. Two reviewers rate family resemblance and task clarity from 1 (inconsistent/confusing), 3 (usable with visible mismatches), to 5 (coherent and clear). Show established references; do not provide target layouts. Record disagreements. Accessibility and correctness failures cannot be offset by aesthetic scores.

Hill climb: classify the dominant development failure as retrieval, ambiguous instruction, missing guidance, scaffold defect or design judgment. Change one coherent cause. Preserve baseline and rerun affected cases plus at least one unrelated regression case. Accept only if critical failures do not increase, median clarity does not decline, and the targeted metric improves (fewer corrections or at least one rating point). Revert otherwise. Stop after three rounds, two rounds without improvement, or a declared time/cost cap; record the reason.

Holdouts: open only after the development candidate is frozen. Run all holdouts under A/B with the same repeats. Do not tune against those results and call them holdouts again. An acceptance target is zero critical failures and a one-point median family-resemblance gain without reduced clarity. Small samples are exploratory; report each run and spread, not a broad reliability claim. Failed holdouts inform a later round with newly authored holdouts.

Corpus-growth test: add an unrelated branch to a temporary corpus copy. Selected context should remain unchanged while whole-corpus reference checks include the added branch. Check an intentionally broken reference and unsupported contract version fail explicitly. These retrieval tests require a measured runner; existing browser tests do not establish them.

Prepare a fresh round with `node scripts/init-eval-round.mjs NEW_OUTPUT MODEL_VERSION`. This snapshots the corpus and creates 18 development run records. It does not launch models or assign scores. Keep generated run output in a fresh `/private/tmp/*` directory outside the skill source. System cleanup may purge it; retain required results and identities in the existing evidence location before publishing durable references. Preserve historical runs and peer-owned files; do not create sibling preview destinations. Specify actual generation settings before starting; never overwrite a previous round. Holdout tasks are in tasks.json but must not be supplied to development generators.

## Cross-model transfer and revision

Apply the same stable inputs, customization boundaries and acceptance to each model; record exact model ID, effort, corpus/template hashes and permissions. Do not infer a model-tier instruction policy from exploratory peer examples. No cross-model reliability claim follows from a single run.

A separately authorized bounded transfer batch uses two unlike task families plus one identical common revision request per model. Freeze evaluator acceptance first, including state-specific measured surfaces from [reuse and measurement](../references/workflows/reuse-and-measure.md). Preserve first-pass and revision artifacts. If failure-specific repair is tested, give equal bounded opportunities and report it separately from ordinary revision.

Report four independent dimensions: input fidelity/provenance, visible paint and actual geometry, real interaction/state/focus, and review feedback’s preserved historical versus fresh current context. Aesthetic scores or successful export cannot cancel another dimension’s failure. Reuse applicable unchanged checks; inspect fragile helpers by observed behavior, not function names. Report requested versus measured width and unavailable telemetry separately. Keep existing sealed holdouts sealed unless their own authorization/protocol permits execution.

Revision preservation is an independent delivery criterion. Use revision-source.mjs prepare with an evaluator-owned predecessor, numbered successor and full-inventory baseline; generate with --preserve and independently verify before/after. Detect additions, deletions and byte changes. Read-only copy permissions are advisory under unrestricted same-user execution. Report prevention only with enforced isolation; otherwise report delivery rejection by detection. Never change user workspace permissions or restore mutated historical evidence by inference.

At the revision phase boundary, prepare-next reserves the next unused numbered successor and freezes the current predecessor inventory. Do not prepare during creation or reuse a stale existing baseline. Isolate dispatch/preparation errors per lane: catch and record that phase as unexecuted/setup failure, then continue unrelated lanes (Promise.allSettled or equivalent per-future exception handling). Preserve reserved failed folders and the original wall cap; resume only undispatched phases. Emit-only success and delivery-qualified success remain separate denominators.

## First-submission screens and screenshot integrity

When a bounded screen forbids repairs, the evaluator supplies `node scripts/eval-submit.mjs ATTEMPT_DIR MANIFEST NEW_OUTPUT PLAYWRIGHT [--controller FILE]` as the generation entry point. ATTEMPT_DIR is evaluator-owned and starts without submission.json. The gate atomically admits one attempt, including compilation failures, and retains its receipt. Use `python3 scripts/run-eval-attempt.py LANE_DIR CAP_SECONDS MODEL EFFORT` with evaluator-authored prompt.txt to stop the agent when that receipt completes; reject later/direct generator submissions from scoring. This detects protocol bypass; unrestricted same-user filesystem access is not prevention. Preserve failed source and traces. Do not treat an agent's repaired output as a first pass.

Capture emitted iframe content with `capturePreviewBody(page, iframeLocator, path)` from scripts/lib/preview-capture.mjs after state/scheme settling. It removes only outer-shell scaling/clipping during capture, verifies inner width and paint bounds, then restores shell styles. Do not modify authored iframe content to make it fit. Retain original incomplete captures as historical evidence and qualify visual judgments separately from scroll/hit checks. The helper rejects a transformed or clipped capture it cannot normalize.

For source-only screens, use the same runner with `--source-only` and evaluator-owned `expected.json` containing `sources: [{path, placement, controller?}]`. Paths are assigned child directories; declared controllers must exist within their source directory. Authors submit a root or source-directory `submission.json` with that envelope. Normal final returns must name the source directories and controller paths; an existing undeclared controller is not inferred. The runner seals source bytes and metadata before evaluator assembly and generation. This mode performs no generation in the author process and does not change the ordinary generation gate. Qualify nested signals and normal-final controller retention before dispatch; preserve failed admission and traces. Polling under same-user access is detection, not atomic filesystem isolation.
