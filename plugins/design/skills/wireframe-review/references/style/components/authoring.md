# Component authoring route

Read shared constraints once with `node scripts/component-context.mjs --shared`. Request used records in small batches, e.g. `node scripts/component-context.mjs --records choices,fields --record-only`; use additional batches or `ID --record-only` for later additions. Each batch rejects output above 12,000 bytes; split it rather than increasing the budget. Reuse returned records. Known IDs need no `--list`; use it only for discovery. Dedicated native-select/navigation-menu lookups return their own complete contracts. Reuse returned records in the session; reread only when the relevant source changes. Do not read the entire family README, catalog runtime or contract merely to find anatomy. For one concrete example, use `demonstration-context.mjs MEMBER_ID`; use `--list` only for an unknown member. For incident review/resolution use member `operations-task`: it demonstrates the collections operationComposition contract without requiring unrelated component examples.

For local behavior retrieve `component-context.mjs --runtime` before controller authoring; register the actual leaf ID and keep DOM access inside mounted render/bind. For a required-title staged flow use the stepper transitionContract and its title-request recipe. For submitted native choices use choices.authoringExample; its inner editor preserves host inset.

Before markup, map each used family to its exact anatomy and native/JavaScript owner. Layout classes do not style native marks: checkbox uses `input.checkbox__control`, radio uses `input.radio__control`, inside the contract's associated label/body composition. Switch follows its separate contract. Do not replace the input semantics. Choice groups use field-group__root plus an inner options__root; choose plain inside cards. Workspace-specific options follow choices.nestedOptions, inside one choice container as sibling labels, never inside its radio label. Staged flows require the [focus and task guide](workflow-patterns.md#focus-and-task-grouping), including the runtime-supplied helper and actual Next/Back checks; use the stepper contract and maintained example: use form.stepper__root and ol.stepper__indicator[data-step-layout=adaptive][role=list] with the explicit indicator/title/status/check slots. Minimal native numbering is an explicitly requested fallback, not the generation default. Identify the current li with aria-current="step" and expose current/completed/upcoming text labels. Upcoming does not mean unavailable; unavailable/branching stages require a separate declared implementation.

Before adding a token reference, look up its exact name with `generate-token-index.mjs --group NAME` (color, typography, geometry, layout or profile). Reuse that group; never guess a name or hide a miss behind a fallback. The generator rejects unknown references.

For exclusive collection filters, use the navigation record’s filterAnatomy: direct aria-pressed buttons in segments__root, never actions__root alone. Apply segmentedGeometry: split one inset between container and items and derive inner radius. Change filter content and pressed state together; verify selected rest paint after moving focus away.

When editable source already contains the maintained implementation, retrieve a duplicate recipe only to resolve a missing seam or adaptation question. Keep exact contracts and runtime prerequisites available; do not load all demonstrations or historical reports to author one component. Reuse unchanged reads and distinguish static packet size from measured authoring overhead.

## Composition decisions before styling

- Geometry ownership: use card__root, page__flow, section__flow, flow__root, cluster__root and their density/spacing contexts before writing layout CSS. Custom grids may arrange columns, but insets and gaps must consume the declared local roles (for example calc(3 * var(--g-inset))), including responsive overrides. Matching 32/24px literals is not token consumption. Do not zero a maintained owner’s margins/gaps to rebuild its anatomy.
- Tables: choose local horizontal scrolling with a labelled, keyboard-reachable scroll region and readable column minimums, or an explicit narrow-screen record representation retaining each value's header association. Preserve native table semantics when scrolling. Associate a persistent visible table__hint through aria-describedby; enable the local scrollbar. Do not solve width by `word-break:break-all` or fragments of short status/priority words. Check actual words at 390px and enlarged text; absence of document overflow is insufficient.
- Selection/detail tasks: put chooser before detail in DOM and narrow-screen reading/focus order. Avoid CSS ordering that disagrees with the task. Keep selected context adjacent to its detail and consequential actions. For incident review/resolution follow collections.operationComposition: selected detail → evidence → bounded plan → Resolve inside one task group, in DOM and narrow reading order. Use collections recordSelection and record-choice__root for record buttons; update aria-pressed and detail together and verify paint after blur.
- Evidence/research tasks: group related claims into quiet collections, emphasize the selected claim rather than every card, and keep evidence/detail/plan visibly connected. Check task distance and scrolling independently of token compliance; do not force a specific desktop arrangement.
- Supporting text: use the foreground paired with the actual surface. Enabled help and readonly content are not disabled exceptions. Verify help, errors and open disclosures in light/dark states; require normal text contrast of at least 4.5:1, retaining measurement uncertainty near the threshold.

## Verify the authored result

Read generation warnings and unverified coverage. Missing mark anatomy is actionable; unknown custom geometry owners require inspection, not a claim that zero warnings means fidelity. Test Save/Start through real user clicks and keyboard activation in Browse mode; see [controller guidance](../prototype-runtime.md#user-activation-and-form-defaults). Inspect current-step paint and mobile order on the final artifact. Static lint does not prove these behaviors or contrast.

Top-level product pages use page__root page__flow: page__root owns the gutter, page__flow owns section gaps. Do not put page__root on nested groups. Non-tabular selectable records use card-option geometry through button.record-choice__root, with title and metadata in separate slots; compact selectors inside td/th retain the control minimum height, 0.5u block/1.5u inline gutters and control radius. Wrapping grows height; a choice-body does not add another inset. For staged collection tasks, read [the stepper workflow guide](workflow-patterns.md#focus-and-task-grouping): it owns post-render heading focus and catalogue/summary/action grouping.

For custom interactive controllers, `component-context.mjs --runtime` gives the supplied module-scope API contract without loading the catalog implementation. Use only listed helpers or explicitly owned recipe dependencies. Runtime startup is separate from final task acceptance.

For a complete task surface represented by one leaf, use authoring-starter.mjs with `--surface page`; its page__root wrapper owns the outer gutter. Keep the default embedded surface for examples placed inside another page. A card is not a page wrapper. Use `assets/recipes/booking-composition.html` for explicit catalogue/summary gap ownership; retrieve the exact stepper demonstration for progress anatomy. Each checkbox remains input.checkbox__control inside its choice label; stepper__root alone does not create indicator/label/connector slots.

When evaluating kit consumption, deliver the authoritative foundations and wireframe stylesheet rather than substituting a simplified parallel palette or geometry ladder. Distinguish native-semantic behavior from actual system styling; preserve source identities and group feedback beside its owning field.

## Applying the retrieved anatomy

Use declared classes and modifiers from the selected record, not plausible aliases such as button-secondary__root. Keep a field's required marker in the same label text run; do not add a separate flex child merely for punctuation. Distinguish a task introduction from the current step instruction: repeat a heading only when it supplies new context. In review summaries, keep each value adjacent to its label and put save/session status outside that pair. Give Back and confirmation their declared action treatments rather than relying on identical default buttons. These are composition checks, not a prescribed layout.
