# Reuse and measured surfaces

Use when adapting a maintained recipe, reproducing a baseline, or reviewing an overlay/constrained surface. The same contract applies across model families; the peer experiments are exploratory, not evidence for model-specific reliability rules.

## Stable inputs and customization seams

Identify the exact baseline implementation, representative fixture/data, token source and required icon assets before authoring. Preserve required values, order, starting state and provenance. Missing inputs are unresolved scope; do not invent a substitute baseline. Keep freedom in task composition and requested alternatives.

The builder owns foundations, icon compilation, review notes/snapshots, feedback export and proposal lifecycle. Use these executable implementations instead of reconstructing them in each proposal. In a maintained controller recipe, customize unit IDs, fixture/domain state, reducers, render selectors and handlers. Retain shared helper behavior and scoped mount/cleanup contracts. If a helper needs a change, make it explicit and verify its original invariant; a retained function name or matching asset path does not prove paint or behavior. Do not copy the entire catalog runtime for one interaction. Recipe source comments identify these seams.

## Surface measurement contract

Keep evaluator measurements outside the manifest; this is an evidence record, not a new manifest field or runtime API. Declare the visible surface in each relevant state: a trigger when closed, the actual popup/dialog when open. A wrapper is valid only if it is itself the constrained surface.

Record selector or resolved element identity, open/closed state, CSS-pixel units, requested width, available container width, actual bounding rectangle and viewport/scheme. Derive the allowed bounds from the brief: fixed width, maximum width and fluid container fit are different requirements. Measure after layout/state settles; include relevant border/inset ownership and long content. Missing or ambiguous surfaces are unverified, never a zero width. Check requested versus actual width, clipping and focus separately. Do not infer rendered dimensions from token values alone.

## Evidence dimensions

Score input fidelity, visible result, actual interaction and review loop separately. Verify actual light/dark icon paint and dimensions; real keyboard/pointer state/focus; and note-time context versus freshly exported current context. Keep historical snapshots immutable when current state changes. Shared shell tests may be reused only for unchanged mechanics; component-specific state and surface behavior still need their own checks.

For transfer evidence, freeze identical inputs/settings per model, choose two unlike task families and one common follow-up revision. Preserve first-pass outputs and revision successors; never evaluator-repair them. Report each dimension, disagreements and untested conditions, including failure-specific repair versus ordinary revision. See the evaluation plan; this guide does not authorize another run or opening a sealed holdout.
