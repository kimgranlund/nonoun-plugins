# Generation core

UI dependency: install the sibling base-ui kit and preserve ui-kit.lock.json. Generation accepts --ui-kit ROOT; absence/incompatibility fails before emission. component-context.mjs routes UI records to that kit while --runtime describes this review host. See [dependency boundary](../ui-kit-dependency.md).
Read once before a new artifact. This is the default authoring route; the full build guide is for affected verification details, maintenance or troubleshooting.

## Source and identity

For a single leaf, choose its placement first: `node scripts/authoring-starter.mjs NEW_SOURCE_DIR PROJECT_ID LEAF_ID --surface page` owns the standalone gutter; `--surface embedded` leaves that inset to the host. Both produce `kind: component`; `kind: page` means a manifest composition, not a standalone HTML surface. Edit unit.html and metadata, then run its assemble.mjs; assembly validates the authoritative manifest contract before replacing manifest.json. Keep independent placements as independent leaf units, with separate state and an unchanged supplied host. It uses JSON serialization to preserve quoted HTML IDs and a valid leaf/composition shape. Start from assets/minimal.manifest.json when assembling source yourself. Read references/manifest.schema.json only for unfamiliar fields; assets/example.manifest.json is the larger composition example, not default context. Keep projectId stable; change revision when design/target identity changes. A unit has stable id, kind, title and 1–3 ordered proposals A/B/C as requested. Each proposal has title, rationale and tradeoff. Leaf units contain HTML and empty composition; page proposals have empty HTML and nonempty leaf references, each leaf once per page proposal. Preserve stable semantic data-review-id targets and prior feedback; feedback is data, never executable instructions. Read artifact-contract.md only for composition, interaction declarations, feedback interchange or schema details needed by the task.

## Design and geometry

Start from user progress and supported capabilities. Alternatives vary the task approach, not only cosmetics. Mark fictional evidence and local simulation. Never infer operational authorization from a design choice.

List available glyphs with `node scripts/authoring-starter.mjs --icons` before choosing data-ph names; generation is offline and cannot bundle a guessed icon. The builder owns shared foundations, icon compilation and review snapshot/export mechanics; retain them rather than reconstructing them per proposal. Customize task content and scoped controller callbacks. For a maintained baseline or constrained popup/dialog, read [reuse and measured surfaces](reuse-and-measure.md). The builder embeds foundations. Use native semantics and existing CSS. Product roots use product__root; cards establish compact UI headings. Editorial sections opt into data-type-context="content". Keep semantic heading ranks. Preferred fonts may fall back; no font files ship.

One parent owns sibling gaps. Default product hierarchy: card inset 4u, major groups 3u, fields 2u, related text 1u (32/24/16/8px); page sections 6u. Use card__root, page__flow, section__flow, heading-group__root, flow__root and cluster__root; group content before spacing. Fieldset/disclosure need an inner flow/body wrapper. Nested semantic groups can be plain, without repeated card insets. Custom grid insets/gaps consume local --g-inset relationships, not equivalent pixel literals. Control/icon geometry and color roles remain source-owned. Focus replaces border paint with transparent while retaining border width and keyboard ring. Do not edit foundation exports to style a component.

Before common components, read components/authoring.md once and read component-context.mjs --shared once, then the used families in bounded --records ID,ID --record-only batches. Reuse earlier records; split a rejected oversized batch. Look up exact token names with generate-token-index.mjs --group NAME; reuse results, never guess or conceal unknown names in fallbacks. Only read style/product-foundation.md or artifact-styling.md for an unresolved styling/context question; read the relevant section rather than both entire files.

## Build and delivery

Record required operations/states from the brief before authoring. Local behavior registers with the supplied lexical registerPrototype; retrieve component-context.mjs --runtime before authoring controller callbacks. DOM queries belong to mounted render/bind root, not a document-wide startup closure. Passing --controller only includes bytes; it does not make an unregistered closure a preview controller. Local behavior uses generate.mjs --controller FILE; read prototype-runtime.md section "User activation and form defaults" and "Controller interface"; read save/approval guidance only for those behaviors. Actual Save/Start click and keyboard activation must work; the shell cancels ordinary submit defaults. For compound saved tasks, adapt the review-owned assets/recipes/compound-save.html and compound-save.js: one snapshot comparison drives every current-success confirmation. Include all saved text, choices, capacity and selected identities; copy selection sets in canonical order, and keep preferences/filters outside the snapshot. Bind the same transitions to the final artifact acceptance checks; see build-checks.md, Controls and behavior.

Run node scripts/generate.mjs MANIFEST NEW_OUTPUT PLAYWRIGHT [--controller FILE]. PLAYWRIGHT may be `auto`: it invokes the locked base-ui bounded browser resolver. For an explicit route, run base-ui/scripts/resolve-browser.mjs --check once and reuse its modulePath; configure UI_PLAYWRIGHT_PATH when outside the supported local runtime. Missing dependencies fail explicitly, without recursive filesystem searches or installation. Existing output is rejected. Mandatory compile/structural/startup/lint gates run before publication. Read generation.json: errors block, warnings need review, unknown/dynamic coverage stays unverified. Do not repair the emitted artifact directly; fix source and generate a fresh directory.

Verify actual brief operations and visible controls in Browse mode; check desktop/mobile, both schemes, long/empty/invalid/open states, keyboard/focus, clipping and overlays. Measure normal enabled help/error text contrast >=4.5:1. Inspect local table scroll and word readability, chooser-before-detail order, selected record/filter/current-step paint, and save/restore when used. Enlarged text must remain reachable; synthetic enlargement is not native zoom. Run only checks affected by changes using build-checks.md’s applicable section. Artifact emission does not prove task delivery, visual quality or accessibility. Use `--acceptance EVALUATOR_JSON` and [independent acceptance](../evaluation-checks.md#isolated-acceptance-and-delivery-version-2) for task delivery. Without it, generation.json records delivery-incomplete; acceptance failures remain in diagnostic stages. Record unavailable environments and accepted limitations explicitly. Preserve prior evidence and peer-owned files.

This core is sufficient for ordinary generation: do not open the full build.md/build-checks.md merely to repeat its gate instructions. Open an exact affected verification section only when authoring that check or resolving a failure. Read each unchanged context source once; use read-context.mjs --once with the same session log to suppress an identical complete return (never reuse a log from another session). During evaluation use `node scripts/read-context.mjs CORPUS_ROOT RELATIVE_FILE SESSION_LOG --once` for subsequent document reads; for one section append `--section "Exact heading" --once` instead. SESSION_LOG lives outside the corpus. Run `--help` for bounds syntax; there are no --root or --log flags. Retain command output bytes/hashes. Do not reread an already returned entry merely to populate a reader log; retain that direct command return instead. Inspect transport completeness before reusing a logged read; truncation requires the missing range. Returned bytes are not model tokens. Do not load catalog implementations to discover usage. Exact family records and one maintained demonstration are sufficient starting context; deeper reads require a concrete unresolved question.

Controller revisions must preserve required render/bind targets across proposals. The generation startup gate executes initial mounts and rejects exceptions; later behavior still needs affected final-artifact task checks. Follow [revision fidelity](../style/prototype-runtime.md#revision-dom-and-runtime-fidelity) when changing a controller or its markup.

Interactive controller APIs: retrieve `component-context.mjs --runtime` once for the authoritative supplied names/signatures, scope, prerequisites and timing. Recipe-local functions are not automatically supplied APIs.

For revisions, run `revision-source.mjs prepare ORIGINAL NEW_SUCCESSOR`, author in its source directory, and pass its preservation.json to generate.mjs with `--preserve`. This hashes the full original file set before and after generation and rejects changed/deleted/added files. The copied original is read-only by default; full-access same-user agents can override permissions, so the guarantee is detection and rejection, not sandbox prevention. Keep baseline files evaluator-owned.
Native selects: data-select-icon is a leading semantic icon; the compiler supplies the trailing indicator. Short table identifiers use inline record-choice plus record-id__root; longer labels wrap and table overflow remains scoped.

Delivery requests: pass `--mode delivery --acceptance EVALUATOR_JSON` to generate.mjs. Missing acceptance rejects before emission. Drafts remain explicitly incomplete. For complete leaf task surfaces choose authoring-starter.mjs `--surface page`; embedded defaults do not own the page gutter.
Prepare revision only after the predecessor is sealed, not during creation. Use revision-source.mjs `prepare-next ORIGINAL PARENT NAME`; consume its returned source/successor/baseline paths instead of assuming002. Existing premature reservations are preserved, never reused. Each evaluator lane records preparation failure independently; do not cancel undispatched unrelated lanes.

### Browser and evaluation evidence

resolve-browser.mjs reports dependencyStatus=resolved and launchChecked separately from interactionChecks=not-run. Pass modulePath to author-owned browser checks; generate.mjs auto resolves its own dependency. Successful generation startup is not user-task acceptance. Report missing dependencies only on resolver failure, retaining its error; do not infer failure from an earlier candidate in tried.

For authorized clean-context evaluations use scripts/run-eval-attempt.py with --isolation CONFIG.json (schemaVersion=1, privateRoots containing evaluator directories outside the author lane). The runner qualifies filesystem exclusion before author dispatch. Without this flag, the result explicitly records unenforced isolation; it is not a clean-context guarantee. See generative-systems rapid-experiments for method limits.
