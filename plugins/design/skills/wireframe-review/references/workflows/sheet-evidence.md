# Sheet evidence format

An external report uses `schemaVersion: 1`, `sourceHash`, `generatorSha256`, `outputInputs` and `records`. Source identity comes from the generated inventory. `outputInputs` maps the subject page and `foundation.css`, `sheets.css`, `sheets.js` to their SHA-256 hashes before evidence attachment. Reports never enter the corpus source hash.

Each record contains `unitId`, `specimenId`, `checkId`, `outcome` (`pass`, `fail`, `inconclusive`, `unverified`), nonempty `sourceInputs` (`path`, `sha256`), and `environment`. A source-only environment declares `kind: source-only`. A browser environment declares `kind: browser`, browser name/version, viewport width/height, light/dark scheme, and geometry tier/scale/size. Record measured values, procedure and limitations as additional fields. Identify synthetic text enlargement separately from native browser zoom. Installed Safari and Playwright WebKit are separate environments.

Routes use `schemaVersion: 1` and nonempty `units`. Each route has a unique `unitId`, generated `page`, target `elementId`, optional `specimenId`, and nonempty `expectedCheckIds`. A route for application behavior also lists its additional generated runtime files in `requiredOutputFiles`; those files must appear in `outputInputs` and match the actual generated bytes. A missing or changed required runtime makes that evidence stale. Invalid paths and duplicate dependency entries are rejected. The target must contain exactly one Verification inspector with a contained body.

Compatibility means the recorded outcome matches these identities and required check IDs. It does not establish coverage of every environment or state. Required environment coverage belongs in the owning verifier and acceptance specification. A source or output mismatch is stale. Missing required checks are unverified. A compatible failure remains a reported failure. Reports are inspectable data; text is escaped and never executed.

The attachment step preserves original scope notes and stores the external report plus `evidence-presentation.json`. That file records both the pre-attachment subject hashes and the resulting page hashes. Do not verify the changed presentation against its old page hash or edit historical reports to make them match new builds.

Optional `measurements` records render as an inspectable table. Each entry provides `label`, `kind` (for example actual-layout or resolved-property), `value`, `unit`, and optional `expected` relationship. Tables preserve the report's evidence kind; they do not convert resolved CSS values into box measurements. The owning verifier must record how actual boxes and expected relationships were derived, and include a deliberate layout failure control.

The presentation provenance also hashes the attachment script and compatibility resolver. These identify the transformation implementation independently of the source report and pre-attachment subject.

The evidence presentation step adds an Index summary of routed unit states and recorded outcomes. Bind `outputInputs.index.html` too; a missing Index identity leaves the rollup unverified, and a mismatch makes it stale. Neither receives credited outcome counts. These are scoped external report counts, separate from work-register acceptance and generation results. Observation-capture passes do not certify typography quality or portable font availability.

Record motion settings and sampling phase with state measurements. A computed hover color during a transition is not the settled hover-role color. Either wait for the declared transition to settle, or explicitly use and record reduced motion for final-state checks. Keep intermediate-paint observations separate; do not compare their ratios as measurements of the same settled pair. Final-state contrast does not prove contrast throughout a transition.

Generated `renderedDependencies` binds page-specific executable files automatically. A dependent-page report includes `inventorySha256` in addition to those files in `outputInputs`; changed inventory bytes or missing runtime identity cannot receive current credit. Optional route dependencies supplement that map. Use canonical relative names without dot segments, duplicate dependency spellings or duplicate page/element targets. Static legacy outputs without the dependency map retain their existing format.

Label copied-snapshot fault data as synthetic predicate guards. They show a predicate rejects bad data; actual lifecycle, reentry and completion require separate DOM/runtime observations. Do not count synthetic guards as runtime fault injection.

Mount computed-color probes in valid document elements, preserving the measured target's computed custom property and color scheme. Inputs are void elements; appending a probe inside an input can return an empty computed color. Keep this instrumentation out of product markup.

For short asynchronous examples, capture the running snapshot, guarded reentry and associated paints in one browser task. Separate observations can cross a legitimate completion boundary. Verify completed work against controlled input, not just nonempty status text. Record any timing/measurement failures as such rather than turning them into canonical contrast or lifecycle defects.
