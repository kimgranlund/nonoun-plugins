Both Terra runs read product-primitives.html, whose footer was a placeholder and whose sequential content had no spacing owner. ## Diagnosis and changes

| Failure | Evidence classification | Revision |
| --- | --- | --- |
| Missing/unstyled account menus | Dedicated recipe reportedly unread by Terra; general contract read; primitive recipe supplied a placeholder | Direct conditional menu route in SKILL, working account menu in product recipe, explicit equivalent-behavior requirement |
| Vertical gaps | General spacing rule reportedly read, but primitive inventory omitted flow/stack and recipe did not demonstrate ownership | Name implemented flow/stack primitives; demonstrate fieldset inner flow and outer flow; distinguish inset from sibling spacing |
| Inverse text pairing | Rule existed and was reportedly read; generic advice to override roles did not prevent direct palette overrides | Explicit contextual aliases and concrete forbidden partial overrides in the owning component contract; styling guide links to it |
| Phosphor adoption | Contradiction confirmed: styling guide demanded per-name mask rules despite runtime resolver | Remove obsolete instruction; document automatic regular-name resolution and delivery check |
| Token invention | Exact lookup existed; generators still guessed; build guard caught unresolved names | Retain lookup/preflight and fallback caveats; no duplicate token-name inventory |
| Missing revision behavior | Runtime rule reportedly read; operations omitted from generator declarations | Require brief-derived acceptance before implementation; list consequential edits before writing reducers |
| Passing incomplete reports | Verifier only checks declared interactions; omission comparison was a late caveat | Make acceptance route mandatory for new builds; explicitly identify completeness, contrast and spacing as separate checks |

The component table formerly called classes opt-in without separating optional syntax from required behavior. It now permits custom anatomy with equivalent verification while retaining behavioral requirements. Plain disclosures remain valid for disclosure content; the menu requirements apply when the task calls for a menu.

No new context layer or manifest was added. SKILL grew from 314 to 343 whitespace words. Product foundation grew from 464 to 642, build guidance from 674 to 800, and runtime guidance from 292 to 329. General styling shrank from 1,424 to 1,408 by reconciling surface guidance and removing the stale icon instruction. This is targeted additional context, not a claim of compression.

## Verification and limits

26 selftests pass; skill metadata validation passes; changed Markdown links resolve; token index and source observations remain current. Product regression suite passes 13 checks, including desktop/mobile nested and outer gaps, a removed-gap negative control and the recipe's new account menu. Final gate still rejects untested declared claims and accepts exercised behavior. Test fixture no longer supplies a grid gap that could conceal a missing recipe spacing owner.

The broad evaluator-owned requirements gate, computed contrast gate for arbitrary generated components and full menu/control inventory are not implemented by this documentation revision. They remain follow-up work. No fresh generation was run against this revised corpus, so improved adherence is unproven.

For the next context experiment, freeze this candidate and capture actual reads: path, requested range, returned/truncated status and bytes, plus command-produced declaration groups. Keep system/tool execution inputs separate from model-visible reads. Name a tokenizer if reporting tokens. Use the same task/model settings and independent acceptance requirements; log pre-emission corrections separately. Test menu adoption, spacing ownership, surface pairing and required-state coverage, with negative controls, before expanding the corpus.
