# Context system specification

## Tasks and scale
Representative tasks, audiences, success checks, observed friction and expected size.
What a local index already solves; why additional machinery is justified.

## Entry and routes
Actual runtime entry behavior, known-path entry, local navigation and acceptable
alternative paths. Separate physical, semantic and task-context relationships.

## Required responsibilities
Use relevant T0-T11 responsibilities only; explain omitted or combined layers.
Declare governing scope and conflict resolution within actual harness authority.

## Metadata, if needed
Canonical descriptors, optional generated registry, path base, IDs/aliases,
relationships, revision/hash provenance, owner, generated-source ownership and
freshness checks. Use the JSON profile or document an equivalent adapter.

## Retrieval and delivery
Read/byte budgets, required versus optional edges, cycle/error/conflict behavior,
stop conditions, and available/requested/returned/submitted ledger support.

## Migration
Stable IDs, compatibility aliases, callers, generated index refresh, rollback and
keeping temporary execution artifacts separate from reviewed durable knowledge.

## Acceptance and evaluation
Task-specific requirements independent of the route implementation. Frozen replay
cases, negative controls, passing neighbors, before/after correctness then costs.
Distinguish structural validation, authored replay and actual runtime outcomes.
