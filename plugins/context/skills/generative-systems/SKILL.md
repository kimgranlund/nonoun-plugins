# Generative systems

Help an author turn authoritative materials into a working, reviewable result, and help a maintainer improve that path with evidence. Resolve the user's outcome and the supplied system before prescribing implementation. Use this skill when context, source ownership or reuse boundaries materially affect the task; domain skills retain their tools, values and delivery procedures.

Choose the mode from the request: design or repair the system; apply it to generation/revision; diagnose drift; or evaluate a proposed change. Read the most relevant reference below first. Follow another only when the task crosses its boundary; a small correction does not need the whole corpus or a new evaluation.

## Authority and delivery

Distinguish authoritative values, semantic decisions, executable capabilities and observed evidence. Give each fact an owning source. Retrieve exact supported names and applicable prerequisites instead of inventing kit fidelity. Examples illustrate a supported adaptation; they do not expand a schema, API or execution permission. Flag material gaps and conflicts explicitly.

Preserve trusted mechanics and make the editable join explicit. Required host slots, callback signatures, mounted scope, generated fields and artifact identity must come from the supplied system. Source parity is one check; it does not prove integration, activation or task success. A visual page and a schema's page composition may be different concepts.

Separate structural validity, runtime startup, user activation, task outcome and visual quality in delivery claims. Reuse unchanged evidence within its tested boundary. Accepted limitations remain scoped; they are not general waivers. Change the responsible source when supported learning warrants it, retaining original failures and uncertain mechanisms.

## Scope

Use the project's existing organization and preserve original artifacts, evidence, peer-owned files and sealed holdouts. Disposable probes belong in an agreed temporary workspace. Do not promote experimental material or run model studies merely because a generation task was requested. Ordinary authoring can self-check and repair; first-submission restrictions apply only to experiments designed to measure that boundary.

This first version synthesizes UI-generation findings. It supplies reasoning rather than a copied kit, runtime, validator framework or universal design scale. Cross-domain efficacy and automatic instruction delivery remain unverified. JSON, Markdown and scoped instruction packages are options with different navigation and authority effects; no universal winning format is established.

Proposed goals and measurement definitions: [performance contract](references/performance-contract.json). Read when evaluating or changing intended outcomes; ordinary authoring does not require it.
