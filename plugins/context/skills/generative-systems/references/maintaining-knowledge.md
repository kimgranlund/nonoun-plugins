# Maintaining knowledge

Use when adding supported learning to a corpus or publishing updated materials. Find the existing owner before adding another rule or reference.

## Upsert by evidence and applicability

Classify the finding as principle, observed failure, scoped verified result, recommendation or open question. State why it changes a decision, when it applies and its evidence boundary. Keep uncertain mechanisms uncertain. Transfer from UI to documents/content/code is a hypothesis until exercised in those domains.

Distinguish absent guidance, failed discovery, contradiction, application, evaluator and environment causes. Repair the responsible boundary. If a critical fact already exists but was not retrieved, improve its task-triggered route instead of copying it everywhere. If a read contract omits a concrete adaptation, add the smallest discriminating example. If machinery is faulty, prose alone is not a fix.

Preserve valid exceptions. A missing form collection owner does not imply every control needs a form; a page-kind error does not imply every task needs a composition manifest. Local design values and browser workarounds remain with their kit/environment owners.

Retire stale current guidance while preserving historical reports and original results. Correct erroneous claims through a successor note with provenance. Keep lesson IDs stable where they support links; avoid accumulating a permanent wall of mandatory rules.

## Migrate existing consumers

When introducing a constraint into an existing system, distinguish reviewed initialization of legacy debt from later regressions. Version the baseline with its rule and source revision. Match debt by qualified occurrence identity: removing one old violation must not authorize a new one elsewhere. Review ambiguous moves or mappings rather than silently resetting the baseline.

For capability deprecation, retain replacement and migration guidance for affected consumers even when new-use discovery excludes the capability. Retirement requires evidence about supported consumers and compatibility, not merely an empty violation baseline. Record unresolved external or dynamic uses and the applicable retirement scope. Keep these controls conditional on migration work; a small authoring change does not require a new baseline framework.

## Budget and publication

Keep current instructions small and route conditional detail. Count added read dependencies as a maintenance cost. An evidence index supports provenance lookup; it is not a default foundation packet. Do not copy full run logs or a domain runtime into a knowledge skill.

Publish derived views from the authoritative current sources. Check source/package parity and affected consumer references; do not hand-edit a generated catalogue while leaving its owner stale. Respect peer-owned files and the canonical destination. For disposable probes use the project's agreed temporary scope and retain necessary evidence before cleanup.

Reuse qualified checks whose dependencies and criteria match. Run only checks affected by the changed lesson, recipe or route, broadening when new failures justify it. Avoid redundant validators that repeat an existing gate without catching a distinct failure. Preservation and unexecuted coverage remain separate from passing behavior.

Close a change with the owning files, evidence pointers, affected checks, publication status and remaining limits. A corpus improvement is not a measured efficacy improvement until independently exercised. Keep proposed changes, experimental candidates and accepted limitations distinguishable from promoted capabilities.
