# Rapid experiments

Use only when asked to evaluate or improve a generative system. An artifact request does not itself require a model study. First check for an equivalent active/completed batch and reuse qualified machinery where applicable.

## Freeze a small comparison

Choose the decision, baseline, changed variable and observable outcome. Set attempt/time/concurrency budgets, stopping rules, equal repair policy and fresh confirmation brief before dispatch. Bound scope to a meaningful task family; do not add a benchmark framework for one question. Use deterministic fixtures for preflight rather than spending author attempts on a broken evaluator. Inspect prerequisite gate results before dispatching dependent trials; those operations are sequential, even when unrelated work can run in parallel.

Freeze corpus/runtime, task briefs, model/effort, author envelope, input layout, submission boundary and assertions. Use fresh sessions and isolated temporary workspaces where supported. Respect authorization for model calls and delegation. Never inspect a sealed holdout to choose improvements.

Keep examples and semantic content matched when studying representation. JSON, linked Markdown and instruction hierarchies may differ in navigation, exposure and authority. Automatic loading must be observed or labelled unknown; do not force an extra read in one lane and call it automatic delivery. If semantic guidance is missing, repair it equally and treat later results as a new cohort.

Describe challenge difficulty through distinct rules, interacting prerequisites and plausible authority conflicts. When corpus size is a factor, report repetition or unique-content measures alongside raw size; lexical diversity is not semantic complexity. Clearly labelled synthetic distractors do not establish performance in organically messy repositories. Preserve frozen confirmation material when a corpus limitation emerges and narrow the resulting claim.

Compare practical packages without attributing all effects to serialization. Read time, returned bytes, model usage and behavior are distinct measurements. Name a tokenizer if estimating tokens. Faster invalid output is not an efficiency improvement. Model identity, capacity, effort, concurrency and repair budgets can confound comparisons; report actual settings and uncertainty.

## Preserve the attempt boundary

Retain prompts, package versions, submitted sources, controller declarations, trace returns, failures, captures and timing. First-submission sealing under same-user polling is detection, not atomic prevention. Do not silently incorporate undeclared controllers or fix output on the evaluator's behalf.

Score required explanations, gap reports and provenance separately when the task requires them; a functional artifact gate does not cover those obligations. Give authors the reporting criteria before dispatch. Qualify a semantic rubric with legitimate paraphrases, honest limits and material false claims in a representative audit workload. For model checkers, a small calibration packet does not establish qualification for a larger audit; changes to rubric, evidence packet or workload may require fresh controls. Withhold affected judgments when those controls fail.

Before judging evidence absence, resolve named references in the audit packet against the submitted files and their identities. Distinguish an author's missing evidence from a packet-builder omission. Qualify packet assembly with an existing-file control and a genuinely missing reference. Preserve original judgments and record corrected-packet reassessments separately; neither a packet fix nor a checker correction improves the candidate's generation result.

Count timeouts, invalid submissions and incomplete runs in denominators. Treat an attempt as the sample, not each viewport. Separate first-pass success, repaired success, deterministic fixtures and fresh-generation reliability. Qualify legitimate alternatives and fault controls before scoring; if an evaluator is wrong, retain original results and reanalyze affected submissions equally.

Make one coherent correction supported by the current evidence, then freeze for fresh confirmation. If unchanged versions tie and there is no actionable signal, stop instead of expanding the study. A positive difference needs transfer confirmation; do not call a post-fix run confirmation of the old package.

Conclude promising within scope, equivalent on the probe, delivery advantage only, rejected or unresolved. Include residual drift and one next action. Restore ordinary self-checking for a later normal-generation adoption check. No universal format, model or speed claims follow from a few attempts.

## Isolation by claim

Before dispatch, name the claim and the access boundary it requires. Fresh conversational context, protection of private grading, restriction to advertised author inputs, and host sandboxing are separate properties; do not infer one from another.

For private grading, protect private assertions, reports, holdouts, and other lane outputs from author reads and writes. Qualify that boundary with synthetic forbidden-read and forbidden-write controls plus an allowed author-file control. Keep private material out of author prompts, enumerable author workspaces, and author-accessible HTTP endpoints. Folder separation alone is not enforcement.

If the study claims the author had access only to specified inputs, additionally qualify an allowlist with a harmless outside-envelope canary. An unrelated readable file defeats that access claim, but does not alone demonstrate exposure to private grading. Account for every author-accessible tool relevant to the claimed boundary; terminal enforcement does not establish host-wide enforcement.

Stop before dispatch when a boundary required by the frozen protocol cannot be qualified. A separately scoped diagnostic may proceed within existing authorization with its limitation explicit; it cannot confirm the stronger claim. Preserve and count accidental unisolated or contaminated attempts, audit available traces, and report uncertainty when access cannot be observed. Do not silently substitute these attempts for valid efficacy evidence.

Use the selected runner's authoritative instructions for configuration and supported environments. Record its version, qualified boundary, and controls with the experiment; this skill supplies no sandbox guarantee.
