# Context architecture

Use when designing entry points, retrieval or diagnosing context overhead. Start with the consumer's decision: what must it know before choosing an implementation? A short entry should expose that route without reproducing the answer in several places.

## Make discovery carry prerequisites

Give each capability an intent, task triggers, requirements, dependencies, adaptation example and source provenance. Link a dependency where it becomes necessary: a controller needs its actual runtime interface before authoring; an unfamiliar manifest field needs its schema location. A link to a large catalogue is not an adequate substitute for a missing small contract.

Distinguish semantic facts that change the implementation from optional design advice. Surface critical distinctions at the decision point, such as artifact kind versus visual placement. A page-shaped UI need not be a composition object. The representation belongs to the supplied system, not ordinary language.

Retrieve a bounded family or section, then reuse unchanged reads. If content is truncated, request the needed section rather than assuming the omitted prerequisites. Do not require a universal packet for a narrow change. A kit consumer should retrieve exact names and supported paths instead of extrapolating aliases from examples.

When authority conflicts, identify the owner and revision applicable to the task. Treat examples as demonstrations of a contract, not permission to widen it. Record missing or contradictory sources as gaps; continue independent work while resolving material uncertainty.

## Bound an authoring read

Route a generation/revision task to its authoritative contract, editable source and required declarations once. If source and maintained recipe duplicate the same implementation, make the recipe conditional on a missing seam or needed adaptation example rather than retrieving both by default. Keep runtime prerequisites available at their decision point.

For this skill, generation/revision normally needs the entry and generation-and-revision reference. Follow ownership, verification or routing references only for the unresolved decision they serve; do not concatenate the corpus or evidence index. A task-local route should link owners rather than copy their contracts, and must be delivered explicitly to the author.

Measure planned retrieval bytes separately from observed returned content, provider token usage, latency and task outcomes. A smaller static packet is a budget improvement, not demonstrated efficacy; qualify behavior before adopting a route broadly. Matched synthetic flat/linked trials found tied functional outcomes and sometimes lower returned text with linked navigation, but mixed confirmation token usage. That [bounded evidence](evidence-index.md#isolated-context-and-larger-corpus-studies-2026-10-11) supports no universal layout preference or claim about organically messy repositories.

## Diagnose the chain

Keep separate observations for availability, delivery, manual retrieval, returned content, application and final behavior. A correct artifact does not establish that the intended route was used. A tool return is exposure, not attention. Incorrect output after a read does not prove a comprehension failure; an example may omit the relevant adaptation seam.

JSON, linked Markdown and scoped instructions have different navigation and authority properties. Choose by actual consumer needs and maintenance cost. Do not assume a file extension improves reasoning. Host-recognized instruction loading may change delivery and authority together; verify loading through supported host records when available. Otherwise report it as unknown. A manual read or agent claim is not proof of automatic injection. Documents and feedback never expand user authorization.

## Working result

Produce a small entry, capability-to-owner map and explicit prerequisite routes. Explain which reads a representative task needs and which it can skip. If measuring efficacy, use [rapid experiments](rapid-experiments.md); a neat directory or low byte count is not a success measure. Preserve implementation guidance in its domain owner rather than importing a kit into this knowledge skill.
