# Qualify reuse through an independent consumer

Priority: high.

## Problem and responsibility

Source parity and successful integration in the originating project can conceal undocumented prerequisites. Generative Systems should qualify claims about reusable mechanics. Progressive Context owns durable capability identity, lifecycle views, and assessment organization; do not recreate those here or require that plugin.

## Proposed edit

In materials and contracts (`references/materials-and-contracts.md`), allow an early capability to contain only identity, intent, boundaries, and unknowns; extend it when facts become available. This prevents the existing detailed contract guidance from encouraging invented requirements.

Add the following compact paragraph after the contract-content guidance:

> Before claiming a supplied mechanism or template reusable beyond its original integration, exercise its advertised interface from a separate consumer context using only its declared dependencies and context. Record exact source and dependency identities, extra context required, failures, and the tested hosts and uses. Original-host success or byte parity alone does not qualify reuse. Repair missing declarations and repeat the affected exercise before extending the claim. Ordinary one-off delivery does not require portability qualification.

Use existing project evidence records. Do not introduce lifecycle labels, release records, a prescribed directory, or a mandatory model study. Independent consumption means testing the advertised boundary; it does not by itself imply private-evaluator isolation.

## Acceptance and verification

- An original-host success with an undeclared helper dependency remains unqualified for external reuse.
- A separate consumer that works using only advertised inputs supports a claim restricted to that tested environment and use.
- An intent-only request records unknowns without fabricating API details.
- A one-off artifact request does not trigger a portability exercise.
- Review the edited reference against these scenarios, inspect links, and run the skill validator. Label a prose walkthrough as such; behavioral reuse evidence requires an actual consumer exercise.

Keep the addition in the existing reference; no new default read or cross-skill dependency.

## Disposition, 2026-10-11

Intent-only allowance and operational consumer boundary retained; duplicated assessment checklist superseded by existing Progressive Context evidence guide after independent review. Evidence: implementation and research report (`resources/reports/context-architecture-research-2026-10-11.md`). Documentation implementation does not demonstrate efficacy.
