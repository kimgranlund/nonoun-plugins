# Semantic change assessment

- **Requested change and reason:** The decision or failure being addressed.
- **Current authority:** IDs, definitions, model/schema/policy versions and evidence.
- **Meaning difference:** Label clarification, changed referents, new relation,
  applicability, mapping, or representation-only change.
- **Affected consumers:** Queries, exports, mappings, context routes and caches.
- **Compatibility approach:** Stable identity, new identity/version, deprecation or
  explicit migration; rationale and unsupported paths.
- **Authored and generated artifacts:** Editing authority and regeneration command,
  when one exists.
- **Verification:** Old interpretation, new behavior, previously valid neighbor and
  incompatible mixed-version case, with actual results or explicit unknowns.
- **Adoption state:** Proposed or supported by the current reader/runtime; existing
  local process and user authorization apply.
- **Remaining limits:** Evidence or consumer work still needed for the requested outcome.
