# CLI routing investigations

Applies to: CLI harness.

Observed in a cross-host repository routing and hardening study. These are
analyst checks, not new automated detectors or universal requirements. Use recorded
calls, returned bodies and independent acceptance; missing telemetry stays unknown.
The architecture/refactoring skill progressive-context is complementary when
available, but is not required to apply these checks.

32. Diagnose route selection by task intent, not merely by target identity.
    - Observed in the cross-host study: guidance-only and behavior tasks loaded unnecessary API or styling bodies until routes distinguished the work being done.
    - Check: compare guidance-only and implementation neighbors from each real host entry; cite the first unnecessary expansion and prove required governing context still arrives before action.
    - Applies to: CLI harness.
33. Establish required-body coverage independently of command success.
    - Observed in the cross-host study: batch discovery could exit successfully with pending documents, and an oversized document required the budget override in its returned read command.
    - Check: record required identities, revision, delivered portions, pending reads and clipping; follow continuation evidence through recovery or report incomplete coverage, even after exit 0.
    - Applies to: CLI harness.
34. Separate repeated retrieval from justified recovery or changed scope.
    - Observed in the cross-host study: reopening delivered guidance added overhead, while focused reads after a clipped broad search recovered implementation evidence.
    - Check: for each repeat, compare identity, revision, covered range and intent; distinguish unchanged rereads, clipping recovery, new dependencies, edits and compaction, and count all recovery costs without inferring waste from repetition alone.
    - Applies to: CLI harness.
35. Verify native host discovery and installed portability as separate claims.
    - Observed in the cross-host study: shared source skills were not initially registered by both hosts, and symlinked support directories escaped a validator that traversed differently from the bundler.
    - Check: cite native registration and the actual entry route per host; use isolated relocation/inventory probes for shipped support files, permitted aliases, escapes and cycles instead of inferring portability from a successful source checkout.
    - Applies to: CLI harness.
36. Score autonomous routing, answer quality and retrieval overhead independently.
    - Observed in the cross-host study: correct discovery routes coexisted with broad-search clipping, answer caveats and searches that encountered historical evaluation answers.
    - Check: run unchanged briefs in clean sessions without coaching or injected expected routes; freeze independent acceptance, record model/host/settings and contamination, verify factual claims and source ownership, and compare costs only for sufficiently correct answers.
    - Applies to: CLI harness.
37. Probe representation boundaries before attributing a failure to the agent.
    - Observed in the cross-host study: parsers and projections mishandled encoded media paths, autolinks, full fragments, HTML context and composed-source provenance despite passing existing checks.
    - Check: isolate supported references in disposable fixtures and verify source meaning, final shape and usable output; classify missing producer/validator coverage separately from agent noncompliance, and keep unsupported forms explicit.
    - Applies to: CLI harness.
38. Bind freshness claims to consumed inputs rather than convenient entry files.
    - Observed in the cross-host study: evidence recording and caching needed coverage of scanned inputs, directory membership and browser-loaded bytes, including encoded bodies.
    - Check: mutate a consumed dependency or scan membership in a fixture and confirm stale evidence is rejected; verify byte capture preserves loading semantics, and do not replace historical receipts with current files.
    - Applies to: CLI harness.

## Report boundary

For applicable checks, record **observation and citation → supported interpretation
or hypothesis → smallest discriminating probe → result and limitations**. Keep
static checks, authored replay, evaluator-directed execution and fresh-agent runs
separate. A disappearing signal or a later passing retry does not establish cause.
Reuse maintained probes; run broader packaging/browser checks only when their
boundary is affected or at an integration checkpoint. Record deferred checks.
