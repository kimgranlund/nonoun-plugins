## Goal
Move Button off its own size variants onto the shared geometry model: geometry read from the `var(--g-*)` and `var(--r-*)` context that a new GeometryScope sets, `primary`/`ghost` plus `iconOnly` recipe variants, an `icon` recipe, and a regenerated Button config schema that rejects `size`.

## Risks
- `scripts/ts-resolve.mjs` needs node 22.15 or newer; the default `node` on this host is 22.14. run.sh gives builder and verifier node 24 from `.nvmrc`, but `steps.py split` runs guards with the caller's PATH, so the two `gen:*` guards source nvm. On a host without nvm those two guards go red at split and the plan is refused.
- `packages/gen-ui/styled-system/` is gitignored host state: Step 1's codegen criteria and typecheck hold only in the worktree where `panda codegen` ran (a fresh install runs it via `prepare`).
- The grader overwrites test files after the run, so the criteria that grep vitest test names hold only within the run.
- Panda emits a `button--iconOnly_false` class for the default; a test asserting the absence of any `iconOnly` class would be wrong.
- The colors criterion checks `bg`, `background`, `backgroundColor`, `color`, `outlineColor`, `borderColor` keys only; a color written under another key (for example inside a shorthand `outline` string) is not checked.
- Every gate is green at the build-start HEAD; a main sync that brings its own red shows up on Step 3 as an inherited red, not as this task's defect.
