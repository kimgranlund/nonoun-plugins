---
name: file
description: Draft the records for a finished task (PR title and body, changelog entry, follow-ups) from its .sdlc artifacts, then publish only what the user approves.
argument-hint: <.sdlc/task dir>
allowed-tools: Bash(${CLAUDE_PLUGIN_ROOT}/scripts/run.sh:*), Bash(python3 ${CLAUDE_PLUGIN_ROOT}/scripts/tickets.py:*), Read, Grep, Glob
---
Arguments: `$ARGUMENTS`

1. Run `${CLAUDE_PLUGIN_ROOT}/scripts/run.sh filer L1 <task dir>/handoff.md` from the project root.
2. Read the result. Show the user the Warnings, the PR title, and the changelog entry.
3. Close the ticket, only if the task `handoff.md` opens with ticket front matter (skip otherwise):
   1. Run `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/tickets.py --root .sdlc close <slug> --dry-run`, where `<slug>` is the task dir name. It lists each proposed follow-up as `<i>. <title> [<slug>]`, marks any `duplicate of T-NNNN`, then lists each other open (proposed, ready, or blocked) ticket as `open T-NNNN <title> [<slug>]`, plus each open ticket that exists only in another git worktree's same-relative ticket root as `open T-NNNN <title> [<slug>] (worktree <name>)` after the local lines (a local copy decides any id it holds), and writes nothing. Its last line is `expect <digest>`; keep that digest. If it refuses because the filer's Warnings are open, show the warnings and ask with AskUserQuestion with three options, in this order: "Leave open" (recommended): stop; "Acknowledge with a reason": the user supplies the why, then add `--ack-warnings "<why>"` to every later call (dry run and real close); "Force close": add `--force` to every later call. An unattended run stops on open warnings and never acks or forces. If it refuses because files outside the ticket folder cite it (numbered mode, before the `.NNNN-<slug>` rename), show the listed files and ask with AskUserQuestion with three options, in this order: "Rewrite references" (recommended): add `--rewrite-refs` to every later call (dry run and real close); "Leave open": stop; "Close anyway": add `--force` to every later call. An unattended run stops on this refusal and never rewrites or forces; never rewrite references silently. If the refusal names another worktree holding the filer record, tell the user to commit or copy it from there into this tree, then rerun the dry run. On any other refusal, report stderr and stop.
   2. Read the task's artifacts (plan, builder, and verifier files). Mark for dropping any follow-up they already resolve, with a one-line reason each. Items marked `duplicate of` are skipped by close automatically. Then compare each follow-up not already marked `duplicate of` against the dry run's `open T-NNNN` lines, including the `(worktree <name>)` ones: mark one that restates an open ticket's problem in different words as `likely duplicate of T-NNNN` for dropping, naming the matching id, with a one-line reason. For example, a follow-up `calc.div raises an unhandled ZeroDivisionError when b == 0` is a likely duplicate of an open ticket titled `div crashes on zero divisor`.
   3. When a person is present, ask with AskUserQuestion (multiSelect) which follow-ups to file. Put the recommended set first: the non-duplicate items minus the artifact-answered ones and the likely duplicates. AskUserQuestion names at most 4 options per question, and one AskUserQuestion call takes at most 4 questions. Split the follow-ups into questions in order, recommended items first, balanced so no question has fewer than 2 options (5 follow-ups become 3 and 2, never 4 and 1). A single follow-up is one question with two options, "File it" and "Skip it". With more than 16 follow-ups, ask the rest in further calls. `--skip` the indices of likely duplicates the user leaves unselected, and any follow-up not selected in any question.
   4. Run `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/tickets.py --root .sdlc close <slug> --skip <unselected indices> --expect <digest>`, or plain `close <slug>` (no token) if nothing is skipped. If close refuses with `does not match`, the filer file changed: rerun the dry run and ask again. Do not retry with the new digest blindly.
   5. Unattended (no one to answer): file the non-duplicate follow-ups minus the artifact-answered ones and the likely duplicates (`--skip` the dropped and likely-duplicate indices, with `--expect <digest>`), and state that choice and the reasons in the report.
   6. Report the tickets created, the duplicates skipped, the likely duplicates dropped with the matching T-NNNN each, and the items dropped, with reasons.
4. Publishing (commit, push, PR, changelog edit) is outward-facing: ask the user with one multiSelect AskUserQuestion that names at most 4 options (commit, push, PR, changelog edit) which items to publish, then do only those. Follow-ups are already tickets, so offer them as GitHub issues only in a separate second AskUserQuestion, and only when the user wants them published; that question carries at least 2 options (for example, file them as issues or keep them as tickets only), since a 1-option question is also invalid. In numbered mode the folder becomes `.NNNN-<slug>` after close. Never publish on your own. `hooks/block-publish.sh` does not guard this session, since it only fires when `SDLC_ROLE` is set (by `scripts/run.sh` per role run, and by `scripts/fanout.py` as `conductor` for lane drivers); the AskUserQuestion approval here is the only publish gate in the user's own session.
