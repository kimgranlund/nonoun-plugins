**Codex host:** Before following this workflow, read the Codex adapter at `${CLAUDE_PLUGIN_ROOT}/skills/sdlc-lite/SKILL.md` and apply its tool, argument, path, and process translations. Claude Code follows the workflow below directly.

Arguments: `$ARGUMENTS`

When launching a role, pass `dispatch.py prepare --routing-reason "<why>"` (or set `SDLC_ROUTING_REASON`) with a short explanation of the chosen role and level (user selection, task scope, or escalation evidence). `dispatch.py prepare` (Codex: `run.sh`) reads it and records the resolved model and effort separately. Read run operations at `${CLAUDE_PLUGIN_ROOT}/skills/handoff-format/run-operations.md` for readiness and interrupted-attempt recovery.

1. Dispatch the filer at L1 on `<task dir>/handoff.md` from the project root, the three steps of `${CLAUDE_PLUGIN_ROOT}/agents/conductor.md` ("How you run roles"): `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/dispatch.py prepare filer L1 <task dir>/handoff.md` runs the gates and prints the dispatch JSON; an `Agent` call passes its `subagent_type`, `name`, `description`, `model`, `prompt`, and `run_in_background` unchanged; `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/dispatch.py record <dispatch_file> --agent-id <id> --tokens <n> --transcript <sub-agent transcript jsonl> --tool-uses <n> --duration-ms <ms>`, with the sub-agent's final message on stdin, validates and records the result. On Codex run `SDLC_BACKEND=codex ${CLAUDE_PLUGIN_ROOT}/scripts/run.sh filer L1 <task dir>/handoff.md` instead. Claude: after `record`, run `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/dispatch.py prune`, make each `TaskStop task_id=<name>` call it lists, then `prune --done <name>`; a finished sub-agent stays an idle teammate until stopped.
2. Read the result. Show the user the Warnings, the PR title, and the changelog entry.
3. Close the ticket, only if the task `handoff.md` opens with ticket front matter (skip otherwise):
   1. Run `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/tickets.py --root .sdlc close <slug> --dry-run`, where `<slug>` is the task dir name. It lists each follow-up as `<i>. <tag>: <title>` with a mark: `[<slug>] ticket` (a `decide:` item that can become the one ticket), `note` (goes to `.sdlc/notes.md` (`.sdlc/notes/notes.md` with `layout: topics`)), `skip (--skip)`, or `duplicate of T-NNNN`, then lists each other open (proposed, ready, or blocked) ticket as `open T-NNNN <title> [<slug>]`, plus each open ticket that exists only in another git worktree's same-relative ticket root as `open T-NNNN <title> [<slug>] (worktree <name>)` after the local lines (a local copy decides any id it holds), and writes nothing. Its last line is `expect <digest>`; keep that digest. If it refuses because the filer's Warnings are open, show the warnings and ask with AskUserQuestion with three options, in this order: "Leave open" (recommended): stop; "Acknowledge with a reason": the user supplies the why, then add `--ack-warnings "<why>"` to every later call (dry run and real close); "Force close": add `--force` to every later call. An unattended run stops on open warnings and never acks or forces. If it refuses because files outside the ticket folder cite it (numbered mode, before the `.NNNN-<slug>` rename), show the listed files and ask with AskUserQuestion with three options, in this order: "Rewrite references" (recommended): add `--rewrite-refs` to every later call (dry run and real close); "Leave open": stop; "Close anyway": add `--force` to every later call. An unattended run stops on this refusal and never rewrites or forces; never rewrite references silently. If the refusal names another worktree holding the filer record, tell the user to commit or copy it from there into this tree, then rerun the dry run. On any other refusal, report stderr and stop.
   2. Read the task's artifacts (plan, builder, and verifier files). Mark for dropping any follow-up they already resolve, with a one-line reason each. Items marked `duplicate of` are skipped by close automatically. Then compare each follow-up not already marked `duplicate of` against the dry run's `open T-NNNN` lines, including the `(worktree <name>)` ones: mark one that restates an open ticket's problem in different words as `likely duplicate of T-NNNN` for dropping, naming the matching id, with a one-line reason. Artifact-answered items and likely duplicates go to `--skip`. For example, a follow-up `calc.div raises an unhandled ZeroDivisionError when b == 0` is a likely duplicate of an open ticket titled `div crashes on zero divisor`.
   3. When a person is present, ask one decide question with AskUserQuestion: which `decide:` follow-up becomes the one ticket. Offer up to 3 `decide:` items as options, leaving out artifact-answered ones and likely duplicates, the recommended one first when one names a defect or risk, plus `None: notes only`. AskUserQuestion names at most 4 options per question. With more than 3 `decide:` items, offer the 3 most consequential; the rest go to notes.md. Under /chain this question is asked in /chain's close-out round together with the publish question, in one AskUserQuestion call; standalone, ask it here together with step 4's publish question in one call. `fix-now:` items were already run by /chain's `Loose ends` step, and `note:` items and unchosen `decide:` items are appended to the notes file (`.sdlc/notes.md`, or `.sdlc/notes/notes.md` with `layout: topics`) by close.
   4. Run `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/tickets.py --root .sdlc close <slug> --ticket N --expect <digest>` for the chosen item N, adding `--skip <indices>` for the artifact-answered and likely-duplicate indices, or plain `close <slug>` (plus `--skip <indices> --expect <digest>` when any are marked) when the answer is `None: notes only`. If close refuses with `does not match`, the filer file changed: rerun the dry run and ask again. Do not retry with the new digest blindly.
   5. Unattended (no one to answer): pass no `--ticket` unless exactly one course is clear, a `decide:` item naming a defect or risk; then `--ticket` the first such item (with `--expect <digest>`, and `--skip` the artifact-answered and likely-duplicate indices) and state that choice and the reason in the report.
   6. Report the ticket created, the lines appended to notes.md, the skips with reasons, and the duplicates (with the matching T-NNNN for each likely duplicate).
4. Publishing (commit, push, PR, changelog edit) is outward-facing: ask the user with one multiSelect AskUserQuestion that names at most 4 options (commit, push, PR, changelog edit) which items to publish, then do only those. Follow-ups are already tickets, so offer them as GitHub issues only in a separate second AskUserQuestion, and only when the user wants them published; that question carries at least 2 options (for example, file them as issues or keep them as tickets only), since a 1-option question is also invalid. In numbered mode the folder becomes `.NNNN-<slug>` after close. Never publish on your own. `hooks/block-publish.sh` does not guard this session: it resolves the role from `SDLC_ROLE`, else from a sub-agent's `agent_type` (`hooks/_role.sh`), and exits 0 with neither (`scripts/fanout.py` sets `SDLC_ROLE` to `conductor` for lane drivers, and Codex `scripts/run.sh` sets it per role run); the AskUserQuestion approval here is the only publish gate in the user's own session.
