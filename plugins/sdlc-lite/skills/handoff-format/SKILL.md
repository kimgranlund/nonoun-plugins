## Layout

Task folders, the roadmap, the notes, `evals/`, `proposals/`, and `fleet.json` live in the work root: `.sdlc/` by default, or the folder a `work_root: <path>` line in `.sdlc/config` names (`docs/work` recommended), where the roadmap and notes are `ROADMAP.md` and `NOTES.md`. `.sdlc/` keeps the config, templates, runtime, messages, and router either way. `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/roots.py paths --root .sdlc` prints every path.

```
<work root>/<task-slug>/  the task folder, committed
  handoff.md            task brief (goal, intent, context, constraints); `tickets.py close` appends ## Outcome
  skips.md              lane history: one "- lane:" line per steps.py lane run, under ## Lane
                        and, under ## Skipped, one entry per full-chain role (planner, verifier
                        per step, filer) a solo, lean, or fix lane skipped (a full lane
                        needs the results instead), in the form
                        "- skip: <role>; step: <n or all>; reason: <why>; decided: <who>"
                        (reason and decided non-empty); tickets.py check and close enforce it
.sdlc/runtime/tasks/<task-slug>/  the records dir (folder name without a leading dot); local, ignored through runtime/.gitignore
  design.md             /grill ratified design (optional)
  decompose/            /decompose manifest-v<n>.json + report.md (optional)
  scout-L1.md           outputs of task-level roles: <role>-<level>.md
  planner-L2.md
  planner-L3-2.md       a replan; the latest runs.jsonl record is current
  plan-reviewer-L1.md   plan review (only for a plan with a step at L4 or L5)
  runs.jsonl            one line per run: role, level, model, effort, cost, duration, file
  *.attempt.json, *.dispatch.json, *.running, *.log, *.limit   run state per role run
  base-sha, budget-ack.md
  end-sha               where a recorded builder's build ended (HEAD, else a tree hash): the verifier brief's Diff range end
  step-1/
    handoff.md          one plan step: level, do, acceptance criteria
    builder-L2.md
    verifier-L1.md
  step-2/ ...
  step-2.superseded-1/   a step replaced by a replan; ignored as a step, still counted for cost
<work root>/.NNNN-<slug>/  a closed ticket in numbered mode (renamed from NNNN-<slug> by `close`, which refuses while other files cite the old path unless `--rewrite-refs` or `--force`); same layout inside
<work root>/roadmap.md  generated by `tickets.py roadmap`; never hand-edited; .sdlc/tickets/roadmap.md with `layout: topics`; ROADMAP.md under `work_root`
<work root>/notes.md    follow-ups that did not become tickets, appended by `tickets.py close`; never a ticket; .sdlc/notes/notes.md with `layout: topics`; NOTES.md under `work_root`
.sdlc/_templates/<type>.md  optional; overrides the plugin's skills/ticket/templates/<type>.md
.sdlc/AGENTS.md         router: stage counts, open tickets, and the create, claim, and close procedures; its managed block is regenerated by tickets.py roadmap, new, and close
.sdlc/CLAUDE.md         @AGENTS.md, so Claude Code loads the router
.sdlc/config            optional lines: ticket_folders: numbered, external_branch: <branch>, ticket_root: tickets, layout: topics|flat, work_root: <path> (refused together with ticket_root: tickets or layout: topics)
.sdlc/tickets/          the ticket folders when config has ticket_root: tickets, with its own AGENTS.md and CLAUDE.md; roadmap.md, notes.md, config, and _templates/ stay in .sdlc/ unless `layout: topics` moves them
.sdlc/work/             `layout: topics` only (with `ticket_root: tickets`): task folders with no ticket, each laid out as a task above; with its own AGENTS.md and CLAUDE.md; tickets/roadmap.md and notes/notes.md hold the roadmap and the notes
.sdlc/runtime/          local and ignored: the records dirs (runtime/tasks/), and traces analysis outputs and cursor written by `traces.py` (runtime/traces/<repo-key>/)
.sdlc/messages/         git-ignored mailbox written by scripts/messages.py: new/, read/, done/ per receiver, shared by worktrees; never committed; its AGENTS.md (the procedures) and CLAUDE.md at the root and in each stage folder are written by messages.py send and tickets.py roadmap
<work root>/evals/      the plugin repository's dated model and effort evals (NNNN-<slug>.md) and table-lock.json, written by scripts/evals.py add and lock; check.py fails a model-table change that cites no newer eval; its AGENTS.md documents the format
<work root>/proposals/  candidate changes mined from past runs (<kind>-<hash>/proposal.md, P-NNNN), written by scripts/proposals.py scan; accept needs an eval in evals/, promote files an idea ticket; its AGENTS.md documents the format
.sdlc/supervisor/       written by `supervisor.py init` in the main checkout: AGENTS.md, CLAUDE.md, .gitignore, limits.json; hosts.local.json, state.json, status.json, lock, STOP, and wakes/ stay local
```

A task folder that already holds records (runs.jsonl, an attempt, a role result, or a step dir with one) keeps them in place; `${CLAUDE_PLUGIN_ROOT}/scripts/order.py records-dir <task dir>` prints the records dir for any task.

A role dispatched as a sub-agent on Claude (`dispatch.py prepare <role> <level> <handoff.md>`, an `Agent` spawn with the printed `name`, `model`, and `run_in_background`, then `dispatch.py record <dispatch_file>`) writes `<role>-<level>.md` in the records dir of the handoff it is given; on Codex, `scripts/run.sh <role> <level> <handoff.md>` writes the same `<role>-<level>.md` and `.log`. Run state files, rerun names (`<role>-<level>-<k>.md`), and how `scripts/order.py` picks the newest result: `references/records.md`. Add `.sdlc/` to the project's `.gitignore` unless the user wants the trail committed.

A live step dir is exactly `step-<digits>`; a replan renames replaced dirs to `step-<n>.superseded-<k>/` (k is the first free number); the board and scripts do not count these as steps.

If the project commits the `.sdlc/` trail, ignore these instead so `/board` and role runs don't dirty the tree:

```
.sdlc/**/.run.lock
.sdlc/runtime/
.sdlc/messages/
.sdlc/supervisor/hosts.local.json
.sdlc/supervisor/status.json
.sdlc/supervisor/state.json
.sdlc/supervisor/lock
.sdlc/supervisor/STOP
.sdlc/supervisor/wakes/
```

- Board cache: lives in `${XDG_CACHE_HOME:-~/.cache}/sdlc-lite/board-state/`, outside the repo, so `/board` writes nothing into the tree. Ignoring `.sdlc/.board-state.json` only matters for older versions that wrote it there.
- `.sdlc/messages/`: the local mailbox written by `scripts/messages.py`; never committed, even when the trail is.

The task folder (`handoff.md`, `skips.md`) is committed; records are local and ignored. A `fanout.py land` close commit keeps only `handoff.md` (and what the folder tracked before the merge) in git and moves the closed folder's other files, `skips.md` included, into its records dir. A role result that must outlive the ticket is promoted to `docs/` before the close, because the records dir never reaches git. How to write the handoff and its `## Outcome`: [writing rules](references/writing-rules.md).

## Ticket front matter (optional)

In numbered mode, `close` renames the folder `NNNN-<slug>` to `.NNNN-<slug>` and refuses while other files cite the old path (`references/ticket-fields.md`).

`<work root>/<task>/handoff.md` may open with a YAML front matter block that makes the handoff double as a ticket:

```
---
id: T-NNNN
title: "..."
type: feature|bug|chore|spike|idea
status: proposed|ready|claimed|paused|blocked|done|dropped
size: L1|L2|L3|L4|L5   # the ticket level: L1 small, L2 medium, L3 large, L4 extra large, L5 reserved
priority: P1|P2|P3
depends: [T-NNNN, file:<path>, cap:<name>, ...]
created: YYYY-MM-DD
from: T-NNNN   # optional, origin ticket id
provides: [name, ...]   # optional, capability names this ticket delivers
successor: T-NNNN|<repo>:T-NNNN   # optional, the ticket that supersedes, delivers, verifies or fixed this one
claimed_by: <harness> <YYYY-MM-DD>   # optional, who works on it; shown in the router; a second claimant checks it first; required when status is claimed
paused_reason: <one line>   # required when status is paused
branch: <lane branch>   # optional, written by the lane opener (lanes.py open, tickets.py branch); removed when the lane closes
worktree: <path>   # optional, beside branch: the lane worktree relative to the main checkout (../<repo>.worktrees/<lane>); check warns when it is not registered on that branch
area: <name>   # optional, one of the areas: line in .sdlc/config; a domain, never a lane
router: .sdlc/AGENTS.md   # stamped by new: the folder rules (.sdlc/tickets/AGENTS.md with ticket_root: tickets)
---
```

The rules for `depends` entries (`file:`, `cap:`), `successor:`, how scripts read front matter, `size`, and `status`: `references/ticket-fields.md`. Front matter is purely additive: a handoff with no front matter keeps working unchanged. `size` is the ticket level (L1 and L2 go to the `solo` lane by default); `status` is a person's decision, not build progress. The ticket templates this plugin ships are in `skills/ticket/templates/`.

## Task handoff (`<work root>/<task>/handoff.md`)

```
## Goal
One or two sentences: the outcome, not the method.

## Intent
Written by /clarify: literal ask, level, verify, deltas, do, non-goals, done when. Optional.

## Context
Decisions already made, relevant paths, links. Point to `design.md` and `decompose/report.md` when they exist. Everything a clean-context agent needs; it sees nothing else.

## Constraints
What must not change, limits, deadlines. "None" if none.

## Question
Only for scout, archaeologist, or researcher runs: the exact question.

## Plan review
Optional. Written by /chain or the conductor, never by a role: a plan defect found before or during the build, quoting the `steps.py split` refusal or the role's `plan defect:` note, or a `recurring finding:` entry quoting both notes of a finding that repeated after it was addressed. A criterion swap adds one line, `swap applied: step <n>: <steps.py swap stdout line>`, and a swap refusal adds the `steps.py swap` stderr (its last line starts `plan defect:`) before the replan. A scope widening (/chain 4.9) adds `scope widened: step <n>: <steps.py widen stdout line>`; a `steps.py widen` refusal adds `scope decision: step <n>: <paths>` and its stderr before the replan. A plan review whose Verdict is `replan` (`steps.py review` prints `replan`, /chain 3) adds `plan review: replan: <result path>` and one `plan review: <verdict>: <finding>` entry per item of the reviewer's `## Findings`, before the planner L3 replan. A review whose every finding is a `notes-fix:` item adds no entry and no replan: `steps.py split` writes those items under `### Notes` in the step handoff. A review whose findings are all `criterion-only:` items (notes-fix allowed beside them; `steps.py review` prints `amend`) adds no `plan review:` entry and no replan: `steps.py split` rewrites each named criterion in the step handoff and itself appends ``- criterion-only amend: <review file>: step <n>: old `<old>` -> new <new>``, a line that never spends the one replan. Earlier entries stay. The planner fixes that step on the replan.

## Outcome
Written by `tickets.py close`, never by hand: one header line (`<date> · lane: <lane> <size> · verdict: <verdict> · verifier: <role-level> (<model>) · base: <sha12>`), then `- Changed:`, `- Commits:`, one `- Check:` line per verifier criterion, and any `- Deviation:` and `- Follow-up:` lines. It is the closed ticket's durable record.
```

## Step handoff (`<records dir>/step-<n>/handoff.md`)

`scripts/steps.py split` writes these files from the newest planner file. /chain 5 writes the `Loose ends` step handoff (`step-<n+1>/`) by hand from the same template and lints it with `steps.py lint`, and so does `/fix` for its single `step-1/`. `steps.py swap` (a verifier `swap old:`/`swap new:` pair, /chain 4.8), `steps.py amend` (a blocked builder's `amend old:`/`amend new:` pair, /chain 4.10), and `steps.py widen` (conductor-allowed paths under `## Scope widened`, /chain 4.9) rewrite one part of a step handoff, never by hand (`references/step-handoff-rules.md`).

The `base: <sha>` line, the `tests: <path>` line for a `(red)` criterion, `(parity)` styling criteria, where evidence goes, `### Read first` entries, and which cited `.sdlc/...` paths `steps.py lint` accepts: `references/step-handoff-rules.md`.

A plan may hold a `guard timeout: <seconds>` line (in `## Goal` for the whole plan, or right after a step's `level:` line for that step); `steps.py split --only` uses it as the `--guard-timeout` default, an explicit `--guard-timeout` wins, and `specgate.py check` refuses a `(guard)` that runs `check.sh` without one.

Copied from the plan's step block, plus the task goal for orientation:

```
## Task goal
<from the task handoff>

## Step <n>: <title>
level: L<n>
### Read first
- `<path>`

### Do
...

### Acceptance criteria
- ...
```

A criterion line may end with one bracket clause, outside any code span, that lets a verifier hold it (see Held criteria):

```
- `test -s out/report.json` [stage: integration; owner: integration]
- `node --test test/schema.test.js` [needs: T-0307, file:schema/progress.json]
```

Keys: `stage` (the stage that normally checks it, informational), `owner` (a lowercase kebab stage word or a `T-NNNN`; makes the criterion deferrable), `needs` (comma separated `T-NNNN`, `file:<path>` or `cap:<name>`; makes it unmet-dependency eligible). An unknown or repeated key, an empty value, or a malformed owner or subject is a `steps.py lint` refusal ending in `plan defect:`; a line with no clause behaves as before.

Never write `grep -P` in a criterion or guard: BSD grep on macOS has no -P, so a negated pipeline passes vacuously and `steps.py lint` refuses it; use `python3 -c` or `grep -E` with a literal byte sequence.

The step's `### Do` states its validation scope (see `agents/planner.md`): the affected behavior and named dependents, tests named by stable title and file rather than by source line, and the integration gate that owns broad coverage when the handoff assigns one.

`### Read first` is optional: the nearest non-root `AGENTS.md` and the routed skill of each file the step changes (`references/step-handoff-rules.md`).

### Merge step

When a task merges one lane into another, the planner emits this block (from `agents/planner.md`, `## Merge steps`) with `<branch>`, `<n>`, and `<gate command>` filled in, and `steps.py split` copies it like any other step:

```merge-step
## Step <n>: Merge <branch>
level: L<n>
### Do
Run `git merge --no-ff <branch>` on a tree with no uncommitted tracked changes. Resolve every conflict so both lanes' intent survives, run the gates below, and create the merge commit. Never push.
### Acceptance criteria
- `test "$(git rev-list --parents -n1 HEAD | wc -w)" -eq 3`
- `git merge-base --is-ancestor <branch> HEAD`
- (guard) `! git rev-parse -q --verify MERGE_HEAD`
- (guard) `out=$(git diff-tree --cc HEAD) && ! printf "%s\n" "$out" | grep -qE "^\+\+(<<<<<<<|>>>>>>>)( |$)"`
- (guard) `<gate command>` shows no new findings versus the first parent: run the same command in a `git worktree add --detach <tmp> HEAD^1` copy and compare.
```

The conflict-marker guard flags only `++` lines; why that miss is accepted: `references/step-handoff-rules.md`.

`## Previous attempt` is appended by /chain 4.4 only after a verifier fail that is not a plan defect (`references/step-handoff-rules.md`).

## Batched verifier result (task dir)

A verifier launched at the task dir writes `verifier-L<k>.md` in the task dir and adds a `## Verified` section listing each builder result it verified (`step-<n>/builder-L<k>[-j].md`). Which steps a batch may verify, and which result decides: `references/verifier-results.md`.

## Held criteria

A criterion has four states: `pass`, `fail`, `unmet-dependency <subject>`, and `deferred <owner>`. The verifier may hold only a criterion whose bracket clause declares it and whose check is red or cannot run now; a held criterion makes the Verdict `fail`, `steps.py open <task dir>` lists what is still held, and no ticket closes while a criterion is held. Refs, routing, settling, and the close exceptions: `references/verifier-results.md`.

## Numbered records across worktrees (ADR numbers)

Lanes that each take "the next ADR number" from their own tree collide. A plan step never says "the next ADR number": it names the number, picked from every worktree and the integration branch, or names the repository's allocator. The full rule: `references/numbered-records.md`.

## Free-text arguments

When a launcher skill gets text instead of a handoff path, create `<work root>/<slug>/handoff.md` (slug: 2 to 5 lowercase words from the text, hyphenated; add `-2` etc. if taken) from the template, put the text in Goal (or Question for question roles), fill Context from what the current conversation established, and show the user the path.
