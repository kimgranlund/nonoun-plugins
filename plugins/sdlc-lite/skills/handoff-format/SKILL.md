## Layout

```
.sdlc/<task-slug>/
  handoff.md            task brief (goal, intent, context, constraints)
  design.md             /grill ratified design (optional)
  decompose/            /decompose manifest-v<n>.json + report.md (optional)
  scout-L1.md           outputs of task-level roles: <role>-<level>.md
  planner-L2.md
  planner-L3-2.md       a replan; the latest runs.jsonl record is current
  runs.jsonl            one line per run: role, level, model, effort, cost, duration, file
  step-1/
    handoff.md          one plan step: level, do, acceptance criteria
    builder-L2.md
    verifier-L1.md
  step-2/ ...
  step-2.superseded-1/   a step replaced by a replan; ignored as a step, still counted for cost
.sdlc/.NNNN-<slug>/     a closed ticket in numbered mode (renamed from NNNN-<slug> by `close`, which refuses while other files cite the old path unless `--rewrite-refs` or `--force`); same layout inside
.sdlc/roadmap.md        generated by `tickets.py roadmap`; never hand-edited
.sdlc/_templates/<type>.md  optional; overrides the plugin's skills/ticket/templates/<type>.md
```

`scripts/run.sh <role> <level> <handoff.md>` writes `<role>-<level>.md` and `.log` next to the handoff it is given. A rerun of the same role and level writes `<role>-<level>-<k>.md` and `.log` (k = 2, 3, ...); the first result is never overwritten, and the newest is decided by `scripts/order.py`: latest runs.jsonl record (run.sh records `file`), else level then rerun index then name; never mtime. runs.jsonl keeps the history. Add `.sdlc/` to the project's `.gitignore` unless the user wants the trail committed.

A live step dir is exactly `step-<digits>`; a replan renames replaced dirs to `step-<n>.superseded-<k>/` (k is the first free number); the board and scripts do not count these as steps.

If the project commits the `.sdlc/` trail, ignore these instead so `/board` and role runs don't dirty the tree:

```
.sdlc/**/*.running
.sdlc/**/*.log
```

- Board cache: lives in `${XDG_CACHE_HOME:-~/.cache}/sdlc-lite/board-state/`, outside the repo, so `/board` writes nothing into the tree. Ignoring `.sdlc/.board-state.json` only matters for older versions that wrote it there.
- `.sdlc/**/*.running`: marker for a role run in progress
- `.sdlc/**/*.log`: raw role transcript

Keep the results `.md` files and `runs.jsonl` committed.

## Ticket front matter (optional)

In numbered mode, `close` renames the folder `NNNN-<slug>` to `.NNNN-<slug>`; tools still treat it as a closed ticket. Before the rename, `close` refuses, writing nothing, when files outside the folder cite `<root>/NNNN-<slug>` (found with `git grep`), naming each; `--rewrite-refs` rewrites them to the dot path with the rename, and `--force` closes and leaves them.

`.sdlc/<task>/handoff.md` may open with a YAML front matter block that makes the handoff double as a ticket:

```
---
id: T-NNNN
title: "..."
type: feature|bug|chore|spike|idea
status: proposed|ready|blocked|done|dropped
size: S|M|L|XL
priority: P1|P2|P3
depends: [T-NNNN, ...]
created: YYYY-MM-DD
from: T-NNNN   # optional, origin ticket id
---
```

Front matter is purely additive: a handoff with no front matter keeps working unchanged, and `run.sh` never requires or parses it. `board.py` reads `id`/`status` from front matter for display only (via `tickets.py`'s parser, so a task without front matter or an unreadable handoff.md just gets empty cells); it still never requires, validates, or writes front matter. `/ticket new` stamps these fields, `/ticket check` validates them, and `scripts/tickets.py` remains the sole parser and writer of front matter semantics. `tickets.py close` sets `status: done` and stamps `from: <id>` on each follow-up idea ticket it creates. `board.py` also uses ticket status to decide which tasks it lists at all: a `dropped` ticket, or a `done` ticket with no recorded step work, is left off the board entirely.

`status` here is a person's decision (proposed, ready to build, blocked, done, dropped), not build progress. It never tracks how far a task got through the roles; that stays derived by `/board` from `.sdlc/` run state. The two are independent: a ticket can sit at `status: ready` while `/board` shows no runs yet, or `status: blocked` while a step has already built.

Origin: this convention comes from `/Users/kimba/Projects/nonoun/gen-ui-system-svelte-lite/.sdlc/_templates/*.md` and that repo's `CONTEXT.md`. In this repo, `.sdlc/tickets/T-*.md` are in-repo examples of the format.

## Task handoff (`.sdlc/<task>/handoff.md`)

```
## Goal
One or two sentences: the outcome, not the method.

## Intent
Written by /clarify: literal ask, deltas, do, non-goals, done when. Optional.

## Context
Decisions already made, relevant paths, links. Point to `design.md` and `decompose/report.md` when they exist. Everything a clean-context agent needs; it sees nothing else.

## Constraints
What must not change, limits, deadlines. "None" if none.

## Question
Only for scout, archaeologist, or researcher runs: the exact question.

## Plan review
Optional. Written by /chain or the conductor, never by a role: a plan defect found before or during the build, quoting the `steps.py split` refusal or the role's `plan defect:` note, or a `recurring finding:` entry quoting both notes of a finding that repeated after it was addressed. A criterion swap adds one line, `swap applied: step <n>: <steps.py swap stdout line>`, and a swap refusal adds the `steps.py swap` stderr (its last line starts `plan defect:`) before the replan. Earlier entries stay. The planner fixes that step on the replan.
```

## Step handoff (`.sdlc/<task>/step-<n>/handoff.md`)

`scripts/steps.py split` writes these files from the newest planner file; no one writes them by hand. `steps.py swap` is the one other writer: it rewrites one criterion line from the verifier's `swap old:`/`swap new:` pair after a `plan defect:` fail (/chain 4.8), never by hand.

Copied from the plan's step block, plus the task goal for orientation:

```
## Task goal
<from the task handoff>

## Step <n>: <title>
level: L<n>

### Do
...

### Acceptance criteria
- ...
```

### Merge step

When a task merges one lane into another, the planner emits this block (from `agents/planner.md`, `## Merge steps`) with `<branch>`, `<n>`, and `<gate command>` filled in, and `steps.py split` copies it like any other step:

```merge-step
## Step <n>: Merge <branch>
level: L<n>
### Do
Run `git merge --no-ff <branch>` on a tree with no uncommitted tracked changes. Resolve every conflict so both lanes' intent survives, run the gates below, and create the merge commit. Never push.
### Acceptance criteria
- `test "$(git rev-list --parents -n1 HEAD | wc -w)" -eq 3`
- `git merge-base --is-ancestor <branch> HEAD`
- (guard) `! git rev-parse -q --verify MERGE_HEAD`
- (guard) `out=$(git diff-tree --cc HEAD) && ! printf "%s\n" "$out" | grep -qE "^\+\+(<<<<<<<|>>>>>>>)( |$)"`
- (guard) `<gate command>` shows no new findings versus the first parent: run the same command in a `git worktree add --detach <tmp> HEAD^1` copy and compare.
```

The conflict-marker guard flags only `++` lines of `git diff-tree --cc HEAD`, so a kept marker line textually identical to a parent line that aligns with it (shown as `+ ` or ` +`) passes. This is accepted, because no one-line guard separates it from a legit lane line in a file both sides changed. The builder must still resolve every conflict, and the check.py probe pins the miss.

`## Previous attempt` is appended by /chain 4.4 only after a verifier fail that is not a plan defect (its For the next attempt does not start with `plan defect:`). A blocked builder or a `plan defect:` fail goes to a replan instead, and the step handoff is rewritten by `steps.py split`, not appended to. A swapped plan defect (a `plan defect:` fail whose criterion `steps.py swap` replaced) rebuilds at the same level without `## Previous attempt`.

## Free-text arguments

When a launcher skill gets text instead of a handoff path, create `.sdlc/<slug>/handoff.md` (slug: 2 to 5 lowercase words from the text, hyphenated; add `-2` etc. if taken) from the template, put the text in Goal (or Question for question roles), fill Context from what the current conversation established, and show the user the path.
