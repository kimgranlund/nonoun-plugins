# Step actions and exceptions

Detail for /chain section 4. The script `steps.py next` implements these rules.

## Actions of `steps.py next`

After each builder run and each verifier run, run `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/steps.py next <task dir>/step-<n>` and follow the action on its first line (on Claude, `dispatch.py advance` runs it and already prepared the builder or verifier for `build`, `rebuild`, `verify` and `reverify`; its `stop: <action> <reason>` line carries every other action): `build`, `rebuild`, or `bump` → builder at that level; `verify` or `reverify` → verifier at that level; `replan` → the 4.2 path; `resplit` (a builder blocked with Notes starting `stale lane:`, meaning merged prerequisites are missing from the lane and the plan is sound) → rebase the lane onto them, rename the step dir to `step-<n>.superseded-<k>` (next free k), run `steps.py split --only <n> .sdlc/<task>`, and rerun the builder; it is never a replan and costs no planner run; `swap` → run `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/steps.py swap <task dir>/step-<n>`: exit 0 → append one line `swap applied: step <n>: <its stdout line>` to the task handoff's `## Plan review` (create it if missing, keep earlier entries) and run the builder at the level `next` printed (a rebuild: no `## Previous attempt`, never a bump, never counted toward "a second fail"); exit 1 → append its stderr to `## Plan review` and take the 4.2 replan path; `amend` (a blocked builder whose Notes carry one `amend old:`/`amend new:` pair for an unbuilt step, item 10) → run `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/steps.py amend <task dir>/step-<n>`: exit 0 → run the builder at the level `next` printed (no `## Previous attempt`, no bump, never counted toward a bump; the script itself records `amend applied:` under `## Plan review`); exit 1 → append its stderr to `## Plan review` and take the 4.2 replan path; `done` → next step; `stop` → ask the user; `inherited` → the gate was already red at the pre-build HEAD (builder Status `inherited red: <tests>`, or verifier Verdict `inherited red: <tests>` from the verifier's pre-build gate check): interactive, ask the user through AskUserQuestion (fix main first, rebuild once main is green, or stop); unattended, stop the task and report the inherited tests. It is never a fail, a rebuild, a bump, a replan, or a reverify, and never waives the gate. `invalid result: <path>: <reason>` (from `steps.py next`, `steps.py review`, or `steps.py resume`, and the same text in a `steps.py split` refusal) → the newest result does not match its `results.py` schema: interactive, report the line and ask the user; unattended, stop the task and report the line. It is never a rebuild, a reverify, a bump, or a replan. A nonzero exit → stop and report its stderr. `dispatch.py record` exits 3 (Codex: `run.sh` exits 3) when the result fails `results.py validate`; the result file still exists, so run `steps.py next` as usual. A missing or disallowed Status or Verdict is not an invalid result to `steps.py next`: it still routes through items 5 and 6. The rules below are the spec the script implements.

## Exceptions to the per-step loop

2. builder Status blocked → skip the verifier (never verify a blocked build) and run planner L3 on the task handoff (replan; it writes a new `planner-L3[-k].md`), move each `step-<n>/` with n at or above the blocked step that already holds builder or verifier output to `step-<n>.superseded-<k>/` (first free k), then run `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/steps.py split .sdlc/<task>` (optionally `--only N` for the steps being rewritten; `--only N` also runs that step's `(guard)` criteria against the current tree and refuses on a red guard or a guard that changed the work tree, a `plan defect` handled like the section 3 split refusal) to write the remaining step handoffs from the newest planner file (earlier plans stay in place; the script refuses a step dir that still holds builder or verifier output, so rename first; it rewrites a cited `step-<n>/<report>` path to the `step-<n>.superseded-<k>` folder that holds that report, and `dispatch.py prepare` refuses a builder or verifier whose step handoff cites a missing path or a prior attempt's report at the live step path, `steps.py lint <task dir>/step-<n>`), continue from the blocked step. Two exceptions: a block only on a file outside the step's scope criterion takes the scope widening route in item 9, and a block whose `plan defect:` Notes carry one `amend old:`/`amend new:` pair for an unbuilt step takes the criterion amend route in item 10 when `steps.py next` prints `amend`. An `amend applied:` line under `## Plan review` is the task's one replan, the same as a second planner result: a later replan asks the user (interactive) or stops the task (unattended). A blocked builder is never rerun at the same or a higher level and its step handoff never gets `## Previous attempt`; the replan reads the builder's Notes itself (a Notes line starting with `plan defect:` names the criterion to fix). A replanned step whose builder blocks again on the same finding (same criterion, same root cause) is a recurring finding: append a `recurring finding:` entry quoting both Notes to the task handoff's `## Plan review` before the replan.
4. Verdict fail → rebuild the same level once (it writes `builder-L<n>-<k>.md`, so earlier attempts stay for the rubric's "earlier builder-*.md with Status blocked" count), with the verifier's "For the next attempt" appended to the step handoff under `## Previous attempt` (`dispatch.py advance` appends it before it prepares the rebuild; never add it twice). Before a second fail bumps, check whether it is a recurring finding: same criterion and same root cause as the first fail's For the next attempt, after the rebuild addressed it. A recurring finding appends a `recurring finding:` entry quoting both notes to the task handoff's `## Plan review` and takes the 4.2 replan path (planner L3, supersede, split, continue from this step); no bump, no `## Previous attempt`, and it does not count toward a bump. Any other second fail → bump the builder one level and repeat. A fail at L5 → stop and ask the user. Exception: a fail whose `## For the next attempt` starts with `plan defect:` takes the 4.2 replan path (planner L3, supersede, split, continue from this step) unless `steps.py next` prints `swap`, which takes the swap route in item 8; either way it never rebuilds as a fail, never bumps a level, never adds `## Previous attempt`, and does not count toward "a second fail". Every other fail keeps the rule above.
7. Builder Status `inherited red: <tests>`, or verifier Verdict `inherited red: <tests>`: the gate was already red at the pre-build HEAD, and `steps.py next` prints `inherited`. Interactive: ask the user through AskUserQuestion (fix main first, rebuild once main is green, or stop). Unattended: stop the task and report the inherited tests. It is never a fail, a rebuild, a bump, a replan, or a reverify, and never waives the gate.
8. Criterion swap: a verifier fail tagged `plan defect:` whose `## For the next attempt` holds exactly one `swap old:` line (the defective criterion's command span) and one `swap new:` line (the full replacement criterion) makes `steps.py next` print `swap L<build level>`. Run `steps.py swap` as in the action list above: it checks the pair, rewrites that one criterion line in the step handoff, and reruns the new spans against the built tree; never edit the criterion by hand. Exit 0 → append `swap applied: step <n>: <its stdout line>` to `## Plan review` and rebuild at the printed level, with no `## Previous attempt`, no bump, and no count toward "a second fail". Exit 1 (a refusal, whose last line starts `plan defect:`) → append its stderr to `## Plan review` and take the 4.2 replan path. A swap comes only from the verifier, because whoever writes the work never sets its check: a builder's `plan defect:` note replans (item 2) unless it carries an amend pair for an unbuilt step (item 10), a route that stays bounded (one criterion, one per step, recorded, the task's one replan) and is still checked by the independent verifier. One swap per step: a second swap proposal on the same step replans.
9. Scope widening: a builder blocked only because a file it needs sits outside the step's scope criterion, when the conductor decides the file serves the task goal (interactive runs confirm through AskUserQuestion). The decision is never recorded as prose alone. Run `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/steps.py widen <task dir>/step-<n> <path>...`. When the step holds no scope criterion at all, add `--reason "<why>"`: the path list and the reason are then recorded under `## Scope widened` as the allow-list instead of refusing. Exit 0 → append `scope widened: step <n>: <its stdout line>` to the task handoff's `## Plan review` (create it if missing, keep earlier entries), then run the builder at the blocked builder's level; that run is not a bump, gets no `## Previous attempt`, and the widened block does not count toward the rubric's blocked-builder bump. Exit 1 → append a `scope decision: step <n>: <paths>` line and the stderr to `## Plan review`, then take the 4.2 replan path. Why: the conductor names only paths and the script rewrites the check, so "never edit the criterion by hand" and "whoever writes the work never sets its check" both hold.
10. Criterion amend: a builder blocked by one defective criterion of its own step, before the step is built, may add one `amend old:` line (the criterion's command span) and one `amend new:` line (the full replacement) under the `plan defect:` first line of its Notes. `steps.py next` prints `amend L<build level>` when the pair is present, no earlier builder in the step dir proposed one, the step is not built (no builder Status done, no verifier result), and the task's one replan is unused (fewer than two planner results, no `amend applied:` line under `## Plan review`); otherwise it prints `replan` with the reason. Run `steps.py amend` as in the action list above: it makes every check `steps.py swap` makes, runs a new `(guard)` span green and a new `(red)` span red now (a plain criterion is not run, since the build is partial), rewrites that one line, and appends `amend applied: step <n>: ...` under `## Plan review` itself. Exit 0 → rebuild at the printed level, no `## Previous attempt`, no bump, never counted toward a bump; after the rebuild `steps.py next` routes as usual, and the independent verifier checks the step against the amended criterion. Exit 1 → append its stderr to `## Plan review` and take the 4.2 replan path. Never edit the criterion by hand.
