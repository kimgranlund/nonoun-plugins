---
name: ticket
description: Stamp a typed ticket with the next id, or generate .sdlc/roadmap.md from ticket front matter in dependency order. NOT for free-text briefs, which stay with /handoff.
argument-hint: new <type> <slug> "title" [--numbered] | close <slug> [--force] [--reason "<text>"] [--ack-warnings "<why>"] [--dry-run] [--skip N[,N...]] [--expect DIGEST] [--numbered] | roadmap [--numbered] | check [--numbered] | archive [--dry-run] [--numbered]
allowed-tools: Bash(python3 ${CLAUDE_PLUGIN_ROOT}/scripts/tickets.py:*)
---
Arguments: `$ARGUMENTS`

1. Run `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/tickets.py --root .sdlc $ARGUMENTS`. With no args, run `check`.
2. On `new`, show the created path and ask the user to fill in the body sections.
3. On exit 1, report stderr.
4. `close <slug> [--force]` is normally run by `/file` after the filer, not by hand. `--reason "<text>"` closes a ticket finished by other work, skips the filer, files no follow-ups, and appends a `## Closed` section. `--ack-warnings "<why>"` closes while filer Warnings are open, files follow-ups normally, and appends a `## Closed` section with the date, the reason, and the quoted warnings; it refuses with `--force` or `--reason`, with empty text, or when no warnings are open, and with `--dry-run` it passes the gate and writes nothing. `--dry-run` applies the same refusals, lists the proposed follow-ups with 1-based indices and any `duplicate of T-NNNN` mark, then one `open T-NNNN <title> [<slug>]` line per other proposed, ready, or blocked ticket, plus each open ticket that exists only in another git worktree's same-relative ticket root as `open T-NNNN <title> [<slug>] (worktree <name>)` after the local lines (a local copy decides any id it holds), and writes nothing; it ends with an `expect <digest>` line. `--skip N[,N...]` files every follow-up except the named indices, needs `--expect <digest>`, and refuses, writing nothing, when the Follow-ups list changed since that dry run. A follow-up that exactly duplicates another ticket (normalized title or slug) is skipped automatically; the ticket being closed never counts. `--reason` does not combine with `--dry-run`, `--skip`, or `--expect`.

Rules:
- Numbered folders are opt-in, by `--numbered` on `new`, `close`, `roadmap`, or `check` for one call, or a `ticket_folders: numbered` line in `.sdlc/config` for the repo (a successful `new --numbered` or `close --numbered` appends that line when it is missing, so later plain calls stay numbered; plain `check` warns, without failing, when every folder has an `NNNN-` prefix but the config lacks the line); in numbered mode `new` names the folder `NNNN-<slug>` after the id it assigns (give the bare slug), `close` does the same for each follow-up with its own id, and `check` fails and `roadmap` refuses (writing nothing) on a `NNNN-` folder whose id is not `T-NNNN`; in numbered mode `close` also renames the folder to `.NNNN-<slug>` (first it runs `git grep --untracked -lF` from the git toplevel for the folder path `<rel>/NNNN-<slug>` (leaving out the ticket's own folder and `<root>/roadmap.md`) and refuses, writing nothing, naming each file that cites it; `--rewrite-refs` rewrites those references to `<rel>/.NNNN-<slug>` with the rename (`--dry-run --rewrite-refs` lists one `rewrite <file>` line each), and `--force` closes and leaves them (outside git there is no scan); hidden, still a closed ticket to every tool, in plain mode too, so archived tickets and their ids stay visible to `depends` and `new`), `check` fails on a dot folder that is not done or dropped, and `archive [--dry-run]` renames existing done/dropped numbered folders the same way; `_templates` and other dot entries stay skipped; without either, plain slugs, as before.
- Ids are allocated across worktrees: `new` and `close` follow-ups take the next id above the max across the same-relative ticket root in every `git worktree list` tree (local root only outside git). `check` fails on two tickets sharing an id and names both folders, which catches branches not checked out in any worktree after merge.
- Never hand-edit `.sdlc/roadmap.md`. Change front matter and then rerun `roadmap`.
- Front matter `status` is a person's decision; build progress stays with `/board`.
