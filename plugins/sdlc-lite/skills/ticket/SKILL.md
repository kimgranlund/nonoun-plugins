Arguments: `$ARGUMENTS`

## Arguments

| Argument | Meaning | Default | Example |
|---|---|---|---|
| `new`, `close`, `claim`, `release`, `roadmap`, `check`, `archive`, `number`, `migrate-layout`, `migrate-size`, `blockers` | The subcommand, passed to `tickets.py` as written | `check` | `roadmap` |
| `<type>` | With `new`: `feature`, `bug`, `chore`, `spike`, or `idea` | - | `new bug board-crash` |
| `<slug>` | With `new`: the bare slug of the new folder. With `close`: the ticket folder | - | `close board-crash` |
| `"title"` | With `new`: the title stamped into the ticket | none | `new bug board-crash "Board crashes on empty root"` |
| `--numbered` | With `new`, `close`, `roadmap`, `check`, or `archive`: use `NNNN-<slug>` folders for this call | the `ticket_folders:` line in `.sdlc/config` | `new bug board-crash --numbered` |
| `<id>` | With `claim` or `release`: the ticket id (`T-NNNN`) or folder name | - | `claim T-0042 --by claude` |
| `--by AGENT` | With `claim`: the agent taking the ticket, written as `claimed_by: <agent> <YYYY-MM-DD>`. In git the claim also creates `refs/sdlc/claims/<id>` (create only if absent), so a second claim from any worktree refuses naming the holder; release and close delete it | `$SDLC_HOST`, else `claude` or `codex` with `:<session>` from the host | `--by codex` |
| `--handover` | With `claim`: take over a held claim, replacing the value and appending one dated body line; needs `--reason` | off | `claim T-0042 --by codex --handover --reason "claude session ended"` |
| `--force` | With `close`: close over open Warnings and leave citing files. With `archive`: archive and leave citing files | off | `close board-crash --force` |
| `--filer` | With `close`: close through the filer's draft (warnings and follow-ups from `filer-L*.md`) instead of the verifier `## Notes`; run only when a filer draft was asked for (`/file`) | off | `close board-crash --filer` |
| `--changed TEXT` | With `close`: the `- Changed:` line of the `## Outcome` | `see commits` | `close board-crash --changed "board renders an empty root"` |
| `--reason TEXT` | With `close`: close a ticket finished by other work, with no verifier gate, no filer and no follow-ups; the `## Outcome` verdict reads `closed by reason (TEXT)`. With `claim --handover`: why the claim changes hands | - | `close board-crash --reason "done by T-0101"` |
| `--ack-warnings TEXT` | With `close --filer`: close while filer Warnings are open, with the reason they no longer apply | - | `close board-crash --ack-warnings "fixed since"` |
| `--dry-run` | With `close`, `archive`, `number`, or `migrate-layout`: list what would happen and write nothing | off | `close board-crash --dry-run` |
| `--skip N[,N...]` | With `close`: drop the follow-ups at these 1-based indices; needs `--expect` | none | `--skip 2,3` |
| `--ticket N` | With `close`: file follow-up N, a `decide:` item, as the one ticket; needs `--expect` | no ticket filed | `--ticket 1` |
| `--expect DIGEST` | With `close`: the digest from the last line of the dry run | - | `--expect 3fa9c1` |
| `--rewrite-refs` | With `close`, `archive`, or `migrate-layout`: rewrite files that cite a moved folder | off | `archive --rewrite-refs` |
| `--preflight` | With `close`: read-only; print `ready` (exit 0) or one line per item close will demand (exit 1), writing nothing | off | `close board-crash --preflight` |
| `--keep-refs` | With `close`: leave citing files as they are and list them on a `- Deviation:` line of the `## Outcome`, without overriding open Warnings | off | `close board-crash --keep-refs` |
| `--apply` | With `migrate-size`: write the rewrites; without it the run is a dry run | off | `migrate-size --apply` |
| `--scope PATH` | With `blockers`: narrow the list to one task or ticket dir | every ticket | `blockers --scope .sdlc/add-retry` |

Config note for `close`: each `citation_skip: a, b` line of `.sdlc/config` holds globs of files the citation scan leaves out, and `runtime/` under the ticket root is always left out. The globs match the toplevel-relative path, which includes its `.sdlc/` prefix, so a bare file-name glob skips nothing (`citation_skip: .sdlc/docs/inventory.md`, not `inventory.md`).

1. Run `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/tickets.py --root .sdlc $ARGUMENTS`. With no args, run `check`.
2. On `new`, show the created path and ask the user to fill in the body sections. Give the new ticket a budget at filing with `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/budget.py set <ticket dir> --tier L1|L2|L3` (by ticket level: L1 $5, L2 $30, L3 $60; L4 and L5 get none), editable with `--usd N`. When a run stops at 80 percent of it (`dispatch.py prepare` exit 4; Codex: `run.sh`), ask the user one question and record the answer with `budget.py ack <ticket dir> --usd N --reason TEXT`.
3. On exit 1, report stderr.
4. `close <slug> [--force]` is normally run by /chain, /fix or `/file`, not by hand. By default it reads each step's newest verifier verdict (the verdict gate) and takes the follow-ups from the verifier `## Notes`; it reads the filer's draft only with `--filer`. Every route appends a `## Outcome` section. Each follow-up bullet starts with a tag: `fix-now:` (small related work, finished in this session), `decide:` (needs a decision or is out of scope), or `note:` (worth remembering, no action); an untagged bullet counts as `decide:`, and the title, slug, and duplicate check use the text after the tag. Close files at most one ticket: `--ticket N` makes item N, which must be a `decide:` item, a proposed idea ticket, and needs `--expect <digest>`; it refuses, writing nothing, on a `fix-now:` or `note:` item, a duplicate, an index out of range or in `--skip`, or with `--reason`. Without `--ticket`, close files no ticket. Every other item that is not skipped or a duplicate is appended to `.sdlc/notes.md` (`.sdlc/notes/notes.md` with `layout: topics`) under `## <id>: <title> (<date>)` as `- <tag>: <text>`. `--reason "<text>"` closes a ticket finished by other work, skips the verifier gate and the filer, files no follow-ups, and writes the `## Outcome` with verdict `closed by reason (<text>)`. `--filer --ack-warnings "<why>"` closes while filer Warnings are open, handles follow-ups as a plain close does, and writes each quoted warning as an `## Outcome` line `- Deviation: acknowledged warning (<why>): <line>`; it refuses without `--filer`, with `--force` or `--reason`, with empty text, or when no warnings are open, and with `--dry-run` it passes the gate and writes nothing. `--dry-run` applies the same refusals, lists each follow-up as `<i>. <tag>: <title>` with a mark (`[<slug>] ticket` for the `--ticket` item, `note` for one bound for notes.md, `skip (--skip)`, or `duplicate of T-NNNN`), then one `open T-NNNN <title> [<slug>]` line per other proposed, ready, or blocked ticket, plus each open ticket that exists only in another git worktree's same-relative ticket root as `open T-NNNN <title> [<slug>] (worktree <name>)` after the local lines (a local copy decides any id it holds), and writes nothing, notes.md included (`--dry-run --ticket N` needs no `--expect`); it ends with an `expect <digest>` line over the full bullets, tags included. `--skip N[,N...]` drops the named indices (neither ticket nor notes.md), needs `--expect <digest>`, and refuses, writing nothing, when the Follow-ups list changed since that dry run. A follow-up that exactly duplicates another ticket (normalized title or slug) is skipped automatically; the ticket being closed never counts. `--reason` does not combine with `--dry-run`, `--skip`, `--expect`, or `--ticket`.

Rules:
- Numbered folders are opt-in, by `--numbered` on `new`, `close`, `roadmap`, or `check` for one call, or a `ticket_folders: numbered` line in `.sdlc/config` for the repo (a successful `new --numbered` or `close --numbered` appends that line when it is missing, so later plain calls stay numbered; plain `check` warns, without failing, when every folder has an `NNNN-` prefix but the config lacks the line); in numbered mode `new` names the folder `NNNN-<slug>` after the id it assigns (give the bare slug), `close` does the same for its one follow-up ticket, and `check` fails and `roadmap` refuses (writing nothing) on a `NNNN-` folder whose id is not `T-NNNN`; in numbered mode `close` also renames the folder to `.NNNN-<slug>` (first it runs `git grep --untracked -lF` from the git toplevel for the folder path `<rel>/NNNN-<slug>` (leaving out the ticket's own folder and `<root>/roadmap.md`) and refuses, writing nothing, naming each file that cites it. The scan finds the folder name, then keeps files with a literal `<rel>/<slug>` (counted only where it starts a path token, at the start of the text or after whitespace, a quote, a backtick, a paren, or a bracket, so `other/<rel>/<slug>`, an absolute path into another tree, and `../other/<rel>/<slug>` are not references, and neither is a URL or prefixed form such as `https://.../<rel>/<slug>` or `key=<rel>/<slug>`; never running on into a longer folder name) or a path token that resolves to the folder, whether toplevel-relative, relative to the citing file's directory, or absolute. Only matched tokens are rewritten, keeping their form; there is no case folding, symlink resolution, `~` expansion or self-reference handling. `--rewrite-refs` rewrites those references to `<rel>/.NNNN-<slug>` with the rename (`--dry-run --rewrite-refs` lists one `rewrite <file>` line each), and `--force` closes and leaves them (outside git there is no scan; a second pass reads every file under `.sdlc/` with ignore rules off, so a gitignored `.sdlc/AGENTS.md` that cites `tickets/NNNN-<slug>` counts too); hidden, still a closed ticket to every tool, in plain mode too, so archived tickets and their ids stay visible to `depends` and `new`), `check` fails on a dot folder that is not done or dropped, and `archive [--dry-run] [--rewrite-refs] [--force]` renames existing done/dropped numbered folders the same way, after running the same reference scan as `close` for every folder it would rename (a file inside another folder archived in the same run counts), and refuses, writing nothing, naming each citing file; `--rewrite-refs` rewrites them to the dot form before renaming (`--dry-run --rewrite-refs` lists one `rewrite <file>` line each), `--force` archives and leaves them, and outside git there is no scan; `_templates` and other dot entries stay skipped; without either, plain slugs, as before. To convert an existing plain-slug root, run `number [--dry-run]`: it renames each `<slug>` ticket folder to `NNNN-<slug>` after its id, rewrites every cite of `<rel>/<slug>` (the same scan, plus files inside the folder) to `<rel>/NNNN-<slug>`, persists the config line, and regenerates the roadmap, refusing and writing nothing on a bad ticket, a non `T-NNNN` id, or an existing target; follow with `archive --rewrite-refs` to hide done and dropped folders.
- Ids are allocated across worktrees: `new` and `close` follow-ups take the next id above the max across the same-relative ticket root in every `git worktree list` tree (local root only outside git). `check` fails on two tickets sharing an id and names both folders, which catches branches not checked out in any worktree after merge. An `external_branch: <branch>` line in `.sdlc/config` (one per line) registers a branch checked out nowhere; `new` and `close` follow-ups also count the ticket ids committed on it, and `check` warns (exit 0) when the name is not a local branch. `check` also warns (exit 0) for each closed ticket whose handoff still holds its type's template prompt text (newest five, then a count).
- `depends:` takes `T-NNNN`, `file:<path>` (repo-relative, met once the path exists, never orders), and `cap:<name>` (met once a `done` ticket lists it in `provides:`, orders after every provider); unmet entries are marked `(unmet)` in the roadmap, and `check` fails a malformed entry or an unprovided `cap:`. A roadmap goes stale when a named file lands or a provider closes, so rerun `roadmap`.
- Delivered work is detected, not trusted to memory: `check` warns (exit 0) for each open ticket whose id starts a commit subject (`T-NNNN:`) on the default branch (`origin/HEAD`, else `main`, else `master`; a commit on an unmerged branch never counts) and prints its `close <folder> --reason "delivered in <sha>"` line. An optional `successor: T-NNNN` (or `<repo>:T-NNNN` for another repository) records one ticket superseded, delivered under another, verified by an integration ticket, or fixed elsewhere; when the local successor is `done`, `check` prints the ready-to-run `close <folder> --reason "..."` line, and a cross-repository successor is shown but not resolved. The roadmap Status cell carries `(successor <ref>)`. `check` fails a malformed `successor:` or a local id no ticket has.
- `ticket_root: tickets` in `.sdlc/config` is opt-in and keeps ticket folders under `.sdlc/tickets/`. roadmap.md, notes.md, config, and `_templates/` stay in `.sdlc/` unless `layout: topics` (which also needs the `ticket_root: tickets` line, so other worktrees and tools find the ticket folders) moves roadmap.md to `.sdlc/tickets/roadmap.md` and notes.md to `.sdlc/notes/notes.md` and adds `.sdlc/work/` for tasks with no ticket, and a ticket folder left directly in `.sdlc/` fails `check`. Every command that regenerates the roadmap also regenerates the router block in `.sdlc/AGENTS.md` (and `.sdlc/tickets/AGENTS.md`). It also writes the mailbox entry files in `.sdlc/messages/`, whose `AGENTS.md` holds the mailbox procedures that the router's Mailbox line links. The block lists each stage's count and the open tickets, and carries the create, claim, and close procedures. A `tickets_cmd: <command>` line in `.sdlc/config` (for example `tickets_cmd: python3 .sdlc/tickets-run.py`) names the repo's own launcher, and the procedures then print it in place of the raw `tickets.py --root .sdlc` command. `check` fails when a router block is missing, stale, or malformed, or when a `CLAUDE.md` lacks `@AGENTS.md`. `check` also warns (exit 0) on a relative link in `.sdlc/AGENTS.md`, outside the block, whose target is missing while its dot folder exists (a link to a ticket folder that `close` renamed). After an upgrade, run `roadmap` once to write the router. Every subcommand except `new` refuses, writing nothing, a `--root` that holds no `config`, `roadmap.md` or ticket folder. An optional `claimed_by: <harness> <YYYY-MM-DD>` front matter line marks a claim and shows in the router. `claim <id> --by <agent>` sets `status: claimed`, writes that line directly after `created:`, and regenerates the roadmap; it refuses a held claim unless `--handover --reason TEXT`. `release <id>` removes the line, sets `status: ready`, and regenerates the roadmap. `check` warns (exit 0) on a claim line with a trailing comment, a claim line not directly after `created:`, and a claim older than `claim_days:` in `.sdlc/config` (default 7) when no `*.running` file sits under the ticket folder.
- Upgrading to the topics layout (`migrate-layout [--dry-run] [--rewrite-refs]`): a flat `.sdlc/` keeps working, and `check` warns. To move, commit everything and run `tickets.py migrate-layout --dry-run` to see each move and citing file, then run `migrate-layout --rewrite-refs` (or fix the cites by hand), commit, and run `onboard.py setup` to refresh the root `AGENTS.md` block. Records under `docs/reports/` are never rewritten. A `layout: flat` line in `.sdlc/config` keeps the flat layout and silences the warning.
- Never hand-edit the roadmap (`.sdlc/roadmap.md`, or `.sdlc/tickets/roadmap.md` with `layout: topics`). Change front matter and then rerun `roadmap`. It lists open tickets only and counts done and dropped ones in one `Closed:` line.
- Front matter `status` is a person's decision; build progress stays with `/board`.
- An optional `area:` names the ticket's domain and must be one of the names on an `areas: a, b, c` line in `.sdlc/config`; the roadmap then gains an Area column and the board Ticket cell reads `<status> · <area>`. `status: claimed` needs `claimed_by:`, and `status: paused` needs `paused_reason:`. `branch:` and `worktree:` (the lane worktree, relative to the main checkout) are written together by the lane opener (`lanes.py open`, or `tickets.py branch <id> <branch> --worktree <path>` for a lane made another way) and removed together when the lane closes; `check` warns (exit 0) when `worktree:` is not a registered worktree on that branch. Existing tickets need no migration: an absent `area` is valid and every existing status stays valid.
