name: ticket
description: "Stamp a typed ticket with the next id, or generate the roadmap (.sdlc/roadmap.md, or .sdlc/tickets/roadmap.md with layout: topics) from ticket front matter in dependency order. NOT for free-text briefs, which stay with /handoff."
argument-hint: "new <type> <slug> \"title\" [--numbered] | close <slug> [--force] [--reason \"<text>\"] [--ack-warnings \"<why>\"] [--dry-run] [--skip N[,N...]] [--ticket N] [--expect DIGEST] [--numbered] | roadmap [--numbered] | check [--numbered] | archive [--dry-run] [--rewrite-refs] [--force] [--numbered] | number [--dry-run] | migrate-layout [--dry-run] [--rewrite-refs]"
allowed-tools: Bash(python3 ${CLAUDE_PLUGIN_ROOT}/scripts/tickets.py:*), Bash(python3 ${CLAUDE_PLUGIN_ROOT}/scripts/budget.py:*)
---

**Codex host:** Before following this workflow, read [the Codex adapter](../sdlc-lite/SKILL.md) and apply its tool, argument, path, and process translations. Claude Code follows the workflow below directly.

Arguments: `$ARGUMENTS`

1. Run `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/tickets.py --root .sdlc $ARGUMENTS`. With no args, run `check`.
2. On `new`, show the created path and ask the user to fill in the body sections. Give the new ticket a budget at filing with `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/budget.py set <ticket dir> --tier S|M|L` (S $5, M $30, L $60; XL gets none), editable with `--usd N`. When a run stops at 80 percent of it (run.sh exit 4), ask the user one question and record the answer with `budget.py ack <ticket dir> --usd N --reason TEXT`.
3. On exit 1, report stderr.
4. `close <slug> [--force]` is normally run by `/file` after the filer, not by hand. Each Follow-ups bullet starts with a tag: `fix-now:` (small related work, finished in this session), `decide:` (needs a decision or is out of scope), or `note:` (worth remembering, no action); an untagged bullet counts as `decide:`, and the title, slug, and duplicate check use the text after the tag. Close files at most one ticket: `--ticket N` makes item N, which must be a `decide:` item, a proposed idea ticket, and needs `--expect <digest>`; it refuses, writing nothing, on a `fix-now:` or `note:` item, a duplicate, an index out of range or in `--skip`, or with `--reason`. Without `--ticket`, close files no ticket. Every other item that is not skipped or a duplicate is appended to `.sdlc/notes.md` (`.sdlc/notes/notes.md` with `layout: topics`) under `## <id>: <title> (<date>)` as `- <tag>: <text>`. `--reason "<text>"` closes a ticket finished by other work, skips the filer, files no follow-ups, and appends a `## Closed` section. `--ack-warnings "<why>"` closes while filer Warnings are open, handles follow-ups as a plain close does, and appends a `## Closed` section with the date, the reason, and the quoted warnings; it refuses with `--force` or `--reason`, with empty text, or when no warnings are open, and with `--dry-run` it passes the gate and writes nothing. `--dry-run` applies the same refusals, lists each follow-up as `<i>. <tag>: <title>` with a mark (`[<slug>] ticket` for the `--ticket` item, `note` for one bound for notes.md, `skip (--skip)`, or `duplicate of T-NNNN`), then one `open T-NNNN <title> [<slug>]` line per other proposed, ready, or blocked ticket, plus each open ticket that exists only in another git worktree's same-relative ticket root as `open T-NNNN <title> [<slug>] (worktree <name>)` after the local lines (a local copy decides any id it holds), and writes nothing, notes.md included (`--dry-run --ticket N` needs no `--expect`); it ends with an `expect <digest>` line over the full bullets, tags included. `--skip N[,N...]` drops the named indices (neither ticket nor notes.md), needs `--expect <digest>`, and refuses, writing nothing, when the Follow-ups list changed since that dry run. A follow-up that exactly duplicates another ticket (normalized title or slug) is skipped automatically; the ticket being closed never counts. `--reason` does not combine with `--dry-run`, `--skip`, `--expect`, or `--ticket`.

Rules:
- Numbered folders are opt-in, by `--numbered` on `new`, `close`, `roadmap`, or `check` for one call, or a `ticket_folders: numbered` line in `.sdlc/config` for the repo (a successful `new --numbered` or `close --numbered` appends that line when it is missing, so later plain calls stay numbered; plain `check` warns, without failing, when every folder has an `NNNN-` prefix but the config lacks the line); in numbered mode `new` names the folder `NNNN-<slug>` after the id it assigns (give the bare slug), `close` does the same for its one follow-up ticket, and `check` fails and `roadmap` refuses (writing nothing) on a `NNNN-` folder whose id is not `T-NNNN`; in numbered mode `close` also renames the folder to `.NNNN-<slug>` (first it runs `git grep --untracked -lF` from the git toplevel for the folder path `<rel>/NNNN-<slug>` (leaving out the ticket's own folder and `<root>/roadmap.md`) and refuses, writing nothing, naming each file that cites it. The scan finds the folder name, then keeps files with a literal `<rel>/<slug>` (counted only where it starts a path token, at the start of the text or after whitespace, a quote, a backtick, a paren, or a bracket, so `other/<rel>/<slug>`, an absolute path into another tree, and `../other/<rel>/<slug>` are not references, and neither is a URL or prefixed form such as `https://.../<rel>/<slug>` or `key=<rel>/<slug>`; never running on into a longer folder name) or a path token that resolves to the folder, whether toplevel-relative, relative to the citing file's directory, or absolute. Only matched tokens are rewritten, keeping their form; there is no case folding, symlink resolution, `~` expansion or self-reference handling. `--rewrite-refs` rewrites those references to `<rel>/.NNNN-<slug>` with the rename (`--dry-run --rewrite-refs` lists one `rewrite <file>` line each), and `--force` closes and leaves them (outside git there is no scan); hidden, still a closed ticket to every tool, in plain mode too, so archived tickets and their ids stay visible to `depends` and `new`), `check` fails on a dot folder that is not done or dropped, and `archive [--dry-run] [--rewrite-refs] [--force]` renames existing done/dropped numbered folders the same way, after running the same reference scan as `close` for every folder it would rename (a file inside another folder archived in the same run counts), and refuses, writing nothing, naming each citing file; `--rewrite-refs` rewrites them to the dot form before renaming (`--dry-run --rewrite-refs` lists one `rewrite <file>` line each), `--force` archives and leaves them, and outside git there is no scan; `_templates` and other dot entries stay skipped; without either, plain slugs, as before. To convert an existing plain-slug root, run `number [--dry-run]`: it renames each `<slug>` ticket folder to `NNNN-<slug>` after its id, rewrites every cite of `<rel>/<slug>` (the same scan, plus files inside the folder) to `<rel>/NNNN-<slug>`, persists the config line, and regenerates the roadmap, refusing and writing nothing on a bad ticket, a non `T-NNNN` id, or an existing target; follow with `archive --rewrite-refs` to hide done and dropped folders.
- Ids are allocated across worktrees: `new` and `close` follow-ups take the next id above the max across the same-relative ticket root in every `git worktree list` tree (local root only outside git). `check` fails on two tickets sharing an id and names both folders, which catches branches not checked out in any worktree after merge. An `external_branch: <branch>` line in `.sdlc/config` (one per line) registers a branch checked out nowhere; `new` and `close` follow-ups also count the ticket ids committed on it, and `check` warns (exit 0) when the name is not a local branch.
- `depends:` takes `T-NNNN`, `file:<path>` (repo-relative, met once the path exists, never orders), and `cap:<name>` (met once a `done` ticket lists it in `provides:`, orders after every provider); unmet entries are marked `(unmet)` in the roadmap, and `check` fails a malformed entry or an unprovided `cap:`. A roadmap goes stale when a named file lands or a provider closes, so rerun `roadmap`.
- `ticket_root: tickets` in `.sdlc/config` is opt-in and keeps ticket folders under `.sdlc/tickets/`. roadmap.md, notes.md, config, and `_templates/` stay in `.sdlc/` unless `layout: topics` (which also needs the `ticket_root: tickets` line, so other worktrees and tools find the ticket folders) moves roadmap.md to `.sdlc/tickets/roadmap.md` and notes.md to `.sdlc/notes/notes.md` and adds `.sdlc/work/` for tasks with no ticket, and a ticket folder left directly in `.sdlc/` fails `check`. Every command that regenerates the roadmap also regenerates the router block in `.sdlc/AGENTS.md` (and `.sdlc/tickets/AGENTS.md`). It also writes the mailbox entry files in `.sdlc/messages/`, whose `AGENTS.md` holds the mailbox procedures that the router's Mailbox line links. The block lists each stage's count and the open tickets, and carries the create, claim, and close procedures. `check` fails when a router block is missing, stale, or malformed, or when a `CLAUDE.md` lacks `@AGENTS.md`. After an upgrade, run `roadmap` once to write the router. An optional `claimed_by: <harness> <YYYY-MM-DD>` front matter line marks a claim and shows in the router.
- Upgrading to the topics layout (`migrate-layout [--dry-run] [--rewrite-refs]`): a flat `.sdlc/` keeps working, and `check` warns. To move, commit everything and run `tickets.py migrate-layout --dry-run` to see each move and citing file, then run `migrate-layout --rewrite-refs` (or fix the cites by hand), commit, and run `onboard.py setup` to refresh the root `AGENTS.md` block. Records under `docs/reports/` are never rewritten. A `layout: flat` line in `.sdlc/config` keeps the flat layout and silences the warning.
- Never hand-edit the roadmap (`.sdlc/roadmap.md`, or `.sdlc/tickets/roadmap.md` with `layout: topics`). Change front matter and then rerun `roadmap`.
- Front matter `status` is a person's decision; build progress stays with `/board`.
