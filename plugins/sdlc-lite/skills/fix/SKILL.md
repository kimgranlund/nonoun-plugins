**Codex host:** Before following this workflow, read the Codex adapter at `${CLAUDE_PLUGIN_ROOT}/skills/sdlc-lite/SKILL.md` and apply its tool, argument, path, and process translations. Claude Code follows the workflow below directly.

For every role launch, pass `--routing-reason` to `dispatch.py prepare` (Codex: `SDLC_ROUTING_REASON`) as the selected role/level rationale, including the recorded cause of any escalation or replan. Read shared run operations at `${CLAUDE_PLUGIN_ROOT}/skills/handoff-format/run-operations.md` for readiness, attempt records, and safe recovery.

Arguments: `$ARGUMENTS`

The fast lane: one step, no planner, no filer, no follow-up tickets. It runs only when the user asks for it or the lane script prints `fix`; otherwise ticket levels L1 and L2 go to `solo` (agents/solo.md). Layout follows `${CLAUDE_PLUGIN_ROOT}/skills/handoff-format/SKILL.md`; levels follow `${CLAUDE_PLUGIN_ROOT}/skills/level-rubric/SKILL.md`.

Long runs: every role is dispatched from the project root as a sub-agent, in three steps that `${CLAUDE_PLUGIN_ROOT}/agents/conductor.md` ("How you run roles") spells out: `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/dispatch.py prepare <role> <level> <handoff.md>` prints the dispatch JSON; an `Agent` call passes its `subagent_type`, `name`, `description`, `model`, `prompt`, and `run_in_background` unchanged; `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/dispatch.py record <dispatch_file> --agent-id <id> --tokens <n> --transcript <sub-agent transcript jsonl> --tool-uses <n> --duration-ms <ms>`, with the sub-agent's final message on stdin, validates and records the result; record each role before you prepare the next. "Dispatch" below means those three steps. Headless (`claude -p`): `prepare` prints `run_in_background: false` under `SDLC_HEADLESS=1`, so spawn in the foreground and wait for the result in the same turn; never end your turn while a role is running, because ending the turn ends the session and abandons the run; headless launchers set `SDLC_HEADLESS=1`, and `hooks/block-background.sh` denies background calls then. In an interactive session: spawn with `run_in_background: true`, then wait for the completion notification. Never poll with `sleep`. Once notified, run `dispatch.py record`, then read the result from `<role>-<level>.md`. On Codex a role runs through `SDLC_BACKEND=codex run.sh <role> <level> <handoff.md>` as the Codex adapter describes. Claude: after `record`, run `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/dispatch.py prune`, make each `TaskStop task_id=<name>` call it lists, then `prune --done <name>`; a finished sub-agent stays an idle teammate until stopped.

1. Level gate. Ticket level L1 means docs, a lint tweak, one test, or a fix in one file with an obvious effect, provable by 1 to 3 checks. Anything else: say so in one line and route to `/sdlc-lite:chain`.
2. Handoff. Use `.sdlc/<slug>/handoff.md` when it exists (a ticket); otherwise create it per handoff-format's free-text rule. Write `.sdlc/<slug>/step-1/handoff.md` yourself per the step template: `## Task goal`, `## Step 1: <title>`, `level: L1` or `L2` per the builder rubric, a `### Read first` subsection when the fixed file's nearest `AGENTS.md` is not the root (same rule as the planner: one ``- `<path>` `` line per entry, after `level:` and before `### Do`), `### Do`, and `### Acceptance criteria` with 1 to 3 criteria, each a runnable command span that is red now or a `(guard)` that is green now, no `||`, no pinned sha. Run `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/steps.py lint .sdlc/<slug>/step-1/handoff.md` and fix any refusal. Never run `steps.py split`.
3. Build and verify. First append `- lane: fix; point: before planning; reasons: user asked for /fix` under a `## Lane` heading in `.sdlc/<slug>/skips.md` (create the file if missing), and under a `## Skipped` heading in the same file `- skip: planner; step: all; reason: /fix runs no planner; decided: fix` and `- skip: filer; step: all; reason: /fix runs no filer; decided: fix`, so `dispatch.py prepare` does not gate the builder as a solo-lane ticket and the close by reason in step 4 is accepted. Dispatch builder `<level>` on `.sdlc/<slug>/step-1/handoff.md`, then run `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/steps.py next .sdlc/<slug>/step-1`, then dispatch verifier L1 on the same handoff. On a fail, rebuild once at the same level with the verifier's note under `## Previous attempt`. A second fail, a blocked builder, or `inherited` or `invalid result` from `steps.py next`: stop, report, and offer /chain (the item was not level L1). Never bump, replan, or fix it yourself.
4. Close. On a pass, when the task handoff has ticket front matter, run `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/tickets.py --root .sdlc close <slug> --reason "fixed in session by /fix: <one line>"`. No filer, no follow-ups. No ticket: nothing to close.
5. Publish (commit, push, PR) only after an AskUserQuestion approval, as in /file step 4; never publish on your own. Unattended (headless, or an unattended goal, no person present): never call AskUserQuestion, never push or open a pull request (a local commit is the most it may do), and end with a report that lists the work waiting to be published. Report with `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/board.py --task <slug>`.
