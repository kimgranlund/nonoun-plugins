**Codex host:** Before following this workflow, read the Codex adapter at `${CLAUDE_PLUGIN_ROOT}/skills/sdlc-lite/SKILL.md` and apply its tool, argument, path, and process translations. Claude Code follows the workflow below directly.

Arguments: `$ARGUMENTS`

## Arguments

| Argument | Meaning | Default | Example |
|---|---|---|---|
| `<agent>` | The agent name: `solo`, `scout`, `researcher`, `architect`, `archaeologist`, or `ui-designer` | - | `scout` |
| `--level L1\|L2\|L3` | The level to launch the agent at | the Default column of the name table | `--level L2` |
| `<instructions>` | Everything after the name and the optional flag: the ticket, task, or question | - | `where is the retry logic` |

The first word is the agent name. Everything after the optional `--level` flag is the instructions. Match the name against this list and nothing else; never guess a near match.

| Name | Start path | Default |
|---|---|---|
| `solo` | The `## Start` section of `${CLAUDE_PLUGIN_ROOT}/agents/solo.md`: a background sub-agent on Claude Code, `sdlc-solo-l1` to `l3` on Codex (in a live Codex session, first run `codex_roles.py preflight <project root> sdlc-solo-l<n> --catalog "<names callable now>"` and stop on a not-ready result; then `SDLC_BACKEND=codex SDLC_CODEX_TRANSPORT=subagent python3 "${CLAUDE_PLUGIN_ROOT}/scripts/solo_run.py" run --backend codex --task-dir <ticket folder> --tier <L1\|L2\|L3> --brief "<brief>" --no-worktree` with a short shell yield; spawn the agent named in `<records dir>/solo-<level>-<attempt>.request.json` (`order.py records-dir <ticket folder>` prints the dir) with exactly its prompt (its first line must be `profile: <fingerprint>`; check it with `codex_roles.py handshake` before accepting any edit); save its final report to a file and run `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/codex_exchange.py" <request.json> <report-file>` (`--failed` on an execution error); await the wrapper, which prints the report, removes the lock and response files and records the run; first check the role is callable and read the resume packet in the "Readiness and resume for conductors" section of `adapters/codex/instructions.md`) | L2, or the named ticket's level (its `size:`, L1 to L3) when the instructions name a ticket |
| `scout` | dispatch `scout` L1 on `<handoff>` (Codex: `scripts/run.sh scout L1 <handoff>`) | L1 |
| `researcher` | dispatch `researcher` at `<level>` on `<handoff>` (Codex: `scripts/run.sh researcher <level> <handoff>`), level per the `researcher` section of the level-rubric skill | per the rubric |
| `architect` | dispatch `architect` L1 on `<handoff>` (Codex: `scripts/run.sh architect L1 <handoff>`) | L1 |
| `archaeologist` | dispatch `archaeologist` L1 on `<handoff>` (Codex: `scripts/run.sh archaeologist L1 <handoff>`) | L1 |
| `ui-designer` | dispatch `ui-designer` at `<level>` on a `<handoff>` that holds a `mode:` line (Codex: `scripts/run.sh ui-designer <level> <handoff>`), level per the `ui-designer` section of the level-rubric skill | L1 |

Other SDLC Lite agents have their own path; answer in one line and stop: `planner` to `/sdlc-lite:plan`, `builder` to `/sdlc-lite:build`, `verifier` to `/sdlc-lite:verify`, `plan-reviewer` to `steps.py review`, `filer` to `/sdlc-lite:file`, `messenger` to `.sdlc/messages/AGENTS.md`. Refuse `conductor`: it is the session you are in. For any other name, print the names above and stop.

Workflow:
1. Resolve the level from the flag, else the default in the table. For `solo`, the ticket level is the solo level (L1, L2, or L3).
2. Print one line before launching: `Lane: <name> <level> because <reason>`. Pass the same reason for any dispatch (`dispatch.py prepare --routing-reason`; Codex: `SDLC_ROUTING_REASON` for `run.sh`).
3. For `solo`, write a typed brief from the instructions (the ticket or task, the files it needs, the check commands, the done criterion) and start it as `agents/solo.md` says, from the project root, through `scripts/solo_run.py`, which checks the budget and prints the dispatch JSON; spawn the Agent tool with that JSON (`subagent_type sdlc-lite:solo-<level>`, its model, effort, and prompt). When the sub-agent ends, close the row with `dispatch.py record <task dir>/<name>.dispatch.json` (add `--agent-id`, `--tool-uses`, `--duration-ms` from the completion notice, and `--transcript` when you have it): it prices the solo row and clears the live marker. When the run needs a lane worktree and branch, add `--worktree <name>` (with `--exec`): the launcher creates `<worktree root>/<name>` (`../<repo>.worktrees/<name>`) on a new branch `<name>` before the session starts, because the solo role cannot (`block-stray-worktree.sh`). When the instructions name a ticket, pass its folder as `--task-dir`; when they name none, pass `--new-task` instead (it creates a small task folder from the brief) so the run is still recorded and metered. A budget stop (exit 4) means the ticket is at 80 percent of its budget: report it and ask the user before `budget.py ack`. A report that starts `already fixed:` changed nothing: close the row and skip the verifier. For levels L2 and L3 a report that says `verify: skipped (docs/records only; docs_check green)` needs no verifier: close the row and stop. A report that changed code says `verify: needed`: run the `verifier` command in the dispatch JSON `solo_run.py` printed (`dispatch.py prepare verifier <level> <task dir>/handoff.md`, the level from `steps.py verifier-level <task dir>`: L2, or L3 for a size L4 or L5, merge, or security ticket or one whose criteria pin an exact label or string) and spawn its JSON (`hooks/block-role-spawn.sh` still denies a nested spawn from a role).
4. For the read-only roles and `ui-designer`, create a task folder under the ticket root (`<slug>/` in `.sdlc/` by default, `.sdlc/tickets/<slug>/` when `.sdlc/config` has `ticket_root: tickets`, `docs/work/<slug>/` when it has `work_root: docs/work`) and write `handoff.md` from the instructions per `${CLAUDE_PLUGIN_ROOT}/skills/handoff-format/SKILL.md`, with the instructions under `## Question`. For `ui-designer`, the handoff also holds one line, `mode: plan`, `mode: review`, or `mode: generate`, taken from the instructions (generate is the only mode that edits the tree); when the instructions name no mode, ask the user before writing it. Then dispatch the role from the project root as a sub-agent, in three steps: `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/dispatch.py prepare <role> <level> <handoff.md>` runs the gates and prints the dispatch JSON; an `Agent` call passes its `subagent_type`, `name`, `description`, `model`, `prompt`, and `run_in_background` unchanged; `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/dispatch.py record <dispatch_file> --agent-id <id> --tokens <n> --tool-uses <n> --duration-ms <ms>`, with the figures from the completion notice and nothing on stdin (stdin only when the role's transcript is missing), reads the result itself, validates and records the result (the contract is `${CLAUDE_PLUGIN_ROOT}/agents/conductor.md`, "How you run roles"). On Codex run `SDLC_BACKEND=codex ${CLAUDE_PLUGIN_ROOT}/scripts/run.sh <role> <level> <handoff.md>` instead. Claude: after `record`, run `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/dispatch.py prune`, make each `TaskStop task_id=<name>` call it lists, then `prune --done <name>`; a finished sub-agent stays an idle teammate until stopped.
5. Follow the interactive vs headless rule in `${CLAUDE_PLUGIN_ROOT}/agents/conductor.md`: in an interactive session start the agent in the background and keep talking with the user; headless, run it in the foreground and do not end your turn until it finishes.
6. When it finishes, report the result file path and a three-line summary. On failure (`record` exit 1 or 3), report the error and the result or `.limit` file path (Codex: the log path). Do not redo or extend the agent's work yourself.
